# Spec Delta

## MODIFIED Requirements

### Requirement: 一轮

事件检测的每一轮 SHALL 开始时从时钟读一次检测时刻、读一次股票池，然后按下表的顺序做六部分；这一轮的检测时刻、交易日、回看起点（检测时刻减「回看时长」）和是否在常规交易时段都按这一次读的时刻算：

| 顺序 | 部分 | 什么时候做 | 读什么 |
| --- | --- | --- | --- |
| 1 | 卖出成交 | 每一轮 | 交易记录，见「卖出成交」 |
| 2 | 价格、成交量和论点条件 | 检测时刻在常规交易时段里 | 账户数据（持仓的紧急阈值和今天开仓成交的均价）一次；全部监控股票的行情一次（market-data spec「取行情」）；论点用这一轮读到的股票池 |
| 3 | 公告 | 启动以后的第一轮，以及距上一次取公告满「公告间隔」时，取到和取不到都算一次 | 公告源，见「取新闻和公告」 |
| 4 | 财报日历 | 每一轮 | 状态库里每只监控股票的财报日历（company-data spec「读取财报」） |
| 5 | 新闻 | 每一轮 | 新闻源，见「取新闻和公告」 |
| 6 | 到价提醒 | 每一轮 | 按这一轮读到的股票池同步到价提醒（price-alerts spec「同步」） |

- 每一部分按 event-rules spec 判断，股票按代码的顺序；同一只股票的公告按受理时刻、新闻按发布时刻、再按 ID 的顺序
- 第 2 部分里每只股票依次判断价格、成交量、论点条件（event-rules spec「论点条件」），论点条件按入场条件、目标价、证伪条件的顺序
- 公告和财报日历在新闻之前：同一轮里财报发布先记下，当天的新闻就不再成为事件
- 股票池是空的时候，第 2 到第 5 部分什么都不做，不向行情源、新闻源和公告源请求；第 6 部分照做，删掉系统设的全部到价提醒
- 盘前、盘后和休市日照常做第 1、3、4、5、6 部分

本 spec 的场景没写论点时，BBB 的关注论点的入场条件是价格不高于 1，CCC 的投资论点目标价 1000、没有代码能检测的证伪条件：论点条件都不满足。

#### Scenario: 一轮里的先后

- **GIVEN** 这一轮取公告；CCC 最新价 95.5；公告源有 BBB 的 8-K（item 2.02），新闻源有 BBB 的标题"BBB Raises FY26 Guidance"的新闻
- **WHEN** 做一轮
- **THEN** 依次排进 K-1（CCC 的价格和成交量异动事件，持仓风险级别）、K-2（BBB 的财报发布事件）
- **AND** BBB 的新闻没有成为事件，程序日志的丢弃事件写明原因是当天已有财报发布事件

#### Scenario: 同一只股票的价格事件和论点条件事件

- **GIVEN** CCC 的投资论点的证伪条件中代码能检测的部分是价格不高于 96；CCC 最新价 95.5
- **WHEN** 做一轮
- **THEN** 依次排进 K-1（CCC 的价格和成交量异动事件，持仓风险级别，事件 ID CCC:2026-10-14:price_down）、K-2（CCC 的达到目标价或证伪条件触发事件，持仓风险级别，事件 ID CCC:2026-10-14:invalidation）
- **AND** 行情源只收到一次请求

#### Scenario: 入场条件满足排进案件

- **GIVEN** BBB 的关注论点的入场条件是价格不高于 95；BBB 最新价 94
- **WHEN** 做一轮
- **THEN** 依次排进 K-1（BBB 的价格和成交量异动事件，事件 ID BBB:2026-10-14:price_down）、K-2（BBB 的入场条件满足事件，事件 ID BBB:2026-10-14:entry，触发时刻 2026-10-14 15:00Z）
- **AND** 程序日志有两条检测到事件

#### Scenario: 盘前不取行情

- **GIVEN** 当前时刻 2026-10-14 12:00Z；新闻源有 BBB 的标题"BBB to Acquire Widget Co"的新闻，发布时刻 2026-10-14 11:50Z
- **WHEN** 做一轮
- **THEN** 行情源和券商账户没有收到请求
- **AND** 排进 K-1：BBB 的新闻事件，事件 ID BBB:2026-10-14:news
- **AND** 到价提醒照常同步

#### Scenario: 休市日照常检测新闻

- **GIVEN** 当前时刻 2026-10-17 15:00Z（周六）；新闻源有 BBB 的标题"BBB to Acquire Widget Co"的新闻，发布时刻 2026-10-17 14:50Z
- **WHEN** 做一轮
- **THEN** 排进 K-1：BBB 的新闻事件，事件 ID BBB:2026-10-19:news

#### Scenario: 公告的间隔

- **GIVEN** 公告间隔 5 分钟；上一次取公告是 2026-10-14 14:55:01Z
- **WHEN** 做一轮
- **THEN** 公告源没有收到请求
- **WHEN** 当前时刻 2026-10-14 15:00:01Z，做一轮
- **THEN** 公告源收到一次请求

#### Scenario: 股票池是空的

- **GIVEN** 股票池是空的；交易记录里有 ZZZ 全部成交的卖单 P9，成交日 2026-10-14；行情源上有系统设的 BBB 的到价提醒
- **WHEN** 做一轮
- **THEN** 行情源、新闻源和公告源都没有收到请求
- **AND** 排进 K-1：ZZZ 的卖出成交，客户端订单 ID 是 P9
- **AND** BBB 的到价提醒被删掉

### Requirement: 没成为事件的新闻和公告

一条新闻或一份公告对一只监控股票判断以后没有成为事件时，SHALL 写一条程序日志的丢弃事件，写明原因：event-rules spec 的初筛原因（来源不在名单里、标注的股票太多、命中排除词、没有命中关键词、级别不够、表单不算），当天已有新闻或公告事件，当天已有财报发布事件，最近已有财报发布事件，加入股票池以前发布。

下面这些 SHALL NOT 写程序日志：价格和成交量没有成为事件（没达到阈值、当天已有同一个事件 ID 的事件、行情不是当天的）；论点条件没有满足或者当天已有同一个事件 ID 的事件；财报日历上的发布还没到预计发布时刻或者已经有财报发布事件；不在监控范围的股票。

#### Scenario: 初筛没通过

- **GIVEN** 新闻源有 BBB 的标题"BBB Shares Are Trading Higher"的新闻；这一轮取公告，公告源有 BBB 的表单 4 的公告
- **WHEN** 做一轮
- **THEN** 没有排进案件
- **AND** 程序日志依次有两条丢弃事件：对象 BBB，输入的引用 0000000001-26-000001，原因表单不算；对象 BBB，输入的引用 101，原因没有命中关键词

#### Scenario: 价格没达到阈值不写

- **GIVEN** CCC 最新价 97
- **WHEN** 做一轮
- **THEN** 程序日志没有新条目

#### Scenario: 论点条件没满足不写

- **GIVEN** BBB 的关注论点的入场条件是价格不高于 95；BBB 最新价 99
- **WHEN** 做一轮
- **THEN** 程序日志没有新条目

### Requirement: 什么时候做一轮

事件检测 SHALL 在自己的线程里运行：

- 开始以后立即做第一轮；每一轮做完以后等「间隔」再做下一轮，间隔从上一轮做完算起
- 收到到价提醒的推送（price-alerts spec「推送」）时：在等下一轮的，立即开始下一轮；在做一轮的，这一轮做完以后立即再做一轮，这一轮里收到几次推送都只多做一轮。提前做的这一轮和平常的一轮完全相同，做完以后照样等间隔
- 一轮出错时写一条 ERROR（bootstrap spec「日志」），这一轮剩下的不做，下一轮照常
- 处于降级模式时照常检测和排队：降级模式不开始新案件，新的触发照常排队（Proposal「故障处理」）
- 停止时：在等下一轮的立即结束；在做一轮的，这一轮做完以后结束；停止以后收到的推送不再开始一轮
- 事件检测只读执行模块，SHALL NOT 拿执行模块和风控的那把锁（session-patrol spec「执行模块和风控的调用串行」）

#### Scenario: 开始以后立即做第一轮

- **WHEN** 事件检测开始
- **THEN** 不等间隔，交易记录和股票池立即被读一次

#### Scenario: 每一轮做完以后等间隔

- **GIVEN** 一轮从 15:00:00Z 开始，15:00:04Z 做完
- **WHEN** 事件检测继续运行
- **THEN** 下一轮在 15:01:04Z 开始

#### Scenario: 推送叫醒

- **GIVEN** 一轮在 15:00:04Z 做完
- **WHEN** 15:00:30Z 收到一次到价提醒的推送
- **THEN** 下一轮在 15:00:30Z 开始，不等到 15:01:04Z
- **WHEN** 这一轮在 15:00:33Z 做完，没有新的推送
- **THEN** 再下一轮在 15:01:33Z 开始

#### Scenario: 做一轮时收到推送

- **GIVEN** 一轮从 15:00:00Z 开始
- **WHEN** 15:00:01Z、15:00:02Z 各收到一次到价提醒的推送，这一轮在 15:00:04Z 做完
- **THEN** 15:00:04Z 再做一轮；这一轮做完以后等间隔

#### Scenario: 一轮出错

- **GIVEN** 这一轮读股票池时数据库出错
- **WHEN** 做一轮
- **THEN** 写一条 ERROR，这一轮没有排进案件
- **WHEN** 数据库恢复，之后一轮
- **THEN** 照常检测

#### Scenario: 降级时照常排队

- **GIVEN** 健康监控处于降级模式；CCC 最新价 95.5
- **WHEN** 做一轮
- **THEN** 排进 K-1：CCC 的价格和成交量异动事件

#### Scenario: 停止

- **GIVEN** 事件检测正在等下一轮
- **WHEN** 停止
- **THEN** 立即结束
- **GIVEN** 事件检测正在做一轮，新闻源还没有响应
- **WHEN** 停止
- **THEN** 新闻源响应、这一轮做完以后才结束
- **WHEN** 结束以后收到一次到价提醒的推送
- **THEN** 不再做一轮

### Requirement: 读不到时

一部分读不到时 SHALL 按下表处理，其他部分照常：

| 读不到 | 处理 |
| --- | --- |
| 行情源不可用，或者读账户数据时券商不可用 | 这一轮不判断价格、成交量和论点条件，写一条 WARNING |
| 行情源没有某只股票的数据 | 这只股票这一轮不判断价格、成交量和论点条件 |
| 持仓在账户数据里没有这只股票（股票池还没跟上持仓） | 这只股票这一轮不判断价格、成交量和论点条件 |
| 公告源不可用 | 这一轮不判断公告，写一条 WARNING；到下一次公告间隔再取 |
| 新闻源不可用 | 这一轮不判断新闻，写一条 WARNING；下一轮照常取 |
| 到价提醒不可用，或者一个到价提醒设置、删除失败 | 按 price-alerts spec「同步失败」 |
| 数据库出错（股票池、交易记录、财报日历、事件、新闻和公告、排队表） | 按「什么时候做一轮」的一轮出错处理 |

新闻源、公告源不可用时没有存下的新闻和公告，之后取到时仍是新存下的，照常判断：回看时长覆盖了这段时间。

#### Scenario: 行情源不可用

- **GIVEN** 行情源这一轮报行情不可用；新闻源有 BBB 的标题"BBB to Acquire Widget Co"的新闻
- **WHEN** 做一轮
- **THEN** 写一条 WARNING；没有价格、成交量和论点条件的事件
- **AND** 排进 K-1：BBB 的新闻事件

#### Scenario: 行情源没有某只股票

- **GIVEN** 行情源没有 BBB 的数据；CCC 最新价 95.5
- **WHEN** 做一轮
- **THEN** 排进 K-1：CCC 的价格和成交量异动事件；BBB 没有事件

#### Scenario: 新闻源不可用以后补上

- **GIVEN** 新闻源这一轮报数据源不可用
- **WHEN** 做一轮
- **THEN** 写一条 WARNING，没有新闻的事件
- **WHEN** 新闻源恢复，给出 BBB 的标题"BBB to Acquire Widget Co"的新闻，之后一轮
- **THEN** 排进 K-1：BBB 的新闻事件

#### Scenario: 公告源不可用

- **GIVEN** 这一轮取公告，公告源报数据源不可用
- **WHEN** 做一轮
- **THEN** 写一条 WARNING
- **WHEN** 之后一轮（15:01Z）
- **THEN** 公告源没有收到请求
- **WHEN** 2026-10-14 15:05Z 做一轮
- **THEN** 公告源收到请求

#### Scenario: 到价提醒不可用不影响事件

- **GIVEN** 到价提醒这一轮不可用；BBB 的关注论点的入场条件是价格不高于 95；BBB 最新价 94
- **WHEN** 做一轮
- **THEN** 排进 BBB 的入场条件满足事件
- **AND** 写一条 WARNING 写明到价提醒这一轮没有同步

## ADDED Requirements

### Requirement: 断线以后

论点条件 SHALL 只由每一轮按行情判断，不靠到价提醒的推送：推送只让下一轮提前开始。所以 OpenD 断线、程序没收到推送时：

- 断线期间行情源不可用，这几轮不判断（「读不到时」）
- OpenD 恢复以后的第一轮按那时的行情判断全部论点条件，满足的照常成为事件；不另外检测断线和恢复，也不另做补查

#### Scenario: 断线期间越过入场价

- **GIVEN** BBB 的关注论点的入场条件是价格不高于 95；OpenD 从 15:00Z 起断线，期间 BBB 跌到 94，没有收到推送
- **WHEN** 15:00Z、15:01Z 各做一轮
- **THEN** 都写 WARNING，没有 BBB 的事件
- **WHEN** 15:02Z OpenD 恢复，BBB 最新价 94，做一轮
- **THEN** 排进 BBB 的入场条件满足事件，事件 ID BBB:2026-10-14:entry

#### Scenario: 断线期间越过又回来

- **GIVEN** BBB 的关注论点的入场条件是价格不高于 95；OpenD 断线期间 BBB 跌到 94 又回到 96
- **WHEN** OpenD 恢复，BBB 最新价 96，做一轮
- **THEN** 没有 BBB 的入场条件满足事件
