# Proposal

## Why

人工确认现在只有一条规则：下单流程对 `/plan` 录入的四种动作一律请求确认（order-flow spec「请求人工确认」），紧急退出一律不请求确认（emergency-exit-flow spec「巡检里的紧急退出」）。完整版 Proposal 还有两条可以开关的规则没有落地：紧急风险退出「可配置为需要」人工确认；模型建议退出默认需要确认，人手动打开自动执行以后，Critic 通过、不处于降级模式的减仓和清仓可以不经确认。M2 的「下单流程」和「紧急退出流程」已经完成，这两条规则现在可以接上。

本变更的目的只有一个：**定下哪些交易方案要人工确认、超时以后怎么办，并让紧急退出在打开开关时先请求确认、确认以后再清仓。**

引用的 Proposal（完整版）章节：

- 「持仓与退出」：
  - 退出路径表的「紧急风险退出」一行：默认不需要人工确认，执行后立即通知；可配置为需要
  - 退出路径表的「模型建议退出」一行：Critic 快速审核，不能否决，有异议时交给你决定；默认需要人工确认，超时不执行，保留止损单并告警
  - 表下一段：模型建议退出的自动执行必须由人手动开启，只适用于减仓和清仓，写入程序日志；Critic 有异议时也不自动执行，改为推送给你决定
- 「Critic」：有分歧的方案在人工确认时连同双方意见交给你决定
- 「故障处理」：Critic 的主模型和备用模型全部不可用时，退出类方案跳过 Critic、交给人确认并注明；降级模式不做新的由模型发起的退出，已经人工确认的退出方案照常执行
- 「健康监控」：降级模式不执行未经人工确认的模型发起退出
- 「订单生命周期」的「止损单挂单失败」一行：本地备用止损触发以后按「紧急风险退出」一行处理，执行后通知
- 「技术栈与部署」通知与人工确认一行：确认请求发不出去的方案按确认超时处理

已经定了的（拆分 M3 时）：紧急退出的确认开关打开时，确认超时就是不执行，止损单照挂，并告警。

## What Changes

- 新的确认规则（通知模块，也就是架构图里的「人工确认」）：
  - 两个开关，默认都关：「模型退出自动执行」「紧急退出要确认」
  - 案件里的交易方案要不要人工确认：开仓类一律要；退出类默认要，自动执行打开、Critic 通过、不处于降级模式时不要；退出类确认超时以后告警。写成纯函数，M4 的案件工作流调用它
- 紧急退出的确认（紧急退出流程）：「紧急退出要确认」打开时，个股跌幅和组合熔断触发的清仓先发一条紧急退出的确认消息，等确认期间什么都不动，确认以后再按现有的步骤作废方案、撤单、清仓：
  - 拒绝、超时、确认请求发不出去：当天不再紧急退出这只股票，止损单照挂；超时和发不出去要告警
  - 熔断时撤掉全部买单、收盘前不再开仓不等确认，只有每只持仓的清仓等确认
  - 本地备用止损不等确认；这只股票在等确认或者已经被拒绝、超时，备用止损触发时照样清仓
  - 到收盘还在等确认：确认消息作废，告警
- 紧急退出的确认消息（Discord）：写明股票、原因、当前持仓、确认以后和拒绝以后会怎样；按钮、截止时刻、结束确认和交易方案的确认消息相同
- bootstrap：按钮的结果先看紧急退出流程是不是在等这个方案的确认，是就送给它，否则照旧送给下单流程

## Non-goals

- 下单流程按方案来源决定要不要确认、模型退出超时以后告警、确认消息附上 Critic 和 PM 双方的意见、案件阶段从风控直接进入等下单：M4 的案件工作流接上本变更的规则时做（现在下单流程只有 `/plan` 录入的方案）
- 打开「模型退出自动执行」时写程序日志：M4（程序日志和这个开关都在 M4 才起作用）
- `/plan` 录入的方案照旧四种动作都要确认，超时不告警
- 确认超时的时长、按钮的处理、`/plan`：不改
- 紧急退出的判定规则、清仓的步骤、本地备用止损的判断：不改
- 省略的少见情况：见 design 的省略清单

## Capabilities

### New Capabilities

- `confirmation-rules`：确认规则的两个开关；案件里的交易方案要不要人工确认、超时以后要不要告警

### Modified Capabilities

- `emergency-exit-flow`：新增「紧急退出的人工确认」；「巡检里的紧急退出」不再写「不请求人工确认」，基准数据加上通知配置；「一只股票的清仓」在开关打开时先确认；「告警」加确认超时、发不出去、到收盘还在等确认，熔断告警写明清仓要确认；「重启以后」加等确认时重启
- `discord-notification`：新增「紧急退出的确认消息」
- `bootstrap`：「模拟盘的装配」写明按钮的结果先送给紧急退出流程，紧急退出流程用通知配置

  - `workflows/emergency_flow.py`：每只股票的确认状态、按钮结果的登记、请求确认、超时、备用止损越过确认、新的告警文字
  - `bootstrap/app.py`：按钮结果的分发，紧急退出流程拿到通知配置
  - contracts、shared、其他模块不改
- **测试**：`tests/modules/notification/`、`tests/integrations/discord/`、`tests/workflows/`（紧急退出）、`tests/bootstrap/` 补测试；`tests/fakes/` 的通知替身加新方法。不需要部署机器、真实 Alpaca、Discord 或 OpenD
- **依赖**：无新依赖；没有新表和迁移
- **部署**：两个开关默认关，部署以后行为不变
- **对后续变更的影响**：
  - M4 案件工作流：风控通过以后调用本变更的规则决定要不要确认；不要时案件阶段从风控直接进入等下单（修改：案件阶段），下单流程不请求确认；退出类确认超时以后告警；确认消息附上 Critic 和 PM 双方的意见或者「Critic 不可用」；自动执行时写程序日志
  - M4：紧急退出在等确认的股票，案件队列算不算「在紧急退出中」（case-queue spec），接线时决定

## 需要人决定

1. **紧急退出要确认时，哪些步骤等确认，完整版没写。** 紧急退出包括作废还没下单的方案、撤掉挂着的订单、市价清仓，熔断时还有撤掉全部买单和收盘前不再开仓。
   推荐做法（spec 已按它写）：
   - 熔断的撤掉全部买单、收盘前不再开仓立即生效，不等确认：它们不卖出持仓，只是不再加风险
   - 每只股票的作废方案、撤单、清仓都等确认以后才做；等确认期间什么都不动，止损单照挂。这样人拒绝时不会留下撤了一半的订单和作废的方案
   - 熔断时每只持仓各一条确认消息，各自确认

   完整版的改法：退出路径表「紧急风险退出」一行的人工确认改为「默认不需要，执行后立即通知；可配置为需要：熔断的撤买单和禁止开仓照常立即生效，每只股票的撤单和清仓等确认以后再做，拒绝或超时不执行，保留止损单并告警」。

   已决定：同意推荐做法，完整版 Proposal 已经照改，spec 和 design 不变。
2. **「紧急退出要确认」打开时，本地备用止损要不要确认，完整版没写。** 「止损单挂单失败」一行写的是备用止损触发以后「按紧急风险退出处理」，如果连确认也照搬，没有止损单保护的仓位跌破止损价时也要等人。
   推荐做法（spec 已按它写）：备用止损不等确认。它替代的是券商端止损单，止损单本来就不需要确认。这只股票在等紧急退出的确认，或者紧急退出已经被拒绝、超时，备用止损触发时照样清仓，在等的确认消息作废。

   完整版的改法：「止损单挂单失败」一行「触发以后按「紧急风险退出」一行处理，执行后通知」改为「触发以后按「紧急风险退出」一行处理，不需要人工确认，执行后通知」。

   已决定：同意推荐做法，完整版 Proposal 已经照改，spec 和 design 不变。
3. **紧急退出的确认被拒绝或超时以后，这只股票当天还判不判定，完整版没写。** 跌幅一直在阈值以外时，每一轮都会再次触发。
   推荐做法（spec 已按它写）：当天不再紧急退出这只股票、不再请求确认，本地备用止损除外；下一个交易日按新的前一交易日收盘价重新判定。到收盘还在等确认的，确认消息作废并告警。和「触发以后当天做到底」相同，每只股票每天只走一次。

   完整版的改法：「紧急风险退出的触发」的「触发以后当天做到底」一条后面加「；要人工确认时，确认以后当天做到底，拒绝或超时以后当天不再紧急退出这只股票，本地备用止损除外」。

   已决定：同意推荐做法，完整版 Proposal 已经照改，spec 和 design 不变。
4. **紧急退出的确认等多久，完整版没写。** 紧急风险退出的时限是分钟级，交易方案的确认超时默认 30 分钟。
   推荐做法（spec 已按它写）：用同一个确认超时（默认 30 分钟），不另设配置项。超时的结果是不执行、止损单照挂，时长只决定多久以后告诉你没有执行；人在的话几分钟内就会按。

   完整版不用改。

   已决定：同意推荐做法，spec 和 design 不变；完整版 Proposal 不用改。
5. **自动执行的模型退出决定以后才进入降级模式，还执行不执行，完整版没写。** 盘后形成的退出方案要等到开盘才下单，这期间可能进入降级模式；「已经人工确认的退出方案照常执行」没有覆盖自动执行的方案。
   推荐做法（spec 已按它写）：只在风控通过、决定要不要确认的那一刻看是否处于降级模式；之后进入降级不追溯，自动执行的退出方案照常下单。退出只减少风险，现金账户只做多，照常卖出不会扩大损失；追溯的话要在下单前再校验时区分方案的来源，M4 接线更复杂。

   完整版的改法：「故障处理」降级模式的第一条「已经人工确认的退出方案照常执行（只要券商连接正常）」改为「已经人工确认的退出方案，以及进入降级模式之前已经决定自动执行的模型退出方案，照常执行（只要券商连接正常）」。

   已决定：同意推荐做法，完整版 Proposal 已经照改，spec 和 design 不变。
