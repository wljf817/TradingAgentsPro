# Proposal

## Why

M1 的风控、执行、紧急退出和健康监控都要用行情：

- 下单前再校验要用实时最新价
- 本地备用止损按最新价判断是否触及止损价
- 紧急退出要用前一交易日收盘价和最新价
- 健康监控要知道行情最近一次是什么时候更新的

M1 写的时候价格都由调用方传进来，所以项目里至今没有行情接口，也没有任何行情源。M2 的流程要把这些串起来跑在模拟盘上，得先有一个能取到真实行情的地方。

行情来源已经定为 moomoo：用户账户的 OpenAPI 行情权限是美股 LV3（2026-10-06 在 OpenD 里确认），推广期内免费。免费的替代品只有 IEX 一家交易所的数据，全市场数据每月 99 美元起；简版也已经写定，行情和到价提醒都用 moomoo OpenAPI + OpenD。

本变更的目的只有一个：**新建行情模块，并用 moomoo OpenD 实现它的行情源，让交易侧能取到持仓和方案涉及的股票的实时行情。**

引用的 Proposal（完整版）章节：

- 「架构 · 触发」的数据源：moomoo 实时行情
- 「技术栈与部署」的数据源和券商两行：行情来自 moomoo OpenAPI（Python SDK）+ OpenD；可靠性要求
- 「风控引擎与执行」的下单前再校验：提交订单前重新读取实时报价；交易时段一段：盘前盘后的跌幅如果开盘时还在，开盘后的第一个价格就会触发紧急退出
- 「持仓与退出」的紧急风险退出的触发：跌幅从前一交易日收盘价算
- 「故障处理」：健康监控检查数据延迟
- 「共享状态库」：当前市场事实里的行情由数据层写入（本变更不写，见 Non-goals）

## What Changes

- 新增模块 `modules/marketdata/`，对应架构图里的「数据源」节点：
  - 一只股票的行情包括最新价、前一交易日收盘价和更新时刻。最新价只算当前交易日的常规时段，开盘后还没有成交时没有最新价，这样开盘那一刻不会把昨天的收盘价当成今天的价格
  - 端口 `QuoteSource`：一次取一组股票的行情；行情源没有数据的股票不出现在结果里；超时、断线或出错时报行情不可用
  - 用例 `MarketDataService`：取行情；给出参考股票（默认 SPY）行情的更新时刻，作为健康监控判断数据延迟用的「行情最近一次更新的时刻」
  - 配置：参考股票
- 新增 `integrations/moomoo/`，用 OpenD 的市场快照实现 `QuoteSource`：
  - 股票代码加上 `US.` 前缀
  - 快照字段映射到行情：价格按十进制读取；更新时刻按美东时间解读，换成 UTC；常规时段成交量为 0 时没有最新价
  - OpenD 查不到的股票（快照里全是 0）不出现在结果里，免得拿价格 0 去判断止损
  - 调用失败一律报行情不可用
  - 连接配置（地址、端口、超时）：OpenD 没开时，建立连接不卡住，取行情在超时后报行情不可用
- 新增依赖 moomoo-api
- 一组连本机 OpenD 的冒烟测试，默认不运行：确认盘中拿到的是实时行情，开盘前没有最新价

## Non-goals

- 把行情接到各个使用方（下单前再校验、风控检查的账户数据、本地备用止损、紧急退出、健康监控），以及取行情的频率：「下单流程」「紧急退出流程」「健康监控接线」
- 读取 OpenD 地址的环境变量、建立连接、退出时关闭连接：「启动与装配」
- 在部署机器上运行和登录 OpenD、行情权限被别的设备占用后怎样恢复：「部署」
- 把行情写进共享状态库：M2 里用行情的都是要实时价的代码，没有读状态库的地方；案件的快照在 M4 做
- 订阅实时推送、到价提醒、事件检测：M4
- 盘前盘后的价格：系统只在常规时段下单和判断，快照里盘前盘后的价格不用
- 备用行情源：现在不做；行情退化（推广期结束、权限被占）由数据延迟检查发现，再决定买行情卡还是换行情源
- 省略的少见情况：见 design 的省略清单

## Capabilities

### New Capabilities

- `market-data`：行情模块：一只股票的行情包括什么，取行情的约定，行情最近一次更新的时刻，配置
- `moomoo-quotes`：moomoo OpenD 行情源：股票代码、快照字段的映射、查不到的股票、调用失败、连接配置

### Modified Capabilities

无。风控、执行、紧急退出和健康监控的规则不变，它们本来就接收调用方传入的价格和时刻。

## Impact

- **代码**：新增 `src/tradingagentspro/modules/marketdata/`（`__init__.py`、`ports.py`、`service.py`、`config.py`、`domain/quote.py`）和 `src/tradingagentspro/integrations/moomoo/`（`__init__.py`、`quotes.py`）
- **测试**：
  - `tests/modules/marketdata/`，测试替身 `tests/fakes/quotes.py`
  - `tests/integrations/moomoo/`：替身 OpenD 返回 2026-10-06 从真实 OpenD 录下的快照
  - 冒烟测试连本机的 OpenD，默认不运行，CI 也不运行
- **依赖**：新增 moomoo-api（顺带 pandas、numpy、protobuf 等）；它没有类型标注，mypy 配置里对它放宽
- **对后续变更的影响**：
  - 「下单流程」：
    - 下单前再校验要用方案股票和全部持仓的行情，一次取齐
    - 开盘后这只股票还没有最新价时，等到有了再校验，不要拿前一天的收盘价去检查跳空
    - 没有行情的股票不能下单
  - 「紧急退出流程」：
    - 每轮把全部持仓的行情一次取齐，填进紧急退出的持仓数据；没有最新价的持仓这一轮不判定（紧急退出模块本来就这样处理空的最新价）
    - 本地备用止损也用同一轮的行情
  - 「健康监控接线」：
    - 定时调用 `MarketDataService.last_update()`，结果作为行情最近一次更新的时刻
    - 取不到（行情不可用）时沿用上一次的值，数据延迟检查会在超过上限后进入降级
  - 「启动与装配」：
    - 按配置建立 OpenD 连接，退出时关闭
    - 模拟盘和实盘都用这个行情源
  - 「部署」：
    - OpenD 要和主程序一起常驻；首次登录可能要手机验证码
    - 行情权限被别的设备占走时，用 OpenD 的 `request_highest_quote_right` 命令要回来
    - moomoo-api 的版本和 OpenD 的版本保持一致
  - 各流程合计的快照请求不能超过每 30 秒 60 次

## 需要人决定

1. **完整版「技术栈与部署」券商一行写"用 asyncio 订阅实时推送和到价提醒推送"，和 moomoo SDK 不符**

   查过 moomoo-api 10.11.7108 的源码：SDK 用自己的网络线程收发数据，推送的回调在它自己的回调线程里执行，没有用 asyncio。项目的执行模块和 DBOS 工作流也都是同步的。照字面去用 asyncio，反而要在两种并发方式之间来回转。

   推荐：删掉"用 asyncio"四个字，改为"订阅实时推送和到价提醒推送作为行情事件源"。订阅推送本身留到 M4 的事件检测再做，本变更只用拉取的快照。
