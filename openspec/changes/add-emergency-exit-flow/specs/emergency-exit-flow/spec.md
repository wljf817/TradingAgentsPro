# Spec Delta

## Purpose

紧急退出流程挂在盘中巡检的每一轮上：常规交易时段内用券商账户和实时行情判定紧急风险退出和本地备用止损，触发的股票先撤掉挂着的订单、作废还没下单的方案，订单都结束以后用代码触发的清仓方案市价清仓；熔断时撤掉全部买单；执行后在 Discord 通知。

## ADDED Requirements

### Requirement: 巡检里的紧急退出

盘中巡检的每一轮 SHALL 在第 3 步（对齐止损单，session-patrol spec「每一轮」）之后、收盘对账（close-reconciliation spec「巡检里的收盘对账」）之前做「紧急退出」这一步。这一步由下面几项组成，按顺序做：

1. 判定：当前时刻不在常规交易时段内（开盘 ≤ 当前时刻 < 收盘）时不做判定，也不做第 2、3 项。在时段内时，按「判定的输入」读数据，按「要清仓的股票」得出这一轮的熔断状态和要清仓的股票
2. 熔断已触发时撤掉全部买单，见「单日亏损熔断」
3. 要清仓的股票按代码顺序各一项，见「一只股票的清仓」
4. 报告结果：不论在不在交易时段都做，见「告警」

每一项和巡检的其他项一样（session-patrol spec「巡检的开始、间隔和停止」「一轮里的失败」）：停止时正在做的那一项做完（包括推送）再结束；一项出错只跳过这一项。

判定的频率就是巡检的间隔（session-patrol spec「巡检配置」，默认 15 秒）。判定用到的阈值都在已有的配置里：熔断比例（emergency-exit spec「紧急退出配置」，默认 0.07）、每只持仓生效的紧急阈值（来自它的开仓方案，没写时用风控配置的默认值 0.08，risk-rules spec）。本流程不另设配置项。

紧急退出 SHALL NOT 请求人工确认，降级模式下照常进行（degraded-mode spec）。

本 spec 的场景除非另有说明，都使用下面的基准数据：

- 当前时刻 2026-10-14 15:00Z（周三，盘中；当天 13:30Z 开盘、20:00Z 收盘），交易日历是纽交所日历
- 风控、执行、紧急退出、巡检的配置都用默认值：执行配置的「买单和止损单错开」打开（和模拟盘的装配一样），立即重试 1 次，状态未知的等待时长 30 秒；熔断比例 0.07；巡检间隔 15 秒
- 执行模块已经完成一次对账，没有不一致；不处于降级模式；今天的熔断没有触发
- 券商账户：权益 10,000，前一交易日收盘时的权益 10,000（熔断线 700），现金 1,000
- 持仓，都能找到开仓订单，今天都没有开仓成交：
  - AAA 50 股，均价 100。开仓订单：板块"科技"，止损价 90，紧急阈值 0.08，2026-10-12 全部成交。AAA-STOP-1 挂着：卖出 50 股，止损价 90
  - BBB 100 股，均价 40。开仓订单：板块"医疗"，止损价 35，紧急阈值 0.15，2026-10-13 全部成交。BBB-STOP-1 挂着：卖出 100 股，止损价 35
- 行情：AAA 前一交易日收盘价 100，最新价 99；BBB 前一交易日收盘价 40，最新价 39.5。AAA 在最新价 92 及以下触及个股跌幅，BBB 在 34 及以下
- 没有未结束的订单，没有有效预留。方案在场景里给出，都已经通过风控并预留：
  - P2：减仓 AAA 20 股，限价单，限价 105
  - P5：买入 CCC，板块"能源"，100 股，限价单，限价 20，止损价 18
- "做一轮"指巡检在当前时刻做一轮，"之后一轮"指 15 秒以后的下一轮
- "AAA 的清仓方案"指交易日 2026-10-14、股票 AAA 的代码触发的清仓方案（emergency-exit spec「代码触发的清仓方案」）；"AAA 的清仓单"指这个方案的订单
- 券商正常受理，订单不成交，除非另有说明；"券商回报……变为……""券商持仓变为……"同 order-lifecycle spec 和 stop-protection spec 的约定
- "推送一条告警"指 discord-notification spec「告警」的一条消息
- "锁"指 session-patrol spec「执行模块和风控的调用串行」的那把锁

### Requirement: 判定的输入

判定 SHALL 按下表读数据，不拿锁：

| 输入 | 来源 |
| --- | --- |
| 当前权益、前一交易日收盘时的权益 | 执行模块的账户数据（trade-records spec「账户数据」），即券商账户的权益和前一交易日收盘时的权益 |
| 全部持仓：股票、板块、生效的紧急阈值、今天开仓成交的均价 | 执行模块的账户数据：只有能找到开仓订单的持仓 |
| 每只持仓的前一交易日收盘价、最新价 | 行情（market-data spec）：全部持仓的股票一次取完；没有持仓时不取。行情没有最新价（开盘后还没有成交）时，最新价为空 |
| 风控用的账户数据 | 用同一次读到的账户数据和行情，按 order-flow spec「风控用的账户数据」拼成，给「一只股票的清仓」用 |

读不到数据时 SHALL 按下表处理：

| 情况 | 处理 |
| --- | --- |
| 读券商账户超时或断线 | 写一条 WARNING；这一轮不判定，也不做第 2、3 项；报告结果照常 |
| 取行情时行情不可用 | 写一条 WARNING；全部持仓的前一交易日收盘价和最新价都为空：这一轮不判定个股跌幅和本地备用止损，熔断照常判定（熔断只用券商的权益），当天触发过的股票照常继续 |
| 行情源没有某只持仓的数据 | 写一条 WARNING，写明这些股票；它们的前一交易日收盘价和最新价为空 |

### Requirement: 要清仓的股票

这一轮要清仓的股票 SHALL 由下面三部分合成，每只股票只出现一次，按代码排序：

| 来源 | 条件 | 原因 |
| --- | --- | --- |
| 紧急退出的判定（emergency-exit spec） | 熔断已触发：全部持仓；没有触发：触及个股跌幅的持仓 | 组合熔断、个股跌幅 |
| 本地备用止损 | 有最新价的持仓，执行模块判断这只股票的本地备用止损该触发（stop-protection spec「本地备用止损的触发」：无保护仓位或错开中、盘中、最新价不高于止损价） | 本地备用止损 |
| 当天已经触发过的股票 | 这次运行里当天触发过、还没有清仓单、也没有结束（见「一只股票的清仓」） | 第一次触发时的原因 |

- 一只股票同时满足几种时，原因按组合熔断、个股跌幅、本地备用止损的顺序取第一个；清仓方案都是这只股票当天的同一个
- 触发以后当天做到底：等撤单结束期间价格回升、跌幅回到阈值以内，或者止损单补挂上了，这只股票照样继续清仓
- 当天的清仓方案已经有订单的股票（不论订单是什么状态）不再清仓，也不算新的触发：订单由巡检跟进；被券商拒绝、到期或撤销的，当天不再重来（emergency-exit spec「代码触发的清仓方案」）。下一个交易日按新的前一交易日收盘价重新判定，用那一天的清仓方案

- **AND** 推送一条告警，写明 BBB、本地备用止损、无保护仓位、最新价 35、止损价 35

#### Scenario: 错开中跌到止损价时先撤买单

- **GIVEN** P6：加仓 BBB 20 股，限价 34，止损价 30，订单已提交、没有成交；BBB-STOP-1 已经撤销，BBB 错开中（stop-protection spec「买单和止损单错开」），止损价仍是 35

- **WHEN** 券商回报 BBB-STOP-2 变为撤销，之后一轮

- **WHEN** BBB 最新价 34，做一轮
- **THEN** 券商只收到一笔 BBB 的卖单：BBB 的清仓单，卖出 100 股

### Requirement: 一只股票的清仓

要清仓的每只股票 SHALL 在一次拿锁里依次：

1. 这只股票当天的清仓方案已经有订单：什么都不做（订单由巡检跟进）
2. 作废这只股票还没下单的方案：有有效预留、还没有订单的每个方案（开仓类和退出类都算，不论在等确认、等开盘还是等重试，当天的清仓方案除外），释放它的预留（risk-reservations spec）。下单流程之后再校验时得到"方案已结束"而作废（order-flow spec、pre-order-recheck spec「已经结束的方案」）
3. 这只股票还有没结束的订单（买单和卖单）：其中有还没记下撤单要求的，就撤掉这只股票的订单（order-lifecycle spec「提前撤单」）；已经都有撤单要求的不再撤。这一项到此结束，等之后的轮次
4. 没有没结束的订单：用风控检查当天的清仓方案（熔断取紧急退出的当前状态，降级取健康监控的当前状态，同 order-flow spec「提交方案」），通过或调整时做下单前再校验，再校验通过或调整时按它的结果提交订单（order-lifecycle spec「提交订单」）

第 4 步的结果 SHALL 按下表处理：

| 结果 | 处理 |
| --- | --- |
| 检查或再校验拒绝（可卖数量为 0） | 不下单；这只股票当天的紧急退出结束；告警 |
| 提交返回订单 | 订单交给巡检跟进：卖单等止损单撤掉才提交给券商，撤掉以后由巡检的跟进提交；之后的结果见「告警」 |
| 提交时券商超时或断线 | 订单记为状态未知（order-lifecycle spec「券商调用失败时状态未知」），交给巡检跟进 |

- 清仓股数是再校验时的可卖数量：撤单之前和撤单期间的成交都已经计入券商持仓
- 第 4 步出了别的错（数据库出错、券商的认证错误、意外的异常），按「一轮里的失败」处理，之后的轮次再从第 1 步来

- **THEN** P2 已撤销，没有有效预留
- **AND** AAA 的清仓单已经建立：卖出 50 股，市价单

- **WHEN** AAA 最新价 92，做一轮
- **THEN** 券商收到 P2 的撤单请求
- **WHEN** 券商回报 P2 变为撤销、累计成交 10，券商持仓变为 40 股，之后一轮

#### Scenario: 撤单迟迟不结束

- **GIVEN** P2 的订单已提交；AAA-STOP-1 已经改为 30 股
- **WHEN** AAA 最新价 92，做一轮
- **THEN** 券商收到 P2 的撤单请求
- **WHEN** 券商回报 P2 仍是已受理、未结束，之后两轮
- **THEN** AAA 的清仓方案没有订单
- **AND** 券商一共只收到一次 P2 的撤单请求

#### Scenario: 作废这只股票还没下单的方案

- **GIVEN** P3：加仓 AAA 5 股，限价 99，止损价 92，在等确认，预留 5 股；P4：减仓 AAA 10 股，市价单，已经确认、在等重试，预留 10 股；P5 在等确认；三个方案都没有订单
- **WHEN** AAA 最新价 92，做一轮
- **THEN** P3、P4 没有有效预留；P5 仍然预留 100 股
- **AND** AAA 的清仓单已经建立：卖出 50 股
- **AND** 推送一条告警，写明作废了 P3、P4
- **WHEN** 之后对 P3 做下单前再校验
- **THEN** 结论为拒绝，原因是"方案已结束"

#### Scenario: 没有可卖的股数

- **GIVEN** P2 改为减仓 AAA 50 股，限价 93，订单已提交；AAA-STOP-1 已经撤销
- **WHEN** AAA 最新价 92，做一轮
- **THEN** 券商收到 P2 的撤单请求
- **WHEN** 券商回报 P2 变为全部成交（撤单生效之前成交）、累计成交 50，券商持仓变为 0，之后一轮
- **THEN** AAA 的清仓方案没有订单
- **AND** 推送一条告警，写明 AAA 没有可卖的股数，紧急退出结束
- **WHEN** 之后一轮
- **THEN** 没有关于 AAA 的新告警

#### Scenario: 提交时券商超时

- **GIVEN** BBB 从 14:50Z 起是无保护仓位，没有挂着的止损单；券商会一直拒绝挂 BBB 的止损单；券商受理下一笔订单时会超时
- **WHEN** BBB 最新价 35，做一轮
- **THEN** BBB 的清仓单状态未知
- **WHEN** 券商回报 BBB 的清仓单已受理、累计成交 0，2026-10-14 15:00:30Z 做一轮
- **THEN** 巡检按客户端订单 ID 查到它，BBB 的清仓单已提交；券商没有收到第二笔 BBB 的清仓单

### Requirement: 单日亏损熔断

这一轮的判定使熔断已触发时（emergency-exit spec「熔断状态」），SHALL：

- 在逐只股票清仓之前，拿一次锁：有还没记下撤单要求的买单时，撤掉全部买单（order-lifecycle spec「提前撤单」）。熔断保持到收盘，每一轮都这样做，所以之后才查到的买单也会撤掉
- 清仓全部持仓：每只持仓按「一只股票的清仓」处理，原因是组合熔断
- 告警一次：这次运行里每个交易日第一次看到熔断触发时推送，见「告警」

熔断以后新的开仓方案在风控检查和下单前再校验时被拒绝（order-flow spec），本流程不另外处理。

#### Scenario: 熔断：撤掉全部买单，清仓全部持仓

- **GIVEN** P5 的订单已提交；当前权益 9,300（单日亏损 700）
- **WHEN** 做一轮
- **THEN** 券商收到 P5 的撤单请求
- **AND** AAA 的清仓单已经建立：卖出 50 股；BBB 的清仓单已经建立：卖出 100 股；券商收到 AAA-STOP-1 和 BBB-STOP-1 的撤单请求
- **AND** 推送一条熔断告警，以及 AAA、BBB 各一条告警，原因都是组合熔断

#### Scenario: 熔断以后的轮次

- **GIVEN** 接着「熔断：撤掉全部买单，清仓全部持仓」，P5 仍是已提交
- **WHEN** 当前权益回升到 9,800，之后一轮
- **THEN** 熔断仍是已触发
- **AND** 券商没有再收到 P5 的撤单请求，没有收到 AAA、BBB 的新订单
- **AND** 没有新的熔断告警

#### Scenario: 单日亏损差一点不到熔断线

- **GIVEN** P5 的订单已提交；当前权益 9,300.01
- **WHEN** 做一轮
- **THEN** 熔断没有触发；券商没有收到 P5 的撤单请求；没有清仓单

#### Scenario: 没有持仓时熔断照样撤买单

- **GIVEN** 券商没有持仓；P5 的订单已提交；当前权益 9,300
- **WHEN** 做一轮
- **THEN** 券商收到 P5 的撤单请求；行情源没有收到请求
- **AND** 推送一条熔断告警

### Requirement: 告警

紧急退出 SHALL 只为下面这些情况推送告警（discord-notification spec「告警」），并把同样的文字写一条 WARNING 日志：

| 情况 | 告警写明 |
| --- | --- |
| 一只股票开始紧急退出：这次运行里第一次处理它当天的清仓 | 股票；原因：个股跌幅写参考价、最新价、跌幅和紧急阈值，组合熔断，本地备用止损写无保护仓位或错开中、最新价和止损价；这一项做了什么：作废的方案（动作、方案 ID），撤掉的订单（动作、股数、方案 ID），已经建立的清仓单（股数），或者等订单都结束以后清仓，或者没有可卖的股数 |
| 熔断触发：这次运行里每个交易日第一次看到 | 前一交易日收盘时的权益、当前权益、单日亏损和它占前一交易日收盘时权益的比例、熔断比例；清仓全部持仓，撤掉全部买单，收盘前不再开仓 |
| 清仓单进入终态 | 全部成交：股票、卖出股数和成交均价。其他终态（已拒绝、已过期、已撤销）：股票、状态、累计成交和委托股数；今天不再清仓这只股票，剩下的持仓由止损单保护 |
| 之后的轮次里没有可卖的股数 | 股票；没有可卖的股数，紧急退出结束 |
| 到收盘还没有清仓单：当天开始的紧急退出，收盘以后的第一轮仍没有订单 | 股票；到收盘还没下清仓单（等撤单结束），今天不再清仓。同时拿锁释放当天清仓方案剩下的预留（有的话） |

- 其余只写 INFO 日志：撤单请求、等订单结束、作废的方案、建立清仓单（股数和状态）。等订单结束的每一轮各写一条
- 推送告警 MUST NOT 拿着锁。发不出去时按 discord-notification spec 只写错误日志，紧急退出照常继续，之后不重发
- 告警过什么只记在内存里：进程重启以后见「重启以后」

#### Scenario: 开始紧急退出的告警

- **GIVEN** AAA 最新价 92
- **WHEN** 做一轮
- **THEN** 推送一条告警，写明 AAA、个股跌幅、参考价 100、最新价 92、跌幅 8.0%、紧急阈值 8.0%、已建立清仓单卖出 50 股
- **AND** 有一条 WARNING，内容和告警相同

#### Scenario: 熔断告警的内容

- **GIVEN** 当前权益 9,300
- **WHEN** 做一轮
- **THEN** 熔断告警写明前一交易日收盘时的权益 10,000、当前权益 9,300、单日亏损 700（7.0%）、熔断比例 7.0%，清仓全部持仓、撤掉全部买单、收盘前不再开仓

#### Scenario: 清仓完成的告警

- **GIVEN** 接着「盘中一轮里触发并清仓」，券商已经收到 AAA 的清仓单
- **WHEN** 券商回报 AAA 的清仓单全部成交、累计成交 50、成交均价 91.5，券商持仓变为 0，之后一轮
- **THEN** 推送一条告警，写明 AAA 紧急清仓完成，卖出 50 股，成交均价 91.5
- **WHEN** 之后一轮
- **THEN** 没有关于 AAA 的新告警

#### Scenario: 清仓被拒的告警

- **GIVEN** AAA 最新价 92，做一轮，AAA 的清仓单已经建立；券商会拒绝下一笔订单
- **WHEN** 券商回报 AAA-STOP-1 变为撤销，之后一轮
- **THEN** 推送一条告警，写明 AAA 的清仓单已拒绝、成交 0 / 50 股、今天不再清仓 AAA、剩下的持仓由止损单保护

#### Scenario: 到收盘还没有清仓单

- **GIVEN** 当前时刻 2026-10-14 19:59:50Z；P2 的订单已提交，AAA-STOP-1 已经改为 30 股；AAA 最新价 92，做一轮，券商收到 P2 的撤单请求
- **WHEN** 券商回报 P2 仍是已受理、未结束，2026-10-14 20:00:05Z 之后一轮
- **THEN** 推送一条告警，写明 AAA 到收盘还没下清仓单，今天不再清仓
- **AND** AAA 的清仓方案没有订单，也没有有效预留

#### Scenario: 告警发不出去

- **GIVEN** AAA 最新价 92；Discord 报错
- **WHEN** 做一轮
- **THEN** AAA 的清仓单照常建立；有一条错误日志，含告警文字和失败原因
- **WHEN** Discord 恢复，之后一轮
- **THEN** 没有推送这条告警

### Requirement: 重启以后

订单（包括撤单要求）、预留和止损保护都在状态库里；熔断状态（emergency-exit spec）、当天触发过哪些股票、告警过什么只在内存里。进程重启以后，巡检的第一轮 SHALL 按下表接着做：

| 重启之前 | 重启以后 |
| --- | --- |
| 清仓单已经建立、还没结束 | 巡检照常跟进；它结束时照样推送结果的告警（判定时把有持仓的股票当天的清仓单找回来）；不再推送开始紧急退出的告警 |
| 在等撤单结束，重启以后仍然触发 | 不再请求撤单；订单都结束以后清仓；再推送一次开始紧急退出的告警 |
| 在等撤单结束，重启以后不再触发 | 不再继续：已经撤掉的订单、作废的方案不恢复，不清仓 |
| 熔断已触发 | 下一次判定重新算（emergency-exit spec「熔断状态」）；单日亏损仍达到熔断线时再告警一次 |

#### Scenario: 清仓单挂着时重启

- **GIVEN** 券商已经收到 AAA 的清仓单，已提交，还没成交；AAA 最新价 91
- **WHEN** 程序重启，巡检做第一轮
- **THEN** 没有开始紧急退出的告警，券商没有收到 AAA 的新订单
- **WHEN** 券商回报 AAA 的清仓单全部成交、累计成交 50、成交均价 90.8，券商持仓变为 0，之后一轮
- **THEN** 推送一条告警，写明 AAA 紧急清仓完成，卖出 50 股，成交均价 90.8

#### Scenario: 等撤单时重启，仍然触发

- **GIVEN** AAA 最新价 92 时做过一轮，券商收到了 P2 的撤单请求，P2 仍是已提交
- **WHEN** 程序重启，AAA 最新价 91，巡检做第一轮
- **THEN** 券商没有再收到 P2 的撤单请求；推送一条开始紧急退出的告警
- **WHEN** 券商回报 P2 变为撤销、累计成交 0，之后一轮
- **THEN** AAA 的清仓单已经建立：卖出 50 股

#### Scenario: 等撤单时重启，不再触发

- **GIVEN** AAA 最新价 92 时做过一轮，券商收到了 P2 的撤单请求，P2 仍是已提交
- **WHEN** 程序重启，AAA 最新价 95，券商回报 P2 变为撤销、累计成交 0，巡检做第一轮
- **THEN** P2 已撤销；AAA 的清仓方案没有订单；没有告警

#### Scenario: 熔断当天重启

- **GIVEN** 当前权益 9,300 时做过一轮，熔断触发，推送过熔断告警
- **WHEN** 程序重启，当前权益 9,250，巡检做第一轮
- **THEN** 熔断触发，再推送一次熔断告警

### Requirement: 一轮里的失败

紧急退出这一步 SHALL 不因为任何失败而让巡检停下：

| 失败 | 处理 |
| --- | --- |
| 读券商账户、取行情失败 | 见「判定的输入」 |
| 撤单、提交、对齐止损单里券商超时或断线 | 执行模块记为状态未知（order-lifecycle spec、stop-protection spec），这一项照常结束 |
| 某一项出了别的错：数据库出错、券商的认证错误、意外的异常 | 写一条 ERROR，带异常栈，写明是哪一项（session-patrol spec「一轮里的失败」）；跳过这一项，接着做下一项；之后的轮次再做 |

#### Scenario: 一只股票出错不影响别的股票

- **GIVEN** 当前权益 9,300；处理 AAA 这一项时读状态库出错
- **WHEN** 做一轮
- **THEN** 有一条 ERROR 写明紧急退出处理 AAA 出错，带异常栈
- **AND** BBB 的清仓单照常建立
- **WHEN** 状态库恢复，之后一轮
- **THEN** AAA 的清仓单已经建立

### Requirement: 执行模块和风控的调用串行

紧急退出 SHALL 按 session-patrol spec「执行模块和风控的调用串行」拿那把锁：

- 熔断撤全部买单：一次拿锁
- 一只股票的清仓：读订单和预留、释放预留、撤单、风控检查、下单前再校验、提交订单在同一次拿锁里完成，别的方案不会插进来下单或改变额度
- 到收盘还没有清仓单时释放预留：一次拿锁
- 判定（读账户数据、取行情、紧急退出的判定、本地备用止损是否该触发）和报告结果不拿锁。紧急退出的判定只由巡检调用
- 推送告警 MUST NOT 拿着锁

#### Scenario: 别的调用拿着锁时等待

- **GIVEN** AAA 最新价 92；另一个线程拿着锁（比如下单流程正在再校验和提交）
- **WHEN** 巡检做到 AAA 这一项
- **THEN** 那个线程放开锁之前，AAA 的清仓方案没有订单，券商没有收到 AAA-STOP-1 的撤单请求
- **WHEN** 那个线程放开锁
- **THEN** AAA 的清仓单已经建立

#### Scenario: 推送告警时不拿锁

- **GIVEN** AAA 最新价 92；推送告警时 Discord 一直没有响应
- **WHEN** 巡检在等这次推送
- **THEN** 另一个线程可以立即拿到锁
