# Spec Delta

## MODIFIED Requirements

### Requirement: 紧急退出的人工确认

通知配置的「紧急退出要确认」（confirmation-rules spec「确认规则的配置」）关闭时，紧急退出 SHALL NOT 请求人工确认，要清仓的股票直接按「一只股票的清仓」处理。

打开时，要清仓的股票 SHALL 先按下表处理它当天的确认，确认以后才按「一只股票的清仓」处理。每只股票每个交易日最多一个确认，指向它当天的代码触发的清仓方案：

| 情况 | 处理 |
| --- | --- |
| 这次运行里第一次处理它当天的清仓，原因是组合熔断或个股跌幅 | 请求紧急退出的确认（discord-notification spec「紧急退出的确认消息」）：原因的写法和开始紧急退出的告警相同（「告警」），当前持仓是这一轮账户数据里的股数；通知模块写程序日志的请求确认（program-log spec「系统的动作」）。这一项到此结束：不作废方案、不撤单、不检查风控，不拿锁，止损单照挂 |
| 在等确认，还没有收到按钮的结果，当前时刻早于截止时刻 | 什么都不做 |
| 收到确认 | 写程序日志的人的确认（program-log spec「人的动作」）；这一轮就按「一只股票的清仓」处理，之后当天做到底（「要清仓的股票」）：价格回升、跌幅回到阈值以内也照样清仓 |
| 收到拒绝 | 这只股票当天的紧急退出结束；写程序日志的人的拒绝，不告警 |
| 没有收到按钮的结果，当前时刻不早于截止时刻 | 写程序日志的人的超时；报告确认消息已超时（discord-notification spec「结束确认」）；这只股票当天的紧急退出结束；告警 |
| 确认请求发不出去（通知不可用） | 按确认超时处理：这只股票当天的紧急退出结束；写一条 ERROR，写明股票和原因；告警。程序日志的请求确认写明没有发出去，没有人的超时 |

- 截止时刻 = 请求的时刻 + 确认超时（通知配置，默认 30 分钟）
- 每一轮先看有没有收到按钮的结果，再看截止时刻：截止时刻之前按下、截止以后的那一轮才处理的，按按钮的结果处理
- 收下按钮的结果：本人按下紧急退出的确认消息的按钮（discord-notification spec「按钮的处理」），紧急退出流程正在等这个方案的确认（已经请求，还没有处理到结果）时 SHALL 收下，留给之后的轮次处理；不在等的不收下，交给下单流程（bootstrap spec「模拟盘的装配」）
- 熔断时撤掉全部买单（「单日亏损熔断」）、收盘前不再开仓（emergency-exit spec「熔断状态」）SHALL 不等确认；每只持仓各请求一次确认，各自处理
- 本地备用止损 SHALL NOT 等确认：这一轮本地备用止损触发（「要清仓的股票」的第二行）的股票直接按「一只股票的清仓」处理，即使它在等确认，或者当天的紧急退出已经因为拒绝、超时、确认请求发不出去而结束。在等的确认消息报告已作废；之前请求过确认的，开始紧急退出的告警写的原因是本地备用止损
- 降级模式下照常请求确认
- 到收盘还在等确认的，见「告警」

#### Scenario: 开关关闭时不请求确认

- **GIVEN** 紧急退出要确认关闭；AAA 最新价 92
- **WHEN** 做一轮
- **THEN** 频道里没有确认消息；AAA 的清仓单已经建立：卖出 50 股

#### Scenario: 请求确认，等确认期间什么都不动

- **GIVEN** 紧急退出要确认打开；P2 的订单已提交；AAA-STOP-1 已经改为 30 股
- **WHEN** AAA 最新价 92，做一轮
- **THEN** 频道里出现 AAA 的确认消息：原因写个股跌幅 8.0%、参考价 100、最新价 92、紧急阈值 8.0%，当前持仓 50 股，截止时刻 2026-10-14 15:30Z
- **AND** 券商没有收到 P2 的撤单请求，AAA-STOP-1 仍是 30 股；P2 仍有有效预留；AAA 的清仓方案没有订单，也没有预留
- **AND** 没有推送开始紧急退出的告警
- **WHEN** 之后一轮
- **THEN** 频道里仍然只有一条 AAA 的确认消息，券商没有收到新的请求

#### Scenario: 确认以后清仓

- **GIVEN** 接着「请求确认，等确认期间什么都不动」
- **WHEN** 15:05Z 按确认，AAA 最新价 95，之后一轮
- **THEN** 券商收到 P2 的撤单请求；推送一条开始紧急退出的告警，写明个股跌幅、撤掉了 P2、订单结束以后清仓
- **WHEN** 券商回报 P2 变为撤销、累计成交 0，之后一轮
- **THEN** AAA 的清仓单已经建立：卖出 50 股

#### Scenario: 截止前一刻确认

- **GIVEN** 紧急退出要确认打开；AAA 最新价 92 时做过一轮，已经请求确认
- **WHEN** 15:29:59Z 按确认，15:30:05Z 之后一轮
- **THEN** 确认消息显示已确认；AAA 的清仓单已经建立：卖出 50 股

#### Scenario: 拒绝以后当天不再紧急退出

- **GIVEN** 紧急退出要确认打开；AAA 最新价 92 时做过一轮，已经请求确认
- **WHEN** 15:05Z 按拒绝，之后一轮
- **THEN** 确认消息显示已拒绝；AAA 的清仓方案没有订单；没有告警
- **WHEN** AAA 最新价 91，之后一轮
- **THEN** 没有新的确认消息；券商没有收到 AAA 的订单，AAA-STOP-1 仍挂着

#### Scenario: 确认超时

- **GIVEN** 紧急退出要确认打开；AAA 最新价 92 时做过一轮，已经请求确认，一直没有人按
- **WHEN** 2026-10-14 15:30:00Z 之后一轮
- **THEN** 确认消息显示已超时
- **AND** 推送一条告警，写明 AAA 到截止时刻没有确认、没有执行、今天不再紧急退出 AAA、止损单照挂
- **AND** AAA-STOP-1 仍挂着 50 股；AAA 的清仓方案没有订单
- **WHEN** 之后一轮
- **THEN** 没有关于 AAA 的新告警和确认消息

#### Scenario: 按钮和超时同时

- **GIVEN** 紧急退出要确认打开；AAA 最新价 92 时做过一轮，已经请求确认；本人在 15:29:59Z 按了确认，回调还没送到
- **WHEN** 2026-10-14 15:30:00Z 之后一轮，然后回调送到
- **THEN** 确认消息显示已超时；紧急退出流程没有收下这次确认，回调抛错
- **AND** AAA 的清仓方案没有订单

#### Scenario: 确认请求发不出去

- **GIVEN** 紧急退出要确认打开；Discord 对发消息报错
- **WHEN** AAA 最新价 92，做一轮
- **THEN** 有一条 ERROR 写明 AAA 的紧急退出确认没有发出去和原因；告警也没有发出去，有一条错误日志
- **AND** AAA 的清仓方案没有订单，AAA-STOP-1 仍挂着
- **WHEN** Discord 恢复，之后一轮
- **THEN** 没有 AAA 的确认消息，没有关于 AAA 的告警

#### Scenario: 下一个交易日重新判定

- **GIVEN** 接着「拒绝以后当天不再紧急退出」，AAA 仍持有 50 股，AAA-STOP-1 挂着
- **WHEN** 当前时刻 2026-10-15 13:30:05Z，AAA 前一交易日收盘价 91、最新价 83（跌幅约 0.088），做一轮
- **THEN** 频道里出现交易日 2026-10-15 的 AAA 的确认消息

#### Scenario: 熔断时撤买单不等确认

- **GIVEN** 紧急退出要确认打开；当前权益 9,300；P5 的订单已提交
- **WHEN** 做一轮
- **THEN** 券商收到 P5 的撤单请求；推送一条熔断告警
- **AND** 频道里出现 AAA、BBB 各一条确认消息，原因都写组合熔断
- **AND** AAA、BBB 的清仓方案都没有订单，AAA-STOP-1、BBB-STOP-1 都挂着
- **WHEN** 按 AAA 的确认、按 BBB 的拒绝，之后一轮
- **THEN** AAA 的清仓单已经建立：卖出 50 股；BBB 的清仓方案没有订单

#### Scenario: 本地备用止损不等确认

- **GIVEN** 紧急退出要确认打开；BBB 从 14:50Z 起是无保护仓位，没有挂着的止损单；券商会一直拒绝挂 BBB 的止损单
- **WHEN** BBB 最新价 35，做一轮
- **THEN** 频道里没有确认消息；券商收到 BBB 的清仓单：卖出 BBB 100 股，市价单
- **AND** 推送一条告警，原因写本地备用止损

#### Scenario: 同时触及个股跌幅和本地备用止损时不等确认

- **GIVEN** 紧急退出要确认打开；BBB 从 14:50Z 起是无保护仓位，没有挂着的止损单；券商会一直拒绝挂 BBB 的止损单
- **WHEN** BBB 最新价 34，做一轮
- **THEN** 频道里没有确认消息；券商收到 BBB 的清仓单：卖出 BBB 100 股
- **AND** 推送一条告警，原因写个股跌幅

#### Scenario: 在等确认时本地备用止损触发

- **GIVEN** 紧急退出要确认打开；AAA 从 14:50Z 起是无保护仓位，没有挂着的止损单；券商会一直拒绝挂 AAA 的止损单
- **WHEN** AAA 最新价 92，做一轮
- **THEN** 频道里出现 AAA 的确认消息；券商没有收到 AAA 的订单
- **WHEN** AAA 最新价 90，之后一轮
- **THEN** 确认消息显示已作废；券商收到 AAA 的清仓单：卖出 AAA 50 股，市价单
- **AND** 推送一条告警，原因写本地备用止损、无保护仓位、最新价 90、止损价 90

#### Scenario: 拒绝以后本地备用止损照样触发

- **GIVEN** 紧急退出要确认打开；AAA 从 14:50Z 起是无保护仓位，没有挂着的止损单；券商会一直拒绝挂 AAA 的止损单；AAA 最新价 92 时做过一轮，按了拒绝，之后一轮
- **WHEN** AAA 最新价 89.5，之后一轮
- **THEN** 券商收到 AAA 的清仓单：卖出 AAA 50 股；推送一条告警，原因写本地备用止损

#### Scenario: 降级模式下照常请求确认

- **GIVEN** 紧急退出要确认打开；处于降级模式
- **WHEN** AAA 最新价 92，做一轮
- **THEN** 频道里出现 AAA 的确认消息

#### Scenario: 确认以后的程序日志

- **GIVEN** 紧急退出要确认打开
- **WHEN** AAA 最新价 92，15:00Z 做一轮；15:05Z 按确认，之后一轮
- **THEN** 程序日志依次有：AAA 当天的清仓方案的请求确认（原因写个股跌幅，当前持仓 50 股）、确认、AAA 的紧急风险退出，之后是这一项的风控检查、下单前再校验和提交订单

#### Scenario: 拒绝和超时的程序日志

- **GIVEN** 紧急退出要确认打开；当前权益 9,300，15:00Z 做过一轮，AAA、BBB 各请求过一次确认
- **WHEN** 按 AAA 的拒绝；BBB 一直没有人按，2026-10-14 15:30:00Z 之后一轮
- **THEN** 程序日志有 AAA 的清仓方案的拒绝；BBB 的清仓方案的超时、结束确认（已超时），以及 BBB 确认超时的告警

### Requirement: 告警

紧急退出 SHALL 只为下面这些情况推送告警（discord-notification spec「告警」），对象是股票（熔断是 `account`）；通知模块把每条告警写进程序日志（program-log spec「系统的动作」）：

| 情况 | 告警写明 |
| --- | --- |
| 一只股票开始紧急退出：这次运行里第一次按「一只股票的清仓」处理它当天的清仓（需要确认的，是确认以后的第一次） | 股票；原因：个股跌幅写参考价、最新价、跌幅和紧急阈值，组合熔断，本地备用止损写无保护仓位或错开中、最新价和止损价；这一项做了什么：作废的方案（动作、方案 ID），撤掉的订单（买卖方向、股数、方案 ID），已经建立的清仓单（股数），或者等订单都结束以后清仓，或者没有可卖的股数 |
| 熔断触发：这次运行里每个交易日第一次看到 | 前一交易日收盘时的权益、当前权益、单日亏损和它占前一交易日收盘时权益的比例、熔断比例；清仓全部持仓，撤掉全部买单，收盘前不再开仓。「紧急退出要确认」打开时写明每只持仓的清仓要确认 |
| 清仓单进入终态 | 全部成交：股票、卖出股数和成交均价。其他终态（已拒绝、已过期、已撤销）：股票、状态、累计成交和委托股数；今天不再清仓这只股票，剩下的持仓由止损单保护 |
| 之后的轮次里没有可卖的股数 | 股票；没有可卖的股数，紧急退出结束 |
| 到收盘还没有清仓单：当天开始、不在等确认的紧急退出，收盘以后的第一轮仍没有订单 | 股票；到收盘还没下清仓单（等撤单结束），今天不再清仓。同时拿锁释放当天清仓方案剩下的预留（有的话） |
| 紧急退出的确认超时 | 股票；到截止时刻没有确认，没有执行；今天不再紧急退出这只股票，止损单照挂 |
| 紧急退出的确认请求发不出去 | 股票；确认请求没有发出去，没有执行；今天不再紧急退出这只股票，止损单照挂 |
| 到收盘还在等确认：收盘以后的第一轮仍在等 | 股票；到收盘还没有确认，没有执行，今天不再紧急退出这只股票。同时报告确认消息已作废 |

- 一只股票开始紧急退出时，先写程序日志的紧急风险退出（原因），再做这一项；熔断触发时写程序日志的熔断，和熔断告警同时
- 其余只写程序日志（program-log spec）：撤单、作废的方案（释放预留）、清仓方案的风控检查和下单前再校验、建立清仓单（提交订单：股数和状态）、到收盘还没有清仓单时释放剩下的预留（有有效预留的话）。等订单结束的轮次 SHALL NOT 写
- 推送告警 MUST NOT 拿着锁。发不出去时按 discord-notification spec 写错误日志，告警的条目写明没有发出去；紧急退出照常继续，之后不重发
- 告警过什么只记在内存里：进程重启以后见「重启以后」

#### Scenario: 开始紧急退出的告警

- **GIVEN** AAA 最新价 92
- **WHEN** 做一轮
- **THEN** 推送一条告警，写明 AAA、个股跌幅、参考价 100、最新价 92、跌幅 8.0%、紧急阈值 8.0%、已建立清仓单卖出 50 股
- **AND** 程序日志依次有：AAA 的紧急风险退出（原因写个股跌幅 8.0%、参考价 100、最新价 92、紧急阈值 8.0%）、清仓方案的风控检查、下单前再校验、提交订单（卖出 50 股，待提交），最后是这条告警，内容和推送的相同

#### Scenario: 熔断告警的内容

- **GIVEN** 当前权益 9,300
- **WHEN** 做一轮
- **THEN** 熔断告警写明前一交易日收盘时的权益 10,000、当前权益 9,300、单日亏损 700（7.0%）、熔断比例 7.0%，清仓全部持仓、撤掉全部买单、收盘前不再开仓

#### Scenario: 清仓完成的告警

- **GIVEN** 接着「盘中一轮里触发并清仓」，券商已经收到 AAA 的清仓单
- **WHEN** 券商回报 AAA 的清仓单全部成交、累计成交 50、成交均价 91.5，券商持仓变为 0，之后一轮
- **THEN** 推送一条告警，写明 AAA 紧急清仓完成，卖出 50 股，成交均价 91.5
- **WHEN** 之后一轮
- **THEN** 没有关于 AAA 的新告警

#### Scenario: 清仓被拒的告警

- **GIVEN** AAA 最新价 92，做一轮，AAA 的清仓单已经建立；券商会拒绝下一笔订单
- **WHEN** 券商回报 AAA-STOP-1 变为撤销，之后一轮
- **THEN** 推送一条告警，写明 AAA 的清仓单已拒绝、成交 0 / 50 股、今天不再清仓 AAA、剩下的持仓由止损单保护

#### Scenario: 到收盘还没有清仓单

- **GIVEN** 当前时刻 2026-10-14 19:59:50Z；P2 的订单已提交，AAA-STOP-1 已经改为 30 股；AAA 最新价 92，做一轮，券商收到 P2 的撤单请求
- **WHEN** 券商回报 P2 仍是已受理、未结束，2026-10-14 20:00:05Z 之后一轮
- **THEN** 推送一条告警，写明 AAA 到收盘还没下清仓单，今天不再清仓
- **AND** AAA 的清仓方案没有订单，也没有有效预留

#### Scenario: 告警发不出去

- **GIVEN** AAA 最新价 92；Discord 报错
- **WHEN** 做一轮
- **THEN** AAA 的清仓单照常建立；有一条错误日志，含告警文字和失败原因
- **WHEN** Discord 恢复，之后一轮
- **THEN** 没有推送这条告警

#### Scenario: 熔断告警写明清仓要确认

- **GIVEN** 紧急退出要确认打开；当前权益 9,300
- **WHEN** 做一轮
- **THEN** 熔断告警写明前一交易日收盘时的权益 10,000、当前权益 9,300、单日亏损 700（7.0%）、熔断比例 7.0%，撤掉全部买单、收盘前不再开仓，每只持仓的清仓要确认

#### Scenario: 到收盘还在等确认
