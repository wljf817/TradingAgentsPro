# Spec Delta

## MODIFIED Requirements

### Requirement: 告警

推送告警 SHALL 往配置的频道发一条消息：开头 @ 配置的用户，后面是调用方给的文字。调用方另外给出告警针对的对象（方案 ID、股票、`account` 或 `system`，program-log spec「程序日志的条目」）。

- 只有配置的用户会被 @ 到：文字里写了 @everyone、@here 或别人的 @，也不会通知任何其他人
- 整条消息超过 Discord 的 2000 字上限时，SHALL 把文字截短，使整条消息正好 2000 字，最后一个字是「…」

通知模块的用例每推送一条告警，SHALL 写一条程序日志的告警（program-log spec「系统的动作」）：对象是调用方给的对象，说明是告警的全文。发不出去（通知不可用）时 SHALL 写一条错误日志（含告警文字），告警的条目写明没有发出去和原因；不抛错，调用方照常继续。

#### Scenario: 推送告警

- **WHEN** 推送告警「AAPL 没有止损单：挂单失败」
- **THEN** 频道 2002 收到一条消息，内容是 @本人 加上这句话
- **AND** 本人收到通知（手机推送）

#### Scenario: 文字里有 @everyone

- **WHEN** 推送告警「对账不一致 @everyone <@4004>」
- **THEN** 消息照原样发出，只有本人被通知，频道里的其他人和 4004 都没有被通知

#### Scenario: 文字太长

- **WHEN** 推送一条 2500 字的告警
- **THEN** 消息正好 2000 字，开头是 @本人，最后一个字是「…」

#### Scenario: 告警发不出去

- **GIVEN** Discord 报错或超过发送超时
- **WHEN** 通知模块的用例推送告警
- **THEN** 写一条错误日志，内容有告警文字和失败原因
- **AND** 程序日志有这条告警，写明没有发出去和失败原因
- **AND** 用例正常返回，不抛错

#### Scenario: 推送告警写程序日志

- **WHEN** 通知模块的用例推送告警「AAPL 没有止损单：挂单失败」，对象是 AAPL
- **THEN** 频道 2002 收到这条告警
- **AND** 程序日志有一条告警，对象 AAPL，说明是「AAPL 没有止损单：挂单失败」

### Requirement: 结束确认

调用方 SHALL 能报告一条确认消息的结果为已超时或已作废，给出方案 ID 和确认消息的标识。报告以后：

- 消息去掉按钮，显示报告的结果和报告的时刻
- 报告的结果覆盖消息上已经显示的结果：调用方是按它实际采用的结果报告的
- 之后再有人按这条消息的按钮（比如按钮还没来得及去掉），按「这条消息已经有结果」处理
- 报告时按下的按钮正在调用回调的，回调返回以后不再改消息
- 确认消息已经被删掉时，什么也不做，不报错

通知模块的用例每报告一次结果，SHALL 写一条程序日志的结束确认（program-log spec「系统的动作」）：对象是方案 ID，输入的引用是确认消息的标识，说明是报告的结果。发不出去（通知不可用）时 SHALL 写一条错误日志，结束确认的条目写明没有改成和原因；不抛错。

#### Scenario: 报告超时

- **GIVEN** P1 的确认消息没有人按
- **WHEN** 调用方在 14:30Z 报告已超时
- **THEN** 消息去掉按钮，显示已超时和 14:30Z

#### Scenario: 报告作废

- **WHEN** 调用方在 14:10Z 报告已作废
- **THEN** 消息去掉按钮，显示已作废

#### Scenario: 按钮的结果和调用方的结果不一致

- **GIVEN** 本人在 14:09Z 按了「确认」，回调成功，消息显示已确认
- **AND** 调用方先收到的是作废，没有采用这次确认
- **WHEN** 调用方报告已作废
- **THEN** 消息显示已作废

#### Scenario: 报告时回调还在运行

- **GIVEN** 本人按了「确认」，回调还在运行
- **WHEN** 调用方报告已作废，然后回调返回
- **THEN** 消息显示已作废，不会再改成已确认

#### Scenario: 报告以后再按

- **GIVEN** 调用方已经报告已作废
- **WHEN** 又收到本人对这条消息的一次按下
- **THEN** 他得到仅自己可见的提示，写明已作废；回调没有被调用

#### Scenario: 消息已被删掉

- **GIVEN** 本人删掉了 P1 的确认消息
- **WHEN** 调用方报告已超时
- **THEN** 什么也不做，不报错

#### Scenario: 报告发不出去

- **GIVEN** Discord 报错
- **WHEN** 通知模块的用例报告已超时
- **THEN** 写一条错误日志，用例正常返回
- **AND** 程序日志有 P1 的结束确认，写明已超时、没有改成和失败原因

#### Scenario: 报告结果写程序日志

- **GIVEN** P1 的确认消息没有人按
- **WHEN** 通知模块的用例在 14:30Z 报告 P1 的这条消息已超时
- **THEN** 消息显示已超时
- **AND** 程序日志有一条结束确认，对象 P1，输入的引用是这条消息的标识，说明写明已超时
