# Spec Delta

## MODIFIED Requirements

### Requirement: 无保护仓位的告警

每一轮第 3 步处理一只股票以后，这只股票是无保护仓位（stop-protection spec「挂单或改单被拒」）时，巡检 SHALL 按下表处理：

| 情况 | 处理 |
| --- | --- |
| 巡检开始以后第一次看到这一段无保护（按无保护开始的时刻区分一段） | 写程序日志的无保护仓位（program-log spec「执行模块的动作」）；推送一条告警（discord-notification spec「告警」），对象是这只股票 |
| 同一段无保护，已经告警过 | 不再告警，不写程序日志 |
| 告警过的股票不再是无保护仓位：补挂成功，卖完，或者不再需要对齐 | 写程序日志的无保护解除，不推送 |

告警文字 SHALL 写明：股票；无保护开始的时刻（UTC，到分钟）；原因是止损单挂单或改单被券商拒绝；巡检每一轮都会重试，补挂成功之前不能加仓。

- 无保护仓位不论在哪里产生（巡检的跟进或对齐、下单流程的提交、紧急撤单、对账），都由之后一轮的对齐发现并告警
- 这一轮跟进过订单的股票，按跟进时对齐的结果告警
- 告警过的记录只在巡检的内存里：程序重启以后，还在继续的一段无保护再告警一次，也再写一次无保护仓位
- 推送告警时不拿锁（见「执行模块和风控的调用串行」）；发不出去时按 discord-notification spec 写错误日志，告警的条目写明没有发出去，这一段无保护不再重发

#### Scenario: 第一次发现时告警

- **GIVEN** P1 已经提交，订单已提交；券商会一直拒绝挂单
- **WHEN** 券商回报 P1 变为已受理、累计成交 30，券商持仓变为 30 股，15:00Z 做一轮
- **THEN** 跟进 P1 时 BBB-STOP-1 挂单两次被拒，第 3 步没有再对齐 BBB；BBB 是无保护仓位，开始时刻 15:00Z
- **AND** 推送一条告警，写明 BBB、2026-10-14 15:00 UTC、止损单挂单或改单被券商拒绝、补挂成功之前不能加仓
- **AND** 程序日志有 BBB 的无保护仓位，写明从 2026-10-14 15:00Z 起

#### Scenario: 同一段无保护不重复告警

- **GIVEN** 接着「第一次发现时告警」，券商仍然一直拒绝挂单
- **WHEN** 之后一轮
- **THEN** BBB 仍是无保护仓位，开始时刻仍是 15:00Z
- **AND** 没有新的告警，程序日志没有新的无保护仓位

#### Scenario: 补挂成功只写日志

- **GIVEN** 接着「第一次发现时告警」
- **WHEN** 券商恢复正常受理，之后一轮
- **THEN** BBB 不再是无保护仓位
- **AND** 程序日志有 BBB 的无保护解除，没有推送

#### Scenario: 新的一段无保护再告警

- **GIVEN** BBB 从 15:00Z 开始的一段无保护已经告警过，15:05Z 补挂成功，BBB 持有 100 股，止损单已对齐
- **AND** P2 已经提交，订单已提交；券商会拒绝接下来两次改单
- **WHEN** 券商回报 P2 变为已受理、累计成交 20，券商持仓变为 120 股，15:10Z 做一轮
- **THEN** BBB 是无保护仓位，开始时刻 15:10Z
- **AND** 推送一条告警，写明 2026-10-14 15:10 UTC

#### Scenario: 别处产生的无保护仓位

- **GIVEN** 持有 BBB 100 股；别的调用方跟进 P2 时改单被拒，BBB 从 15:00:05Z 起是无保护仓位，P2 已经全部成交，券商持仓 150 股
- **AND** 券商会拒绝接下来两次改单
- **WHEN** 15:00:15Z 做一轮
- **THEN** 推送一条告警，写明 BBB 和 2026-10-14 15:00 UTC

#### Scenario: 跟进时被拒，下一轮跟进时补挂

- **GIVEN** P1 已经提交，订单已提交；券商会拒绝接下来两次挂单
- **WHEN** 券商回报 P1 变为已受理、累计成交 30，券商持仓变为 30 股，做一轮
- **THEN** 跟进 P1 时 BBB 变为无保护仓位，第 3 步没有再对齐 BBB；推送一条告警
- **WHEN** 之后一轮
- **THEN** 跟进 P1 时挂上 BBB-STOP-2，BBB 不再是无保护仓位；程序日志有 BBB 的无保护解除，没有新的告警

#### Scenario: 重启以后再告警一次

- **GIVEN** 持有 BBB 100 股，BBB 从 15:00Z 起是无保护仓位，没有挂着的止损单，重启之前已经告警过；券商会一直拒绝挂单
- **WHEN** 程序重启，巡检做第一轮
- **THEN** 推送一条告警，写明 BBB 和 2026-10-14 15:00 UTC；程序日志再有一条 BBB 的无保护仓位
- **WHEN** 之后一轮
- **THEN** 没有新的告警

#### Scenario: 告警发不出去

- **GIVEN** 持有 BBB 100 股，BBB 从 15:00Z 起是无保护仓位，巡检还没有告警过；券商会一直拒绝挂单；Discord 报错
- **WHEN** 做一轮
- **THEN** 写一条错误日志，含告警文字和失败原因；程序日志的告警写明没有发出去；巡检照常做完这一轮
- **WHEN** Discord 恢复，之后一轮 BBB 仍是同一段无保护
- **THEN** 没有推送告警

### Requirement: 订单和止损单变化的日志

巡检 SHALL 把看到的变化各写一条程序日志（program-log spec「执行模块的动作」），不推送 Discord：

| 变化 | 程序日志 |
| --- | --- |
| 跟进一笔订单前后，状态或累计成交变了 | 订单变化：对象是方案 ID；股票、买卖方向、变化前后的状态、累计成交和委托股数，有成交时写成交均价和累计费用 |
| 第 3 步处理一只股票以后，当前止损单和巡检上次看到的不同（换了一张，或者状态、未成交股数、止损价变了）；巡检开始以后第一次看到的止损单也算 | 止损单变化：对象是止损单的客户端订单 ID；股票、状态、未成交股数、止损价，有成交时写累计成交和成交均价 |

没有变化时 SHALL NOT 写。别的调用方里止损单的变化（比如下单流程的提交、对账），巡检在之后一轮看到时才写；别的调用方跟进订单时的变化由它们自己写（program-log spec「执行模块的动作」的订单变化）。巡检上次看到的止损单只记在内存里，写进程序日志以后才记下。

#### Scenario: 订单成交写日志

- **GIVEN** P1 已经提交，订单已提交
- **WHEN** 券商回报 P1 变为已受理、累计成交 30，做一轮
- **THEN** 程序日志有一条订单变化，写明 BBB、P1、买入、已提交变为部分成交、累计成交 30 / 100
- **AND** 没有推送 Discord

#### Scenario: 换了一张止损单写日志

- **GIVEN** 持有 BBB 100 股，止损单已对齐；巡检已经做过一轮
- **WHEN** 券商回报 BBB-STOP-1 变为撤销，做一轮，挂上 BBB-STOP-2
- **THEN** 程序日志有一条止损单变化，对象 BBB-STOP-2，写明 BBB、挂着、100 股、止损价 45

#### Scenario: 没有变化不写日志

- **GIVEN** 持有 BBB 100 股，止损单已对齐；巡检已经做过一轮；P1 已经全部成交
- **WHEN** 做一轮，券商那边没有任何变化
- **THEN** 巡检没有写程序日志
