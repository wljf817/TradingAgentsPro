# Spec Delta

## Purpose

执行模块把每笔买单、卖单和止损单记成一条交易记录，像银行 App 的交易流水；并用交易记录、订单和券商账户给出账户数据：已结算资金、每只持仓的开仓信息、每只股票的最近成交日。

## ADDED Requirements

### Requirement: 交易记录的内容

执行模块 SHALL 为每笔订单和每张止损单各记一条交易记录，键是客户端订单 ID。内容如下：

| 项 | 买单、卖单 | 止损单 |
| --- | --- | --- |
| 客户端订单 ID | 方案 ID | 止损单的客户端订单 ID，比如 BBB-STOP-1 |
| 类型 | 买单是买入，卖单是卖出 | 止损单 |
| 股票 | 订单的 | 止损单的 |
| 来源方案 ID | 订单的方案 ID | 这只股票止损价来自的开仓订单的方案 ID：最近创建的、累计成交大于 0 的开仓订单（见 stop-protection spec「止损价」）；没有这样的订单时没有 |
| 委托股数 | 订单的委托股数 | 止损单的未成交股数加累计成交股数 |
| 累计成交股数、成交均价、累计费用 | 订单的 | 止损单的 |
| 状态 | 订单的状态 | 见「止损单交易记录的状态」 |
| 创建时刻 | 订单的创建时刻 | 止损单的创建时刻 |
| 成交日、结算日 | 见「成交日和结算日」 | 同左 |

本 spec 的场景除非另有说明，都使用 order-lifecycle spec「提交订单」的基准数据，以及 stop-protection spec「止损单」里的方案和说法，另外：

- P1 的再校验结果里生效的紧急阈值是 0.08；P2 的是 0.06
- P5：减仓 AAA 60 股，市价单；再校验通过，最终股数 60，生效的有效期是当天收盘
- 券商账户：权益 100,000，现金 40,000，前一交易日收盘时的权益 101,000。现金已经包含当天卖出成交的钱
- "券商回报 P1 变为……"没写累计费用时，累计费用是 0
- "券商回报 BBB-STOP-1 变为……"指之后按客户端订单 ID 查询时，券商给出的这张止损单的状态、未成交股数、止损价、累计成交股数、成交均价和累计费用；没写累计成交和累计费用时都是 0
- "读取账户数据"指在当时的时刻向执行模块要账户数据

#### Scenario: 买单的交易记录

- **GIVEN** 基准数据
- **WHEN** 提交 P1，券商受理，没有成交
- **THEN** P1 的交易记录：买入 BBB，来源方案 P1，委托 100 股，累计成交 0，没有成交均价，累计费用 0，已提交，创建时刻 2026-10-14 15:00Z，没有成交日和结算日

#### Scenario: 卖单的交易记录

- **GIVEN** 基准数据
- **WHEN** 提交 P5，券商回报 P5 变为全部成交、累计成交 60、成交均价 101、累计费用 2，跟进 P5
- **THEN** P5 的交易记录：卖出 AAA，来源方案 P5，委托 60 股，累计成交 60，成交均价 101，累计费用 2，全部成交，成交日 2026-10-14，结算日 2026-10-15

#### Scenario: 止损单的交易记录

- **GIVEN** P1 已经提交，订单已提交
- **WHEN** 券商回报 P1 部分成交、累计成交 30、成交均价 49.90，券商持仓变为 30 股，2026-10-14 15:00Z 跟进 P1，券商受理止损单
- **THEN** BBB-STOP-1 的交易记录：止损单，BBB，来源方案 P1，委托 30 股，累计成交 0，已提交，创建时刻 2026-10-14 15:00Z，没有成交日和结算日

#### Scenario: 加仓成交后，止损单的来源方案换成加仓方案

- **GIVEN** 持有 BBB 100 股，止损单已对齐，P2 已经提交，订单已提交
- **WHEN** 券商回报 P2 部分成交、累计成交 20，券商持仓变为 120 股，跟进 P2
- **THEN** 券商收到 BBB-STOP-1 的改单：120 股，止损价 48
- **AND** BBB-STOP-1 的交易记录：来源方案 P2，委托 100 股（改单还没生效）
- **WHEN** 券商回报 BBB-STOP-1 变为挂着、未成交 120 股、止损价 48，对齐 BBB
- **THEN** BBB-STOP-1 的交易记录：来源方案 P2，委托 120 股

### Requirement: 交易记录的写入

订单或止损单每次变化时，执行模块 SHALL 更新它的交易记录，包括新建、按券商回报更新和状态变化。交易记录按 state-store spec 的只追加版本表保存，内容和最新版本相同时不写新版本，所以只有跟进用的状态变化（比如撤单要求、改单请求）时不多出版本。

执行模块 SHALL 先写交易记录，再保存订单或止损保护。保存订单或止损保护出错时，交易记录可能已经是新的；之后再跟进订单或对齐止损单时，订单和止损保护跟上。交易记录 MUST NOT 落后于已经保存的订单和止损单。

#### Scenario: 每次变化都更新交易记录

- **GIVEN** 基准数据
- **WHEN** 提交 P1，券商受理
- **AND** 券商回报 P1 变为部分成交、累计成交 30、成交均价 49.90，跟进 P1
- **AND** 券商回报 P1 变为全部成交、累计成交 100、成交均价 49.95、累计费用 2，跟进 P1
- **THEN** P1 的交易记录依次有 4 个版本：待提交；已提交；部分成交、累计成交 30、成交均价 49.90；全部成交、累计成交 100、成交均价 49.95、累计费用 2

#### Scenario: 只有撤单要求时不写新版本

- **GIVEN** P1 已经提交，订单已提交，P1 的交易记录有 2 个版本
- **WHEN** 2026-10-14 15:10Z 撤掉 BBB 的订单，券商还没回报撤销
- **THEN** 订单有撤单要求，P1 的交易记录仍是 2 个版本，最新的是已提交

#### Scenario: 保存订单出错时交易记录已经更新

- **GIVEN** P1 已经提交，订单已提交；下一次保存订单时存储会出错
- **WHEN** 券商回报 P1 变为全部成交、累计成交 100、成交均价 50，跟进 P1
- **THEN** 跟进报错；P1 的交易记录已经是全部成交，存储里的订单仍是已提交
- **WHEN** 再跟进 P1
- **THEN** 订单全部成交，P1 的交易记录不变

#### Scenario: 保存止损保护出错时交易记录已经更新

- **GIVEN** P1 已经提交，订单已提交；下一次保存止损保护时存储会出错
- **WHEN** 券商回报 P1 部分成交、累计成交 30，券商持仓变为 30 股，跟进 P1
- **THEN** 跟进报错；BBB-STOP-1 的交易记录是待提交，券商没有收到挂单
- **WHEN** 再跟进 P1
- **THEN** 券商收到止损单 BBB-STOP-1：卖出 30 股，止损价 45；BBB-STOP-1 的交易记录是已提交

### Requirement: 止损单交易记录的状态

止损单的交易记录 SHALL 按下表给出状态，和订单的 8 种状态一致（见 order-lifecycle spec「订单状态和券商回报」）：

| 止损单 | 交易记录的状态 |
| --- | --- |
| 还没挂出去 | 待提交 |
| 挂着，累计成交为 0 | 已提交 |
| 挂着，累计成交大于 0 | 部分成交 |
| 状态未知 | 状态未知 |
| 已经结束，未成交股数为 0，累计成交大于 0 | 全部成交 |
| 已经结束，券商受理过，其他情况 | 已撤销 |
| 已经结束，券商从没受理过 | 已拒绝 |

券商受理过的止损单撤销、长期有效单到期失效都记为已撤销；挂单被拒都记为已拒绝。

#### Scenario: 挂单超时时先后是待提交和状态未知

- **GIVEN** P1 已经提交，下一次挂单超时，券商没有收到
- **WHEN** 券商回报 P1 部分成交、累计成交 30，券商持仓变为 30 股，2026-10-14 15:00Z 跟进 P1
- **THEN** BBB-STOP-1 的交易记录有 2 个版本：待提交；状态未知

#### Scenario: 挂着、没有成交时是已提交

- **GIVEN** P1 已经提交
- **WHEN** 券商回报 P1 部分成交、累计成交 30，券商持仓变为 30 股，跟进 P1，券商受理止损单
- **THEN** BBB-STOP-1 的交易记录是已提交，委托 30 股，累计成交 0

#### Scenario: 止损单部分成交

- **GIVEN** 持有 BBB 100 股，止损单已对齐
- **WHEN** 券商回报 BBB-STOP-1 变为挂着、未成交 60 股、止损价 45、累计成交 40、成交均价 44.90、累计费用 2，券商持仓变为 60 股，对齐 BBB
- **THEN** BBB-STOP-1 的交易记录：部分成交，委托 100 股，累计成交 40，成交均价 44.90，累计费用 2

#### Scenario: 止损单全部成交

- **GIVEN** 持有 BBB 100 股，止损单已对齐
- **WHEN** 券商回报 BBB-STOP-1 变为全部成交、未成交 0、累计成交 100、成交均价 44.80、累计费用 2，券商持仓变为 0 股，对齐 BBB
- **THEN** BBB-STOP-1 的交易记录：全部成交，委托 100 股，累计成交 100，成交均价 44.80，累计费用 2

#### Scenario: 清仓时撤销的止损单

- **GIVEN** 持有 BBB 100 股，止损单已对齐
- **WHEN** 提交 P4，券商回报 BBB-STOP-1 变为撤销、未成交 100 股，跟进 P4
- **THEN** BBB-STOP-1 的交易记录：已撤销，委托 100 股，累计成交 0

#### Scenario: 挂单都被拒的止损单

- **GIVEN** P1 已经提交，券商会拒绝接下来两次挂单
- **WHEN** 券商回报 P1 部分成交、累计成交 30，券商持仓变为 30 股，跟进 P1
- **THEN** BBB-STOP-1 的交易记录：已拒绝，委托 30 股，累计成交 0

### Requirement: 成交日和结算日

累计成交大于 0 的交易记录 SHALL 有成交日和结算日；累计成交为 0 的都没有。

- 订单的成交日：订单创建时所在交易时段的交易日。订单都是当日有效单，只在这个时段内成交
- 止损单的成交日：执行模块最近一次发现这张止损单累计成交增加的时刻所在的交易日。这个时刻在常规交易时段内时，是当天的交易日；否则是这个时刻之前最后一个收盘的交易日，因为止损单只在常规交易时段触发
- 结算日：成交日之后的下一个交易日（T+1）

结算状态 SHALL 按执行交易日判断：执行交易日不早于结算日时为已结算，否则为未结算。执行交易日和 risk-rules spec「开仓类规则」相同：当前时刻在常规交易时段内时是当天的交易日，否则是下一个开盘的交易日。

#### Scenario: 收盘后才查到成交的订单

- **GIVEN** P1 已经提交，订单已提交
- **WHEN** 券商回报 P1 变为全部成交、累计成交 100、成交均价 50，2026-10-14 20:00:05Z 跟进 P1
- **THEN** P1 的交易记录：成交日 2026-10-14，结算日 2026-10-15

#### Scenario: 盘中发现成交的止损单

- **GIVEN** 持有 BBB 100 股，止损单已对齐
- **WHEN** 券商回报 BBB-STOP-1 变为全部成交、未成交 0、累计成交 100、成交均价 44.80，2026-10-14 15:30Z 对齐 BBB
- **THEN** BBB-STOP-1 的交易记录：成交日 2026-10-14，结算日 2026-10-15

#### Scenario: 第二天开盘前才发现成交的止损单

- **GIVEN** 持有 BBB 100 股，止损单已对齐
- **WHEN** 券商回报 BBB-STOP-1 变为全部成交、未成交 0、累计成交 100、成交均价 44.80，2026-10-15 13:00Z（周四开盘前）对齐 BBB
- **THEN** BBB-STOP-1 的交易记录：成交日 2026-10-14，结算日 2026-10-15

#### Scenario: 周五成交，周一结算

- **GIVEN** 当前时刻改为 2026-10-16 15:00Z（周五，盘中），基准结果的生效有效期改为 2026-10-16 20:00Z
- **WHEN** 提交 P1，券商回报 P1 变为全部成交、累计成交 100、成交均价 50，跟进 P1
- **THEN** P1 的交易记录：成交日 2026-10-16，结算日 2026-10-19

#### Scenario: 结算日跳过休市日

- **GIVEN** 当前时刻改为 2026-11-25 15:00Z（感恩节前一天，盘中），基准结果的生效有效期改为 2026-11-25 21:00Z
- **WHEN** 提交 P1，券商回报 P1 变为全部成交、累计成交 100、成交均价 50，跟进 P1
- **THEN** P1 的交易记录：成交日 2026-11-25，结算日 2026-11-27

#### Scenario: 没有成交的交易记录没有成交日

- **GIVEN** P1 已经提交，订单已提交
- **WHEN** 券商回报 P1 变为撤销、累计成交 0，跟进 P1
- **THEN** P1 的交易记录：已撤销，没有成交日和结算日

#### Scenario: 结算状态随执行交易日变化

- **GIVEN** P5 的交易记录：全部成交，成交日 2026-10-14，结算日 2026-10-15
- **WHEN** 2026-10-14 19:00Z（盘中，执行交易日 2026-10-14）判断结算状态
- **THEN** 未结算
- **WHEN** 2026-10-14 21:00Z（盘后，执行交易日 2026-10-15）判断结算状态
- **THEN** 已结算

### Requirement: 已结算资金

执行模块给出的已结算资金 SHALL 等于券商现金减去未结算的卖出成交额：

- 卖出成交额：类型是卖出或止损单、结算状态为未结算的交易记录，每条的累计成交股数 × 成交均价之和；不扣费用
- 买入不调整：买入成交时券商现金已经减少

#### Scenario: 盘中当天的卖出未结算

- **GIVEN** P5 已经提交，券商回报全部成交、累计成交 60、成交均价 101、累计费用 2，已经跟进
- **WHEN** 2026-10-14 19:00Z 读取账户数据
- **THEN** 已结算资金 33,940（40,000 − 60 × 101），不扣费用

#### Scenario: 部分成交的卖单按已成交的部分算

- **GIVEN** P5 已经提交，券商回报部分成交、累计成交 20、成交均价 101，已经跟进
- **WHEN** 2026-10-14 19:00Z 读取账户数据
- **THEN** 已结算资金 37,980（40,000 − 20 × 101）

#### Scenario: 当天成交的止损单未结算

- **GIVEN** 持有 BBB 100 股，止损单已对齐；2026-10-14 15:30Z 对齐 BBB 时，券商回报 BBB-STOP-1 全部成交、未成交 0、累计成交 100、成交均价 44.80
- **WHEN** 2026-10-14 19:00Z 读取账户数据
- **THEN** 已结算资金 35,520（40,000 − 100 × 44.80）

#### Scenario: 收盘以后当天的卖出算已结算

- **GIVEN** P5 已经提交，券商回报全部成交、累计成交 60、成交均价 101，已经跟进
- **WHEN** 2026-10-14 21:00Z（盘后，下一个开盘的交易日是 2026-10-15）读取账户数据
- **THEN** 已结算资金 40,000

#### Scenario: 前一交易日的卖出已结算

- **GIVEN** 2026-10-13 提交了 P5，当天全部成交、累计成交 60、成交均价 101
- **WHEN** 2026-10-14 15:00Z 读取账户数据
- **THEN** 已结算资金 40,000

#### Scenario: 买入不调整已结算资金

- **GIVEN** P1 已经提交，券商回报全部成交、累计成交 100、成交均价 50，已经跟进
- **WHEN** 2026-10-14 19:00Z 读取账户数据
- **THEN** 已结算资金 40,000

#### Scenario: 周五的卖出在周末算已结算

- **GIVEN** 2026-10-16（周五）15:00Z 提交了 P5，全部成交、累计成交 60、成交均价 101，已经跟进
- **WHEN** 2026-10-16 19:00Z 读取账户数据
- **THEN** 已结算资金 33,940
- **WHEN** 2026-10-17 15:00Z（周六，执行交易日 2026-10-19）读取账户数据
- **THEN** 已结算资金 40,000

### Requirement: 最近成交日

每只股票的最近成交日 SHALL 是它全部累计成交大于 0 的交易记录（买入、卖出、止损单）里最晚的成交日。没有这样的交易记录的股票没有最近成交日。清仓以后最近成交日仍然保留。

#### Scenario: 买入、止损都算，取最晚的

- **GIVEN** 2026-10-13 提交了 P1，当天全部成交；2026-10-14 15:30Z 对齐 BBB 时，券商回报 BBB-STOP-1 全部成交、未成交 0、累计成交 100、成交均价 44.80
- **WHEN** 2026-10-14 19:00Z 读取账户数据
- **THEN** BBB 的最近成交日是 2026-10-14

#### Scenario: 没有成交的订单不算

- **GIVEN** 买入 CCC 的方案已经提交，券商回报撤销、累计成交 0，已经跟进；CCC 没有别的交易记录
- **WHEN** 读取账户数据
- **THEN** CCC 没有最近成交日

#### Scenario: 清仓以后仍有最近成交日

- **GIVEN** 2026-10-13 提交了 P1，当天全部成交；2026-10-14 15:00Z 提交了 P4，止损单撤销以后 P4 全部成交；券商账户里没有 BBB 的持仓
- **WHEN** 2026-10-14 19:00Z 读取账户数据
- **THEN** 持仓里没有 BBB，BBB 的最近成交日是 2026-10-14

### Requirement: 账户数据

执行模块 SHALL 给出账户数据：

| 项 | 来源 |
| --- | --- |
| 权益、前一交易日收盘时的权益 | 券商账户 |
| 已结算资金 | 见「已结算资金」 |
| 持仓 | 券商账户里股数大于 0 的每只持仓，见下表 |
| 最近成交日 | 每只有最近成交日的股票，见「最近成交日」 |

每只持仓：

| 项 | 来源 |
| --- | --- |
| 股数、均价 | 券商 |
| 板块、止损价、紧急阈值 | 这只股票最近创建的、累计成交大于 0 的开仓订单（和 stop-protection spec「止损价」取同一笔） |
| 今天开仓成交的均价 | 当前时刻在常规交易时段内，并且这只股票有当天创建、累计成交大于 0 的开仓订单时，是其中最近创建的那笔的成交均价；否则没有 |

券商的持仓没有累计成交大于 0 的开仓订单时，SHALL NOT 列在持仓里：账户只给系统用，这样的持仓按 reconciliation spec「来历不明的持仓」处理。

读取券商账户超时或断线时，SHALL 报券商不可用的错误。

#### Scenario: 读取账户数据

- **GIVEN** 2026-10-13 15:00Z 提交了 P1，当天全部成交、累计成交 100、成交均价 49.95；券商账户的持仓是 BBB 100 股，均价 49.95

### Requirement: 保存交易记录

执行模块 SHALL 把交易记录保存在存储中，可以按客户端订单 ID 读取，也可以列出累计成交大于 0 的全部交易记录。数据库实现按 state-store spec 的只追加版本表保存在交易记录表里，列出时只看每条的最新版本。进程重启后，执行模块 SHALL 从存储读出交易记录，给出同样的已结算资金和最近成交日。

#### Scenario: 列出有成交的交易记录

- **GIVEN** P1 全部成交；P5 已撤销，累计成交 0；BBB-STOP-1 部分成交，累计成交 40
- **WHEN** 列出有成交的交易记录
- **THEN** 结果是 P1 和 BBB-STOP-1 的交易记录，都是最新版本；没有 P5

#### Scenario: 交易记录原样读回

- **GIVEN** P1 的交易记录：部分成交 30 股，成交均价 49.9533333333，累计费用 2.15，创建时刻 2026-10-14 15:00Z，成交日 2026-10-14，结算日 2026-10-15
- **WHEN** 保存，再按 P1 读取
- **THEN** 读到的交易记录和保存的相同

#### Scenario: 重启后给出同样的账户数据

- **GIVEN** 「盘中当天的卖出未结算」场景的数据
- **WHEN** 进程重启（用同一个存储重新创建执行模块），2026-10-14 19:00Z 读取账户数据
- **THEN** 已结算资金 33,940，AAA 的最近成交日是 2026-10-14
