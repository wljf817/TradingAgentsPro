# Proposal

## Why

M2 的下单流程和紧急退出流程要给风控和紧急退出喂账户数据，其中几项只有本系统自己的记录才能给出：

- 已结算资金：Proposal 要求按交易记录的结算状态计算；模拟盘的 Alpaca 是保证金账户，券商不区分已结算和未结算的资金
- 每只股票的最近成交日：买入、卖出和止损单成交都算
- 每只持仓的板块、止损价、紧急阈值，以及今天开仓成交的均价

现在执行模块只有订单和止损保护：订单上没有板块和紧急阈值，止损单只记未成交股数，成交了多少、什么价格都没记下，也没有交易流水。

本变更的目的只有一个：**执行模块把每笔买单、卖单和止损单记成交易记录，并用交易记录、订单和券商账户给出风控和紧急退出要的账户数据。**

引用的 Proposal（完整版）章节：

- 「记录、复盘与经验」的「交易记录」：每笔买入、卖出、止损单一条，状态变化时更新这一条；字段（类型、股票和数量、状态、成交价、费用、结算状态、来源案件 ID、客户端订单 ID 和时间）；开仓可用的已结算资金按交易记录的结算状态计算，每日对账时和券商核对
- 「记录、复盘与经验」的记录表：交易记录由执行模块写入，存在 PostgreSQL 里
- 「风控引擎与执行」的开仓类规则：已结算的可用资金按交易记录的结算状态计算，现金账户按 T+1 结算；同一股票的最短交易间隔
- 「持仓与退出」的紧急风险退出的触发：跌幅从前一交易日收盘价算，当天有买入或加仓成交的从这笔成交的均价算；组合单日亏损按前一交易日收盘时的权益算
- 「订单生命周期」：每次状态变化都写入交易记录；每日对账包括交易记录的成交、费用和结算状态

## What Changes

- 执行模块新增交易记录：每笔买单、卖单、止损单一条，以客户端订单 ID 为键，订单或止损单每次变化都更新这一条
  - 内容：类型（买入、卖出、止损单）、股票、来源方案 ID、委托股数、累计成交股数、成交均价、费用、状态（和订单的 8 种状态一致）、创建时刻、成交日、结算日
  - 结算日是成交日之后的下一个交易日（T+1）；结算状态按结算日和执行交易日判断
  - 存在新表 `execution_trades` 里，用状态库的只追加版本表
- 止损单记下成交：券商回报增加累计成交股数、成交均价和费用；止损单记下这些，以及创建时刻和发现成交的时刻
- 订单记下板块、紧急阈值和费用：板块取方案的，紧急阈值取再校验结果里生效的（只有买单有），费用取券商回报的累计费用
- 券商接口增加读取账户：权益、现金、前一交易日收盘时的权益，每只持仓的股数和均价
- 执行模块给出账户数据：
  - 已结算资金 = 券商现金 − 还没结算的卖出成交额（卖单和止损单）
  - 每只持仓：股数和均价取券商的；板块、止损价、紧急阈值取最近一次有成交的开仓订单；今天有开仓成交的，给出这笔成交的均价
  - 每只股票的最近成交日
  - 权益和前一交易日收盘时的权益取券商的

## Non-goals

- 来源案件 ID：M2 还没有案件，本变更记来源方案 ID（止损单记止损价来自的开仓方案），M4 有了案件再加
- 交易记录写入程序日志：程序日志在 M4
- Alpaca 的实现：读取账户、费用按配置估算、改单产生的替换订单的累计成交，都在「Alpaca 模拟盘」里做
- 把账户数据拼成风控的账户数据和紧急退出的持仓、读取行情：在「下单流程」「紧急退出流程」里做（design D7 给出拼法）
- 按股票、时间查询交易记录：M5 的查询工具
- 盈亏计算：M6 复盘
- 每日对账时核对费用和结算状态：见「需要人决定」第 2 条
- 省略的少见情况：见 design 的省略清单

## Capabilities

### New Capabilities

- `trade-records`：交易记录的内容和状态、什么时候写入、成交日和结算日、已结算资金、最近成交日、账户数据、交易记录的保存

### Modified Capabilities

- `order-lifecycle`：「提交订单」订单记下板块和紧急阈值；「订单状态和券商回报」按回报记下累计费用；「保存订单」增加这三项
- `stop-protection`：「对齐止损单」按回报记下累计成交、成交均价和费用，以及发现成交的时刻；「保存止损保护」增加这些和创建时刻
- `state-store`：「表的归属和迁移」增加交易记录表

## 需要人决定

1. **模拟盘是保证金账户**：完整版假设现金账户，「交易记录」写的是按 T+1 结算区分已结算和未结算资金。Alpaca 只有保证金账户，券商给的现金里已经包含当天卖出的钱，也不报已结算资金。

   推荐：把 Alpaca 当现金账户用。账户设置最大保证金倍数 1、关闭做空（在「Alpaca 模拟盘」里做）；已结算资金由本系统算，等于券商现金减去还没结算的卖出成交额。完整版「交易记录」最后一段改为："开仓可用的已结算资金 = 券商现金 − 还没结算的卖出成交额，按交易记录的结算日计算。模拟盘（Alpaca）只有保证金账户，设为最大保证金倍数 1、不做空，按现金账户使用。"
2. **每日对账时核对交易记录的费用和结算状态**：完整版「订单生命周期」的每日对账一行和「交易记录」都要求和券商核对成交、费用和结算状态。模拟盘做不到：
   - 成交：交易记录由订单和止损单推出，对账时本来就跟进每笔订单、对齐每张止损单，已经和券商一致，不用另外核对
   - 费用：Alpaca 模拟盘不收费，交易记录里的费用是按配置估算的，没有可以比的
   - 结算状态：Alpaca 不报已结算资金，没有可以比的

   推荐：M2 不另外核对费用和结算状态，M7 接 moomoo 实盘时再按券商能给出的数据核对。完整版「交易记录」的"每日对账时和券商核对"后面加"（接入实盘以后）"；「订单生命周期」的每日对账一行，"包括交易记录的成交、费用和结算状态"改为"交易记录随订单和止损单和券商一致；费用和结算状态在接入实盘以后核对"。
