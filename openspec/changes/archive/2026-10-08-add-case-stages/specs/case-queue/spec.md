# Spec Delta

## MODIFIED Requirements

### Requirement: 降级模式

处于降级模式时，队列的决定 SHALL 不启动任何案件：

| 降级模式 | 启动 | 不再运行和作废 |
| --- | --- | --- |
| 处于（降级或等待对账） | 不启动，排队的案件留在队列里 | 照常 |
| 不处于 | 按「启动的顺序」 | 照常 |

- 新的触发照常排队；运行中的案件不中止
- 退出降级模式（对账完成、健康监控回到正常）以后，积压的整个队列按「启动的顺序」启动：持仓案件优先级最高，自然在前；非持仓的案件也照常启动
- 紧急退出的决定不看降级模式（见「紧急退出」）

#### Scenario: 降级期间不启动

- **GIVEN** 处于降级模式；运行中：EEE 的持仓复查（调用模型）；排队：AAA 的有新候选（20:00Z）、BBB 的关注复查日到期（20:00Z）、CCC 的持仓复查日到期（20:00Z）
- **WHEN** 取得队列的决定
- **THEN** 不启动；EEE 的持仓复查照常运行

#### Scenario: 降级期间照常不再运行和作废

- **GIVEN** 处于降级模式；运行中：BBB 的关注股事件（等下单），P-1 等下单；排队：BBB 的新闻事件（14:00Z）、CCC 的持仓复查日到期（20:00Z）
- **WHEN** CCC 的止损单成交、变为候选以后，取得队列的决定
- **THEN** CCC 的持仓复查日到期不再运行；作废 P-1；不启动

#### Scenario: 恢复后按优先级运行积压的案件

- **GIVEN** 排队的案件同「降级期间不启动」，EEE 的持仓复查已经结束
- **WHEN** 退出降级模式以后，取得队列的决定
- **THEN** 依次启动 CCC 的持仓复查、BBB 的关注复查、AAA 的候选评估
- **WHEN** 并发上限配置为 2，取得队列的决定
- **THEN** 依次启动 CCC 的持仓复查、BBB 的关注复查；AAA 的有新候选留在队列里

### Requirement: 新案件排队时作废开仓方案

队列的决定 SHALL 按下表作废方案。"这只股票有案件在排队"指这只股票有复盘以外的案件在排队，并且这次确定得了类型；因为股票忙、降级、预算或并发上限暂时启动不了的也算，这次启动的也算：

| 方案 | 阶段 | 这只股票有案件在排队 | 结果 |
| --- | --- | --- | --- |
| 开仓类 | 审核 | 有 | 不作废：属于运行中的案件，运行中不打断 |
| 开仓类 | 等人工确认 | 有 | 作废 |
| 开仓类 | 等下单 | 有 | 作废 |
| 开仓类 | 任何阶段 | 没有，或者只有复盘在排队 | 不作废 |
| 退出类 | 任何阶段 | 有 | 不作废；排队的案件等运行中的案件结束再运行 |

- 这是随时成立的条件：每次决定都检查，所以新案件排队时、方案进入等人工确认时都会作废
- 作废以后，调用方 SHALL 释放方案的预留（risk-reservations spec「方案或订单结束时释放预留」）；方案所属的案件怎么结束不在本 spec 的范围内。新案件的 PM 想买，就重新提方案、重新确认

#### Scenario: 还在审核的开仓方案不作废

- **GIVEN** 运行中：BBB 的关注股事件（调用模型），P-1 在审核；排队：BBB 的关注复查日到期（20:00Z）
- **WHEN** 取得队列的决定
- **THEN** 不作废；不启动

#### Scenario: 等人工确认时有新案件排队就作废

- **GIVEN** 运行中：BBB 的关注股事件（等人工确认），P-1 等人工确认
- **WHEN** BBB 的新闻事件（15:00Z）排队以后，取得队列的决定
- **THEN** 作废 P-1；不启动，BBB 的新闻事件等 BBB 的关注股事件结束

#### Scenario: 已经确认的开仓方案也作废

- **GIVEN** 运行中：BBB 的关注股事件（等下单），P-1 等下单
- **WHEN** BBB 的关注复查日到期（20:00Z）排队以后，取得队列的决定
- **THEN** 作废 P-1；不启动
- **WHEN** BBB 的关注股事件因方案被作废结束以后，取得队列的决定
- **THEN** 启动 BBB 的关注复查

#### Scenario: 方案进入等人工确认时已经有案件在排队

- **GIVEN** 运行中：BBB 的关注股事件（调用模型），P-1 在审核；排队：BBB 的新闻事件（15:00Z）
- **WHEN** P-1 通过风控、进入等人工确认，BBB 的关注股事件不再调用模型以后，取得队列的决定
- **THEN** 作废 P-1

#### Scenario: 加仓也是开仓类

- **GIVEN** 运行中：CCC 的持仓复查（等人工确认），P-2 等人工确认；排队：CCC 的新闻事件（15:00Z）
- **WHEN** 取得队列的决定
- **THEN** 作废 P-2

#### Scenario: 只有复盘在排队不作废

- **GIVEN** 运行中：CCC 的持仓复查（等人工确认），P-2 等人工确认；排队：CCC 的卖出成交（15:00Z）
- **WHEN** 取得队列的决定
- **THEN** 不作废；启动 CCC 的卖出复盘

#### Scenario: 退出类方案不作废

- **GIVEN** 运行中：CCC 的持仓事件（等人工确认），P-3 等人工确认；排队：CCC 的持仓复查日到期（20:00Z）
- **WHEN** 取得队列的决定
- **THEN** 不作废；不启动
- **WHEN** P-3 确认、进入等下单以后，取得队列的决定
- **THEN** 不作废；不启动
- **WHEN** P-3 的订单提交、CCC 的持仓事件结束以后，取得队列的决定
- **THEN** 启动 CCC 的持仓复查

#### Scenario: 暂时启动不了的排队案件也算

- **GIVEN** 普通预算用完；运行中：BBB 的关注股事件（等下单），P-1 等下单；排队：BBB 的关注复查日到期（20:00Z）
- **WHEN** 取得队列的决定
- **THEN** 作废 P-1；不启动

#### Scenario: 确定不了类型的排队案件不算

- **GIVEN** 运行中：BBB 的关注股事件（等人工确认），P-1 等人工确认；排队：BBB 的有新候选（20:00Z，BBB 还是候选时开出，之后升级为关注）
- **WHEN** 取得队列的决定
- **THEN** BBB 的有新候选不再运行；不作废

#### Scenario: 别的股票的案件不影响

- **GIVEN** 运行中：BBB 的关注股事件（等人工确认），P-1 等人工确认；排队：AAA 的新闻事件（15:00Z）
- **WHEN** 取得队列的决定
- **THEN** 不作废；启动 AAA 的候选股事件

### Requirement: 紧急退出

一只股票触发紧急风险退出（emergency-exit spec）时，调用方 SHALL 在撤单和生成清仓方案之前取得这只股票的紧急退出的决定，中止决定里的案件、作废决定里的方案并释放预留，然后把这只股票记为正在紧急退出，直到清仓卖单结束。紧急退出的决定 SHALL 按下表给出：

| 对象 | 结果 |
| --- | --- |
| 这只股票正在运行的、复盘以外的案件 | 中止，不论在哪个阶段 |
| 这只股票正在运行的复盘案件 | 不中止 |
| 这只股票还没提交订单的方案 | 全部作废：开仓类和退出类，不论阶段 |
| 这只股票排队的案件 | 不动：留在队列里，紧急退出结束后按新的状态运行（见「同一只股票一次一个案件」） |
| 别的股票的案件和方案 | 不动 |

- 不看降级模式、预算和并发上限
- 中止的案件怎么结束不在本 spec 的范围内
- 组合熔断清仓全部持仓时，对每只持仓各取一次

#### Scenario: 中止运行中的案件并作废它的方案

- **GIVEN** 运行中：CCC 的持仓事件（等人工确认），P-3 等人工确认
- **WHEN** CCC 触发紧急退出，取得 CCC 的紧急退出的决定
- **THEN** 中止 CCC 的持仓事件；作废 P-3

#### Scenario: 开仓类和退出类、各个阶段的方案都作废

- **GIVEN** 运行中：CCC 的持仓复查（调用模型），P-3 在审核
- **WHEN** 取得 CCC 的紧急退出的决定
- **THEN** 中止 CCC 的持仓复查；作废 P-3
- **GIVEN** 运行中：CCC 的持仓事件（等下单），P-2 等下单
- **WHEN** 取得 CCC 的紧急退出的决定
- **THEN** 中止 CCC 的持仓事件；作废 P-2

#### Scenario: 复盘案件不中止

- **GIVEN** 运行中：CCC 的卖出复盘，以及 CCC 的持仓事件（等下单），P-2 等下单
- **WHEN** 取得 CCC 的紧急退出的决定
- **THEN** 中止 CCC 的持仓事件，不中止 CCC 的卖出复盘；作废 P-2

#### Scenario: 排队的案件和别的股票不动

- **GIVEN** 排队：CCC 的新闻事件（15:00Z）；运行中：BBB 的关注股事件（等人工确认），P-1 等人工确认
- **WHEN** 取得 CCC 的紧急退出的决定
- **THEN** 不中止，不作废；CCC 的新闻事件留在队列里

#### Scenario: 降级模式和预算用完时照常

- **GIVEN** 处于降级模式，普通预算用完；运行中：CCC 的持仓事件（等人工确认），P-3 等人工确认
- **WHEN** 取得 CCC 的紧急退出的决定
- **THEN** 中止 CCC 的持仓事件；作废 P-3
