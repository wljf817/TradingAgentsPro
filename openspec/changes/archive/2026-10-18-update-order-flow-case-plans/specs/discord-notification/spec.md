# Spec Delta

## MODIFIED Requirements

### Requirement: 确认消息

请求确认 SHALL 往配置的频道发一条确认消息，带「确认」和「拒绝」两个按钮。案件的方案请求确认时，调用方还可以给出案件的意见（order-flow spec「请求人工确认」）：Critic 有分歧时的双方意见，或者 Critic 不可用。消息 SHALL 依次写明：

| 内容 | 说明 |
| --- | --- |
| @配置的用户和动作 | 第一行：@用户，然后「请确认：」加动作、股票和风控给出的最终股数（清仓也写股数） |
| 订单类型和价格 | 限价单写限价和金额（最终股数 × 限价，保留两位小数）；市价单写「市价」 |
| 止损价、紧急阈值 | 只有买入和加仓有；紧急阈值用风控给出的生效值，写成百分数 |
| 允许价格偏离 | 方案填了才写，百分数 |
| 板块、有效期 | 有效期用风控给出的生效有效期 |
| 已被风控调整 | 只在风控结果为调整时写：「已被风控调整」、方案原来的股数和调整后的股数，以及每条不通过的规则名称和说明 |
| 截止时刻 | 过了截止时刻按超时处理 |
| 方案 ID | |
| 案件的意见 | 只在调用方给出时写，见下 |

案件的意见 SHALL 这样写：

| 意见 | 写法 |
| --- | --- |
| Critic 有分歧 | 「Critic 有分歧，双方的意见：」；PM 的方案理由；然后按先后写 Critic 的每次审核（第几次、结论、理由、逐条质询）和 PM 的每轮回应（第几轮、决定、逐条回应；修改的写修改后的股数、限价、止损价和紧急阈值） |
| Critic 不可用 | 「Critic 不可用，方案没有经过审核」 |

整条消息超过 Discord 的 2000 字上限时，SHALL 只截短案件的意见，使整条消息正好 2000 字，最后一个字是「…」；案件的意见以前的各项 SHALL NOT 截短。

时刻（有效期、截止时刻）SHALL 用 Discord 的时间戳标记，每个人按自己设备的时区看到。只有配置的用户会被 @ 到。

#### Scenario: 买入方案通过风控

- **WHEN** 请求确认 P1
- **THEN** 第一行是 @本人 和「请确认：买入 AAPL 100 股」
- **AND** 消息写了限价 180.50、金额 18,050.00、止损价 171.00、紧急阈值 8%、科技板块、有效期 2026-10-08 20:00Z、截止时刻 2026-10-08 14:30Z 和方案 ID
- **AND** 没有「已被风控调整」，没有允许价格偏离，没有案件的意见
- **AND** 消息带「确认」「拒绝」两个按钮

#### Scenario: 加仓方案被风控调整

- **GIVEN** 方案 P2：加仓 MSFT，科技板块，200 股，限价 410.00，止损价 395.00，允许价格偏离 0.05
- **AND** 风控结果：调整为 120 股，紧急阈值 0.075，不通过的规则是「单笔计划风险：MSFT 的计划风险将是 3,040.00，超过上限 2,000.00」和「组合合计风险：组合合计风险将是 9,000.00，超过上限 8,000.00」
- **WHEN** 请求确认 P2
- **THEN** 第一行是「请确认：加仓 MSFT 120 股」
- **AND** 消息写了金额 49,200.00、紧急阈值 7.5%、允许价格偏离 5%
- **AND** 消息写了「已被风控调整」、200 股调整为 120 股，以及这两条规则的名称和说明

#### Scenario: 市价减仓

- **GIVEN** 方案 P3：减仓 AAPL 60 股，市价单；风控结果通过，60 股，有效期 2026-10-08 20:00Z
- **WHEN** 请求确认 P3
- **THEN** 第一行是「请确认：减仓 AAPL 60 股」，消息写「市价」
- **AND** 没有金额、止损价和紧急阈值

#### Scenario: 限价清仓

- **GIVEN** 方案 P4：清仓 AAPL，限价 185.00；风控结果通过，股数 100（全部可卖）
- **WHEN** 请求确认 P4
- **THEN** 第一行是「请确认：清仓 AAPL 100 股」，消息写限价 185.00、金额 18,500.00

#### Scenario: 开仓方案的双方意见

- **GIVEN** P1 的案件的意见是 Critic 有分歧：PM 的方案理由"新品周期带动收入加速"；Critic 第 1 次审核质询，理由"止损太近"，质询"止损价离限价只有 5%"；PM 第 1 轮回应修改，回应"止损放宽"，修改后 100 股、限价 180.50、止损价 165.00、紧急阈值 0.08；Critic 第 2 次审核质询，理由"仍有分歧"，质询"仓位偏大"
- **WHEN** 请求确认 P1
- **THEN** 方案 ID 之后依次写了：「Critic 有分歧，双方的意见：」、PM 的方案理由、Critic 第 1 次审核（质询、理由和那条质询）、PM 第 1 轮回应（修改、回应、修改后的股数、限价、止损价 165.00 和紧急阈值 8%）、Critic 第 2 次审核（质询、理由和那条质询）

#### Scenario: 退出方案有异议

- **GIVEN** 方案 P3（减仓 AAPL 60 股）的案件的意见是 Critic 有分歧：PM 的方案理由"跌破 50 日均线"；Critic 第 1 次审核质询，理由"跌幅还没有触及证伪条件"，质询"只看了一天的走势"；没有回应
- **WHEN** 请求确认 P3
- **THEN** 方案 ID 之后写了「Critic 有分歧，双方的意见：」、PM 的方案理由和 Critic 第 1 次审核，没有回应

#### Scenario: Critic 不可用

- **GIVEN** 方案 P3 的案件的意见是 Critic 不可用
- **WHEN** 请求确认 P3
- **THEN** 消息的最后一行是「Critic 不可用，方案没有经过审核」

#### Scenario: 意见太长时截短

- **GIVEN** P1 的案件的意见是 Critic 有分歧，PM 的方案理由有 3000 字
- **WHEN** 请求确认 P1
- **THEN** 消息正好 2000 字，最后一个字是「…」
- **AND** 截止时刻、方案 ID 和「Critic 有分歧，双方的意见：」都完整
