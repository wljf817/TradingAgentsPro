## MODIFIED Requirements

### Requirement: 模型的配置

Agent 网关 SHALL 从配置得到六个 agent（PM、News、Quant、Fundamentals、Critic、Reviewer）各自的模型：一个主模型，加上按顺序的 0 个或多个备用模型。每个模型写：

| 项 | 要求 |
| --- | --- |
| 厂商 | 模型出自哪家公司，不是调用的平台；非空的文字，去掉首尾空白并转成小写 |
| 模型名 | 非空的文字，去掉首尾空白，大小写不变 |

- 厂商和模型名都相同就是同一个模型；不同 agent 可以用同一个模型
- 缺少任何一个 agent、某项不符合上表、同一个 agent 的主模型和备用模型里出现同一个模型，都 MUST 配置报错
- 配置在启动时读取，运行中不变

本 spec 的场景除非另有说明，都使用默认配置和下面的基准数据：

- 当前时刻 2026-10-14 15:00Z
- 子 agent 的单次调用超时配置为 60 秒，PM、Critic、Reviewer 的单次调用超时配置为 180 秒，任务时限配置为 5 分钟
- 基准模型的配置，模型写作"厂商/模型名"，下文只写模型名，比如 p-1 就是 anthropic/p-1：

  | agent | 主模型 | 备用模型（按顺序） |
  | --- | --- | --- |
  | PM | anthropic/p-1 | anthropic/p-2、google/p-3 |
  | Critic | openai/c-1 | openai/c-2 |
  | News、Quant、Fundamentals | google/s-1 | openai/s-2 |
  | Reviewer | anthropic/p-1 | 没有 |

- 案件 K-1、K-2。"PM 在 K-1 调用"指为 K-1 的 PM 开始一次调用，Critic、Reviewer 同理，都没有截止时间；"News 在 K-1 为 T-1 调用"指为 News 的任务 T-1 开始一次调用，T-1 的截止时间是 2026-10-14 15:05Z
- "p-1 失败（限流）"指正在进行的这次尝试失败，调用错误是限流；"p-1 成功"指这次尝试拿到了输出
- "p-1 不可用（限流）"指 p-1 在这次调用里的两次尝试都失败，第二次的调用错误是限流；括号省略时是超时。"p-1 在 t 不可用"指在某次调用里，p-1 在时刻 t 不可用
- 开始时所有模型都正常，没有不可用过；"p-1 冷却到 t"指 p-1 在冷却中，冷却结束的时刻是 t
- 时刻没有写明时，都是当前时刻
- GIVEN 里的几步依次进行；一个 WHEN 里用"；"或"或者"隔开的几种情况，各自从 GIVEN 的数据开始；同一个场景里的几组 WHEN、THEN，除非写"接着"，也各自从 GIVEN 的数据开始

#### Scenario: 基准配置

- **WHEN** 用基准模型的配置
- **THEN** 配置正确；PM 的模型依次是 p-1、p-2、p-3；Reviewer 只有主模型 p-1；Reviewer 和 PM 的主模型是同一个模型

#### Scenario: 厂商去掉空白、转成小写

- **WHEN** PM 的主模型的厂商写成 " Anthropic "
- **THEN** 配置正确，厂商是 anthropic，PM 和 Reviewer 的主模型仍是同一个模型

#### Scenario: 配置不合法

- **WHEN** 不配 Reviewer；News 的主模型的厂商是 "  "；Critic 的备用模型的模型名是 ""；PM 的备用模型依次是 p-2、p-1；PM 的备用模型依次是 p-2、p-2；PM 的备用模型是 Anthropic/p-1
- **THEN** 都配置报错

### Requirement: 尝试的超时

每次尝试 SHALL 有超时：

| agent | 每次尝试的超时 |
| --- | --- |
| News、Quant、Fundamentals | "子 agent 的单次调用超时"（默认 150 秒）和离任务截止时间还剩的时间，两者中较短的 |
| PM、Critic、Reviewer | "PM、Critic、Reviewer 的单次调用超时"（默认 300 秒） |

- 超时管整次尝试：一次尝试可以发多个请求（model-adapter spec「一次尝试」），全部算在这个超时里
- 重试和换备用模型 SHALL 从头开始，上一次尝试查到的内容不保留
- 子 agent 的调用带任务的截止时间（task-dispatch spec「超时」）。现在不早于截止时间时 SHALL NOT 再开始尝试，这次调用停止：停止不是全部不可用，不给出调用失败，也不告警，这个任务由 task-dispatch spec「超时」记超时
- 停止时那次失败已经让模型不可用的，照样计入熔断
- PM、Critic、Reviewer 的调用没有截止时间
- 配置保证子 agent 的主模型和第一个备用模型的全部尝试放得进任务时限（见「备用模型的配置」）

#### Scenario: 两类 agent 的超时

- **WHEN** News 在 K-1 为 T-1 调用
- **THEN** 先试 s-1，超时 60 秒
- **WHEN** PM 在 K-1 调用；或者 Critic 在 K-1 调用；或者 Reviewer 在 K-1 调用
- **THEN** 第一次尝试的超时都是 180 秒

#### Scenario: 主模型和第一个备用模型放得进任务时限

- **GIVEN** News 在 K-1 为 T-1 调用
- **WHEN** s-1 在 15:01:00Z 失败，在 15:02:00Z 又失败
- **THEN** s-1 不可用，换到 s-2，超时 60 秒
- **WHEN** 接着 s-2 在 15:03:00Z 失败，在 15:04:00Z 又失败
- **THEN** 全部不可用，说明是"模型都不可用：google/s-1 超时；openai/s-2 超时"

#### Scenario: 超时不超过离截止时间还剩的时间

- **WHEN** 2026-10-14 15:04:30Z 才开始 News 为 T-1 的调用
- **THEN** 先试 s-1，超时 30 秒
- **WHEN** 2026-10-14 15:04:00Z 开始
- **THEN** 先试 s-1，超时 60 秒

#### Scenario: 到了截止时间就停止

- **GIVEN** 2026-10-14 15:04:00Z 开始 News 为 T-1 的调用，s-1 在 15:04:10Z 失败（连接失败），重试 s-1
- **WHEN** 15:05:00Z s-1 又失败
- **THEN** 这次调用停止：不换 s-2，不是全部不可用；s-1 记下一次不可用
- **WHEN** 15:04:59Z s-1 又失败
- **THEN** s-1 不可用，换到 s-2，超时 1 秒
- **WHEN** 2026-10-14 15:05:00Z 才开始 News 为 T-1 的调用
- **THEN** 停止，不尝试任何模型

#### Scenario: 工具循环中途失败从头开始

- **GIVEN** News 在 K-1 为 T-1 调用，s-1 发了三个请求，第三个失败（连接失败）
- **WHEN** 重试 s-1
- **THEN** 这次尝试从第一个请求开始，不带上一次查到的内容

#### Scenario: PM、Critic、Reviewer 没有截止时间

- **GIVEN** PM 在 K-1 调用
- **WHEN** 2026-10-14 16:00Z p-1 失败
- **THEN** 重试 p-1，超时 180 秒

### Requirement: 备用模型的配置

备用模型的阈值 SHALL 是可配置项：

| 配置项 | 说明 | 默认值 | 要求 |
| --- | --- | --- | --- |
| 重试次数 | 一个模型在一次调用里失败以后，最多再试这么多次 | 1 | 不小于 0 的整数 |
| 子 agent 的单次调用超时 | News、Quant、Fundamentals 每次尝试最多等这么久 | 150 秒 | 大于 0 |
| PM、Critic、Reviewer 的单次调用超时 | 这三个 agent 每次尝试最多等这么久 | 300 秒 | 大于 0 |
| 熔断的连续不可用次数 | 连续这么多次不可用就冷却 | 3 | 正整数 |
| 熔断的时间窗口 | 这几次里最早一次到最后一次不超过这么久才冷却 | 10 分钟 | 大于 0 |
| 冷却时间 | 冷却这么久 | 5 分钟 | 大于 0 |
| PM 用备用模型时不能提的决定 | case-types spec 的决定 | 开仓方案、加仓、升级 | 可以为空 |

- 另外 MUST 满足：（重试次数 + 1）× 子 agent 的单次调用超时 × 2 不超过任务时限（task-dispatch spec「派发的配置」，默认 10 分钟），保证子 agent 的主模型和第一个备用模型的全部尝试都放得进截止时间
- 不满足要求时 MUST 配置报错
- 各 agent 的模型见「模型的配置」，没有默认值

#### Scenario: 默认配置

- **WHEN** 不传任何配置项新建配置
- **THEN** 重试次数 1，子 agent 的单次调用超时 150 秒，PM、Critic、Reviewer 的单次调用超时 300 秒，熔断的连续不可用次数 3，熔断的时间窗口 10 分钟，冷却时间 5 分钟，PM 用备用模型时不能提的决定是开仓方案、加仓、升级

#### Scenario: 配置不合法

- **WHEN** 重试次数配置为 -1；子 agent 的单次调用超时配置为 0 秒；PM、Critic、Reviewer 的单次调用超时配置为 0 秒；熔断的连续不可用次数配置为 0；熔断的时间窗口配置为 0 秒；冷却时间配置为 0 秒
- **THEN** 都配置报错

#### Scenario: 放得进任务时限的边界

- **WHEN** 子 agent 的单次调用超时配置为 75 秒（2 × 75 秒 × 2 = 5 分钟）；或者重试次数配置为 0、子 agent 的单次调用超时配置为 150 秒；或者重试次数配置为 2、任务时限配置为 6 分钟
- **THEN** 都配置正确
- **WHEN** 子 agent 的单次调用超时配置为 76 秒；或者重试次数配置为 2（3 × 60 秒 × 2 = 6 分钟）
- **THEN** 都配置报错

#### Scenario: 改成别的值

- **GIVEN** 熔断的连续不可用次数配置为 1
- **WHEN** p-1 在 15:00Z 不可用
- **THEN** p-1 冷却到 15:05Z
- **GIVEN** 熔断的时间窗口配置为 5 分钟
- **WHEN** p-1 在 14:52Z、14:56Z、15:00Z 不可用
- **THEN** p-1 正常
- **GIVEN** 冷却时间配置为 1 分钟
- **WHEN** p-1 在 14:52Z、14:56Z、15:00Z 不可用
- **THEN** p-1 冷却到 15:01Z
- **GIVEN** PM、Critic、Reviewer 的单次调用超时配置为 240 秒
- **WHEN** PM 在 K-1 调用
- **THEN** 第一次尝试的超时是 240 秒
