# Spec Delta

## Purpose

规定子 agent 的信号和 PM 结论里信号的统一格式（评估窗口、评分刻度、置信度、数据截至时刻、引用、理由和主要风险，以及无信号），并由 Agent 网关在收到模型输出时校验它是否合法、不合法时给出原因。

## ADDED Requirements

### Requirement: 信号的格式

子 agent 给出的信号和 PM 结论里的信号 SHALL 是同一种格式，包含下面几项：

| 项 | 说明 |
| --- | --- |
| 评估窗口 | 交易日数，正整数，从配置的选项里选（见「收到输出时的校验」）；只用于评估准确性，不代表持仓周期 |
| 评分 | -2 到 +2 的整数，每档的含义见「评分的刻度」 |
| 置信度 | 0 到 1，含两端：这个判断成立的把握 |
| 数据截至时刻 | 带时区的时刻：所依据的数据最新到什么时候 |
| 引用的条目 | 所依据的状态库条目 ID 的列表，至少一条；每个 ID 是非空的文字 |
| 理由 | 文字 |
| 主要风险 | 文字：可能让这个判断落空的主要风险 |

- 缺少任何一项、文字去掉首尾空白后为空、某项不符合上表、包含上表以外的项，都 MUST 是格式错误，并指出是哪一项
- 一个信号只针对一只股票，信号里不写股票：子 agent 的信号针对 Task 指定的股票；PM 的信号针对案件的股票，寻股的是加入的那只候选
- 信号构造以后 MUST NOT 被修改：评估窗口写入以后不能再改，只按这个窗口评估

本 spec 的场景除非另有说明，都使用默认配置和下面的基准数据：

- 当前时刻 2026-10-14 15:00Z（周三，盘中）
- 基准信号：评估窗口 5 个交易日；评分 1；置信度 0.6；数据截至 2026-10-14 14:30Z；引用条目 E-1 和 E-2；理由"订单回暖，放量突破前高"；主要风险"板块整体回调时跟跌"
- 基准无信号：原因"最近一期财报还没有进状态库，无法判断"，不引用条目
- "评分 n 的信号""评估窗口 n 的信号""数据截至 t 的信号"指只把基准信号的这一项改为 n 或 t

#### Scenario: 完整的信号

- **WHEN** 用基准信号的各项构造信号
- **THEN** 格式正确
- **WHEN** 只引用 E-1
- **THEN** 格式正确

#### Scenario: 缺少一项

- **WHEN** 分别缺少评估窗口、评分、置信度、数据截至时刻、引用的条目、理由、主要风险
- **THEN** 都是格式错误，并指出缺少的是哪一项

#### Scenario: 评估窗口不是正整数

- **WHEN** 评估窗口是 0、-5 或 2.5
- **THEN** 都是格式错误

#### Scenario: 置信度的边界

- **WHEN** 置信度是 0 或 1
- **THEN** 格式正确
- **WHEN** 置信度是 -0.1 或 1.1
- **THEN** 都是格式错误

#### Scenario: 引用的条目

- **WHEN** 不引用任何条目；或者引用 E-1 和 "  "
- **THEN** 都是格式错误

#### Scenario: 只有空白的文字

- **WHEN** 理由是 "  "，或者主要风险是 ""
- **THEN** 都是格式错误

#### Scenario: 数据截至时刻不带时区

- **WHEN** 数据截至时刻是不带时区的 2026-10-14 14:30
- **THEN** 格式错误

#### Scenario: 多出来的项

- **WHEN** 基准信号另外写了股票 "AAA"
- **THEN** 格式错误

#### Scenario: 构造以后不能修改

- **GIVEN** 基准信号
- **WHEN** 把评估窗口改为 20，或者把评分改为 2
- **THEN** 都报错，信号不变

### Requirement: 评分的刻度

评分 SHALL 是下表五档之一。评分比较的是评估窗口内这只股票相对它的板块 ETF 的超额收益，不是绝对涨跌。名字和含义供 M5 写进系统宪章的评分刻度；代码只检查评分是 -2 到 +2 的整数。

| 评分 | 名字 | 含义 |
| --- | --- | --- |
| +2 | 强烈看多 | 预计评估窗口内明显跑赢板块 |
| +1 | 看多 | 预计评估窗口内跑赢板块，但幅度有限 |
| 0 | 中性 | 预计评估窗口内和板块大致同步 |
| -1 | 看空 | 预计评估窗口内跑输板块，但幅度有限 |
| -2 | 强烈看空 | 预计评估窗口内明显跑输板块 |

- 置信度是这个判断成立的把握，和评分分开：把握不大时降低置信度，不把评分往 0 靠
- 中性也是一个判断；根据提供的数据给不出判断时答无信号（见「无信号」），不给 0

#### Scenario: 五档评分

- **WHEN** 评分分别是 -2、-1、0、1、2
- **THEN** 都格式正确

#### Scenario: 评分超出范围或不是整数

- **WHEN** 评分是 -3、3 或 1.5
- **THEN** 都是格式错误

### Requirement: 无信号

子 agent 的输出 SHALL 是一个信号或一个无信号，不能是别的。无信号表示根据提供的数据给不出判断，只包含：

| 项 | 说明 |
| --- | --- |
| 原因 | 文字：为什么给不出判断，比如数据不足 |
| 引用的条目 | 看过的状态库条目 ID 的列表，可以为空；每个 ID 是非空的文字 |

- 无信号 MUST NOT 写信号的其他项（评估窗口、评分、置信度、数据截至时刻、理由、主要风险）
- 缺少原因、原因去掉首尾空白后为空、包含上表以外的项，都是格式错误；既不是格式正确的信号、也不是格式正确的无信号的输出 MUST 是格式错误
- PM 结论里的信号不能是无信号（case-types spec「结论的公共部分」「寻股的结论」）

#### Scenario: 子 agent 的两种输出

- **WHEN** 子 agent 输出基准信号的各项
- **THEN** 得到一个信号
- **WHEN** 子 agent 输出基准无信号；或者输出原因相同、引用 E-1 的无信号
- **THEN** 都得到一个无信号

#### Scenario: 无信号缺少原因

- **WHEN** 无信号的原因是 "  "；或者只写了引用的条目 E-1
- **THEN** 都是格式错误

#### Scenario: 无信号不写信号的项

- **WHEN** 基准无信号另外写了评分 0；或者另外写了评估窗口 5
- **THEN** 都是格式错误

#### Scenario: 既不是信号也不是无信号

- **WHEN** 子 agent 的输出没有任何项；或者是缺少主要风险的基准信号
- **THEN** 都是格式错误

### Requirement: 收到输出时的校验

Agent 网关收到子 agent 的输出时，SHALL 先按「信号的格式」「无信号」检查格式；格式正确的信号再按下表的顺序检查，给出第一项不通过的原因。无信号没有这两项，格式正确就合法。

| 顺序 | 检查 | 不通过时的原因 |
| --- | --- | --- |
| 1 | 评估窗口是配置的选项之一（见「信号的配置」） | 评估窗口不在配置的选项里 |
| 2 | 数据截至时刻不晚于现在（收到输出的时刻） | 数据截至时刻晚于现在 |

- 格式错误和上表不通过都是格式不合法：合法时得到信号或无信号，不合法时给出格式不合法和原因（格式错误指出是哪一项，上表不通过给出上表的原因）
- 格式不合法 SHALL NOT 算模型不可用，不切换备用模型；记成 Result 的哪种状态由「任务派发」规定（已决定：记为失败，并注明格式不合法）
- 上表只在收到输出时检查：之后改了配置，已经写入的信号不受影响，照旧按自己的评估窗口评估

#### Scenario: 选项里的评估窗口

- **WHEN** 收到评估窗口 3、5、20、60 的信号
- **THEN** 都合法

#### Scenario: 选项以外的评估窗口

- **WHEN** 收到评估窗口 1、4 或 61 的信号
- **THEN** 都不合法，原因是"评估窗口不在配置的选项里"

#### Scenario: 数据截至时刻的边界

- **WHEN** 收到数据截至 2026-10-14 15:00Z 的信号；数据截至 2026-10-14 23:00+08:00（就是 15:00Z）的信号；数据截至 2026-10-01 20:00Z 的信号
- **THEN** 都合法
- **WHEN** 收到数据截至 2026-10-14 15:00:01Z 的信号；或者数据截至 2026-10-14 11:00-05:00（就是 16:00Z）的信号
- **THEN** 都不合法，原因是"数据截至时刻晚于现在"

#### Scenario: 两项都不通过

- **WHEN** 收到评估窗口 4、数据截至 2026-10-14 16:00Z 的信号
- **THEN** 不合法，原因是"评估窗口不在配置的选项里"

#### Scenario: 无信号格式正确就合法

- **WHEN** 收到基准无信号
- **THEN** 合法

#### Scenario: 改配置不影响已经写入的信号

- **GIVEN** 2026-10-14 15:00Z 收到并写入了评估窗口 3 的信号
- **WHEN** 评估窗口的选项改为 5 和 20 以后，用写入的各项重新构造这个信号
- **THEN** 格式正确，和写入的信号相同，评估窗口仍是 3

### Requirement: 结论里的信号

PM 的结论 SHALL 带信号：持仓、关注、候选的结论各一个，寻股的结论每只加入的候选一个（case-types spec「结论的公共部分」「寻股的结论」）；格式和子 agent 的信号相同，不能是无信号。Agent 网关收到 PM 的结论时，SHALL 按「收到输出时的校验」的表检查结论里的每个信号（寻股按加入的顺序），给出第一个不通过的信号的原因；都通过、或者寻股没有加入候选时，结论里的信号合法。

- 信号不合法时整份结论格式不合法，不能只丢掉信号、照常采用结论；怎样退回 PM 由 M5 和结论其他部分的格式错误一起定
- 结论通过以后，调用方把信号里的评分记为这只股票的最新评分（stock-pool spec「股票池的记录」）；PM 的信号和子 agent 的信号一样参与评估

结论用 case-types spec 的基准数据，结论的公共部分里的信号是基准信号。

#### Scenario: 每种结论的信号都检查

- **WHEN** 收到持仓的结论（持有）、关注的结论（继续关注）、候选的结论（保持），信号都是基准信号
- **THEN** 结论里的信号都合法
- **WHEN** 同上三个结论，信号都是评估窗口 10 的信号
- **THEN** 都不合法，原因是"评估窗口不在配置的选项里"

#### Scenario: PM 的数据截至时刻晚于现在

- **WHEN** 收到候选的结论（保持），信号是数据截至 2026-10-14 15:00:01Z 的信号
- **THEN** 不合法，原因是"数据截至时刻晚于现在"

#### Scenario: 寻股的每只候选都检查

- **WHEN** 收到寻股的结论：加入 DDD（基准信号）和 EEE（评估窗口 10 的信号）
- **THEN** 不合法，原因是"评估窗口不在配置的选项里"
- **WHEN** 收到寻股的结论：加入 DDD（数据截至 2026-10-14 16:00Z 的信号）和 EEE（评估窗口 10 的信号）
- **THEN** 不合法，原因是"数据截至时刻晚于现在"，因为 DDD 在前
- **WHEN** 收到寻股的结论：加入 DDD 和 EEE，信号都是基准信号；或者不加入任何候选
- **THEN** 结论里的信号都合法

### Requirement: 信号的配置

评估窗口的选项 SHALL 是可配置项：

| 配置项 | 说明 | 默认值 | 要求 |
| --- | --- | --- | --- |
| 评估窗口的选项 | 子 agent 和 PM 出信号时可以选的评估窗口，交易日数 | 3、5、20、60 | 至少一个，每个都是正整数 |

不满足要求时 MUST 配置报错。

#### Scenario: 默认配置

- **WHEN** 不传任何配置项新建配置
- **THEN** 评估窗口的选项是 3、5、20、60

#### Scenario: 配置不合法

- **WHEN** 评估窗口的选项配置为空；或者配置为 0 和 5
- **THEN** 都配置报错

#### Scenario: 改成别的选项

- **GIVEN** 评估窗口的选项配置为 5 和 20
- **WHEN** 收到评估窗口 3 的信号
- **THEN** 不合法，原因是"评估窗口不在配置的选项里"
- **WHEN** 收到评估窗口 20 的信号
- **THEN** 合法
