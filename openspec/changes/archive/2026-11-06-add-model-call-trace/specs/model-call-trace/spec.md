## Purpose

规定每次向真实模型的尝试留下什么记录：写哪些内容、什么时候写、存在哪里、写入出错时怎么办，让模型的输入、输出和工具往来事后都查得到。

## ADDED Requirements

### Requirement: 调用记录

Agent 网关每次向真实模型尝试（agent-calls spec「一次调用」的一次尝试）SHALL 写一条调用记录，包含：

| 项 | 内容 |
| --- | --- |
| 案件 ID | 这次调用所属的案件 |
| task_id | 子 agent 的任务才有；PM、Critic、Reviewer 没有 |
| agent | 被调用的 agent |
| 模型 | 这次尝试用的模型 |
| 回答里写的模型名 | model-adapter spec「输出」；没有拿到时没有 |
| 快照版本 | 这次调用读的快照的版本 |
| 开始时刻、结束时刻 | 这次尝试开始和结束时从时钟读取的时刻 |
| 用量 | 这次尝试各请求之和；拿不到时没有 |
| 调用错误 | 没有拿到输出时的调用错误（model-fallback spec「什么算不可用」）；拿到输出时没有，输出不合法也算拿到输出 |
| 消息 | 这次尝试的全部消息（model-adapter spec「这次尝试的消息」） |

- 一次调用里重试和换模型的每次尝试 SHALL 各写一条
- 没有发生的尝试 SHALL NOT 写：模型在冷却中被跳过，到了截止时间停止尝试
- 替身不调用模型，SHALL NOT 写调用记录；替身的费用照常记（stand-ins spec「替身」）
- 先记费用，再写调用记录

本 spec 的场景使用 agent-calls spec 和 task-dispatch spec 的基准数据，模型都是真实模型；消息 m-1、m-2 指适配器给出的这次尝试的全部消息；"重启"指用同一个数据库新建存储和 Agent 网关。

#### Scenario: PM 拿到输出

- **WHEN** 2026-10-14 15:00:00Z 调用 K-1 的 PM，p-1 在 15:00:20Z 给出输出，用量 20,000/2,000，回答里写的模型名 p-1-20261001，消息 m-1，读第 1 版快照
- **THEN** 写一条调用记录：案件 K-1，没有 task_id，PM，模型 p-1，回答里写的模型名 p-1-20261001，快照版本 1，开始 15:00:00Z，结束 15:00:20Z，用量 20,000/2,000，没有调用错误，消息 m-1

#### Scenario: 子 agent 的任务

- **GIVEN** PM 派发价格请求（T-1）
- **WHEN** 运行 T-1，s-1 给出基准信号，消息 m-1
- **THEN** 写一条调用记录：案件 K-1，task_id T-1，Quant，模型 s-1，消息 m-1

#### Scenario: 重试和换模型每次尝试各一条

- **WHEN** 调用 K-1 的 PM，p-1 失败（限流，消息 m-1），再失败（服务端出错，用量 10,000/0，消息 m-2），再 p-2 给出输出
- **THEN** 依次写三条调用记录：p-1，调用错误限流，没有用量，消息 m-1；p-1，调用错误服务端出错，用量 10,000/0，消息 m-2；p-2，没有调用错误

#### Scenario: 全部不可用也有记录

- **WHEN** 调用 K-5 的 Reviewer，p-1 失败（超时），再失败（超时）
- **THEN** 调用失败，写两条调用记录，调用错误都是超时，都没有回答里写的模型名和用量

#### Scenario: 输出不合法

- **WHEN** 调用 K-1 的 PM，p-1 给出不合法的输出，用量 20,000/2,000，消息 m-1
- **THEN** 写一条调用记录，没有调用错误，用量 20,000/2,000，消息 m-1

#### Scenario: 冷却中的模型没有记录

- **GIVEN** p-1 在冷却中
- **WHEN** 调用 K-1 的 PM，p-2 给出输出
- **THEN** 只写一条调用记录，模型是 p-2

#### Scenario: 到了截止时间没有开始尝试

- **GIVEN** PM 派发价格请求（T-1），s-1 失败（超时）以后已经到了截止时间
- **WHEN** 停止尝试，记超时
- **THEN** 只有 s-1 那次尝试的调用记录

#### Scenario: 替身没有记录

- **GIVEN** PM 用替身，Quant 用真实模型 s-1
- **WHEN** 调用 K-1 的 PM；再运行派给 Quant 的 T-1，s-1 给出基准信号
- **THEN** 只写 T-1 的一条调用记录，模型是 s-1
- **AND** PM 的调用照常记一条费用，费用是 0

### Requirement: 调用记录的存储

调用记录 SHALL 存在状态库所在的数据库里（调用记录表 gateway_model_calls，state-store spec「表的归属和迁移」），只由 Agent 网关写入：

- 只追加：写入以后不修改、不删除
- 按案件读回这个案件的全部记录，按写入的先后；读回的内容和写入的完全相同，时刻读回的是同一时刻，和数据库服务器、本机的时区都无关
- 消息里的任何文字都 SHALL 能写入并原样读回，包括控制字符
- 几个调用（不同的案件，或者一个案件里并行的子 agent）同时写入时，每一条 SHALL 都写入

#### Scenario: 原样读回

- **GIVEN** 进程的本机时区是 UTC+14
- **WHEN** 写入一条 K-1 的调用记录；重启，读回 K-1 的记录
- **THEN** 读到一条，每一项都和写入的相同，开始时刻和结束时刻是同样的时刻

#### Scenario: 只读这个案件的

- **GIVEN** K-1 有两条调用记录，K-3 有一条
- **WHEN** 读回 K-1 的记录
- **THEN** 读到两条，按写入的先后

#### Scenario: 消息里有控制字符

- **GIVEN** 工具返回的文字里有 NUL 字符
- **WHEN** 写入这次尝试的调用记录，再读回
- **THEN** 写入成功，读回的消息和写入的相同

#### Scenario: 同时写入都写进去

- **WHEN** 10 个调用同时各写一条 K-1 的调用记录
- **THEN** 10 条都写入

### Requirement: 写入失败

写入调用记录时数据库出错（连不上、表不存在、语句报错），Agent 网关 SHALL 报错，MUST NOT 当作已经写入，也 MUST NOT 跳过，和费用记录写入出错相同（call-budget spec「费用的存储」）。已经记下的费用不撤回。

#### Scenario: 数据库连不上

- **GIVEN** 调用记录写入时数据库连不上，费用已经记下
- **WHEN** 调用 K-1 的 PM，p-1 给出输出
- **THEN** 这次调用报错，不给出输出；费用记录还在
