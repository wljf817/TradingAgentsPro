# Proposal

## Why

Proposal 要求每个案件开始时生成共享状态库快照，本案件的 agent 都读这份快照，保证可复现；信号要引用状态库条目 ID，Task 的输入是条目引用。现在这些都还没有：没有快照，也没有谁给事实分配条目 ID（`contracts/signal.py` 的 `EntryId` 只是"非空的文字，格式 M4 再定"）。后面的「替身」「案件工作流」「案件记录」和 M6 的回放都建在快照上，所以它排在案件组的第一个。

本变更的目的只有一个：**案件开始时由代码把本案件 agent 要读的事实整份复制成一份快照存下，给每条事实一个条目 ID，并能按条目 ID 查回内容；补充研究需要新数据时生成新的版本并记下原因。**

引用的 Proposal（完整版）章节：

- 「共享状态库」：事实仓库是所有 agent 读取事实的唯一来源；写入带时间戳和版本号，案件里产生的条目带案件 ID，只追加不覆盖；每个案件开始时生成快照，本案件的 agent 都读这份快照；每条结果引用它依据的上游条目 ID
- 「共享上下文」：Shared State 一层是当前持仓、现金、当日 P&L、市场状态（日期、交易时段、指数、波动率、重要日程）、股票池、已发生的事件、已确认的结论；同一案件的所有 agent 读同一版本的快照，补充研究需要新数据时生成新的快照版本并记录原因；案件上下文由调度器给出
- 「调度器与运行模块」运行约束：每个案件开始时生成共享状态库快照；排队规则：每个案件开始时用最新数据生成快照
- 「记录、复盘与经验 · 状态库」：保持现有设计；「复盘」的回放回测用存下的快照重跑历史案件
- 「Task / Result 通信」：Task 的输入是共享状态库条目引用，Result 带引用的条目 ID
- 「Agent」信号统一格式：至少引用一条所依据的状态库条目 ID

已经定了的：

- 快照把事实复制进一份存下的记录，不引用其他表的旧版本（M2 定的：没有全局序号）；行情和账户本来也没有历史
- 只放现在已经有来源的事实：持仓、现金、当日 P&L（执行模块）；交易日和交易时段（交易日历）、指数行情（行情模块）；股票池；案件股票的行情、新闻、公告、财报日历、EPS surprise 和板块 ETF 的行情；寻股的粗筛结果。还没有来源的由建出来源的变更加进来（见 Non-goals）
- 案件上下文（案件类型、触发、论点、近期结论、待执行的跟进）属于调度器和案件工作流，不进快照
- 快照的表只属于状态库模块（`statestore_snapshots`）；读很多模块的组装放在 workflows；迁移 v0011
- 还没有运行中的调用方（「案件工作流」才有），本变更只提供生成和读取的接口，不接 bootstrap

## What Changes

- 新增 `contracts/snapshot.py`：一份快照和它的各种条目（账户、市场状态、股票池、行情、新闻、公告、财报发布、surprise、粗筛结果），条目 ID 的写法和解析，按条目 ID 在快照里找条目。网关、替身、案件记录和 M6 的回放都读这个格式
- 条目 ID 写成 `s<版本>/<类别>` 或 `s<版本>/<类别>/<键>`，比如 `s1/account`、`s1/quote/BBB`、`s2/news/104`：带上快照的版本，所以在整个案件里不重复，凭案件 ID 和条目 ID 就能查回内容
- 快照按案件类型放不同的事实：
  - 每份都有共享事实：账户（权益、前一交易日收盘权益、当日盈亏、已结算现金、持仓）、市场状态（交易日、是否盘中、交易日的开盘和收盘时刻）、股票池（每只股票的状态和板块）、指数和持仓股票的行情
  - 针对单只股票的 11 种案件另有案件股票的事实：它和它的板块 ETF 的行情、最近 N 个交易日的新闻和公告、财报日历、surprise
  - 寻股另有当场粗筛出的名单；复盘案件只有共享事实
- 状态库模块 `modules/statestore` 加快照的存储和用例：表 `statestore_snapshots`（按案件 ID 和版本，只追加），保存快照时写一条程序日志；按案件和版本读、读最新的一版、按条目 ID 查条目
- 新增 workflow `workflows/snapshot_flow.py`：读执行模块、行情、股票池、新闻和公告、公司数据、寻股粗筛，组出快照并保存；同一个案件同一版已经存在时直接返回它（崩溃重跑不重复生成）；配置指数、新闻和公告的回看交易日数
- 程序日志：调度器加一个动作「生成快照」
- 迁移 v0011 建快照表
- `contracts/signal.py` 的 `EntryId` 注释改为指向快照条目的写法，类型不变
- 完整版 Proposal 改一处（apply 时做）：「共享状态库」读写规则的第三条改为"每个案件开始时生成快照，本案件的 agent 都读这份快照，保证可复现。快照把 Shared State 一层的事实整份复制下来存好，单只股票的案件另带这只股票的事实，寻股另带代码粗筛的结果；每条事实是快照里的一个条目，条目 ID 带快照的版本，在案件内不重复"

## Non-goals

- 装配：bootstrap 不建快照的 workflow、用例和存储；DBOS 不接。由「案件工作流」接上
- 什么时候生成、哪个 agent 读哪一版、Critic 的补充研究什么时候要新版本：「案件工作流」
- 案件上下文（案件类型的问题、触发原因和事件内容、论点和近期结论、经验和历史案件的索引、待执行的跟进）：「案件工作流」
- 已发生的事件：「事件检测」；已确认的结论：「案件记录」「案件工作流」；VIX 和重要日程：M5。都由建出来源的变更加进快照
- 日线和代码算好的指标：M5 接 Quant 时加（理由见 design D3）；寻股名单里各只股票的行情、新闻和财报：M5
- 复盘案件要读的交易记录和案件记录：M6 的 Reviewer
- 把快照放进 prompt（共享上下文的注入、条目怎样展示给模型、新闻正文转成文字）：M5
- 检查信号和 Task 输入引用的条目是否存在：本变更只提供按条目 ID 查条目，谁在什么时候检查由 M5 定
- 刷新新闻、公告和财报：快照只读状态库里已经存下的，由「事件检测」等触发变更去取
- 当前任务状态（队列、订单、预留、待确认方案）：不属于 Shared State，不进快照
- 回放：M6
- 清理旧快照：一直保留
- 省略的少见情况：见 design 的省略清单

## Capabilities

### New Capabilities

- `state-snapshot`：状态库快照：每种案件的快照有哪些事实、条目和条目 ID、共享事实、案件股票的事实、寻股的粗筛结果、新版本、同一版再生成、读取和按条目 ID 查条目、数据读不到时、存储、配置

### Modified Capabilities

- `state-store`：修改「表的归属和迁移」，加快照表 `statestore_snapshots`，属于状态库模块
- `program-log`：修改「程序日志的条目」（对象加上快照的版本）和「调度器的动作」（加生成快照）

- **并行的变更**：「案件记录」（v0012）也改 state-store「表的归属和迁移」，后归档的那个在自己的 delta 里带上先归档的表

## 需要人决定

完整版 Proposal 对应章节的问题：只有一处缺口，就是 What Changes 里那一处修改（Proposal 没说条目是什么、快照里放什么）。下面 8 条都已按推荐定下：

行为上的：

1. **数据读不到时**：券商账户、行情源或寻股粗筛的数据源读不到时，快照报错、不生成，案件不往下走（怎样结束由「案件工作流」定，可以是系统故障，也可以稍后重试）。不把缺的部分留空照常开始：没有账户和行情的快照做不了可靠的判断，也会让替身和以后的模型在残缺的数据上出方案
2. **回看多久**：默认新闻 5 个交易日、公告 65 个交易日（约一个季度，盖住最近一份 10-Q）、财报日历给出状态库里这只股票的全部发布、指数 SPY 和 QQQ；都是配置项

技术上的（已经写进 spec 和 design）：

3. **条目 ID 带版本**：`s<版本>/…`，在案件内不重复，凭案件 ID 和条目 ID 就能查回；同一条事实在第 2 版里是新的 ID。Task 去重按输入的 ID 比较，所以 PM 用第 1 版、Critic 用第 2 版派的相同任务不会复用，这是对的：数据变了
4. **寻股的名单当场粗筛**：生成寻股的快照时调用粗筛（排除股票池给出的现在不能加入的股票），名单复制进快照；不另找地方先跑粗筛
5. **事实的格式在 contracts 里另定**：不直接用各模块 domain 的 dataclass（行情、财报、粗筛结果），复制字段；新闻和公告直接用已有的 contracts。存下的快照格式不随模块内部的改动变化
6. **新闻正文整份复制**：一份快照约几十到一百多 KB（主要是新闻正文），一年估计几百 MB 到 1 GB，PostgreSQL 会压缩；回放要的就是当时的原文
7. **财报日历现在没有刷新的调用方**：快照只读状态库；由「收盘心跳」每个交易日收盘后刷新池内股票和持仓的财报（Finnhub 每分钟 60 次），新闻和公告由「事件检测」轮询时存下
8. **程序日志**：每生成一版写一条，行为者是调度器（Proposal 把"每个案件开始时生成快照"放在调度器的运行约束里），对象是 `s<版本>`，输出的引用是这一版的全部条目 ID；同一版再生成、读不到数据时不写

由 Claude 按推荐决定。
