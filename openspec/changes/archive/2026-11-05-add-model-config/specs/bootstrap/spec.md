# Spec Delta

## MODIFIED Requirements

### Requirement: 启动失败

「启动顺序」里写着启动失败的步骤失败时，程序 SHALL：

1. 写一条 ERROR 日志：哪一步失败，原因（异常的类型和信息），带异常栈
2. 不做后面的步骤
3. 按打开的相反顺序关闭已经打开的部分，规则同「停止」
4. 以退出码 1 退出，由进程管理器决定是否重启

| 失败 | 步骤 | 例子 |
| --- | --- | --- |
| 环境变量缺少或格式不对 | 1 | 见「环境变量」 |
| 数据库连不上 | 2 | 地址或密码不对，PostgreSQL 没有运行 |
| 数据库升级失败 | 2 | 迁移的建表语句报错；升级在一个事务里，失败时数据库不变 |
| 模型文件出错 | 4 | 见 model-config spec「文件出错」 |
| Alpaca 认证失败 | 5 | key 不对，Alpaca 回答 401 或 403 |
| Alpaca 不可用 | 5、6 | 超时、连不上、429、5xx |
| Discord 启动失败 | 8 | token 无效、注册 `/plan` 失败、频道不对、超过连接超时（默认 30 秒） |
| DBOS 启动失败 | 9 | 建 `dbos` schema 失败 |

OpenD 没有运行或没有登录 SHALL NOT 算启动失败，见「第一次健康判定」。

#### Scenario: 数据库连不上

- **GIVEN** 数据库地址指向一个没有 PostgreSQL 的端口
- **WHEN** 运行 `tradingagentspro run`
- **THEN** 启动失败，错误日志写明数据库这一步和连接的错误
- **AND** 没有连接 Alpaca、OpenD、Discord

#### Scenario: 数据库升级失败

- **GIVEN** 数据库里已经有一张 `risk_reservations` 表，但没有迁移版本的记录
- **WHEN** 运行 `tradingagentspro run`
- **THEN** 启动失败，错误日志写明数据库这一步和建表的错误
- **AND** 数据库里没有迁移版本的记录，没有新建别的表
- **AND** 没有连接 Alpaca、OpenD、Discord

#### Scenario: 模型文件出错

- **GIVEN** 模型文件里 Critic 和 PM 是同一家厂商
- **WHEN** 运行 `tradingagentspro run`
- **THEN** 启动失败，错误日志写明装配这一步和配置的错误
- **AND** 没有连接 OpenD、Discord，Alpaca 没有收到账户设置的请求，DBOS 没有启动
- **AND** 数据库连接已关闭

#### Scenario: Alpaca 认证失败

- **GIVEN** Alpaca 对账户设置的请求回答 401
- **WHEN** 运行 `tradingagentspro run`
- **THEN** 启动失败，错误日志写明 Alpaca 账户设置这一步和 401
- **AND** Alpaca 没有收到读取挂单和持仓的请求，Discord 没有连接，DBOS 没有启动
- **AND** OpenD 行情连接和数据库连接已关闭，日志依次写出这两项关闭

#### Scenario: 账户设置时 Alpaca 超时

- **GIVEN** 账户设置的请求超时
- **WHEN** 运行 `tradingagentspro run`
- **THEN** 启动失败，错误日志写明 Alpaca 账户设置这一步和券商不可用
- **AND** 没有对账，Discord 没有连接

#### Scenario: 对账时 Alpaca 不可用

- **GIVEN** 启动对账读取全部挂单时连不上
- **WHEN** 运行 `tradingagentspro run`
- **THEN** 启动失败，错误日志写明启动对账这一步和券商不可用
- **AND** Discord 没有连接，DBOS 没有启动

#### Scenario: Discord 启动失败

- **GIVEN** Discord 登录失败（token 无效）
- **WHEN** 运行 `tradingagentspro run`
- **THEN** 启动失败，错误日志写明 Discord 这一步和登录失败
- **AND** DBOS 没有启动，数据库里没有 `dbos` schema
- **AND** OpenD 行情连接和数据库连接已关闭

### Requirement: 模拟盘的装配

`tradingagentspro run` SHALL 按模拟盘装配，各部件如下。全部模块共用同一个系统时钟和同一份交易日历；阈值都取各自配置的默认值，只有模型和预算额度来自模型文件（model-config spec）。

| 部件 | 装配 |
| --- | --- |
| 券商 | Alpaca 模拟盘：普通订单和止损单两个适配器共用一个客户端，key 来自环境变量；估算费用用的每笔佣金 SHALL 等于风控配置的每笔佣金（默认 2） |
| 执行模块 | 订单、止损保护、交易记录存在状态库；执行配置的「买单和止损单错开」SHALL 打开（Alpaca 不允许同一只股票的买单和止损卖单同时挂着），其余用默认值 |
| 风控 | 预留存在状态库；风控配置用默认值 |
| 股票池、跟进、案件记录 | 记录都存在状态库；股票池配置和跟进配置用默认值 |
| Agent 网关 | 任务、Result 和费用记录存在状态库；模型配置和三个预算额度来自模型文件（model-config spec「读到以后怎么用」），调用 agent 的是替身（stand-ins spec），替身配置用默认值；网关配置的其他项用默认值 |
| 新闻和公告、公司数据、寻股粗筛 | 新闻源是 Alpaca 新闻、公告源是 SEC EDGAR、公司数据源是 Finnhub，寻股的日线来自 Alpaca、股票列表来自 moomoo（和行情共用一个 OpenD 行情连接）；Alpaca 的 key 和模拟盘的是同一组；记录都存在状态库；各自的配置用默认值，粗筛和股票池用同一份股票池配置 |
| 快照 | 存在状态库；读下面装配好的事件；快照配置的指数是 SPY、QQQ、VIXY，其余用默认值 |
| 紧急退出、健康监控 | 各自配置的默认值 |
| 行情 | 行情源是 OpenD（默认 127.0.0.1:11111）；VIX 源是 Cboe；行情配置用默认值（参考股票 SPY） |
| 到价提醒 | moomoo 到价提醒（moomoo-price-alerts spec），和行情共用一个 OpenD 行情连接 |
| 通知 | 通知通道是 Discord 机器人，配置来自环境变量；通知配置用默认值（确认超时 30 分钟，模型退出自动执行和紧急退出要确认都关闭） |
| `/plan` | 方案 ID 用随机 UUID；提交接口是下单流程的（order-flow spec「提交方案」） |
| 确认按钮的回调 | 紧急退出流程在等这个方案的确认时送给紧急退出流程（emergency-exit-flow spec「紧急退出的人工确认」），否则送给下单流程（order-flow spec「按钮的结果只送给在等确认的方案」） |
| 锁 | 全程序一把进程内的锁（session-patrol spec「执行模块和风控的调用串行」）；巡检（包括其中的紧急退出）和下单流程用的是同一把 |
| 盘中巡检 | 调用上面装配好的执行模块、风控和通知，用这把锁；巡检配置用默认值（间隔 15 秒）。每一轮里的紧急退出（emergency-exit-flow spec）另外调用上面装配好的紧急退出、健康监控和行情，用同一份通知配置；每一轮里的股票池跟上持仓（pool-position-sync spec）另外调用上面装配好的股票池、跟进和案件记录 |
| 下单流程 | 调用上面装配好的执行模块、风控、紧急退出、健康监控、行情、通知和案件记录，用这把锁和同一份通知配置（案件的方案的确认规则，order-flow spec「案件的方案」）；下单流程配置用默认值（重试间隔 30 秒） |
| 案件工作流 | 调用上面装配好的网关、案件记录、快照、股票池、跟进、事件、通知和程序日志；交给下单的是下单流程（order-flow spec「案件的方案」）；调度器配置、心跳配置和案件工作流配置用默认值，案件工作流和排队运行用同一份调度器配置 |
| 排队运行 | 排队的案件存在状态库；每一轮先把上面装配好的跟进里到点的排进来；读上面装配好的股票池、紧急退出流程、健康监控和网关的预算，启动案件工作流，作废交给下单流程；排队运行的配置用默认值（间隔 5 秒） |
| 健康监控接线 | PM 和 Critic 还有没有可用的模型取网关的备用模型，持仓保留预算取网关的预算，调度器心跳取排队运行（health-monitoring spec「健康信号」） |
| 事件 | 事件存在状态库；事件规则的配置用默认值 |
| 事件检测 | 读上面装配好的股票池、执行模块（账户数据和已经结束的卖出）、行情、新闻和公告、公司数据和事件，同步上面装配好的到价提醒、收它的推送，排进排队运行，写程序日志；不用那把锁；事件检测的配置用默认值（间隔 60 秒） |
| 收盘心跳 | 移出上面装配好的股票池里过期的候选，刷新上面装配好的公司数据，读股票池、案件记录、排队运行的队列和运行中的案件做收盘检查，排进排队运行，写程序日志；每个交易日的收盘心跳是一个 DBOS 工作流；不用那把锁；心跳配置和案件工作流用的是同一份，收盘心跳的配置用默认值（间隔 60 秒、延迟 15 分钟、刷新间隔 3 秒） |

#### Scenario: 打开买单和止损单错开

- **WHEN** 按模拟盘装配券商
- **THEN** 执行模块的「买单和止损单错开」是打开的

#### Scenario: 估算费用用风控的每笔佣金

- **GIVEN** 风控配置的每笔佣金是默认值 2；Alpaca 那边有一笔全部成交的买单和一张全部成交的止损单
- **WHEN** 按模拟盘装配的两个券商适配器查询这两笔
- **THEN** 两笔回报的费用都是 2

#### Scenario: 巡检和以后的流程共用一把锁

- **WHEN** 正常启动
- **THEN** 巡检的间隔是 15 秒
- **AND** 启动给以后的流程用的锁，就是巡检用的那一把：另一个线程拿着它时，巡检不调用执行模块和风控

#### Scenario: 录入并确认一个买入方案

- **GIVEN** 正常启动；Alpaca 模拟盘账户的权益和现金都是 10,000，前一交易日收盘时的权益 10,000；OpenD 有 BBB 的行情，最新价 50
- **WHEN** 本人运行 `/plan buy symbol:BBB sector:医疗 quantity:20 limit:50 stop:45`
- **THEN** 回复风控通过：买入 BBB 20 股；频道里出现这个方案的确认消息
- **WHEN** 本人按确认消息的「确认」
- **THEN** 消息显示已确认
- **AND** Alpaca 收到一笔买单：客户端订单 ID 是这个方案的 ID，BBB 20 股，限价 50

#### Scenario: 盘中紧急清仓

- **GIVEN** 当前时刻在常规交易时段内；Alpaca 模拟盘账户的权益和前一交易日收盘时的权益都是 10,000，持有 AAA 50 股；状态库里有 AAA 全部成交的开仓订单（板块"科技"，止损价 90，紧急阈值 0.08），AAA-STOP-1 挂着 50 股；OpenD 的 AAA 前一交易日收盘价 100、最新价 92
- **WHEN** 正常启动，巡检做第一轮
- **THEN** Alpaca 收到 AAA-STOP-1 的撤单请求；Discord 收到一条告警，写明 AAA 开始紧急退出
- **WHEN** Alpaca 回报 AAA-STOP-1 已撤销，巡检做下一轮
- **THEN** Alpaca 收到一笔市价卖单：AAA 50 股，客户端订单 ID 是 AAA 当天的代码触发的清仓方案的 ID

#### Scenario: 按钮的结果按方案送给紧急退出流程或下单流程

- **GIVEN** 正常启动；紧急退出流程在等 AAA 当天的清仓方案的确认；方案 P1 的下单流程在等确认
- **WHEN** 本人按 AAA 的紧急退出的确认消息的「确认」
- **THEN** 紧急退出流程收下这次确认，下单流程没有收到
- **WHEN** 本人按 P1 的确认消息的「确认」
- **THEN** P1 的下单流程收到确认，紧急退出流程没有收到

#### Scenario: 排进的案件由替身跑到下单

- **GIVEN** 正常启动；Alpaca 模拟盘账户的权益和现金都是 10,000，前一交易日收盘时的权益 10,000；状态库的股票池里 BBB 是关注，有关注论点；OpenD 有 BBB 的行情，前一交易日收盘价 50，最新价 50；状态库里没有 BBB 的新闻、公告和财报；事件表里有 BBB 的入场条件满足事件 E-1
- **WHEN** 排进 E-1 的事件触发（BBB 的入场条件满足事件，事件 ID E-1）
- **THEN** 排队运行启动 BBB 的关注股事件，案件上下文的事件是 E-1；PM 替身给出开仓方案，Critic 替身通过；频道里出现这个方案的确认消息
- **WHEN** 本人按确认消息的「确认」
- **THEN** Alpaca 收到一笔买单：客户端订单 ID 是这个方案的 ID，来源案件是这个案件
- **AND** 这个案件结束：订单已提交

#### Scenario: 新案件排队时作废等确认的方案

- **GIVEN** 同上一个场景，频道里已经出现 BBB 的开仓方案的确认消息，本人还没有按；事件表里另有 BBB 的新闻事件 BBB:2026-10-14:news
- **WHEN** 排进 BBB:2026-10-14:news 的事件触发
- **THEN** 确认消息改为已作废；第一个案件结束：方案被作废；BBB 没有有效预留
- **AND** 之后排队运行启动 BBB 的关注股事件（新闻事件开出的）

#### Scenario: 事件检测排进的案件跑起来

#### Scenario: 巡检里股票池跟上持仓

- **WHEN** 巡检做一轮

#### Scenario: 事件检测设到价提醒、按论点条件排案件

#### Scenario: 收盘心跳排进的案件跑起来

- **WHEN** 排队运行做第一轮
- **THEN** F-1 已触发；排队运行启动 BBB 的关注跟进，问题"站上 55 以后能不能守住？"，案件上下文的跟进是 F-1 的申请和 K1 的结论
- **AND** PM 替身给出继续关注，这个案件结束；程序日志有 F-1 的触发跟进

### Requirement: 第一次健康判定

启动对账之后、Discord 和 DBOS 之前，程序 SHALL 让健康监控判定一次（degraded-mode spec），健康信号如下：

| 信号 | 取值 | 理由 |
| --- | --- | --- |
| PM、Critic 还有可用的模型 | 网关的备用模型给出的 | 刚启动，没有模型在冷却中，都有 |
| 持仓保留预算用完 | 网关现在的预算的情况（call-budget spec「预算用完」） | 费用记录在状态库里，重启以前用完的照样算 |
| 调度器最近一次心跳 | 排队运行装配好的时刻（queue-runner spec「调度器心跳」） | 排队运行在 DBOS 之后才开始，这时还没有做过一轮 |
| 券商连接 | 正常 | 启动对账刚读过券商；读取失败时已经启动失败 |
| 行情最近一次更新的时刻 | 和盘中巡检的判定取法相同（health-monitoring spec「健康信号」）：行情模块给出的参考股票的更新时刻；取不到（OpenD 没开、没登录、出错）时为没有（启动以后还没取到过），并写一条 WARNING 写明原因 | 这次取到的更新时刻也算「程序启动以后最近一次取到的」 |

| 判定结果 | 处理 |
| --- | --- |
| 正常 | 写 INFO，继续启动 |
| 降级 | 写 WARNING，列出异常的检查；继续启动。风控按 degraded-mode spec 暂停开仓。Discord 连上以后、DBOS 启动以前推送一条告警（discord-notification spec「告警」），在启动对账的告警（如果有）之后 |

告警写明启动时处于降级模式，其余和 health-monitoring spec「状态变化的告警和日志」的「进入降级模式」相同：进入降级模式的时刻（这次判定的时刻）、异常的检查、已暂停开仓、止损单照常保留、各项恢复并和券商对账以后恢复开仓。告警发不出去时只写错误日志，照常继续启动。

这次判定的状态由盘中巡检接着用：巡检的判定仍是降级时不再告警，各项恢复以后照 health-monitoring spec「恢复后的对账」对账、回到正常。

#### Scenario: 盘中行情正常

- **WHEN** 正常启动
- **THEN** 健康是正常，启动完成
- **AND** Discord 没有收到健康的告警

#### Scenario: 盘中 OpenD 没开

- **GIVEN** 取行情时 OpenD 报错
- **WHEN** 正常启动
- **THEN** 有一条 WARNING 写明取不到行情和 OpenD 的错误
- **AND** 进入降级模式，异常的检查是数据延迟，有一条 WARNING 写明
- **AND** Discord 连上以后、DBOS 启动以前收到一条告警，写明启动时处于降级模式、数据延迟、已暂停开仓
- **AND** 启动完成

#### Scenario: 盘外 OpenD 没开

- **GIVEN** 启动时刻是 2026-10-14T12:00:00Z（美东 8:00，开盘前）；取行情时 OpenD 报错
- **WHEN** 正常启动
- **THEN** 有一条 WARNING 写明取不到行情
- **AND** 健康是正常（盘外不检查数据延迟），启动完成
- **AND** Discord 没有收到健康的告警

#### Scenario: 开盘后行情一直没有更新

- **GIVEN** 参考股票的行情停在前一个交易日收盘
- **WHEN** 正常启动
- **THEN** 进入降级模式，异常的检查是数据延迟，启动完成
- **AND** Discord 收到一条告警，写明启动时处于降级模式、数据延迟

#### Scenario: 启动时持仓保留预算已经用完

- **GIVEN** 状态库里今天记到持仓保留预算的费用已经到模型文件里持仓保留预算的额度
- **WHEN** 正常启动
- **THEN** 进入降级模式，异常的检查是调用预算，有一条 WARNING 写明
- **AND** Discord 连上以后、DBOS 启动以前收到一条告警，写明启动时处于降级模式、调用预算
- **AND** 启动完成

#### Scenario: 启动对账和健康都要告警

- **GIVEN** Alpaca 模拟盘持有 CCC 100 股，状态库里没有 CCC 的订单；取行情时 OpenD 报错
- **WHEN** 正常启动
- **THEN** Discord 连上以后先收到启动对账的告警，再收到启动时处于降级模式的告警，之后 DBOS 才启动

#### Scenario: 健康的告警发不出去

- **GIVEN** 取行情时 OpenD 报错；Discord 连上以后，发告警时报错
- **WHEN** 正常启动
- **THEN** 有一条错误日志，含告警的文字和失败原因
- **AND** 启动完成

#### Scenario: 巡检第一轮仍是降级时不再告警

- **GIVEN** 取行情时 OpenD 一直报错
- **WHEN** 正常启动，巡检做完第一轮
- **THEN** 状态仍是降级
- **AND** Discord 一共只收到一条健康的告警（启动时的那一条）
