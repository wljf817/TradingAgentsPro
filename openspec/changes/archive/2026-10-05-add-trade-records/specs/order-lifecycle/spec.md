# Spec Delta

## MODIFIED Requirements

### Requirement: 提交订单

执行模块 SHALL 按方案和它的再校验结果（通过或调整）提交订单。每个方案最多一个订单，订单的内容如下：

| 项 | 取值 |
| --- | --- |
| 客户端订单 ID | 方案 ID |
| 买卖方向 | 买入、加仓是买入；减仓、清仓是卖出 |
| 股票、板块、订单类型、限价 | 取方案的 |
| 委托股数 | 再校验的最终股数 |
| 有效期类型 | 当日有效 |
| 截止时刻 | 再校验结果里生效的有效期，和当天收盘，两者中较早的那个 |
| 止损价 | 买入、加仓取方案的止损价；减仓、清仓没有 |
| 紧急阈值 | 买入、加仓取再校验结果里生效的紧急阈值；减仓、清仓没有 |

新订单的状态是待提交，累计成交和累计费用都是 0，记下创建时刻，然后立即按「先查询再提交」提交给券商。

提交新订单 MUST 在常规交易时段内；不在时 SHALL 报不在交易时段的错误，不创建订单，也不调用券商。同一个方案已经有订单时，再次提交 SHALL NOT 新建订单，只跟进一次已有的订单（见「订单状态和券商回报」）并返回它。无保护仓位的股票不能提交新的买单，见 stop-protection spec「无保护时禁止加仓」。执行模块还没完成过对账时，不能提交新订单；最近一次对账有不一致时，不能提交新的买单，见 reconciliation spec「对账之前不接受新订单」「有不一致时暂停开仓」。

本 spec 的场景除非另有说明，都使用下面的基准数据：

- 当前时刻 2026-10-14 15:00Z（周三，盘中；当天收盘 20:00Z），交易日历是纽交所日历
- 基准方案：方案 ID 记为 P1，买入 BBB，板块"医疗"，100 股，限价单，限价 50，止损价 45
- 基准结果：基准方案的再校验结论为通过，最终股数 100，生效的有效期 2026-10-14 20:00Z，生效的紧急阈值 0.08
- 状态未知的等待时长是默认的 30 秒
- 执行模块已经完成一次对账，没有不一致
- 券商持仓 AAA 100 股，执行模块没有 AAA 的止损单，所以 AAA 的卖单不用等止损单让出（见 stop-protection spec「卖单先让出股数」）
- "提交基准方案"指在当前时刻用基准方案和基准结果提交。没有另外说明时，券商正常受理，订单不成交
- "券商回报变为……"指之后按客户端订单 ID 查询时，券商给出的这笔订单的状态、累计成交股数、成交均价和累计费用；没写累计费用时是 0

#### Scenario: 买入方案提交限价买单

- **GIVEN** 基准数据
- **WHEN** 提交基准方案
- **THEN** 券商收到一笔订单：客户端订单 ID 是 P1，买入 BBB 100 股，限价单，限价 50，当日有效
- **AND** 订单状态是已提交，截止时刻 2026-10-14 20:00Z，创建时刻 2026-10-14 15:00Z，累计成交 0，记下了券商订单号
- **AND** 订单记下板块"医疗"、止损价 45、紧急阈值 0.08，累计费用 0

#### Scenario: 减仓方案提交市价卖单

- **GIVEN** 基准数据，减仓方案 P2：减仓 AAA（板块"科技"）60 股，市价单；再校验通过，最终股数 60，生效的有效期 2026-10-14 20:00Z，没有生效的紧急阈值
- **WHEN** 提交 P2
- **THEN** 券商收到一笔订单：客户端订单 ID 是 P2，卖出 AAA 60 股，市价单，当日有效
- **AND** 订单记下板块"科技"，没有止损价和紧急阈值

#### Scenario: 按再校验的最终股数下单

- **GIVEN** 基准数据，基准方案的再校验结论改为调整，最终股数 60
- **WHEN** 提交基准方案
- **THEN** 委托股数是 60
- **WHEN** 提交清仓方案 P2：清仓 AAA，市价单，不写股数；再校验通过，最终股数 100
- **THEN** 券商收到卖出 AAA 100 股的订单

#### Scenario: 方案的有效期早于当天收盘

- **GIVEN** 基准数据，基准结果的生效有效期改为 2026-10-14 16:00Z
- **WHEN** 提交基准方案
- **THEN** 截止时刻是 2026-10-14 16:00Z

#### Scenario: 方案的有效期晚于当天收盘

- **GIVEN** 基准数据，基准结果的生效有效期改为 2026-10-16 20:00Z
- **WHEN** 提交基准方案
- **THEN** 截止时刻是 2026-10-14 20:00Z

#### Scenario: 提前收盘的交易日

- **GIVEN** 基准数据，当前时刻改为 2026-11-27 15:00Z（感恩节次日，18:00Z 提前收盘），基准结果的生效有效期改为 2026-11-30 21:00Z
- **WHEN** 提交基准方案
- **THEN** 截止时刻是 2026-11-27 18:00Z

#### Scenario: 不在交易时段时提交报错

- **GIVEN** 基准数据，当前时刻改为 2026-10-14 21:00Z（盘后）
- **WHEN** 提交基准方案
- **THEN** 报不在交易时段的错误
- **AND** 没有 P1 的订单，券商没有收到任何调用

#### Scenario: 同一个方案重复提交

- **GIVEN** 基准方案已经提交，订单已提交
- **WHEN** 再次提交基准方案
- **THEN** 券商仍然只有一笔客户端订单 ID 是 P1 的订单
- **AND** 返回的是同一笔订单，状态是已提交

### Requirement: 订单状态和券商回报

订单 SHALL 处于下面 8 种状态之一：

| 状态 | 含义 | 终态 |
| --- | --- | --- |
| 待提交 | 已经建立，还没确认券商收到 | 否 |
| 已提交 | 券商已受理，还没有成交 | 否 |
| 部分成交 | 券商已受理，成交了一部分 | 否 |
| 全部成交 | 委托股数全部成交 | 是 |
| 已撤销 | 截止时刻之前被撤销 | 是 |
| 已过期 | 到截止时刻结束：到期撤单、当日单收盘失效，以及截止时刻之后才确认券商没有收到的订单 | 是 |
| 已拒绝 | 券商拒绝受理，或者受理后拒绝 | 是 |
| 状态未知 | 券商调用超时或断线，或者券商报结果未知 | 否 |

跟进一笔未结束的订单时，执行模块按客户端订单 ID 查询券商，SHALL 按券商回报更新状态、券商订单号、累计成交股数、成交均价和累计费用：

| 券商回报 | 订单状态 |
| --- | --- |
| 已受理、未结束，累计成交为 0 | 已提交 |
| 已受理、未结束，累计成交大于 0 | 部分成交 |
| 全部成交 | 全部成交 |
| 撤销或失效，当前时刻不早于截止时刻 | 已过期 |
| 撤销或失效，当前时刻早于截止时刻 | 已撤销 |
| 拒绝 | 已拒绝 |
| 结果未知 | 状态未知 |

撤销、失效和拒绝时，已经成交的部分保留在累计成交里。累计费用取券商回报里这笔订单的佣金和其他费用之和。

券商回报只能让订单往前走：

- 回报的累计成交股数少于订单已记录的，这条回报 SHALL 被忽略
- 进入终态的订单 SHALL NOT 再变化；跟进时不再调用券商

#### Scenario: 部分成交后全部成交

- **GIVEN** 基准方案已经提交，订单已提交
- **WHEN** 券商回报变为已受理、累计成交 30、成交均价 49.90，跟进订单
- **THEN** 订单部分成交，累计成交 30，成交均价 49.90
- **WHEN** 券商回报变为全部成交、累计成交 100、成交均价 49.95、累计费用 2.15，跟进订单
- **THEN** 订单全部成交，累计成交 100，成交均价 49.95，累计费用 2.15

#### Scenario: 已撤销和已过期以截止时刻为界

- **GIVEN** 基准方案已经提交，订单部分成交，累计成交 30
- **WHEN** 券商回报变为撤销、累计成交 30（比如在券商 App 里手动撤单），2026-10-14 19:59:59Z 跟进
- **THEN** 订单已撤销，累计成交 30
- **GIVEN** 另一次，同样的订单和券商回报
- **WHEN** 2026-10-14 20:00:00Z 跟进
- **THEN** 订单已过期，累计成交 30

#### Scenario: 当日单收盘失效

- **GIVEN** 基准方案已经提交，订单已提交，截止时刻 2026-10-14 20:00Z
- **WHEN** 券商回报变为失效、累计成交 0，2026-10-14 20:00:05Z 跟进
- **THEN** 订单已过期，累计成交 0，没有请求撤单

#### Scenario: 受理后被拒

- **GIVEN** 基准方案已经提交，订单已提交
- **WHEN** 券商回报变为拒绝，跟进订单
- **THEN** 订单已拒绝，累计成交 0

#### Scenario: 券商报结果未知

- **GIVEN** 基准方案已经提交，订单已提交
- **WHEN** 券商回报变为结果未知，2026-10-14 15:10Z 跟进
- **THEN** 订单状态未知，记下的时刻是 2026-10-14 15:10Z

#### Scenario: 累计成交变少的回报被忽略

- **GIVEN** 基准方案已经提交，订单部分成交，累计成交 50
- **WHEN** 券商回报变为已受理、累计成交 30（过时的回报），跟进订单
- **THEN** 订单仍是部分成交，累计成交 50

#### Scenario: 终态不再变化

- **GIVEN** 基准方案已经提交，订单全部成交
- **WHEN** 跟进订单
- **THEN** 不调用券商，订单仍是全部成交

### Requirement: 保存订单

执行模块 SHALL 把每笔订单的最新状态保存在存储中，每次变化都保存。订单记录包括：

- 方案 ID（即客户端订单 ID）、股票、板块、买卖方向、订单类型、限价、委托股数、止损价、紧急阈值
- 截止时刻、创建时刻
- 状态、券商订单号、累计成交股数、成交均价、累计费用
- 跟进需要的状态：变为状态未知的时刻、是否已经请求撤单、是否有撤单要求（见「提前撤单」）

进程重启后，执行模块 SHALL 从存储读出订单，继续跟进。

#### Scenario: 重启后继续跟进

- **GIVEN** 基准方案已经提交，订单已提交
- **WHEN** 进程重启（用同一个存储重新创建执行模块），券商回报变为全部成交、累计成交 100、成交均价 50，跟进订单
- **THEN** 订单全部成交，累计成交 100，成交均价 50

#### Scenario: 重启后不重复撤单

- **GIVEN** 截止时刻 2026-10-14 16:00Z，16:00Z 已经请求撤单，订单已提交
- **WHEN** 进程重启，券商回报仍是已受理，2026-10-14 16:00:05Z 跟进订单
- **THEN** 券商没有收到第二次撤单请求，订单仍是已提交

#### Scenario: 重启后继续提前撤单

- **GIVEN** 基准方案已经提交，订单已提交；2026-10-14 15:10Z 撤掉 BBB 的订单，撤单请求超时，券商没有收到，订单状态未知
- **WHEN** 进程重启，2026-10-14 15:10:30Z 跟进订单，券商回报仍是已受理、累计成交 0
- **THEN** 券商再次收到 P1 的撤单请求，订单已提交，有撤单要求
