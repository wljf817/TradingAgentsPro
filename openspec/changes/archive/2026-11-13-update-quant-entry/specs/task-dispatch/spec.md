# Spec Delta

## ADDED Requirements

### Requirement: Quant 任务的量化指标

运行目标是 Quant 的任务时，Agent 网关 SHALL 在调用模型以前取得这个任务的量化指标条目（agent-calls spec「子 agent 的任务」）：

- 这个任务已经有条目时（比如崩溃以后重做这一步）用它，SHALL NOT 再算
- 没有时，按下表由 Task 和这次运行读的这版快照组出请求，经行情模块算出量化指标（quant-indicators spec），存下条目以后再调用模型

| 请求的项 | 取自 |
| --- | --- |
| 股票 | Task 的股票 |
| 板块 ETF | 快照的股票池里这只股票的板块；不在股票池里时，快照的粗筛名单里它的板块；都没有时没有 |
| 周期和范围 | Task 的周期和范围 |
| 快照时刻 | 快照的生成时刻 |
| 最新价 | 快照里每个有最新价的行情条目的最新价 |
| 量比 | 快照里这只股票的行情条目的量比；没有这个条目或者它没有量比时没有 |
| 事件 | Task 的输入里、在这版快照中查得到的事件条目，按输入的顺序，每个取事件 ID 和发生时刻；输入里别的条目和查不到的 ID 不算 |

条目：

- 条目 ID 是 `quant/` 加上 task_id；内容是行情模块算出的量化指标，原样
- 一个任务最多一个条目；不是 Quant 的任务、被拒绝的任务、K 线取不到的任务没有条目
- 取得一个任务或者本案件的任务（「本案件的任务和用量」）时，有条目的任务 SHALL 带上它
- 条目存在状态库所在的数据库里（量化指标表 gateway_indicators，state-store spec「表的归属和迁移」），只由 Agent 网关写入：只追加，写入以后 MUST NOT 被修改或删除；读回的和写入的完全相同，进程重启以后照样读得到
- 读写出错（数据库连不上、表不存在、存着的条目读不出来）时 SHALL 报错，MUST NOT 当作没有条目，也 MUST NOT 当作已经写入
- 行情模块报 K 线的数据源不可用（quant-indicators spec「数据源不可用」）时没有条目，这个任务不调用模型，Result 见 agent-calls spec「子 agent 的任务」；行情模块的其他错误原样报错

本 requirement 的场景里，这次运行读的快照是 K-1 的第 1 版 S1：股票池里 BBB 的板块是 XLV；行情条目有 s1/quote/BBB（最新价 52，量比 1.8）、s1/quote/XLV（最新价 140.2，没有量比）、s1/quote/SPY（最新价 580.25）、s1/quote/QQQ（没有最新价）；事件条目有 s1/event/BBB:2026-10-14:news（发生时刻 2026-10-14 14:20Z）和 s1/event/BBB:2026-10-14:price_down（发生时刻 2026-10-14 14:40Z）。价格请求的输入改为 s1/quote/BBB、s1/event/BBB:2026-10-14:price_down、s1/event/BBB:2026-10-14:news。"quant/T-n"指 `quant/` 加上 T-n 的 task_id。行情模块算得出量化指标，除非另有说明。

#### Scenario: 按 Task 和快照组出请求

- **GIVEN** PM 派发价格请求（T-1）
- **WHEN** 运行 T-1
- **THEN** 行情模块收到一次请求：股票 BBB，板块 ETF XLV，日线、60 个交易日，快照时刻 2026-10-14 15:00Z，最新价 BBB 52、XLV 140.2、SPY 580.25（没有 QQQ），量比 1.8，事件依次是 BBB:2026-10-14:price_down（14:40Z）、BBB:2026-10-14:news（14:20Z）
- **AND** 存下 T-1 的条目 quant/T-1，内容是行情模块给出的量化指标；之后才调用 Quant 的模型

#### Scenario: 寻股的股票取粗筛名单里的板块

- **GIVEN** 寻股 K-2 的第 1 版快照：股票池里没有 DDD 和 GGG，粗筛名单里 DDD 的板块是 XLF，没有 GGG；没有 DDD 和 GGG 的行情条目
- **WHEN** 运行 K-2 的 PM 派发的 DDD 的价格请求、GGG 的价格请求，输入都为空
- **THEN** DDD 的请求板块 ETF 是 XLF，没有量比，没有事件
- **AND** GGG 的请求没有板块 ETF，没有量比，没有事件

#### Scenario: 输入里不是事件的和查不到的不算

- **GIVEN** PM 派发价格请求，输入改为 s1/quote/BBB、s1/news/1、s1/event/BBB:2026-10-13:news（这版快照里没有）
- **WHEN** 运行这个任务
- **THEN** 行情模块收到的请求没有事件

#### Scenario: 只算一次

- **GIVEN** PM 派发价格请求（T-1）；运行 T-1 时存下 quant/T-1 以后进程崩溃，T-1 还没有 Result
- **WHEN** 重启，再运行 T-1
- **THEN** 行情模块没有收到请求；调用 Quant 用的是存下的 quant/T-1

#### Scenario: 原样读回

- **GIVEN** PM 派发价格请求（T-1），T-1 有条目 quant/T-1，然后完成
- **WHEN** 重启，取得 T-1；取得 K-1 的任务
- **THEN** 两次 T-1 都带 quant/T-1，内容和写入的完全相同：每个数字的每一位小数、每个时刻、价位和缺口的顺序

#### Scenario: 不是 Quant 的任务没有条目

- **GIVEN** PM 派发新闻请求（T-1）、AAA 的价格请求（T-2，被拒绝）
- **WHEN** 运行 T-1，T-1 完成；取得 K-1 的任务
- **THEN** 行情模块没有收到请求；T-1 和 T-2 都没有条目

#### Scenario: K 线取不到

- **GIVEN** PM 派发价格请求（T-1）
- **WHEN** 运行 T-1，行情模块报数据源不可用"Alpaca 超时"
- **THEN** 没有存下条目，没有调用 Quant 的模型；T-1 的 Result 是失败，原因是数据取不到
- **WHEN** 取得 K-1 的任务
- **THEN** T-1 没有条目

#### Scenario: 读写出错

- **GIVEN** PM 派发价格请求（T-1），之后数据库连不上
- **WHEN** 运行 T-1；或者取得 K-1 的任务
- **THEN** 都报错，没有调用模型
- **GIVEN** PM 派发价格请求（T-1），T-1 有条目；存着的 quant/T-1 缺了截止时刻
- **WHEN** 取得 K-1 的任务；或者再运行 T-1
- **THEN** 都报错，不当作 T-1 没有条目，也不重新算

## MODIFIED Requirements

### Requirement: Result 的格式

每个 Task SHALL 只有一个 Result，用它的 task_id 标识：PM 和 Critic 引用 Result 时写它的 task_id。Result 包含 task_id、状态、输出、原因、说明、模型、耗时和费用，各状态的内容如下：

| 状态 | 输出 | 原因 | 说明 | 模型 |
| --- | --- | --- | --- | --- |
| 完成 | 合法的信号 | 无 | 无 | 给出输出的模型 |
| 无信号 | 合法的无信号 | 无 | 无 | 给出输出的模型 |
| 超时 | 无 | 无 | 无 | 无 |
| 失败 | 无 | 格式不合法、调用失败或数据取不到 | 必填的文字 | 格式不合法时是给出输出的模型；调用失败和数据取不到时无 |
| 被拒绝 | 无 | 被拒绝的原因（见「派发的顺序」） | 无 | 无 |

- 数据取不到只用于 Quant 的任务取不到 K 线、没有调用模型（agent-calls spec「子 agent 的任务」）
- 模型是 model-fallback spec「实际使用的模型」：给出输出的模型，以及它是不是目标子 agent 的备用模型；按实际使用的模型统计评估
- 引用的条目 ID 取自输出（信号或无信号的引用的条目）；没有输出时没有
- 耗时是生成 Result 的时刻减派发时刻；被拒绝的是 0
- 费用是调用方给出的这个任务调用模型的费用，不小于 0；被拒绝的是 0
- 和上表不符、耗时或费用小于 0，都 MUST 报错

本 requirement 和「子 agent 的输出变成 Result」的场景里，Quant 的主模型是 google/s-1，备用模型是 openai/s-2（model-fallback spec 的基准模型的配置）。

#### Scenario: 完成和无信号的 Result

- **GIVEN** PM 派发价格请求（T-1）
- **WHEN** 2026-10-14 15:01:30Z 收到 s-1 给出的基准信号，费用 0.02
- **THEN** T-1 的 Result 是完成，输出是基准信号，引用的条目是 E-1 和 E-2，模型是 s-1、不是备用模型，耗时 90 秒，费用 0.02
- **WHEN** 同样的时刻收到 s-1 给出的基准无信号，费用 0.02
- **THEN** T-1 的 Result 是无信号，输出是基准无信号，没有引用的条目，模型是 s-1、不是备用模型

#### Scenario: 状态和内容不符

- **WHEN** 构造这些 Result：完成，没有输出；完成，输出是基准无信号；无信号，输出是基准信号；超时，输出是基准信号；失败，没有原因；失败，原因是格式不合法，没有说明；被拒绝，原因是格式不合法；无信号，原因是"轮次已用完"；完成，费用 -0.01
- **THEN** 都报错

#### Scenario: 模型和状态不符

- **WHEN** 构造这些 Result：完成，没有模型；无信号，没有模型；失败，原因是格式不合法，没有模型；超时，模型是 s-1；失败，原因是调用失败，模型是 s-1；失败，原因是数据取不到，模型是 s-1；被拒绝，模型是 s-1
- **THEN** 都报错
- **WHEN** 构造失败的 Result：原因是格式不合法，说明"评估窗口不在配置的选项里"，模型是 s-2、是备用模型
- **THEN** 格式正确

#### Scenario: 数据取不到的 Result

- **WHEN** 构造失败的 Result：原因是数据取不到，说明"取不到 K 线：Alpaca 超时"，没有模型，耗时 60 秒，费用 0
- **THEN** 格式正确，引用的条目为空
- **WHEN** 构造这些 Result：失败，原因是数据取不到，没有说明；被拒绝，原因是数据取不到
- **THEN** 都报错
