# Spec Delta

## MODIFIED Requirements

### Requirement: 提交订单

执行模块 SHALL 按方案和它的再校验结果（通过或调整）提交订单。每个方案最多一个订单，订单的内容如下：

| 项 | 取值 |
| --- | --- |
| 客户端订单 ID | 方案 ID |
| 买卖方向 | 买入、加仓是买入；减仓、清仓是卖出 |
| 股票、订单类型、限价 | 取方案的 |
| 委托股数 | 再校验的最终股数 |
| 有效期类型 | 当日有效 |
| 截止时刻 | 再校验结果里生效的有效期，和当天收盘，两者中较早的那个 |
| 止损价 | 买入、加仓取方案的止损价；减仓、清仓没有 |

新订单的状态是待提交，记下创建时刻，然后立即按「先查询再提交」提交给券商。

提交新订单 MUST 在常规交易时段内；不在时 SHALL 报不在交易时段的错误，不创建订单，也不调用券商。同一个方案已经有订单时，再次提交 SHALL NOT 新建订单，只跟进一次已有的订单（见「订单状态和券商回报」）并返回它。无保护仓位的股票不能提交新的买单，见 stop-protection spec「无保护时禁止加仓」。

本 spec 的场景除非另有说明，都使用下面的基准数据：

- 当前时刻 2026-10-14 15:00Z（周三，盘中；当天收盘 20:00Z），交易日历是纽交所日历
- 基准方案：方案 ID 记为 P1，买入 BBB，板块"医疗"，100 股，限价单，限价 50，止损价 45
- 基准结果：基准方案的再校验结论为通过，最终股数 100，生效的有效期 2026-10-14 20:00Z
- 状态未知的等待时长是默认的 30 秒
- 券商持仓 AAA 100 股，执行模块没有 AAA 的止损单，所以 AAA 的卖单不用等止损单让出（见 stop-protection spec「卖单先让出股数」）
- "提交基准方案"指在当前时刻用基准方案和基准结果提交。没有另外说明时，券商正常受理，订单不成交
- "券商回报变为……"指之后按客户端订单 ID 查询时，券商给出的这笔订单的状态、累计成交股数和成交均价

#### Scenario: 买入方案提交限价买单

- **GIVEN** 基准数据
- **WHEN** 提交基准方案
- **THEN** 券商收到一笔订单：客户端订单 ID 是 P1，买入 BBB 100 股，限价单，限价 50，当日有效
- **AND** 订单状态是已提交，截止时刻 2026-10-14 20:00Z，创建时刻 2026-10-14 15:00Z，累计成交 0，记下了券商订单号
- **AND** 订单记下止损价 45

#### Scenario: 减仓方案提交市价卖单

- **GIVEN** 基准数据，减仓方案 P2：减仓 AAA 60 股，市价单；再校验通过，最终股数 60，生效的有效期 2026-10-14 20:00Z
- **WHEN** 提交 P2
- **THEN** 券商收到一笔订单：客户端订单 ID 是 P2，卖出 AAA 60 股，市价单，当日有效
- **AND** 订单没有止损价

#### Scenario: 按再校验的最终股数下单

- **GIVEN** 基准数据，基准方案的再校验结论改为调整，最终股数 60
- **WHEN** 提交基准方案
- **THEN** 委托股数是 60
- **WHEN** 提交清仓方案 P2：清仓 AAA，市价单，不写股数；再校验通过，最终股数 100
- **THEN** 券商收到卖出 AAA 100 股的订单

#### Scenario: 方案的有效期早于当天收盘

- **GIVEN** 基准数据，基准结果的生效有效期改为 2026-10-14 16:00Z
- **WHEN** 提交基准方案
- **THEN** 截止时刻是 2026-10-14 16:00Z

#### Scenario: 方案的有效期晚于当天收盘

- **GIVEN** 基准数据，基准结果的生效有效期改为 2026-10-16 20:00Z
- **WHEN** 提交基准方案
- **THEN** 截止时刻是 2026-10-14 20:00Z

#### Scenario: 提前收盘的交易日

- **GIVEN** 基准数据，当前时刻改为 2026-11-27 15:00Z（感恩节次日，18:00Z 提前收盘），基准结果的生效有效期改为 2026-11-30 21:00Z
- **WHEN** 提交基准方案
- **THEN** 截止时刻是 2026-11-27 18:00Z

#### Scenario: 不在交易时段时提交报错

- **GIVEN** 基准数据，当前时刻改为 2026-10-14 21:00Z（盘后）
- **WHEN** 提交基准方案
- **THEN** 报不在交易时段的错误
- **AND** 没有 P1 的订单，券商没有收到任何调用

#### Scenario: 同一个方案重复提交

- **GIVEN** 基准方案已经提交，订单已提交
- **WHEN** 再次提交基准方案
- **THEN** 券商仍然只有一笔客户端订单 ID 是 P1 的订单
- **AND** 返回的是同一笔订单，状态是已提交

### Requirement: 先查询再提交

执行模块每次向券商提交订单之前，SHALL 先按客户端订单 ID 查询：

- 查到：采用券商回报（见「订单状态和券商回报」），不再提交
- 查不到，当前时刻早于截止时刻：提交，客户端订单 ID 不变
- 查不到，当前时刻不早于截止时刻：不再提交，订单结束为已过期，累计成交 0

需要提交的订单只有两种：待提交的订单；券商从没受理过（没有券商订单号）的状态未知订单，见「券商调用失败时状态未知」。券商受理过的订单 MUST NOT 重新提交。

卖单查不到、当前时刻早于截止时刻时，SHALL 先按 stop-protection spec「卖单先让出股数」确认这只股票的止损单已经让出股数，才提交；还没让出时这次不提交，订单状态不变。

券商拒绝受理时，订单结束为已拒绝，没有券商订单号。

#### Scenario: 首次提交时先查询

- **GIVEN** 基准数据
- **WHEN** 提交基准方案
- **THEN** 券商先收到按 P1 的查询，查不到，再收到提交

#### Scenario: 券商拒绝受理

- **GIVEN** 基准数据，券商会拒绝受理这笔订单（比如购买力不足）
- **WHEN** 提交基准方案
- **THEN** 订单已拒绝，累计成交 0，没有券商订单号

#### Scenario: 止损单还没让出股数时不提交卖单

- **GIVEN** 基准数据，P1 全部成交，券商持仓 BBB 100 股，止损单 BBB-STOP-1 挂着 100 股
- **WHEN** 提交减仓 BBB 60 股的方案 P3
- **THEN** 券商收到按 P3 的查询，查不到，但没有收到 P3 的提交；P3 的订单待提交

#### Scenario: 提交之后、保存结果之前进程退出

- **GIVEN** 存储里有基准方案的待提交订单，券商已经受理了客户端订单 ID 是 P1 的订单（进程在提交后、保存结果前退出）
- **WHEN** 进程重启后，2026-10-14 15:05Z 跟进这笔订单
- **THEN** 不再提交，券商仍然只有一笔 P1 的订单
- **AND** 订单已提交，记下了券商订单号

#### Scenario: 提交之前进程退出

- **GIVEN** 存储里有基准方案的待提交订单，券商没有 P1 的订单
- **WHEN** 进程重启后，2026-10-14 15:05Z 跟进这笔订单
- **THEN** 券商收到 P1 的提交，订单已提交

#### Scenario: 停机到截止时刻之后

- **GIVEN** 存储里有基准方案的待提交订单，截止时刻 2026-10-14 20:00Z，券商没有 P1 的订单
- **WHEN** 进程在 2026-10-15 13:00Z 重启后跟进这笔订单
- **THEN** 不提交，订单已过期，累计成交 0

### Requirement: 保存订单

执行模块 SHALL 把每笔订单的最新状态保存在存储中，每次变化都保存。订单记录包括：

- 方案 ID（即客户端订单 ID）、股票、买卖方向、订单类型、限价、委托股数、止损价
- 截止时刻、创建时刻
- 状态、券商订单号、累计成交股数、成交均价
- 跟进需要的状态：变为状态未知的时刻、是否已经请求撤单

进程重启后，执行模块 SHALL 从存储读出订单，继续跟进。

#### Scenario: 重启后继续跟进

- **GIVEN** 基准方案已经提交，订单已提交
- **WHEN** 进程重启（用同一个存储重新创建执行模块），券商回报变为全部成交、累计成交 100、成交均价 50，跟进订单
- **THEN** 订单全部成交，累计成交 100，成交均价 50

#### Scenario: 重启后不重复撤单

- **GIVEN** 截止时刻 2026-10-14 16:00Z，16:00Z 已经请求撤单，订单已提交
- **WHEN** 进程重启，券商回报仍是已受理，2026-10-14 16:00:05Z 跟进订单
- **THEN** 券商没有收到第二次撤单请求，订单仍是已提交

### Requirement: 执行配置

执行模块的阈值 SHALL 可以配置：

| 配置项 | 含义 | 默认值 |
| --- | --- | --- |
| 状态未知的等待时长 | 订单或止损单变为状态未知之后，等多久才再查询券商 | 30 秒 |
| 立即重试次数 | 止损单挂单或改单被券商拒绝后，立即用同样的内容重试几次 | 1 |

等待时长 MUST 大于 0，立即重试次数 MUST NOT 小于 0，否则配置报错。

#### Scenario: 默认配置

- **WHEN** 不指定任何配置项
- **THEN** 状态未知的等待时长是 30 秒，立即重试次数是 1

#### Scenario: 修改等待时长

- **GIVEN** 基准数据，状态未知的等待时长改为 60 秒，提交超时，券商其实收到了，订单状态未知，记下 2026-10-14 15:00Z
- **WHEN** 2026-10-14 15:00:59Z 跟进订单
- **THEN** 不调用券商
- **WHEN** 2026-10-14 15:01:00Z 跟进订单
- **THEN** 查到这笔订单，订单已提交

#### Scenario: 等待时长不大于 0

- **WHEN** 状态未知的等待时长配置为 0 秒
- **THEN** 配置报错

#### Scenario: 立即重试次数为 0

- **GIVEN** P1 已经提交，立即重试次数改为 0，券商会拒绝下一次挂单
- **WHEN** 券商回报 P1 部分成交、累计成交 30，券商持仓变为 30 股，跟进 P1
- **THEN** 券商只收到一次 BBB-STOP-1 的挂单，BBB 是无保护仓位

#### Scenario: 立即重试次数小于 0

- **WHEN** 立即重试次数配置为 -1
- **THEN** 配置报错
