# Spec Delta

## Purpose

执行模块按通过下单前再校验的方案提交订单，并把订单跟踪到终态：防止重复提交，按券商回报更新状态和累计成交，到截止时刻撤单；券商调用超时或断线时进入状态未知，查清之前暂停这只股票的新订单。

## ADDED Requirements

### Requirement: 提交订单

执行模块 SHALL 按方案和它的再校验结果（通过或调整）提交订单。每个方案最多一个订单，订单的内容如下：

| 项 | 取值 |
| --- | --- |
| 客户端订单 ID | 方案 ID |
| 买卖方向 | 买入、加仓是买入；减仓、清仓是卖出 |
| 股票、订单类型、限价 | 取方案的 |
| 委托股数 | 再校验的最终股数 |
| 有效期类型 | 当日有效 |
| 截止时刻 | 再校验结果里生效的有效期，和当天收盘，两者中较早的那个 |

新订单的状态是待提交，记下创建时刻，然后立即按「先查询再提交」提交给券商。

提交新订单 MUST 在常规交易时段内；不在时 SHALL 报不在交易时段的错误，不创建订单，也不调用券商。同一个方案已经有订单时，再次提交 SHALL NOT 新建订单，只跟进一次已有的订单（见「订单状态和券商回报」）并返回它。

本 spec 的场景除非另有说明，都使用下面的基准数据：

- 当前时刻 2026-10-14 15:00Z（周三，盘中；当天收盘 20:00Z），交易日历是纽交所日历
- 基准方案：方案 ID 记为 P1，买入 BBB，板块"医疗"，100 股，限价单，限价 50，止损价 45
- 基准结果：基准方案的再校验结论为通过，最终股数 100，生效的有效期 2026-10-14 20:00Z
- 状态未知的等待时长是默认的 30 秒
- "提交基准方案"指在当前时刻用基准方案和基准结果提交。没有另外说明时，券商正常受理，订单不成交
- "券商回报变为……"指之后按客户端订单 ID 查询时，券商给出的这笔订单的状态、累计成交股数和成交均价

#### Scenario: 买入方案提交限价买单

- **GIVEN** 基准数据
- **WHEN** 提交基准方案
- **THEN** 券商收到一笔订单：客户端订单 ID 是 P1，买入 BBB 100 股，限价单，限价 50，当日有效
- **AND** 订单状态是已提交，截止时刻 2026-10-14 20:00Z，创建时刻 2026-10-14 15:00Z，累计成交 0，记下了券商订单号

#### Scenario: 减仓方案提交市价卖单

- **GIVEN** 基准数据，减仓方案 P2：减仓 AAA 60 股，市价单；再校验通过，最终股数 60，生效的有效期 2026-10-14 20:00Z
- **WHEN** 提交 P2
- **THEN** 券商收到一笔订单：客户端订单 ID 是 P2，卖出 AAA 60 股，市价单，当日有效

#### Scenario: 按再校验的最终股数下单

- **GIVEN** 基准数据，基准方案的再校验结论改为调整，最终股数 60
- **WHEN** 提交基准方案
- **THEN** 委托股数是 60
- **WHEN** 提交清仓方案 P2：清仓 AAA，市价单，不写股数；再校验通过，最终股数 100
- **THEN** 券商收到卖出 AAA 100 股的订单

#### Scenario: 方案的有效期早于当天收盘

- **GIVEN** 基准数据，基准结果的生效有效期改为 2026-10-14 16:00Z
- **WHEN** 提交基准方案
- **THEN** 截止时刻是 2026-10-14 16:00Z

#### Scenario: 方案的有效期晚于当天收盘

- **GIVEN** 基准数据，基准结果的生效有效期改为 2026-10-16 20:00Z
- **WHEN** 提交基准方案
- **THEN** 截止时刻是 2026-10-14 20:00Z

#### Scenario: 提前收盘的交易日

- **GIVEN** 基准数据，当前时刻改为 2026-11-27 15:00Z（感恩节次日，18:00Z 提前收盘），基准结果的生效有效期改为 2026-11-30 21:00Z
- **WHEN** 提交基准方案
- **THEN** 截止时刻是 2026-11-27 18:00Z

#### Scenario: 不在交易时段时提交报错

- **GIVEN** 基准数据，当前时刻改为 2026-10-14 21:00Z（盘后）
- **WHEN** 提交基准方案
- **THEN** 报不在交易时段的错误
- **AND** 没有 P1 的订单，券商没有收到任何调用

#### Scenario: 同一个方案重复提交

- **GIVEN** 基准方案已经提交，订单已提交
- **WHEN** 再次提交基准方案
- **THEN** 券商仍然只有一笔客户端订单 ID 是 P1 的订单
- **AND** 返回的是同一笔订单，状态是已提交

### Requirement: 订单状态和券商回报

订单 SHALL 处于下面 8 种状态之一：

| 状态 | 含义 | 终态 |
| --- | --- | --- |
| 待提交 | 已经建立，还没确认券商收到 | 否 |
| 已提交 | 券商已受理，还没有成交 | 否 |
| 部分成交 | 券商已受理，成交了一部分 | 否 |
| 全部成交 | 委托股数全部成交 | 是 |
| 已撤销 | 截止时刻之前被撤销 | 是 |
| 已过期 | 到截止时刻结束：到期撤单、当日单收盘失效，以及截止时刻之后才确认券商没有收到的订单 | 是 |
| 已拒绝 | 券商拒绝受理，或者受理后拒绝 | 是 |
| 状态未知 | 券商调用超时或断线，或者券商报结果未知 | 否 |

跟进一笔未结束的订单时，执行模块按客户端订单 ID 查询券商，SHALL 按券商回报更新状态、券商订单号、累计成交股数和成交均价：

| 券商回报 | 订单状态 |
| --- | --- |
| 已受理、未结束，累计成交为 0 | 已提交 |
| 已受理、未结束，累计成交大于 0 | 部分成交 |
| 全部成交 | 全部成交 |
| 撤销或失效，当前时刻不早于截止时刻 | 已过期 |
| 撤销或失效，当前时刻早于截止时刻 | 已撤销 |
| 拒绝 | 已拒绝 |
| 结果未知 | 状态未知 |

撤销、失效和拒绝时，已经成交的部分保留在累计成交里。

券商回报只能让订单往前走：

- 回报的累计成交股数少于订单已记录的，这条回报 SHALL 被忽略
- 进入终态的订单 SHALL NOT 再变化；跟进时不再调用券商

#### Scenario: 部分成交后全部成交

- **GIVEN** 基准方案已经提交，订单已提交
- **WHEN** 券商回报变为已受理、累计成交 30、成交均价 49.90，跟进订单
- **THEN** 订单部分成交，累计成交 30，成交均价 49.90
- **WHEN** 券商回报变为全部成交、累计成交 100、成交均价 49.95，跟进订单
- **THEN** 订单全部成交，累计成交 100，成交均价 49.95

#### Scenario: 已撤销和已过期以截止时刻为界

- **GIVEN** 基准方案已经提交，订单部分成交，累计成交 30
- **WHEN** 券商回报变为撤销、累计成交 30（比如在券商 App 里手动撤单），2026-10-14 19:59:59Z 跟进
- **THEN** 订单已撤销，累计成交 30
- **GIVEN** 另一次，同样的订单和券商回报
- **WHEN** 2026-10-14 20:00:00Z 跟进
- **THEN** 订单已过期，累计成交 30

#### Scenario: 当日单收盘失效

- **GIVEN** 基准方案已经提交，订单已提交，截止时刻 2026-10-14 20:00Z
- **WHEN** 券商回报变为失效、累计成交 0，2026-10-14 20:00:05Z 跟进
- **THEN** 订单已过期，累计成交 0，没有请求撤单

#### Scenario: 受理后被拒

- **GIVEN** 基准方案已经提交，订单已提交
- **WHEN** 券商回报变为拒绝，跟进订单
- **THEN** 订单已拒绝，累计成交 0

#### Scenario: 券商报结果未知

- **GIVEN** 基准方案已经提交，订单已提交
- **WHEN** 券商回报变为结果未知，2026-10-14 15:10Z 跟进
- **THEN** 订单状态未知，记下的时刻是 2026-10-14 15:10Z

#### Scenario: 累计成交变少的回报被忽略

- **GIVEN** 基准方案已经提交，订单部分成交，累计成交 50
- **WHEN** 券商回报变为已受理、累计成交 30（过时的回报），跟进订单
- **THEN** 订单仍是部分成交，累计成交 50

#### Scenario: 终态不再变化

- **GIVEN** 基准方案已经提交，订单全部成交
- **WHEN** 跟进订单
- **THEN** 不调用券商，订单仍是全部成交

### Requirement: 先查询再提交

执行模块每次向券商提交订单之前，SHALL 先按客户端订单 ID 查询：

- 查到：采用券商回报（见「订单状态和券商回报」），不再提交
- 查不到，当前时刻早于截止时刻：提交，客户端订单 ID 不变
- 查不到，当前时刻不早于截止时刻：不再提交，订单结束为已过期，累计成交 0

需要提交的订单只有两种：待提交的订单；券商从没受理过（没有券商订单号）的状态未知订单，见「券商调用失败时状态未知」。券商受理过的订单 MUST NOT 重新提交。

券商拒绝受理时，订单结束为已拒绝，没有券商订单号。

#### Scenario: 首次提交时先查询

- **GIVEN** 基准数据
- **WHEN** 提交基准方案
- **THEN** 券商先收到按 P1 的查询，查不到，再收到提交

#### Scenario: 券商拒绝受理

- **GIVEN** 基准数据，券商会拒绝受理这笔订单（比如购买力不足）
- **WHEN** 提交基准方案
- **THEN** 订单已拒绝，累计成交 0，没有券商订单号

#### Scenario: 提交之后、保存结果之前进程退出

- **GIVEN** 存储里有基准方案的待提交订单，券商已经受理了客户端订单 ID 是 P1 的订单（进程在提交后、保存结果前退出）
- **WHEN** 进程重启后，2026-10-14 15:05Z 跟进这笔订单
- **THEN** 不再提交，券商仍然只有一笔 P1 的订单
- **AND** 订单已提交，记下了券商订单号

#### Scenario: 提交之前进程退出

- **GIVEN** 存储里有基准方案的待提交订单，券商没有 P1 的订单
- **WHEN** 进程重启后，2026-10-14 15:05Z 跟进这笔订单
- **THEN** 券商收到 P1 的提交，订单已提交

#### Scenario: 停机到截止时刻之后

- **GIVEN** 存储里有基准方案的待提交订单，截止时刻 2026-10-14 20:00Z，券商没有 P1 的订单
- **WHEN** 进程在 2026-10-15 13:00Z 重启后跟进这笔订单
- **THEN** 不提交，订单已过期，累计成交 0

### Requirement: 到期撤单

跟进已提交或部分成交的订单时，如果按券商回报更新状态之后订单仍未结束，并且当前时刻不早于截止时刻，执行模块 SHALL 向券商请求撤单。每笔订单只请求一次，请求失败的除外（见「券商调用失败时状态未知」）。

请求之后订单状态不变，直到券商回报撤销或失效；那时按「订单状态和券商回报」记为已过期。在此之前的成交照常计入累计成交。

#### Scenario: 截止时刻之前不撤单，到达截止时刻撤单

- **GIVEN** 基准数据，基准结果的生效有效期改为 2026-10-14 16:00Z，基准方案已经提交，订单已提交
- **WHEN** 2026-10-14 15:59:59Z 跟进订单
- **THEN** 不请求撤单
- **WHEN** 2026-10-14 16:00:00Z 跟进订单
- **THEN** 券商收到撤单请求，订单仍是已提交
- **WHEN** 券商回报变为撤销、累计成交 0，2026-10-14 16:00:10Z 跟进订单
- **THEN** 订单已过期，累计成交 0

#### Scenario: 部分成交后到期

- **GIVEN** 截止时刻 2026-10-14 16:00Z，订单部分成交，累计成交 30
- **WHEN** 2026-10-14 16:00Z 跟进订单
- **THEN** 券商收到撤单请求
- **WHEN** 券商回报变为撤销、累计成交 30，再跟进订单
- **THEN** 订单已过期，累计成交 30

#### Scenario: 请求撤单之后又有成交

- **GIVEN** 截止时刻 2026-10-14 16:00Z，16:00Z 已经请求撤单，订单部分成交，累计成交 30
- **WHEN** 券商回报变为已受理、累计成交 50，2026-10-14 16:00:05Z 跟进订单
- **THEN** 订单部分成交，累计成交 50，券商没有收到第二次撤单请求
- **WHEN** 券商回报变为撤销、累计成交 50，再跟进订单
- **THEN** 订单已过期，累计成交 50

#### Scenario: 到截止时刻已经全部成交

- **GIVEN** 截止时刻 2026-10-14 16:00Z，订单已提交
- **WHEN** 券商回报变为全部成交、累计成交 100，2026-10-14 16:00Z 跟进订单
- **THEN** 订单全部成交，不请求撤单

### Requirement: 券商调用失败时状态未知

查询、提交、撤单中任何一次券商调用超时或断线，订单 SHALL 变为状态未知，记下这个时刻；已经记录的券商订单号和累计成交保留。跟进时券商查不到一笔受理过（有券商订单号）的订单，订单 SHALL 同样变为状态未知。

状态未知的订单，从记下的时刻起满等待时长（见「执行配置」）之前，跟进时 SHALL NOT 调用券商。满等待时长之后跟进，按客户端订单 ID 查询：

- 查到：采用券商回报；之后仍未结束、并且到了截止时刻的，按「到期撤单」请求撤单
- 查不到，券商从没受理过：按「先查询再提交」的规则提交或结束为已过期
- 查不到，券商受理过：仍是状态未知，重新计时，等对账处理，MUST NOT 重新提交
- 查询又失败：仍是状态未知，从这次失败的时刻重新计时

#### Scenario: 提交超时，券商其实收到了

- **GIVEN** 基准数据，券商会受理这笔订单，但提交的响应超时
- **WHEN** 提交基准方案
- **THEN** 订单状态未知，记下的时刻是 2026-10-14 15:00Z
- **WHEN** 2026-10-14 15:00:29Z 跟进订单
- **THEN** 不调用券商，订单仍是状态未知
- **WHEN** 2026-10-14 15:00:30Z 跟进订单
- **THEN** 查到这笔订单，订单已提交，券商只有一笔 P1 的订单

#### Scenario: 提交超时，券商没有收到

- **GIVEN** 基准数据，提交超时，券商没有收到这笔订单
- **WHEN** 提交基准方案
- **THEN** 订单状态未知
- **WHEN** 2026-10-14 15:00:30Z 跟进订单
- **THEN** 券商收到客户端订单 ID 仍是 P1 的提交，订单已提交，券商只有一笔 P1 的订单

#### Scenario: 查询又失败时重新计时

- **GIVEN** 基准数据，提交超时，券商其实收到了，订单状态未知，记下 2026-10-14 15:00Z
- **WHEN** 2026-10-14 15:00:30Z 跟进订单，查询超时
- **THEN** 订单仍是状态未知，记下的时刻是 2026-10-14 15:00:30Z
- **WHEN** 2026-10-14 15:00:59Z 跟进订单
- **THEN** 不调用券商
- **WHEN** 2026-10-14 15:01:00Z 跟进订单，券商恢复正常
- **THEN** 查到这笔订单，订单已提交

#### Scenario: 截止时刻之后才确认券商没有收到

- **GIVEN** 基准数据，基准结果的生效有效期改为 2026-10-14 16:00Z，2026-10-14 15:59:50Z 提交基准方案，提交超时，券商没有收到
- **WHEN** 2026-10-14 16:00:20Z 跟进订单
- **THEN** 券商没有收到提交，订单已过期，累计成交 0

#### Scenario: 跟进时断线

- **GIVEN** 基准方案已经提交，订单部分成交，累计成交 30
- **WHEN** 2026-10-14 15:10Z 跟进订单，查询时断线
- **THEN** 订单状态未知，累计成交 30，券商订单号不变
- **WHEN** 券商恢复，回报变为已受理、累计成交 60，2026-10-14 15:10:30Z 跟进订单
- **THEN** 订单部分成交，累计成交 60

#### Scenario: 撤单请求失败

- **GIVEN** 截止时刻 2026-10-14 16:00Z，订单已提交
- **WHEN** 2026-10-14 16:00Z 跟进订单，撤单请求超时，券商没有收到
- **THEN** 订单状态未知，记下的时刻是 2026-10-14 16:00Z
- **WHEN** 2026-10-14 16:00:30Z 跟进订单，券商回报仍是已受理、累计成交 0
- **THEN** 订单已提交，券商再次收到撤单请求

#### Scenario: 券商受理过的订单查不到

- **GIVEN** 基准方案已经提交，订单已提交，记下了券商订单号
- **WHEN** 2026-10-14 15:10Z 跟进订单，券商查不到 P1
- **THEN** 订单状态未知，记下的时刻是 2026-10-14 15:10Z
- **WHEN** 2026-10-14 15:10:30Z 跟进订单，仍然查不到
- **THEN** 订单仍是状态未知，券商没有收到提交

### Requirement: 状态未知时暂停这只股票的新订单

一只股票有其他方案的订单处于待提交或状态未知时，执行模块 SHALL 拒绝为这只股票提交新订单（买入和卖出都算），报暂停的错误，不创建订单，也不调用券商。这些订单都离开这两种状态后，恢复提交。已经有订单的方案再次提交，不受暂停影响。

#### Scenario: 状态未知时暂停同一股票的卖单

- **GIVEN** 基准数据，加仓 AAA 的方案 P2 已经提交，提交超时，订单状态未知
- **WHEN** 提交减仓 AAA 的方案 P3
- **THEN** 报暂停的错误
- **AND** 没有 P3 的订单，券商没有收到和 P3 有关的调用

#### Scenario: 其他股票不受影响

- **GIVEN** 基准数据，加仓 AAA 的方案 P2 订单状态未知
- **WHEN** 提交基准方案
- **THEN** 正常提交，订单已提交

#### Scenario: 查清之后恢复

- **GIVEN** 基准数据，加仓 AAA 的方案 P2 提交超时，券商其实收到了，订单状态未知
- **WHEN** 2026-10-14 15:00:30Z 跟进 P2，查到已受理
- **THEN** P2 的订单已提交
- **WHEN** 提交减仓 AAA 的方案 P3
- **THEN** 正常提交，P3 的订单已提交

#### Scenario: 待提交的订单也暂停

- **GIVEN** 存储里有加仓 AAA 的方案 P2 的待提交订单（进程在提交前退出）
- **WHEN** 提交减仓 AAA 的方案 P3
- **THEN** 报暂停的错误，没有 P3 的订单

#### Scenario: 同一个方案再次提交不受影响

- **GIVEN** 基准数据，基准方案提交超时，订单状态未知，记下 2026-10-14 15:00Z
- **WHEN** 2026-10-14 15:00:10Z 再次提交基准方案
- **THEN** 不报错，返回 P1 的订单，仍是状态未知，不调用券商

### Requirement: 保存订单

执行模块 SHALL 把每笔订单的最新状态保存在存储中，每次变化都保存。订单记录包括：

- 方案 ID（即客户端订单 ID）、股票、买卖方向、订单类型、限价、委托股数
- 截止时刻、创建时刻
- 状态、券商订单号、累计成交股数、成交均价
- 跟进需要的状态：变为状态未知的时刻、是否已经请求撤单

进程重启后，执行模块 SHALL 从存储读出订单，继续跟进。

#### Scenario: 重启后继续跟进

- **GIVEN** 基准方案已经提交，订单已提交
- **WHEN** 进程重启（用同一个存储重新创建执行模块），券商回报变为全部成交、累计成交 100、成交均价 50，跟进订单
- **THEN** 订单全部成交，累计成交 100，成交均价 50

#### Scenario: 重启后不重复撤单

- **GIVEN** 截止时刻 2026-10-14 16:00Z，16:00Z 已经请求撤单，订单已提交
- **WHEN** 进程重启，券商回报仍是已受理，2026-10-14 16:00:05Z 跟进订单
- **THEN** 券商没有收到第二次撤单请求，订单仍是已提交

### Requirement: 执行配置

执行模块的阈值 SHALL 可以配置：

| 配置项 | 含义 | 默认值 |
| --- | --- | --- |
| 状态未知的等待时长 | 订单变为状态未知之后，等多久才再查询券商 | 30 秒 |

等待时长 MUST 大于 0，否则配置报错。

#### Scenario: 默认配置

- **WHEN** 不指定任何配置项
- **THEN** 状态未知的等待时长是 30 秒

#### Scenario: 修改等待时长

- **GIVEN** 基准数据，状态未知的等待时长改为 60 秒，提交超时，券商其实收到了，订单状态未知，记下 2026-10-14 15:00Z
- **WHEN** 2026-10-14 15:00:59Z 跟进订单
- **THEN** 不调用券商
- **WHEN** 2026-10-14 15:01:00Z 跟进订单
- **THEN** 查到这笔订单，订单已提交

#### Scenario: 等待时长不大于 0

- **WHEN** 状态未知的等待时长配置为 0 秒
- **THEN** 配置报错
