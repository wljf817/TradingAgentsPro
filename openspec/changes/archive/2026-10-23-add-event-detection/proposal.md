# Proposal

## Why

「排队运行」装好以后，案件只能由别人排进来，可现在没有任何触发源：股票池里的股票涨跌、出新闻、交公告、发财报，系统都看不见；止损单成交了，也没有人排卖出复盘。新闻和公告模块、公司数据模块也只有"取"的用例，没有谁去取，快照里的新闻和公告一直是空的。

本变更的目的只有一个：**按代码规则从行情、新闻、公告、财报日历里检测股票池里的股票的事件，达到阈值的记下来、排进案件；并给每笔有成交的卖出排一个卖出复盘。**

引用的 Proposal（完整版）章节：

- 「架构 · 触发」：事件检测层只监控股票池和持仓；阈值和规则可配置；给每个事件标注类型、强度和来源；未达阈值的事件只写日志，不进入队列
- 「触发 · 1. 事件驱动」：监控范围；价格和成交量异动（候选股阈值更高）、新闻和公告按来源、关键词和强度初筛、财报发布按财报日历、止损单成交开复盘案件；持仓风险事件与紧急风险事件的分界
- 「触发 · 通用规则」的排队优先级：持仓风险事件最高
- 「故障处理」的紧急风险事件例外：触及紧急阈值不开案件，由紧急风险退出处理
- 「风控引擎与执行 · 交易时段」：盘前盘后照常监控事件、开案件（比如盘后财报）
- 「共享上下文」：案件上下文里的"触发原因和事件内容"，Shared State 里的"已发生的事件"
- 「共享状态库」：事件属于当前市场事实，写入者是事件检测层
- 「记录、复盘与经验」：程序日志表的「事件检测层」一行；复盘一节（每笔卖出成交后复盘一次，包括减仓；止损单成交由事件驱动，主动退出成交后自动开始）
- 「技术栈与部署」的数据源一行：moomoo 行情、SEC EDGAR、Alpaca 新闻、Finnhub 财报日历

已经定了的（不在本变更里讨论）：2026-10-16 人同意的事件规则：价格只在常规时段按当日涨跌幅判断，持仓跌到紧急阈值的一半算持仓风险事件，持仓涨 5%、关注涨跌 5%、候选涨跌 8% 算普通事件；量比不低于 3、开盘 30 分钟以后才判断；新闻只看标注不超过 2 只股票的、标题命中重大事件关键词的，维持评级和调目标价不算，持仓命中负面关键词算持仓风险事件；公告算 8-K、10-Q、10-K、增发和 13D，8-K 的 item 2.02 算财报发布，表单 4 不算；价格和成交量每类每只股票每天最多一个，新闻和公告合起来每只股票每天最多一个；不开案件的新闻和公告照样存下，PM 在下一个案件里看得到。`/plan` 买入的持仓不进股票池（update-order-flow-case-plans），所以事件检测不看它们。

## What Changes

- 事件（新的 event-rules）：
  - 事件的内容：事件 ID、股票、类别、是否持仓风险级别、来源、强度、发生时刻、检测时刻、说明、引用、处理（排队，或交给紧急风险退出）
  - 价格异动：按股票状态的阈值判断当日涨跌幅；持仓的参考价和紧急退出相同（今天有开仓成交时用成交均价）；跌幅达到紧急阈值的一半是持仓风险事件，达到紧急阈值的记下事件、不排队
  - 成交量异动：行情源给出的量比；候选的阈值更高
  - 行情要是当天的：开盘前 moomoo 快照还是上一个交易日的数据，价格和成交量只用开盘以后更新过的行情判断
  - 新闻的初筛：来源、标注的股票数、排除词、关键词表（级别一般或重大、是否负面）；候选只认重大的
  - 公告的初筛：按表单和 8-K 的 item 分级；增发和破产、退市、财务重述这几类 8-K 是负面的
  - 财报发布：8-K 的 item 2.02，或者财报日历上一次发布的预计发布时刻过了，先到的算；同一只股票 5 个交易日内最多一个
  - 去重：事件 ID 就是去重的键，比如 `CCC:2026-10-14:price_down`
- 事件检测的运行（新的 event-detection）：
  - 自己的线程，每 60 秒一轮：卖出成交、价格和成交量（只在常规交易时段）、公告（每 5 分钟取一次）、财报日历、新闻；盘前盘后和休市日照常检测新闻、公告和财报
  - 取新闻和公告：每轮取最近 24 小时的，新存下的才判断，加入股票池以前发布的不算
  - 达到阈值的记下事件、写程序日志、排进案件；没达到的新闻和公告只写程序日志
  - 卖出成交：交易记录里已经结束、有成交的卖单和止损单，每笔排一个卖出复盘，按排队表去重
  - 数据源读不到时这一部分跳过，下一轮再来；重启以后按事件 ID 和排队表去重
  - 事件存在状态库的事件表里（迁移 v0014）
- 案件类型与结论（case-types）：事件的触发带事件 ID，卖出成交的触发带卖出的客户端订单 ID
- 排队运行（queue-runner）：给出排过卖出复盘的客户端订单 ID
- 状态库快照（state-snapshot）：针对单只股票的案件另带这只股票近 5 个交易日的事件
- 案件工作流、替身（case-workflow、agent-calls）：案件上下文的"事件类别"换成整个事件
- 交易记录（trade-records）：给出已经结束、有成交的卖出
- 量比：行情的量比由 add-moomoo-quotes 加上（它新加的任务 6.1），本变更 apply 时先做那个任务
- 程序日志（program-log）：新的行为者事件检测层，动作是检测到事件、丢弃事件
- 启动与装配（bootstrap）：装配事件检测，排队运行之后、盘中巡检之前开始，停止时在巡检之后关闭
- 完整版 Proposal：改三句话，见「需要人决定」第 8 条

## Non-goals

- 关注股入场条件、持仓目标价和证伪条件、moomoo 到价提醒、OpenD 断线以后补查：「论点条件与到价提醒」
- 收盘心跳（复查日、催化剂、新候选、寻股、每周复盘）和每天收盘刷新财报日历：「收盘心跳」。在那以前财报日历没人刷新，财报发布只能靠 8-K 的 item 2.02
- 跟进到点：「跟进到点」
- 订阅 moomoo 的实时推送：本变更用快照轮询（design D5）
- 卖出复盘的内容（收益、相对基准的表现、Reviewer 怎么写）：M6。本变更只排进案件
- 用模型判断新闻：架构铁律，触发全是代码
- 事件阈值的回测和调参：M6 评估以后再改配置
- 省略的少见情况：见 design 的省略清单

## Capabilities

### New Capabilities

- `event-rules`：事件的内容、价格异动、成交量异动、行情要是当天的、新闻的初筛、新闻关键词、公告的初筛、财报发布、去重和事件 ID、事件规则的配置
- `event-detection`：监控范围、一轮、取新闻和公告、记下和排队、不排队的新闻和公告、卖出成交、什么时候做一轮、读不到时、重启以后、事件的存储、读取事件、事件检测的配置

### Modified Capabilities

- `case-types`：修改「触发」（事件带事件 ID，卖出成交带客户端订单 ID，`/plan` 的卖出也算）
- `queue-runner`：新增「排过的卖出成交」
- `state-snapshot`：修改「条目和条目 ID」「案件股票的事实」（加事件）
- `case-workflow`：修改「案件上下文」（事件类别换成事件）
- `agent-calls`：修改「每个 agent 的输入和输出」（案件上下文的事件）
- `trade-records`：新增「已经结束的卖出」
- `program-log`：修改「程序日志的条目」（加行为者）；新增「事件检测层的动作」
- `state-store`：修改「表的归属和迁移」（加事件表）
- `bootstrap`：修改「启动顺序」「模拟盘的装配」「停止」

## 需要人决定

下面 8 条 2026-10-23 用户同意（「按推荐」），已经写进 spec 和 design。

1. **卖出复盘覆盖全部卖出，从交易记录发现**：已经结束、有成交的卖单和止损单，每条交易记录排一个卖出复盘。止损单、紧急退出（包括本地备用止损）、PM 的减仓和清仓、`/plan` 的卖出都算，不论在不在股票池里；部分成交以后过期的在结束时复盘一次。理由：交易记录是所有卖出唯一共同的地方，重启以后也查得到
2. **候选的新闻和公告只认重大级别，候选的量比阈值 5**：一般级别（评级调整、回购分红、10-Q、10-K 和普通 8-K）只对关注和持仓开案件；持仓和关注的量比阈值 3。理由：候选数量最多、优先级最低，候选评估本来就会看它
3. **新闻关键词和排除词用 event-rules spec「新闻关键词」的默认表**：关键词分一般和重大两级，负面的另外标出；排除词在 10-16 的基础上加 reaffirms。理由：先照表用，以后按 M6 的评估改配置
4. **公告按 event-rules spec「公告的初筛」分级**：增发只算 S-1、S-3、424B4、424B5、424B7，不算 424B2；增发和 8-K 的破产（1.03）、减值（2.06）、退市通知（3.01）、财务报表不可依赖（4.02）对持仓算持仓风险事件。理由：424B2 是银行几乎每天都交的结构性票据，算进来持有银行股会天天开案件
5. **财报发布两路都用，先到的算**：8-K 的 item 2.02 一到就算；财报日历上一次发布的预计发布时刻（盘前是发布日开盘，盘中是发布日收盘，盘后和没写的是发布日收盘后 1 小时）过了还没有财报发布事件，也算。同一只股票 5 个交易日内最多一个；财报发布事件以后当天的新闻和公告不再开案件，当天更早的新闻事件不挡财报发布。理由：ADR 交 6-K、没有 8-K，要靠财报日历
6. **持仓风险的新闻和公告单独计数**：每只股票每天最多一个持仓风险级别的新闻或公告事件，不被当天更早的普通新闻事件挡住。理由：上午一条普通新闻开过案件，下午出了诉讼，持仓风险事件不能因此不开
7. **价格和成交量没成为事件时不写程序日志**：只有新闻和公告没成为事件时每条写一条丢弃事件（每条只判断一次）。理由：价格每分钟读一次，每只股票每轮都写会把日志淹掉
8. **完整版 Proposal 改了三句话**（2026-10-23 已改）：
   - 「触发 · 1. 事件驱动」的事件来源"财报发布：按财报日历"改为"财报发布：按财报日历；公司交的财报公告（8-K 的 item 2.02）先到时以它为准"
   - 同一节"未达阈值的事件只写入程序日志，不开案件"改为"未达阈值的新闻和公告只写入程序日志，不开案件；同一只股票的同一类事件每个交易日最多开一个案件，财报发布 5 个交易日最多一个"
   - 「风控引擎与执行 · 交易时段」"盘前盘后照常监控事件、开案件（比如盘后财报）"改为"价格和成交量异动只在常规交易时段判断；盘前盘后照常监控新闻、公告和财报、开案件（比如盘后财报）"（价格那句放在前面，"这类方案"仍紧跟盘前盘后形成的方案）
