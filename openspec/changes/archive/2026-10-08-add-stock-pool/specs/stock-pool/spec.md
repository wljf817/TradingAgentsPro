# Spec Delta

## Purpose

股票池是系统关注范围的唯一来源：保存每只股票的状态（候选、关注、持仓）和记录，由代码强制执行加入和删除的校验、冷却期、容量和关注名额、每天增删次数、升降级、候选超期移出和成交后的状态变化。

## ADDED Requirements

### Requirement: 股票池的记录

股票池 SHALL 为池子里的每只股票保存一条记录：

| 字段 | 说明 |
| --- | --- |
| 状态 | 候选、关注、持仓 |
| 来源 | PM 探索或手动添加 |
| 理由与论点草稿 | 加入时填写 |
| 板块 | 加入时由调用方从数据源传入；交易方案和持仓的板块都取这里 |
| 关注论点 | 只有关注有，格式见「关注论点的格式」 |
| 最新评分 | PM 最近一次对这只股票给出结论时的评分；还没有时为空 |
| 加入时刻 | 加入股票池的时刻 |
| 上次复查时间 | PM 最近一次对这只股票给出结论的时刻；还没有时为空 |
| 过期时间 | 只有候选有，见「候选的过期时间」 |

股票池 SHALL 给出池子里的全部股票，以及按股票代码给出一只股票的记录。移出以后这只股票不在池子里；股票池仍然记下它移出的时刻和原因（删除、超期、清仓后移出），用来判断冷却期，重新加入时换成新的记录。

记录评分：PM 每次对池子里的一只股票给出结论后，调用方 SHALL 把结论里的评分记到这只股票上，最新评分改为它，上次复查时间改为当前时刻。评分 MUST 是 -2 到 +2 的整数，否则报错。不在池子里的股票不能记录评分，原因是"不在池子里"。

本 spec 的场景除非另有说明，都使用默认配置和下面的基准数据：

- 当前时刻 2026-10-14 15:00Z（周三，盘中），交易日历是纽交所日历
- 股票池里有三只股票，2026-10-14 这个交易日还没有增删：
  - AAA：候选，2026-10-13 15:00Z 由 PM 探索加入，板块"科技"，过期时间 2026-10-27 20:00Z，没有评分
  - BBB：关注，板块"医疗"，关注论点是基准关注论点
  - CCC：持仓，板块"能源"
- 基准上市信息：纽交所上市的普通股，日均成交额 5,000 万美元，板块"科技"
- 基准关注论点：
  - 看好理由"新品周期带动收入加速"
  - 入场条件一条：价格不高于 50
  - 催化剂"Q3 财报"，截止日期 2026-10-29，不引用日程项或事件
  - 证伪条件"毛利率连续两个季度下滑"
  - 复查日 2026-10-21
- "加入 DDD"指来源是 PM 探索、理由"放量突破，论点草稿：订单回暖"、上市信息是基准上市信息；"删除"的理由都是"论点不再成立"

#### Scenario: 记录评分

- **GIVEN** 基准数据
- **WHEN** 记录 AAA 的评分 1
- **THEN** AAA 的最新评分是 1，上次复查时间 2026-10-14 15:00Z
- **WHEN** 当前时刻 2026-10-14 16:00Z，记录 AAA 的评分 -1，记录 CCC 的评分 2
- **THEN** AAA 的最新评分是 -1，上次复查时间 2026-10-14 16:00Z；CCC 的最新评分是 2

#### Scenario: 评分超出范围

- **GIVEN** 基准数据
- **WHEN** 记录 AAA 的评分 3 或 -3
- **THEN** 报错，AAA 仍然没有评分

#### Scenario: 不在池子里的股票不能记录评分

- **GIVEN** 基准数据
- **WHEN** 记录 ZZZ 的评分 1
- **THEN** 被拒绝，原因是"不在池子里"

#### Scenario: 移出后不在池子里

- **GIVEN** 基准数据
- **WHEN** 删除 AAA
- **THEN** 池子里的股票是 BBB 和 CCC，AAA 不在池子里

### Requirement: 状态变化

股票池 SHALL 只按下表改变股票的状态。表里没有的组合：PM 发起的升级、降为候选、保持 SHALL 被拒绝，不改变记录，股票不在池子里时原因是"不在池子里"，否则是"状态不允许"；代码发起的操作（买入成交、清仓）SHALL 报错。

| 当前状态 | 操作 | 之后 |
| --- | --- | --- |
| 不在池子里 | 加入（PM 探索或手动添加） | 候选，设过期时间 |
| 候选 | 升级 | 关注，关注论点是 PM 写的，没有过期时间 |
| 候选 | 保持 | 候选，重设过期时间 |
| 候选 | 删除 | 移出，原因是删除 |
| 候选 | 过期时间已到，代码移出 | 移出，原因是超期 |
| 候选 | 买入成交 | 持仓，没有过期时间 |
| 关注 | 降为候选 | 候选，去掉关注论点，设过期时间 |
| 关注 | 删除 | 移出，原因是删除 |
| 关注 | 买入成交 | 持仓，去掉关注论点 |
| 持仓 | 买入成交（加仓） | 持仓，不变 |
| 持仓 | 删除 | 拒绝，原因是"持仓不能删除"（见「删除」） |
| 持仓 | 代码触发的清仓（止损单、紧急风险退出） | 候选，设过期时间 |
| 持仓 | PM 发起的清仓，PM 选择转为关注 | 关注，关注论点是 PM 写的 |
| 持仓 | PM 发起的清仓，PM 选择移出 | 移出，原因是清仓后移出 |

- 买入成交指这只股票的买单有成交，部分成交也算；清仓指持仓的股数变为 0，减仓不改变状态。调用方在成交时调用
- 候选买入成交：关注股的买单挂着时被降为候选，随后成交
- 加入、删除的校验见「加入候选」「删除」；升级的关注名额见「池子容量和关注名额」；过期时间见「候选的过期时间」

#### Scenario: 加入成为候选

- **GIVEN** 基准数据
- **WHEN** 加入 DDD
- **THEN** DDD 在池子里：候选，来源 PM 探索，理由"放量突破，论点草稿：订单回暖"，板块"科技"，加入时刻 2026-10-14 15:00Z，过期时间 2026-10-28 20:00Z
- **AND** DDD 没有关注论点、最新评分和上次复查时间

#### Scenario: 候选升级为关注

- **GIVEN** 基准数据
- **WHEN** 以基准关注论点升级 AAA
- **THEN** AAA 是关注，关注论点是基准关注论点，没有过期时间

#### Scenario: 候选保持

- **GIVEN** 基准数据
- **WHEN** 保持 AAA
- **THEN** AAA 仍是候选，过期时间改为 2026-10-28 20:00Z

#### Scenario: 删除候选或关注

- **GIVEN** 基准数据
- **WHEN** 删除 AAA，再删除 BBB
- **THEN** 两只都被移出，原因是删除，移出时刻 2026-10-14 15:00Z
- **AND** 池子里只剩 CCC

#### Scenario: 候选超期由代码移出

- **GIVEN** 基准数据
- **WHEN** 当前时刻 2026-10-27 20:00Z，代码移出到期的候选
- **THEN** AAA 被移出，原因是超期

#### Scenario: 关注降为候选

- **GIVEN** 基准数据
- **WHEN** BBB 降为候选
- **THEN** BBB 是候选，没有关注论点，过期时间 2026-10-28 20:00Z

#### Scenario: 关注股买入成交变为持仓

- **GIVEN** 基准数据
- **WHEN** BBB 买入成交
- **THEN** BBB 是持仓，没有关注论点，也没有过期时间

#### Scenario: 候选买入成交也变为持仓

- **GIVEN** 基准数据
- **WHEN** AAA 买入成交
- **THEN** AAA 是持仓，没有过期时间

#### Scenario: 加仓成交不改变持仓

- **GIVEN** 基准数据
- **WHEN** CCC 买入成交
- **THEN** CCC 的记录不变

#### Scenario: 代码触发的清仓转为候选

- **GIVEN** 基准数据
- **WHEN** CCC 的止损单成交，持仓变为 0，代码触发的清仓
- **THEN** CCC 是候选，过期时间 2026-10-28 20:00Z，板块、来源、理由和最新评分都不变

#### Scenario: PM 清仓后转为关注

- **GIVEN** 基准数据
- **WHEN** CCC 由 PM 发起的清仓完成，PM 选择转为关注，关注论点是基准关注论点
- **THEN** CCC 是关注，关注论点是基准关注论点

#### Scenario: PM 清仓后移出

- **GIVEN** 基准数据
- **WHEN** CCC 由 PM 发起的清仓完成，PM 选择移出
- **THEN** CCC 被移出，原因是清仓后移出，不在池子里

#### Scenario: 状态不允许的操作

- **GIVEN** 基准数据
- **WHEN** 以基准关注论点升级 BBB 或 CCC；AAA 或 CCC 降为候选；保持 BBB 或 CCC
- **THEN** 都被拒绝，原因是"状态不允许"，三只股票的记录都不变

#### Scenario: 对不在池子里的股票升降级或保持

- **GIVEN** 基准数据，删除 AAA
- **WHEN** 以基准关注论点升级 AAA 或 ZZZ；ZZZ 降为候选；保持 AAA
- **THEN** 都被拒绝，原因是"不在池子里"

#### Scenario: 代码发起的操作遇到不对的状态

- **GIVEN** 基准数据
- **WHEN** ZZZ 买入成交；AAA 或 BBB 代码触发的清仓；BBB 由 PM 发起的清仓完成
- **THEN** 都报错，记录都不变

### Requirement: 加入候选

股票池 SHALL 按下表的顺序检查加入请求，给出第一项不通过的原因；全部通过才加入，成为候选。

| 顺序 | 检查 | 不通过时的原因 |
| --- | --- | --- |
| 1 | 理由去掉首尾空白后不为空 | 缺少理由 |
| 2 | 这只股票不在池子里 | 已在池子里 |
| 3 | 不在重新加入的冷却期内（见「重新加入的冷却期」） | 冷却期内 |
| 4 | 股票代码存在：调用方查到了上市信息 | 股票代码不存在 |
| 5 | 交易所在允许的交易所里，并且证券类型在允许的证券类型里 | 不在允许交易的范围内 |
| 6 | 日均成交额不低于流动性门槛 | 流动性不达标 |
| 7 | 池子没满（见「池子容量和关注名额」） | 池子已满 |
| 8 | 今天的增删次数没用完（见「每天的增删次数」） | 增删次数已用完 |

上市信息由调用方从数据源查好传入，查不到时传空，包括：

- 交易所：纽交所、纳斯达克、其他（包括 OTC）
- 证券类型：普通股、ADR、ETF、杠杆产品（杠杆和反向产品，包括杠杆 ETF）、其他
- 日均成交额：美元
- 板块：写进记录

PM 探索和手动添加走同样的检查。被拒绝时不改变任何记录。

#### Scenario: 缺少理由

- **GIVEN** 基准数据
- **WHEN** 以理由 "" 或 "   " 加入 DDD
- **THEN** 都被拒绝，原因是"缺少理由"，DDD 不在池子里

#### Scenario: 已在池子里

- **GIVEN** 基准数据
- **WHEN** 加入 AAA、BBB 或 CCC
- **THEN** 都被拒绝，原因是"已在池子里"，记录都不变

#### Scenario: 股票代码不存在

- **GIVEN** 基准数据，调用方查不到 DDD 的上市信息
- **WHEN** 加入 DDD
- **THEN** 被拒绝，原因是"股票代码不存在"

#### Scenario: 允许交易的范围

- **GIVEN** 基准数据
- **WHEN** 加入 DDD，上市信息分别改为：纽交所的 ETF；纳斯达克的杠杆产品；其他交易所的普通股
- **THEN** 都被拒绝，原因是"不在允许交易的范围内"
- **WHEN** 加入 DDD，上市信息改为纳斯达克的 ADR
- **THEN** DDD 成为候选

#### Scenario: 流动性门槛的边界

- **GIVEN** 基准数据
- **WHEN** 加入 DDD，日均成交额 9,999,999.99 美元
- **THEN** 被拒绝，原因是"流动性不达标"
- **WHEN** 加入 DDD，日均成交额 10,000,000 美元
- **THEN** DDD 成为候选

#### Scenario: 多项不通过时给出第一项

- **GIVEN** 基准数据
- **WHEN** 加入 DDD，上市信息是纽交所的 ETF，日均成交额 100 万美元
- **THEN** 被拒绝，原因是"不在允许交易的范围内"

#### Scenario: 手动添加

- **GIVEN** 基准数据
- **WHEN** 来源改为手动添加，上市信息是纽交所的 ETF，加入 DDD
- **THEN** 被拒绝，原因是"不在允许交易的范围内"
- **WHEN** 来源改为手动添加，以基准上市信息加入 DDD
- **THEN** DDD 成为候选，来源是手动添加

### Requirement: 删除

PM SHALL 只能删除池子里的候选和关注。股票池按下表的顺序检查删除请求，给出第一项不通过的原因；全部通过才移出，原因是删除，记下理由和移出时刻，进入冷却期。

| 顺序 | 检查 | 不通过时的原因 |
| --- | --- | --- |
| 1 | 理由去掉首尾空白后不为空 | 缺少理由 |
| 2 | 这只股票在池子里 | 不在池子里 |
| 3 | 不是持仓 | 持仓不能删除 |
| 4 | 今天的增删次数没用完（见「每天的增删次数」） | 增删次数已用完 |

#### Scenario: 删除要写理由

- **GIVEN** 基准数据
- **WHEN** 以理由 " " 删除 AAA
- **THEN** 被拒绝，原因是"缺少理由"，AAA 仍是候选

#### Scenario: 删除不在池子里的股票

- **GIVEN** 基准数据
- **WHEN** 删除 ZZZ
- **THEN** 被拒绝，原因是"不在池子里"
- **WHEN** 删除 AAA，再删除一次 AAA
- **THEN** 第二次被拒绝，原因是"不在池子里"

#### Scenario: 持仓不能删除

- **GIVEN** 基准数据
- **WHEN** 删除 CCC
- **THEN** 被拒绝，原因是"持仓不能删除"，CCC 仍是持仓

### Requirement: 重新加入的冷却期

股票移出以后（删除、超期、清仓后移出都算），SHALL 在冷却期内不能重新加入，原因是"冷却期内"。冷却期按交易日计：移出时刻归属的交易日之后，满冷却期（默认 5 个交易日）那个交易日起才能重新加入。归属的交易日见 trading-calendar spec「时刻归属的交易日」：收盘时刻或之后、休市日移出，从下一个交易日算起。

#### Scenario: 冷却期的边界

- **GIVEN** 基准数据，删除 AAA（2026-10-14 这个交易日）
- **WHEN** 当前时刻 2026-10-20 19:59Z（归属 2026-10-20，过了 4 个交易日），加入 AAA
- **THEN** 被拒绝，原因是"冷却期内"
- **WHEN** 当前时刻 2026-10-20 20:00Z（归属 2026-10-21，过了 5 个交易日），加入 AAA
- **THEN** AAA 成为候选，加入时刻 2026-10-20 20:00Z，没有评分

#### Scenario: 收盘后移出从下一个交易日算起

- **GIVEN** 基准数据，当前时刻 2026-10-14 20:00Z，删除 AAA（归属 2026-10-15）
- **WHEN** 当前时刻 2026-10-21 19:59Z，加入 AAA
- **THEN** 被拒绝，原因是"冷却期内"
- **WHEN** 当前时刻 2026-10-21 20:00Z，加入 AAA
- **THEN** AAA 成为候选

#### Scenario: 超期移出也进入冷却期

- **GIVEN** 基准数据，当前时刻 2026-10-27 20:00Z，代码移出到期的候选，AAA 被移出
- **WHEN** 当前时刻 2026-10-28 15:00Z，加入 AAA
- **THEN** 被拒绝，原因是"冷却期内"

#### Scenario: 清仓后移出也进入冷却期

- **GIVEN** 基准数据，CCC 由 PM 发起的清仓完成，PM 选择移出
- **WHEN** 当前时刻 2026-10-15 15:00Z，加入 CCC
- **THEN** 被拒绝，原因是"冷却期内"

### Requirement: 池子容量和关注名额

- 池子容量：候选和关注合计 SHALL NOT 超过池子容量（默认 30），持仓不计入。加入时，已有的候选和关注合计达到池子容量就拒绝，原因是"池子已满"
- 关注名额：关注 SHALL NOT 超过关注名额（默认 8）。升级时先检查状态（见「状态变化」），再检查名额：已有的关注达到关注名额就拒绝，原因是"关注名额已满"。升级不经过 Critic；关注论点是否齐全由「关注论点的格式」保证
- 成交后的状态变化（买入成交、代码触发的清仓、PM 发起的清仓）不检查容量和名额，照常变化，可能超出上限；超出期间加入或升级照样按上面的规则拒绝，直到降回上限以下

#### Scenario: 池子容量的边界

- **GIVEN** 基准数据，池子容量 3
- **WHEN** 加入 DDD
- **THEN** DDD 成为候选，候选和关注合计 3 只
- **WHEN** 加入 EEE
- **THEN** 被拒绝，原因是"池子已满"

#### Scenario: 持仓不占池子容量

- **GIVEN** 基准数据，池子容量 2
- **WHEN** 加入 DDD
- **THEN** 被拒绝，原因是"池子已满"
- **WHEN** BBB 买入成交变为持仓，再加入 DDD
- **THEN** DDD 成为候选

#### Scenario: 关注名额的边界

- **GIVEN** 基准数据，关注名额 2
- **WHEN** 以基准关注论点升级 AAA
- **THEN** AAA 是关注，关注合计 2 只
- **WHEN** 加入 DDD，再以基准关注论点升级 DDD
- **THEN** 升级被拒绝，原因是"关注名额已满"，DDD 仍是候选

#### Scenario: 清仓后转为关注可以超出关注名额

- **GIVEN** 基准数据，关注名额 1
- **WHEN** CCC 由 PM 发起的清仓完成，PM 选择转为关注
- **THEN** CCC 是关注，关注合计 2 只
- **WHEN** 以基准关注论点升级 AAA
- **THEN** 被拒绝，原因是"关注名额已满"

#### Scenario: 清仓后转为候选可以超出池子容量

- **GIVEN** 基准数据，池子容量 2
- **WHEN** CCC 代码触发的清仓
- **THEN** CCC 是候选，候选和关注合计 3 只
- **WHEN** 加入 DDD
- **THEN** 被拒绝，原因是"池子已满"

### Requirement: 每天的增删次数

每个交易日，通过的加入和删除合计 SHALL NOT 超过每天增删次数上限（默认 10）；达到上限后，这个交易日的加入和删除都被拒绝，原因是"增删次数已用完"。

- 交易日按时刻归属的交易日划分（trading-calendar spec「时刻归属的交易日」）：从上一个交易日收盘（含）到这个交易日收盘（不含），周末和休市日并进下一个交易日
- 计入：PM 探索和手动添加的加入、PM 的删除，只算通过的
- 不计入：被拒绝的操作、升级、降为候选、保持、记录评分、超期移出、成交后的状态变化

#### Scenario: 次数上限的边界

- **GIVEN** 基准数据，每天增删次数上限 2
- **WHEN** 加入 DDD，再删除 AAA
- **THEN** 都通过
- **WHEN** 加入 EEE，或者删除 BBB
- **THEN** 都被拒绝，原因是"增删次数已用完"

#### Scenario: 被拒绝的操作不计入

- **GIVEN** 基准数据，每天增删次数上限 1
- **WHEN** 加入 ZZZ，调用方查不到上市信息；删除 CCC
- **THEN** 都被拒绝
- **WHEN** 加入 DDD
- **THEN** DDD 成为候选

#### Scenario: 不是增删的变化不计入

- **GIVEN** 基准数据，每天增删次数上限 1
- **WHEN** 以基准关注论点升级 AAA；BBB 降为候选；记录 BBB 的评分 1；CCC 由 PM 发起的清仓完成，PM 选择移出
- **THEN** 都通过
- **WHEN** 加入 DDD
- **THEN** DDD 成为候选
- **WHEN** 加入 EEE
- **THEN** 被拒绝，原因是"增删次数已用完"

#### Scenario: 收盘后的增删算下一个交易日

- **GIVEN** 基准数据，每天增删次数上限 1
- **WHEN** 当前时刻 2026-10-14 19:59Z，加入 DDD
- **THEN** DDD 成为候选
- **WHEN** 当前时刻 2026-10-14 20:00Z（归属 2026-10-15），加入 EEE
- **THEN** EEE 成为候选
- **WHEN** 当前时刻 2026-10-15 15:00Z，加入 FFF
- **THEN** 被拒绝，原因是"增删次数已用完"

#### Scenario: 周末并进下一个交易日

- **GIVEN** 基准数据，每天增删次数上限 1
- **WHEN** 当前时刻 2026-10-17 15:00Z（周六，归属 2026-10-19），加入 DDD
- **THEN** DDD 成为候选
- **WHEN** 当前时刻 2026-10-19 15:00Z，加入 EEE
- **THEN** 被拒绝，原因是"增删次数已用完"
- **WHEN** 当前时刻 2026-10-19 20:00Z（归属 2026-10-20），加入 EEE
- **THEN** EEE 成为候选

### Requirement: 候选的过期时间

股票每次成为候选或保持时（加入、保持、降为候选、代码触发的清仓），过期时间 SHALL 设为：当前时刻归属的交易日之后，第"候选过期期限"（默认 10）个交易日的收盘时刻。升级为关注、买入成交以后没有过期时间。

股票池 SHALL 提供"移出到期的候选"：当前时刻不早于过期时间、仍是候选的股票由代码移出，原因是超期，给出这次移出的股票。调用方每个交易日收盘后调用一次；错过的话，下一次调用照样移出所有已经到期的候选。

#### Scenario: 过期时间按交易日计算

- **GIVEN** 基准数据
- **WHEN** 加入 DDD
- **THEN** DDD 的过期时间是 2026-10-28 20:00Z
- **WHEN** 当前时刻 2026-10-14 20:30Z（收盘后，归属 2026-10-15），加入 EEE
- **THEN** EEE 的过期时间是 2026-10-29 20:00Z
- **WHEN** 当前时刻 2026-10-20 15:00Z，保持 AAA
- **THEN** AAA 的过期时间是 2026-11-03 21:00Z（夏令时结束后，收盘是 21:00Z）

#### Scenario: 到期的边界

- **GIVEN** 基准数据
- **WHEN** 当前时刻 2026-10-27 19:59:59Z，移出到期的候选
- **THEN** 没有股票被移出，AAA 仍是候选
- **WHEN** 当前时刻 2026-10-27 20:00Z，移出到期的候选
- **THEN** 移出的股票是 AAA，原因是超期；BBB 和 CCC 不变

#### Scenario: 错过收盘后的那一次

- **GIVEN** 基准数据
- **WHEN** 当前时刻 2026-10-29 15:00Z，移出到期的候选
- **THEN** 移出的股票是 AAA

#### Scenario: 保持以后按新的过期时间

- **GIVEN** 基准数据，当前时刻 2026-10-20 15:00Z，保持 AAA
- **WHEN** 当前时刻 2026-10-27 20:00Z，移出到期的候选
- **THEN** 没有股票被移出，AAA 仍是候选

#### Scenario: 升级以后不再过期

- **GIVEN** 基准数据，以基准关注论点升级 AAA
- **WHEN** 当前时刻 2026-10-29 15:00Z，移出到期的候选
- **THEN** 没有股票被移出，AAA 仍是关注

### Requirement: 关注论点的格式

关注论点 SHALL 包含下面五项，缺任何一项、或者文字去掉首尾空白后为空，都是格式错误：

- 看好理由：文字
- 入场条件：代码能检测的条件，至少一条；任一条件满足就算入场条件满足
- 催化剂：描述（文字）、截止日期；可以引用一个日程项或事件（带 ID）。没有固定日期的催化剂可以先不引用，事件发生后再关联
- 证伪条件：文字
- 复查日：日期

代码能检测的条件 SHALL 是下面三类之一：

| 类型 | 比较的量 | 比较 | 值 |
| --- | --- | --- | --- |
| 价格 | 最新价 | 不低于或不高于 | 大于 0 |
| 涨跌幅 | 当日涨跌幅：相对前一交易日收盘价的比例，下跌为负 | 不低于或不高于 | 任意 |
| 成交量 | 当日累计成交量（股） | 只能是不低于 | 大于 0 |

复查日和催化剂截止日期取什么值，不在本 spec 的范围内。

#### Scenario: 完整的关注论点

- **WHEN** 用基准关注论点的五项构造关注论点
- **THEN** 格式正确

#### Scenario: 缺少一项

- **WHEN** 分别缺少看好理由、入场条件（没有一条）、催化剂、证伪条件、复查日，构造关注论点
- **THEN** 都是格式错误

#### Scenario: 只有空白的文字

- **WHEN** 看好理由、证伪条件或催化剂描述是 "  "，构造关注论点
- **THEN** 都是格式错误

#### Scenario: 三类条件

- **WHEN** 分别构造条件：价格不高于 50；价格不低于 60；涨跌幅不高于 -0.05；涨跌幅不低于 0.03；成交量不低于 2,000,000 股
- **THEN** 都正确
- **WHEN** 分别构造条件：价格不高于 0；成交量不低于 0；成交量不高于 2,000,000 股
- **THEN** 都是格式错误

#### Scenario: 催化剂引用日程项或事件

- **WHEN** 催化剂引用日程项 "E-1"、引用事件 "V-7"、或者不引用
- **THEN** 格式都正确
- **WHEN** 催化剂引用事件，ID 为空
- **THEN** 格式错误

### Requirement: 股票池配置

股票池的阈值 SHALL 是可配置项，默认值如下：

| 配置项 | 默认值 | 含义 |
| --- | --- | --- |
| 池子容量 | 30 | 候选和关注合计不超过这么多只 |
| 关注名额 | 8 | 关注不超过这么多只 |
| 每天增删次数上限 | 10 | 每个交易日通过的加入和删除合计 |
| 候选过期期限 | 10 个交易日 | 成为候选或保持后，过这么多个交易日收盘时还是候选就移出 |
| 重新加入的冷却期 | 5 个交易日 | 移出后过这么多个交易日才能重新加入 |
| 流动性门槛 | 1,000 万美元 | 日均成交额不低于它 |
| 允许的交易所 | 纽交所、纳斯达克 | 交易所不在其中的不能加入 |
| 允许的证券类型 | 普通股、ADR | 证券类型不在其中的不能加入 |

数值项都 MUST 大于 0，两个允许范围都 MUST 至少有一项，否则配置报错。

#### Scenario: 默认配置

- **WHEN** 不传任何配置项新建配置
- **THEN** 各项是上表的默认值

#### Scenario: 配置不合法

- **WHEN** 池子容量、关注名额、每天增删次数上限、候选过期期限、重新加入的冷却期或流动性门槛配置为 0，或者允许的交易所、允许的证券类型为空
- **THEN** 都配置报错

#### Scenario: 允许 ETF

- **GIVEN** 基准数据，允许的证券类型是普通股、ADR 和 ETF
- **WHEN** 加入 DDD，上市信息是纽交所的 ETF
- **THEN** DDD 成为候选
- **WHEN** 加入 EEE，上市信息是纳斯达克的杠杆产品
- **THEN** 被拒绝，原因是"不在允许交易的范围内"
