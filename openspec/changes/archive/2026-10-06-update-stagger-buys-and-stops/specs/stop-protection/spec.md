## ADDED Requirements

### Requirement: 买单和止损单错开

order-lifecycle spec「执行配置」的「买单和止损单错开」打开时，执行模块 SHALL 让同一只股票的买单和券商端止损单不同时挂着。这是给不允许两者同时挂着的券商用的，比如 Alpaca 模拟盘：

- 这只股票有没结束的买单（待提交、已提交、部分成交、状态未知）时，止损目标的股数为 0，止损价照常，见「止损目标」。所以按「对齐止损单」，挂着的止损单撤单，还没挂出去的放弃，不挂新的
- 买单需要提交给券商时（见 order-lifecycle spec「先查询再提交」），执行模块 SHALL 先对齐这只股票的止损单，再确认止损单已经撤掉：
  - 没有止损单，或者当前止损单已经结束、还没挂出去：已撤掉
  - 止损单挂着（包括已经请求撤单、券商还没确认结束的），或者状态未知：没有撤掉

  没有撤掉时这次不提交，订单保持待提交，等之后跟进时再确认。截止时刻之后仍未提交的，按「先查询再提交」结束为已过期
- 这只股票的买单都结束以后，对齐时按止损目标挂一张序号加 1 的新止损单。买单结束的那次跟进之后就会对齐，见「对齐止损单」
- 对齐时，止损目标的股数因为这条规则为 0、不按这条规则会大于 0 时，这只股票 SHALL 记为错开中；之后某次对齐不是这样时，SHALL 解除错开中。错开中不是无保护仓位：不发无保护仓位的告警，也不禁止提交新的买单。这段时间由本地备用止损按止损价盯着，见「本地备用止损的触发」

「买单和止损单错开」关闭时（默认），本 requirement 不起作用，买单和止损单照常同时挂着。

本 requirement 的场景除非另有说明，都打开「买单和止损单错开」。

#### Scenario: 加仓时先撤止损单，券商确认结束后再提交买单

- **GIVEN** 持有 BBB 100 股，止损单已对齐
- **WHEN** 提交 P2
- **THEN** 券商收到 BBB-STOP-1 的撤单请求，没有收到 P2 的提交；P2 的订单待提交
- **AND** BBB 错开中，不是无保护仓位
- **WHEN** 券商回报 BBB-STOP-1 仍挂着，跟进 P2
- **THEN** 券商再次收到 BBB-STOP-1 的撤单请求，仍然没有收到 P2 的提交
- **WHEN** 券商回报 BBB-STOP-1 变为撤销，跟进 P2
- **THEN** 券商收到 P2 的提交：买入 BBB 50 股，限价 52；没有挂新的止损单

#### Scenario: 加仓部分成交时不挂止损单

- **GIVEN** 持有 BBB 100 股，提交 P2 以后 BBB-STOP-1 已经撤销，P2 的订单已提交
- **WHEN** 券商回报 P2 部分成交、累计成交 20，券商持仓变为 120 股，跟进 P2
- **THEN** 券商没有收到止损单的挂单；止损目标是 0 股，止损价 48
- **AND** BBB 错开中

#### Scenario: 加仓结束后按合计持仓挂新止损单

- **GIVEN** 持有 BBB 100 股，提交 P2 以后 BBB-STOP-1 已经撤销，P2 部分成交、累计成交 20，券商持仓 120 股
- **WHEN** 券商回报 P2 全部成交、累计成交 50，券商持仓变为 150 股，跟进 P2
- **THEN** 券商收到止损单 BBB-STOP-2：卖出 BBB 150 股，止损价 48
- **AND** BBB 不再错开中

#### Scenario: 加仓一股没成交就结束，按原来的止损价挂回

- **GIVEN** 持有 BBB 100 股，提交 P2 以后 BBB-STOP-1 已经撤销，P2 的订单已提交
- **WHEN** 券商回报 P2 撤销、累计成交 0（收盘失效），券商持仓仍是 100 股，2026-10-14 20:00:05Z 跟进 P2
- **THEN** P2 已过期，券商收到止损单 BBB-STOP-2：卖出 BBB 100 股，止损价 45
- **AND** BBB 不再错开中

#### Scenario: 新买入部分成交时不挂止损单，买单结束后再挂

- **GIVEN** 基准数据，没有 BBB 的持仓和止损单
- **WHEN** 提交 P1
- **THEN** 券商收到 P1 的提交，没有收到止损单的调用；BBB 不是错开中
- **WHEN** 券商回报 P1 部分成交、累计成交 30，券商持仓变为 30 股，跟进 P1
- **THEN** 券商没有收到止损单的挂单；BBB 错开中
- **WHEN** 券商回报 P1 全部成交，券商持仓变为 100 股，跟进 P1
- **THEN** 券商收到止损单 BBB-STOP-1：卖出 BBB 100 股，止损价 45
- **AND** BBB 不再错开中

#### Scenario: 止损单状态未知时不提交买单

- **GIVEN** 持有 BBB 100 股，BBB-STOP-1 状态未知，记下 2026-10-14 15:00Z
- **WHEN** 2026-10-14 15:00:10Z 提交 P2
- **THEN** 没有收到 P2 的提交，P2 的订单待提交，券商没有收到止损单的调用

#### Scenario: 错开中不是无保护仓位，可以再提交买单

- **GIVEN** 持有 BBB 100 股，提交 P2 以后 BBB-STOP-1 已经撤销，P2 的订单已提交，BBB 错开中
- **WHEN** 提交加仓 BBB 30 股的方案 P5（限价 52，止损价 48）
- **THEN** 正常提交，P5 的订单已提交

#### Scenario: 撤掉还在等止损单撤掉的买单后，挂回止损单

- **GIVEN** 持有 BBB 100 股，提交 P2 以后券商还没确认 BBB-STOP-1 的撤单，P2 的订单待提交
- **WHEN** 撤掉 BBB 的订单（见 order-lifecycle spec「提前撤单」）
- **THEN** P2 已撤销，累计成交 0，券商没有收到 P2 的提交；BBB 不再错开中
- **WHEN** 券商回报 BBB-STOP-1 变为撤销，对齐 BBB
- **THEN** 券商收到止损单 BBB-STOP-2：卖出 BBB 100 股，止损价 45

#### Scenario: 开关关闭时加仓不撤止损单

- **GIVEN** 「买单和止损单错开」关闭，持有 BBB 100 股，止损单已对齐
- **WHEN** 提交 P2
- **THEN** 券商收到 P2 的提交，没有收到 BBB-STOP-1 的撤单请求；BBB 不是错开中

## MODIFIED Requirements

### Requirement: 止损目标

对齐止损单时，执行模块 SHALL 按下面的方法计算止损目标：

- 股数 = 券商持仓股数 − 这只股票所有未结束卖单（待提交、已提交、部分成交、状态未知）的未成交股数（委托股数 − 累计成交）；小于 0 时为 0
- 未覆盖的股数：上面的差小于 0 时，卖单超出持仓的股数；否则为 0。用于「卖单先让出股数」
- 止损价：见「止损价」
- 「买单和止损单错开」打开、这只股票有没结束的买单（待提交、已提交、部分成交、状态未知）时，股数为 0；未覆盖的股数和止损价照常。见「买单和止损单错开」

止损单本身占用的股数不算在卖单里。

#### Scenario: 卖单待提交时目标让出它的股数

- **GIVEN** 持有 BBB 100 股，P3 的订单待提交
- **THEN** 止损目标是 40 股，止损价 45

#### Scenario: 卖单部分成交时目标不变

- **GIVEN** 持有 BBB 100 股，P3 的订单部分成交、累计成交 20，券商持仓 80 股
- **THEN** 止损目标是 40 股

#### Scenario: 卖单结束后目标恢复为剩下的持仓

- **GIVEN** 持有 BBB 100 股，P3 的订单已过期、累计成交 20，券商持仓 80 股
- **THEN** 止损目标是 80 股

#### Scenario: 清仓卖单让出全部股数

- **GIVEN** 持有 BBB 100 股，P4 的订单待提交
- **THEN** 止损目标是 0 股

#### Scenario: 卖单股数超过持仓时目标为 0

- **GIVEN** 持有 BBB 100 股，P4 的订单待提交，券商持仓变为 70 股（其余已被止损卖出）
- **THEN** 止损目标是 0 股，不是 -30；未覆盖的股数是 30

#### Scenario: 错开时有买单没结束，目标为 0

- **GIVEN** 「买单和止损单错开」打开，持有 BBB 100 股，P2 的订单已提交
- **THEN** 止损目标是 0 股，止损价 45
- **WHEN** 「买单和止损单错开」关闭，其他不变
- **THEN** 止损目标是 100 股，止损价 45

#### Scenario: 错开时买单都结束了，目标恢复

- **GIVEN** 「买单和止损单错开」打开，持有 BBB 100 股，P2 的订单已过期、累计成交 0
- **THEN** 止损目标是 100 股，止损价 45

### Requirement: 本地备用止损的触发

执行模块 SHALL 给出一只股票的本地备用止损现在是否该触发。下面三个条件都满足时该触发，否则不该：

- 这只股票是无保护仓位，或者错开中（见「买单和止损单错开」）
- 当前时刻在常规交易时段内
- 这只股票有止损价，并且调用方传入的最新价不高于止损价

触发之后怎样卖出不在本 spec 范围内。

#### Scenario: 无保护、盘中、价格跌到止损价时触发

- **GIVEN** 持有 BBB 100 股，BBB 是无保护仓位，止损价 45
- **WHEN** 最新价 45，判断 BBB 的备用止损
- **THEN** 该触发
- **WHEN** 最新价 44
- **THEN** 该触发

#### Scenario: 价格高于止损价时不触发

- **GIVEN** 持有 BBB 100 股，BBB 是无保护仓位，止损价 45
- **WHEN** 最新价 45.01，判断 BBB 的备用止损
- **THEN** 不该触发

#### Scenario: 常规交易时段之外不触发

- **GIVEN** 持有 BBB 100 股，BBB 是无保护仓位，止损价 45，当前时刻 2026-10-14 21:00Z（盘后）
- **WHEN** 最新价 40，判断 BBB 的备用止损
- **THEN** 不该触发

#### Scenario: 有保护时不触发

- **GIVEN** 持有 BBB 100 股，止损单已对齐
- **WHEN** 最新价 40，判断 BBB 的备用止损
- **THEN** 不该触发

#### Scenario: 错开中、价格跌到止损价时触发

- **GIVEN** 「买单和止损单错开」打开，持有 BBB 100 股，提交 P2 以后 BBB-STOP-1 已经撤销，P2 的订单已提交，BBB 错开中
- **WHEN** 最新价 45，判断 BBB 的备用止损
- **THEN** 该触发
- **WHEN** 最新价 45.01
- **THEN** 不该触发
- **WHEN** 券商回报 P2 部分成交、累计成交 20，券商持仓变为 120 股，跟进 P2；最新价 47.50
- **THEN** 该触发：止损价已经换成 P2 的 48

#### Scenario: 错开结束、挂上止损单后不触发

- **GIVEN** 「买单和止损单错开」打开，持有 BBB 100 股，提交 P2 以后 BBB-STOP-1 已经撤销，P2 全部成交，跟进 P2 以后挂上了 BBB-STOP-2
- **WHEN** 最新价 40，判断 BBB 的备用止损
- **THEN** 不该触发

### Requirement: 保存止损保护

执行模块 SHALL 把每只股票的止损保护保存在存储中，每次变化都保存：

- 股票；这只股票已经用过几个止损单序号
- 当前这张止损单：客户端订单 ID、券商订单号、创建时刻、股数、止损价、状态（还没挂出去、挂着、状态未知、已经结束）、变为状态未知的时刻、最近一次还没生效的改单请求的股数、累计成交股数、成交均价、累计费用、发现成交的时刻
- 是否无保护仓位，以及开始的时刻
- 是否错开中，见「买单和止损单错开」

进程重启后，执行模块 SHALL 从存储读出，继续对齐。

#### Scenario: 重启后继续对齐

- **GIVEN** P1 部分成交、累计成交 30，BBB-STOP-1 挂着 30 股
- **WHEN** 进程重启（用同一个存储重新创建执行模块），券商回报 P1 全部成交，券商持仓变为 100 股，跟进 P1
- **THEN** 券商收到 BBB-STOP-1 的改单：100 股；没有挂第二张止损单

#### Scenario: 挂单之后、保存结果之前进程退出

- **GIVEN** 券商持仓 BBB 30 股，P1 部分成交、累计成交 30；存储里 BBB-STOP-1 还没挂出去，券商已经受理了 BBB-STOP-1
- **WHEN** 进程重启后对齐 BBB
- **THEN** 没有再挂单，BBB-STOP-1 挂着，券商只有一张 BBB-STOP-1

#### Scenario: 重启后仍是错开中

- **GIVEN** 「买单和止损单错开」打开，持有 BBB 100 股，提交 P2 以后 BBB-STOP-1 已经撤销，P2 的订单已提交，BBB 错开中
- **WHEN** 进程重启（用同一个存储重新创建执行模块），最新价 45，判断 BBB 的备用止损
- **THEN** BBB 仍是错开中，该触发
