## MODIFIED Requirements

### Requirement: 先查询再提交

执行模块每次向券商提交订单之前，SHALL 先按客户端订单 ID 查询：

- 查到：采用券商回报（见「订单状态和券商回报」），不再提交
- 查不到，当前时刻早于截止时刻，没有撤单要求：提交，客户端订单 ID 不变
- 查不到，当前时刻早于截止时刻，有撤单要求（见「提前撤单」）：不再提交，订单结束为已撤销，累计成交 0
- 查不到，当前时刻不早于截止时刻：不再提交，订单结束为已过期，累计成交 0

需要提交的订单只有两种：待提交的订单；券商从没受理过（没有券商订单号）的状态未知订单，见「券商调用失败时状态未知」。券商受理过的订单 MUST NOT 重新提交。

卖单查不到、当前时刻早于截止时刻、没有撤单要求时，SHALL 先按 stop-protection spec「卖单先让出股数」确认这只股票的止损单已经让出股数，才提交；还没让出时这次不提交，订单状态不变。

「执行配置」的「买单和止损单错开」打开时，买单查不到、当前时刻早于截止时刻、没有撤单要求，SHALL 先按 stop-protection spec「买单和止损单错开」确认这只股票的止损单已经撤掉，才提交；还没撤掉时这次不提交，订单状态不变。关闭时，买单不等止损单。

券商拒绝受理时，订单结束为已拒绝，没有券商订单号。

#### Scenario: 首次提交时先查询

- **GIVEN** 基准数据
- **WHEN** 提交基准方案
- **THEN** 券商先收到按 P1 的查询，查不到，再收到提交

#### Scenario: 券商拒绝受理

- **GIVEN** 基准数据，券商会拒绝受理这笔订单（比如购买力不足）
- **WHEN** 提交基准方案
- **THEN** 订单已拒绝，累计成交 0，没有券商订单号

#### Scenario: 止损单还没让出股数时不提交卖单

- **GIVEN** 基准数据，P1 全部成交，券商持仓 BBB 100 股，止损单 BBB-STOP-1 挂着 100 股
- **WHEN** 提交减仓 BBB 60 股的方案 P3
- **THEN** 券商收到按 P3 的查询，查不到，但没有收到 P3 的提交；P3 的订单待提交

#### Scenario: 买单和止损单错开时，止损单还没撤掉不提交买单

- **GIVEN** 基准数据，「买单和止损单错开」打开，P1 全部成交，券商持仓 BBB 100 股，止损单 BBB-STOP-1 挂着 100 股
- **WHEN** 提交加仓 BBB 50 股的方案 P5（限价 52，止损价 48）
- **THEN** 券商收到 BBB-STOP-1 的撤单请求，收到按 P5 的查询，查不到，但没有收到 P5 的提交；P5 的订单待提交

#### Scenario: 提交之后、保存结果之前进程退出

- **GIVEN** 存储里有基准方案的待提交订单，券商已经受理了客户端订单 ID 是 P1 的订单（进程在提交后、保存结果前退出）
- **WHEN** 进程重启后，2026-10-14 15:05Z 跟进这笔订单
- **THEN** 不再提交，券商仍然只有一笔 P1 的订单
- **AND** 订单已提交，记下了券商订单号

#### Scenario: 提交之前进程退出

- **GIVEN** 存储里有基准方案的待提交订单，券商没有 P1 的订单
- **WHEN** 进程重启后，2026-10-14 15:05Z 跟进这笔订单
- **THEN** 券商收到 P1 的提交，订单已提交

#### Scenario: 停机到截止时刻之后

- **GIVEN** 存储里有基准方案的待提交订单，截止时刻 2026-10-14 20:00Z，券商没有 P1 的订单
- **WHEN** 进程在 2026-10-15 13:00Z 重启后跟进这笔订单
- **THEN** 不提交，订单已过期，累计成交 0

### Requirement: 执行配置

执行模块的阈值和开关 SHALL 可以配置：

| 配置项 | 含义 | 默认值 |
| --- | --- | --- |
| 状态未知的等待时长 | 订单或止损单变为状态未知之后，等多久才再查询券商 | 30 秒 |
| 立即重试次数 | 止损单挂单或改单被券商拒绝后，立即用同样的内容重试几次 | 1 |
| 买单和止损单错开 | 同一只股票的买单和券商端止损单不同时挂着，见 stop-protection spec「买单和止损单错开」。给不允许两者同时挂着的券商打开，比如 Alpaca | 关闭 |

等待时长 MUST 大于 0，立即重试次数 MUST NOT 小于 0，否则配置报错。

#### Scenario: 默认配置

- **WHEN** 不指定任何配置项
- **THEN** 状态未知的等待时长是 30 秒，立即重试次数是 1，买单和止损单错开关闭

#### Scenario: 修改等待时长

- **GIVEN** 基准数据，状态未知的等待时长改为 60 秒，提交超时，券商其实收到了，订单状态未知，记下 2026-10-14 15:00Z
- **WHEN** 2026-10-14 15:00:59Z 跟进订单
- **THEN** 不调用券商
- **WHEN** 2026-10-14 15:01:00Z 跟进订单
- **THEN** 查到这笔订单，订单已提交

#### Scenario: 等待时长不大于 0

- **WHEN** 状态未知的等待时长配置为 0 秒
- **THEN** 配置报错

#### Scenario: 立即重试次数为 0

- **GIVEN** P1 已经提交，立即重试次数改为 0，券商会拒绝下一次挂单
- **WHEN** 券商回报 P1 部分成交、累计成交 30，券商持仓变为 30 股，跟进 P1
- **THEN** 券商只收到一次 BBB-STOP-1 的挂单，BBB 是无保护仓位

#### Scenario: 立即重试次数小于 0

- **WHEN** 立即重试次数配置为 -1
- **THEN** 配置报错

#### Scenario: 打开买单和止损单错开

- **WHEN** 买单和止损单错开配置为打开
- **THEN** 配置成功，买单和止损单错开打开
