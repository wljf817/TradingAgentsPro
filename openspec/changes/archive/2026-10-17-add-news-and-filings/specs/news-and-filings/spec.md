# Spec Delta

## Purpose

新闻和公告模块把池内股票和持仓的新闻、SEC 公告从数据源取下来，存进共享状态库（当前市场事实，写入者是数据层），并告诉调用方这次新存下了哪些；之后的事件检测、状态库快照和 Agent 网关从这里读。新闻源和公告源是哪一家只在启动时决定。

## ADDED Requirements

### Requirement: 新闻和公告的条目

一条新闻 SHALL 有下面这些项，内容来自新闻源，原样保存，不加约束：

| 项 | 含义 |
| --- | --- |
| 新闻 ID | 新闻源给的编号，一条新闻一个，用来去重 |
| 标题 | |
| 摘要 | 可以为空 |
| 正文 | HTML，原样保存；新闻源没有正文时为空 |
| 作者 | 可以为空 |
| 稿件来源 | 比如 benzinga |
| 链接 | 原文地址；可以没有 |
| 标注的股票 | 新闻源给这条新闻标注的全部股票，按新闻源给的顺序；可以有调用方没有问的股票 |
| 发布时刻 | UTC |

一份公告 SHALL 有下面这些项：

| 项 | 含义 |
| --- | --- |
| accession number | SEC 给的编号，比如 0000320193-26-000018，一份公告一个，用来去重 |
| 标注的股票 | 调用方问到的股票里，属于这份公告所列公司的那些 |
| 表单类型 | SEC 的写法，原样保存，比如 8-K、10-Q、SCHEDULE 13D/A、4 |
| item | 8-K 和 8-K/A 列出的 item，比如 2.02、9.01，按 SEC 给的顺序；别的表单没有 |
| 受理时刻 | SEC 受理这份公告的时刻，UTC |
| 主文件地址 | 公告主文件在 SEC 网站上的地址 |

本 spec 的场景除非另有说明，都使用下面的基准数据：

| 新闻 | 新闻 ID | 标注的股票 | 发布时刻 | 其他 |
| --- | --- | --- | --- | --- |
| N1 | 101 | AAA | 2026-10-14 12:00:00Z | 标题"AAA raises guidance"，正文 `<p>AAA 上调全年指引</p>`，链接 https://www.benzinga.com/101 |
| N2 | 102 | AAA、BBB | 2026-10-14 13:30:00Z | 没有正文，没有链接 |
| N3 | 103 | CCC | 2026-10-14 14:00:00Z | |

| 公告 | accession number | 标注的股票 | 表单类型 | item | 受理时刻 |
| --- | --- | --- | --- | --- | --- |
| F1 | 0000000001-26-000001 | AAA | 8-K | 2.02、9.01 | 2026-10-14 20:30:00Z |
| F2 | 0000000001-26-000002 | AAA | 4 | 无 | 2026-10-14 22:00:00Z |
| F3 | 0000000002-26-000003 | BBB | 10-Q | 无 | 2026-10-15 10:00:00Z |

#### Scenario: 没有正文、没有链接的新闻

- **GIVEN** 新闻源有 N2
- **WHEN** 取 AAA 自 2026-10-14 00:00Z 的新闻
- **THEN** 存下 N2，正文为空，没有链接，标注的股票依次是 AAA、BBB

#### Scenario: 不是 8-K 的公告没有 item

- **GIVEN** 公告源有 F2
- **WHEN** 取 AAA 自 2026-10-14 00:00Z 的公告
- **THEN** 存下 F2，表单类型 4，没有 item

### Requirement: 取新闻

模块 SHALL 按调用方给出的一组股票和起始时刻，向新闻源取起始时刻（含）以来发布、标注了这些股票中至少一只的新闻，然后：

- 把还没存过的新闻存下：按新闻 ID 判断，已经存过的 MUST NOT 再写入，也 MUST NOT 修改已经存下的那条，内容变了也一样
- 返回这次新存下的新闻，按发布时刻排序，发布时刻相同的按新闻 ID 排序
- 新闻源这次给出的结果里同一个新闻 ID 出现几次，只存一次、返回一次
- 没有给出股票时，结果为空，不向新闻源取
- 同一只股票给出多次，只向新闻源问一次
- 新闻源超时、断线、限频或出错时，报数据源不可用，这次什么都不存；模块不重试，下一次调用再取

#### Scenario: 第一次取

- **GIVEN** 新闻源对 AAA、BBB 给出 N2、N1；还没有存过新闻
- **WHEN** 取 AAA、BBB 自 2026-10-14 00:00Z 的新闻
- **THEN** 新闻源被问到的是 AAA、BBB，起始时刻 2026-10-14 00:00Z
- **AND** 存下 N1、N2，返回 N1、N2，按这个顺序

#### Scenario: 再取一次只返回新的

- **GIVEN** 已经存过 N1；新闻源给出 N1、N2
- **WHEN** 取 AAA 自 2026-10-14 00:00Z 的新闻
- **THEN** 存下 N2，返回只有 N2
- **AND** N1 仍然只存了一次

#### Scenario: 存过的新闻后来被改了

- **GIVEN** 已经存过 N1，标题"AAA raises guidance"；新闻源给出新闻 ID 101，标题改成了"UPDATE: AAA raises guidance"
- **WHEN** 取 AAA 自 2026-10-14 00:00Z 的新闻
- **THEN** 返回为空
- **AND** 读到的 101 的标题仍是"AAA raises guidance"

#### Scenario: 同一条新闻在结果里出现两次

- **GIVEN** 新闻源给出 N1、N1
- **WHEN** 取 AAA 自 2026-10-14 00:00Z 的新闻
- **THEN** 存下 N1 一条，返回 N1 一条

#### Scenario: 没有给出股票

- **WHEN** 取新闻，没有给出任何股票
- **THEN** 结果为空
- **AND** 没有向新闻源取

#### Scenario: 同一只股票给出多次

- **WHEN** 取 AAA、AAA、BBB 自 2026-10-14 00:00Z 的新闻
- **THEN** 新闻源被问到一次，股票是 AAA、BBB

#### Scenario: 新闻源不可用

- **GIVEN** 新闻源这次报数据源不可用
- **WHEN** 取 AAA 自 2026-10-14 00:00Z 的新闻
- **THEN** 报数据源不可用
- **AND** 什么都没有存，新闻源只被问了一次

### Requirement: 取公告

模块 SHALL 按调用方给出的一组股票和起始时刻，向公告源取这些股票所属公司起始时刻（含）以来被 SEC 受理的公告，然后：

- 把还没存过的公告存下：按 accession number 判断，已经存过的 MUST NOT 再写入，也 MUST NOT 修改
- 返回这次新存下的公告，按受理时刻排序，受理时刻相同的按 accession number 排序
- 公告源这次给出的结果里同一个 accession number 出现几次，只存一次、返回一次
- 没有给出股票时，结果为空，不向公告源取
- 同一只股票给出多次，只向公告源问一次
- 公告源超时、断线、限频或出错时，报数据源不可用，这次什么都不存；模块不重试

公告源对哪些股票查不到公司，见 sec-filings spec「股票代码到 CIK」；模块不区分，只存公告源给出的。

#### Scenario: 第一次取公告

- **GIVEN** 公告源对 AAA、BBB 给出 F3、F2、F1；还没有存过公告
- **WHEN** 取 AAA、BBB 自 2026-10-14 00:00Z 的公告
- **THEN** 公告源被问到的是 AAA、BBB，起始时刻 2026-10-14 00:00Z
- **AND** 存下 F1、F2、F3，返回 F1、F2、F3，按这个顺序

#### Scenario: 再取一次只返回新的公告

- **GIVEN** 已经存过 F1；公告源给出 F1、F2
- **WHEN** 取 AAA 自 2026-10-14 00:00Z 的公告
- **THEN** 存下 F2，返回只有 F2

#### Scenario: 没有给出股票时不取公告

- **WHEN** 取公告，没有给出任何股票
- **THEN** 结果为空
- **AND** 没有向公告源取

#### Scenario: 公告源不可用

- **GIVEN** 公告源这次报数据源不可用
- **WHEN** 取 AAA 自 2026-10-14 00:00Z 的公告
- **THEN** 报数据源不可用
- **AND** 什么都没有存

### Requirement: 读一只股票的新闻和公告

模块 SHALL 能按一只股票和一个时刻 T 读出已经存下的：

- 新闻：标注的股票里有这只股票、发布时刻不早于 T 的，按发布时刻、新闻 ID 排序
- 公告：标注的股票里有这只股票、受理时刻不早于 T 的，按受理时刻、accession number 排序

没有时结果为空。

#### Scenario: 按股票和时刻读新闻

- **GIVEN** 已经存下 N1、N2、N3
- **WHEN** 读 AAA 自 2026-10-14 12:00:00Z 的新闻
- **THEN** 读到 N1、N2，按这个顺序；没有 N3
- **WHEN** 读 BBB 自 2026-10-14 12:00:00Z 的新闻
- **THEN** 读到 N2
- **WHEN** 读 AAA 自 2026-10-14 12:00:01Z 的新闻
- **THEN** 读到 N2

#### Scenario: 按股票和时刻读公告

- **GIVEN** 已经存下 F1、F2、F3
- **WHEN** 读 AAA 自 2026-10-14 20:30:00Z 的公告
- **THEN** 读到 F1、F2，按这个顺序
- **WHEN** 读 CCC 自 2026-10-14 00:00Z 的公告
- **THEN** 结果为空

### Requirement: 新闻和公告的存储

模块 SHALL 把新闻和公告存在状态库所在的数据库里（新闻表 news_articles、公告表 news_filings，state-store spec「表的归属和迁移」），只由本模块写入：

- 只追加：一条新闻、一份公告各一行，写入以后 MUST NOT 被修改或删除；每行带写入时刻，从时钟读取
- 读回的新闻和公告和写入的完全相同：正文里的 HTML 和中文、没有的链接、标注的股票和 item 的顺序；发布时刻、受理时刻读回的是同一时刻，和数据库服务器、本机的时区都无关
- 进程重启以后（用同一个数据库新建存储），SHALL 读到之前存下的全部条目，之后取到的照样按 ID 去重
- 两个调用同时取到同一条新闻或公告时，SHALL 只存一行，并且只有一个调用把它当作新存下的返回
- 读写出错（数据库连不上、表不存在、存着的条目读不出来）时 SHALL 报错：MUST NOT 当作没有条目返回空，也 MUST NOT 当作已经存下

#### Scenario: 原样读回

- **GIVEN** 进程的本机时区是 UTC+14
- **WHEN** 2026-10-14 15:00:00Z 取到并存下 N1、N2 和 F1，再读 AAA 自 2026-10-14 00:00Z 的新闻和公告
- **THEN** 读到的 N1、N2、F1 和存下的完全相同：N1 的正文仍是 `<p>AAA 上调全年指引</p>`，N2 仍然没有链接、标注的股票仍依次是 AAA、BBB，F1 的 item 仍依次是 2.02、9.01，发布时刻和受理时刻不变
- **AND** 新闻表里 N1、N2 的写入时刻和公告表里 F1 的写入时刻都是 2026-10-14 15:00:00Z

#### Scenario: 重启以后接着去重

- **GIVEN** 已经存下 N1
- **WHEN** 重启，新闻源给出 N1、N2，取 AAA 自 2026-10-14 00:00Z 的新闻
- **THEN** 返回只有 N2，N1 仍然只有一行

#### Scenario: 同时取到同一条

- **GIVEN** 还没有存过新闻；新闻源对两个调用都给出 N1
- **WHEN** 两个调用同时取 AAA 自 2026-10-14 00:00Z 的新闻
- **THEN** 新闻表里 N1 只有一行
- **AND** 一个调用返回 N1，另一个返回为空

#### Scenario: 读写出错

- **GIVEN** 数据库连不上
- **WHEN** 取 AAA 的新闻；或者读 AAA 的公告
- **THEN** 都报错，读不返回空
- **GIVEN** 空数据库，没有升级
- **WHEN** 读 AAA 的新闻
- **THEN** 报错
- **GIVEN** 新闻表里 N1 那一行缺了必填的标题
- **WHEN** 读 AAA 自 2026-10-14 00:00Z 的新闻
- **THEN** 报错，不跳过 N1
