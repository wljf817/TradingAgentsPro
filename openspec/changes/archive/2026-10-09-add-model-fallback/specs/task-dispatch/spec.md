# Spec Delta

## MODIFIED Requirements

### Requirement: Result 的格式

每个 Task SHALL 只有一个 Result，用它的 task_id 标识：PM 和 Critic 引用 Result 时写它的 task_id。Result 包含 task_id、状态、输出、原因、说明、模型、耗时和费用，各状态的内容如下：

| 状态 | 输出 | 原因 | 说明 | 模型 |
| --- | --- | --- | --- | --- |
| 完成 | 合法的信号 | 无 | 无 | 给出输出的模型 |
| 无信号 | 合法的无信号 | 无 | 无 | 给出输出的模型 |
| 超时 | 无 | 无 | 无 | 无 |
| 失败 | 无 | 格式不合法或调用失败 | 必填的文字 | 格式不合法时是给出输出的模型；调用失败时无 |
| 被拒绝 | 无 | 被拒绝的原因（见「派发的顺序」） | 无 | 无 |

- 模型是 model-fallback spec「实际使用的模型」：给出输出的模型，以及它是不是目标子 agent 的备用模型；按实际使用的模型统计评估
- 引用的条目 ID 取自输出（信号或无信号的引用的条目）；没有输出时没有
- 耗时是生成 Result 的时刻减派发时刻；被拒绝的是 0
- 费用是调用方给出的这个任务调用模型的费用，不小于 0；被拒绝的是 0
- 和上表不符、耗时或费用小于 0，都 MUST 报错

本 requirement 和「子 agent 的输出变成 Result」的场景里，Quant 的主模型是 google/s-1，备用模型是 openai/s-2（model-fallback spec 的基准模型的配置）。

#### Scenario: 完成和无信号的 Result

- **GIVEN** PM 派发价格请求（T-1）
- **WHEN** 2026-10-14 15:01:30Z 收到 s-1 给出的基准信号，费用 0.02
- **THEN** T-1 的 Result 是完成，输出是基准信号，引用的条目是 E-1 和 E-2，模型是 s-1、不是备用模型，耗时 90 秒，费用 0.02
- **WHEN** 同样的时刻收到 s-1 给出的基准无信号，费用 0.02
- **THEN** T-1 的 Result 是无信号，输出是基准无信号，没有引用的条目，模型是 s-1、不是备用模型

#### Scenario: 状态和内容不符

- **WHEN** 构造这些 Result：完成，没有输出；完成，输出是基准无信号；无信号，输出是基准信号；超时，输出是基准信号；失败，没有原因；失败，原因是格式不合法，没有说明；被拒绝，原因是格式不合法；无信号，原因是"轮次已用完"；完成，费用 -0.01
- **THEN** 都报错

#### Scenario: 模型和状态不符

- **WHEN** 构造这些 Result：完成，没有模型；无信号，没有模型；失败，原因是格式不合法，没有模型；超时，模型是 s-1；失败，原因是调用失败，模型是 s-1；被拒绝，模型是 s-1
- **THEN** 都报错
- **WHEN** 构造失败的 Result：原因是格式不合法，说明"评估窗口不在配置的选项里"，模型是 s-2、是备用模型
- **THEN** 格式正确

### Requirement: 子 agent 的输出变成 Result

调用方 SHALL 把子 agent 的输出（JSON 文本）、这个任务的费用和实际使用的模型（model-fallback spec「实际使用的模型」）交给 Agent 网关，"现在"是收到输出的时刻。不晚于截止时间收到时，网关 SHALL 按 signal-format spec「收到输出时的校验」检查，按下表生成 Result，Result 的模型就是调用方给出的实际使用的模型；晚于截止时间的见「超时」，Result 没有模型：

| 收到的输出 | Result |
| --- | --- |
| 合法的信号 | 完成，输出是这个信号 |
| 合法的无信号 | 无信号，输出是这个无信号 |
| 不能解析成格式正确的信号或无信号（结构错误） | 失败，原因是格式不合法，说明指出是哪一项、为什么 |
| 格式正确的信号，评估窗口或数据截至时刻不通过 | 失败，原因是格式不合法，说明是 signal-format spec 给出的原因 |

格式不合法的 Result 就是这个任务最终的 Result：SHALL NOT 重新调用子 agent，也不切换备用模型；发起者可以之后再派（失败的不复用，见「相同的任务」）。

#### Scenario: 收到合法的信号和无信号

- **GIVEN** PM 派发价格请求（T-1）
- **WHEN** 2026-10-14 15:01:30Z 收到 s-1 给出的基准信号
- **THEN** T-1 完成，输出是基准信号，模型是 s-1、不是备用模型
- **WHEN** 同样的时刻收到 s-1 给出的基准无信号
- **THEN** T-1 是无信号，输出是基准无信号，模型是 s-1

#### Scenario: 备用模型给出的输出

- **GIVEN** PM 派发价格请求（T-1）
- **WHEN** 2026-10-14 15:03:00Z 收到 s-2 给出的基准信号
- **THEN** T-1 完成，模型是 s-2、是备用模型

#### Scenario: 结构错误

- **GIVEN** PM 派发价格请求（T-1）
- **WHEN** 2026-10-14 15:01:30Z 收到 s-1 给出的缺少主要风险的基准信号
- **THEN** T-1 失败，原因是格式不合法，说明指出缺少主要风险，模型是 s-1
- **WHEN** 同样的时刻收到不是 JSON 的文字"看多，理由见上"；或者收到基准无信号另外写了评分 0
- **THEN** T-1 都失败，原因是格式不合法

#### Scenario: 评估窗口不在配置的选项里

- **GIVEN** PM 派发价格请求（T-1）
- **WHEN** 2026-10-14 15:01:30Z 收到 s-2 给出的评估窗口 4 的信号
- **THEN** T-1 失败，原因是格式不合法，说明是"评估窗口不在配置的选项里"，模型是 s-2、是备用模型

#### Scenario: 数据截至时刻晚于收到的时刻

- **GIVEN** PM 派发价格请求（T-1）
- **WHEN** 2026-10-14 15:01:30Z 收到数据截至 2026-10-14 15:01:31Z 的信号
- **THEN** T-1 失败，原因是格式不合法，说明是"数据截至时刻晚于现在"
- **WHEN** 同样的时刻收到数据截至 2026-10-14 15:01:30Z 的信号
- **THEN** T-1 完成

#### Scenario: 晚于截止时间收到的不记模型

- **GIVEN** PM 派发价格请求（T-1，截止时间 2026-10-14 15:05:00Z）
- **WHEN** 2026-10-14 15:05:01Z 收到 s-1 给出的基准信号
- **THEN** T-1 超时，没有输出，也没有模型

### Requirement: 调用失败

调用子 agent 的这次调用全部不可用（model-fallback spec「切换顺序」）时，调用方 SHALL 给出调用失败、model-fallback 给出的说明和这个任务的费用。不晚于截止时间时，Result SHALL 是失败，原因是调用失败，说明是调用方给的说明，没有模型。

到了截止时间、调用停止尝试时（model-fallback spec「尝试的超时」），调用方 SHALL NOT 给出调用失败：这个任务由「超时」记超时。

#### Scenario: 调用失败

- **GIVEN** PM 派发价格请求（T-1）
- **WHEN** 2026-10-14 15:02:00Z 调用方给出调用失败，说明"模型都不可用：google/s-1 连接失败；openai/s-2 连接失败"，费用 0
- **THEN** T-1 失败，原因是调用失败，说明"模型都不可用：google/s-1 连接失败；openai/s-2 连接失败"，没有模型，耗时 2 分钟

#### Scenario: 停止尝试以后记超时

- **GIVEN** PM 派发价格请求（T-1），T-1 的调用在 2026-10-14 15:05:00Z 到了截止时间、停止尝试
- **WHEN** 调用方不给出调用失败，同一时刻记超时
- **THEN** T-1 超时，没有模型
