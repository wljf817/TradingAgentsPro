# Spec Delta

## MODIFIED Requirements

### Requirement: 状态变化的告警和日志

每次判定和对账完成以后，巡检 SHALL 按之前和之后的状态处理，同一个状态不重复告警：

| 之前 | 之后 | 告警 | 程序日志（program-log spec） |
| --- | --- | --- | --- |
| 正常 | 正常 | 不推送 | 不写 |
| 正常 | 降级 | 推送「进入降级模式」 | 进入降级模式：进入的时刻、异常的检查 |
| 降级 | 降级，异常的检查不变 | 不推送 | 不写 |
| 降级 | 降级，异常的检查变了 | 不推送 | 降级模式里的变化：现在异常的检查 |
| 降级 | 等待对账 | 不推送 | 降级模式里的变化：各项检查已恢复，下一轮和券商对账 |
| 等待对账 | 降级 | 不推送 | 降级模式里的变化：等待对账时又有检查异常，以及异常的检查 |
| 等待对账 | 正常（恢复后的对账完成） | 推送「降级模式结束」 | 执行模块的对账（恢复后的对账的结果），然后退出降级模式：进入降级模式的时刻 |

告警文字 SHALL 写明：

- 进入降级模式：进入降级模式的时刻；异常的检查（模型 API、券商连接、数据延迟、调用预算、调度器心跳，按这个顺序）；已暂停开仓，已经确认、还没下单的开仓方案下单时作废；止损单照常保留；各项恢复并和券商对账以后恢复开仓
- 降级模式结束：进入降级模式的时刻；各项检查已恢复，和券商对账完成。对账没有不一致时写明已恢复开仓；有不一致时每一条不一致一行（写法和 close-reconciliation spec「结果消息」的差异行相同），最后一行写明已暂停开仓，之后的对账没有不一致时恢复

降级和等待对账都算降级模式（degraded-mode spec），开仓一直暂停，所以两者之间来回只写程序日志。告警的对象是 `system`，通知模块把它写进程序日志；推送发不出去时写错误日志（discord-notification spec「告警」），告警的条目写明没有发出去，不重发；状态照常变化。

#### Scenario: 券商断开时进入降级并告警

- **WHEN** 券商断开，15:00Z 做一轮
- **THEN** 状态是降级，异常的检查是券商连接，进入时刻 2026-10-14 15:00Z
- **AND** 推送一条告警，写明进入降级模式、2026-10-14 15:00 UTC、券商连接、已暂停开仓、止损单照常保留
- **AND** 程序日志有一条进入降级模式，写明 2026-10-14 15:00 UTC、券商连接；之后是这条告警，内容和推送的相同

#### Scenario: 降级期间不重复告警

- **GIVEN** 券商断开，15:00Z 做一轮，进入降级并推送了告警
- **WHEN** 券商仍然断开，之后一轮
- **THEN** 状态仍是降级，异常的检查仍是券商连接
- **AND** 没有新的告警，健康判定没有写程序日志

#### Scenario: 降级期间异常的检查变了只写日志

- **GIVEN** 券商断开，15:00Z 做一轮，进入降级
- **WHEN** SPY 的更新时刻停在 14:58:00Z，券商仍然断开，之后一轮
- **THEN** 状态仍是降级，异常的检查是券商连接和数据延迟
- **AND** 没有新的告警；程序日志有一条降级模式里的变化，写明现在异常的检查是券商连接、数据延迟

#### Scenario: 各项恢复以后只写日志

- **GIVEN** 券商断开，15:00Z 做一轮，进入降级
- **WHEN** 券商恢复，之后一轮
- **THEN** 状态是等待对账
- **AND** 没有新的告警；程序日志有一条降级模式里的变化，写明各项检查已恢复，下一轮和券商对账

#### Scenario: 等待对账时又有检查异常只写日志

- **GIVEN** 券商断开，15:00Z 做一轮；券商恢复，之后一轮，状态是等待对账
- **WHEN** 券商又断开，之后一轮
- **THEN** 状态是降级，进入时刻仍是 2026-10-14 15:00Z
- **AND** 没有新的告警；程序日志有一条降级模式里的变化，写明等待对账时又有检查异常、券商连接

#### Scenario: 告警发不出去

- **GIVEN** Discord 报错
- **WHEN** 券商断开，15:00Z 做一轮
- **THEN** 状态是降级；有一条错误日志，含告警的文字和失败原因；程序日志的告警写明没有发出去；巡检照常做完这一轮
- **WHEN** Discord 恢复，券商仍然断开，之后一轮
- **THEN** 没有推送

#### Scenario: 数据延迟来回抖动

- **GIVEN** 15:00:00Z 做一轮，数据延迟异常，进入降级并推送了一条告警
- **WHEN** 之后四轮的数据延迟依次是正常、异常、正常、异常
- **THEN** 四轮以后的状态依次是等待对账、降级、等待对账、降级；没有对账，没有新的告警
- **WHEN** 之后两轮的数据延迟都正常
- **THEN** 第一轮以后是等待对账；第二轮对账，状态回到正常，推送一条降级模式结束的告警

#### Scenario: 券商偶发一次超时

- **WHEN** 15:00:00Z 做一轮，第 3 步读取全部持仓超时一次，之后券商正常
- **THEN** 15:00:00Z 进入降级，推送一条进入降级模式的告警
- **AND** 15:00:15Z 那一轮以后是等待对账；15:00:30Z 那一轮对账，回到正常，推送一条降级模式结束的告警

### Requirement: 恢复后的对账

断线或重启「恢复后先与券商对账，以券商为准修正状态库，再恢复运行」。健康判定 SHALL 按这一轮判定之前和之后的状态决定是否对账：

| 判定之前 | 判定之后 | 处理 |
| --- | --- | --- |
| 降级 | 等待对账 | 不对账，等下一轮 |
| 等待对账 | 等待对账 | 拿着锁让执行模块和券商对账一次（reconciliation spec「对账」），在同一次拿锁里告诉健康监控对账完成，状态回到正常；放开锁以后按「状态变化的告警和日志」推送 |
| 等待对账 | 降级 | 不对账 |
| 正常 | 正常或降级 | 不对账 |

- 各项检查恢复的那一轮不对账：这一轮的前几步可能刚补上断线期间的成交、刚改过止损单，同一时刻再对齐会碰上券商还在改单（session-patrol spec「每一轮」）。等一轮以后再对账，对账以前这些变化都已经由上一轮的跟进和对齐处理过
- 对账有没有不一致都算完成（degraded-mode spec）：有不一致时执行模块按 reconciliation spec「有不一致时暂停开仓」继续暂停开仓，直到之后的对账没有不一致
- 对账完成以后，风控检查和下单前再校验不再因为降级模式拒绝开仓类方案
- 收盘对账（close-reconciliation spec）不算恢复后的对账：它不改变健康监控的状态

#### Scenario: 各项恢复以后下一轮对账

- **GIVEN** 券商断开，15:00:00Z 做一轮，进入降级
- **WHEN** 券商恢复，15:00:15Z 做一轮
- **THEN** 状态是等待对账；券商没有收到读取全部挂单的请求
- **WHEN** 15:00:30Z 做一轮
- **THEN** 健康判定这一项里券商收到读取全部挂单、全部止损单和全部持仓的请求（对账）；状态是正常
- **AND** 推送一条告警，写明降级模式结束、2026-10-14 15:00 UTC、各项检查已恢复、对账没有不一致、已恢复开仓
- **AND** 程序日志依次有对账（恢复后的对账，没有不一致）、退出降级模式（2026-10-14 15:00 UTC）和这条告警
- **WHEN** 之后风控检查 P5
- **THEN** 不因为降级模式拒绝

#### Scenario: 断线期间的变化在对账以前已经补上

- **GIVEN** 券商 15:00:00Z 断开，做一轮，进入降级；断线期间券商回报 BBB-STOP-1 变为撤销（长期有效单到期）
- **WHEN** 券商恢复，15:00:15Z 做一轮
- **THEN** 第 3 步对齐 BBB，券商收到止损单 BBB-STOP-2：卖出 100 股，止损价 45
- **AND** 状态是等待对账，这一轮没有对账
- **WHEN** 15:00:30Z 做一轮
- **THEN** 对账；这一轮券商没有收到挂单、改单和撤单；状态是正常

#### Scenario: 恢复后的对账有不一致

- **GIVEN** 券商 15:00:00Z 断开，做一轮，进入降级；断线期间券商持仓多了 CCC 100 股，执行模块没有 CCC 的订单
- **WHEN** 券商恢复，15:00:15Z 和 15:00:30Z 各做一轮
- **THEN** 15:00:30Z 对账，有来历不明的持仓 CCC 100 股；状态是正常
- **AND** 推送一条告警，写明降级模式结束、各项检查已恢复、来历不明的持仓 CCC 100 股，最后一行写明已暂停开仓，之后的对账没有不一致时恢复
- **AND** 程序日志依次有对账（恢复后的对账，来历不明的持仓 CCC 100 股）、退出降级模式和这条告警
- **WHEN** 之后风控检查 P5，通过以后提交订单
- **THEN** 风控不因为降级模式拒绝；提交时报对账不一致，券商没有收到订单

#### Scenario: 对账时券商又断开

- **GIVEN** 券商 15:00:00Z 断开，做一轮；券商恢复，15:00:15Z 做一轮，状态是等待对账
- **WHEN** 15:00:30Z 做一轮，第 3 步读取全部持仓正常，对账读取全部挂单时断线
- **THEN** 有一条 WARNING 写明恢复后的对账没做成、券商不可用；状态仍是等待对账，没有推送
- **WHEN** 券商仍然断开，15:00:45Z 做一轮
- **THEN** 状态是降级，没有新的告警
- **WHEN** 券商恢复，15:01:00Z 和 15:01:15Z 各做一轮
- **THEN** 15:01:00Z 以后是等待对账；15:01:15Z 对账，状态是正常，推送一条降级模式结束的告警

#### Scenario: 对账时别的调用拿着锁

- **GIVEN** 券商 15:00:00Z 断开，做一轮；券商恢复，15:00:15Z 做一轮，状态是等待对账；另一个线程拿着锁
- **WHEN** 巡检在 15:00:30Z 做健康判定这一项
- **THEN** 那个线程放开锁之前，券商没有收到读取全部挂单的请求，状态仍是等待对账
- **WHEN** 那个线程放开锁
- **THEN** 对账，状态是正常

#### Scenario: 收盘以后数据延迟不再检查

- **GIVEN** OpenD 从 19:58:00Z 起断开，19:59:30Z 做一轮，状态是降级，异常的检查是数据延迟
- **WHEN** OpenD 仍然断开，20:00:15Z 做一轮（盘后）
- **THEN** 状态是等待对账
- **WHEN** 20:00:30Z 做一轮
- **THEN** 对账，状态是正常，推送一条降级模式结束的告警
- **WHEN** OpenD 仍然断开，下一个交易日 2026-10-15 13:31:01Z 做一轮
- **THEN** 状态是降级，异常的检查是数据延迟，推送一条进入降级模式的告警

#### Scenario: 程序启动时处于降级模式

- **GIVEN** 程序 15:00Z 启动，OpenD 没开，第一次健康判定是降级（bootstrap spec「第一次健康判定」），已经推送了启动时的告警
- **WHEN** OpenD 仍然没开，15:00:10Z 巡检做第一轮
- **THEN** 状态仍是降级，没有新的告警
- **WHEN** OpenD 连上，之后两轮
- **THEN** 第一轮以后是等待对账；第二轮对账，状态是正常，推送一条降级模式结束的告警
