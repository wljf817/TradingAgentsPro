## MODIFIED Requirements

### Requirement: 什么算不可用

一次调用是网关为一个 agent 拿一次输出，可能经过几个模型、每个模型几次尝试；一次尝试是向一个模型发一次请求。尝试 SHALL 是下面两种结果之一：

- 成功：模型给出了输出。输出格式不合法也是成功，不切换模型：子 agent 的由 task-dispatch spec 记失败、不重新调用；PM 的由调用方退回重交（case-stages spec「唤醒 PM 和结论」「PM 回应」），下一次调用是新的一次调用
- 失败：没有拿到输出，调用错误是下表之一

| 调用错误 | 含义 |
| --- | --- |
| 超时 | 超过这次尝试的超时（见「尝试的超时」）仍没有输出 |
| 连接失败 | 连不上厂商的服务 |
| 限流 | 厂商因为请求太频繁拒绝 |
| 额度或余额用完 | 厂商因为账户的额度或余额用完拒绝；本系统的调用预算用完不在此列 |
| 认证失败 | 厂商因为密钥无效或没有权限拒绝 |
| 服务端出错 | 厂商的服务出错或过载 |
| 其他调用错误 | 以上之外、没有拿到输出的错误 |

- 尝试失败以后 SHALL 重试同一个模型：每个模型在一次调用里最多尝试"重试次数"加 1 次（默认 2 次），重试前不等待，不分调用错误的种类
- 一个模型的尝试都失败，就是这个模型在这次调用里不可用，按「切换顺序」换下一个；不可用的原因是最后一次尝试的调用错误
- 模型的每次不可用和每次成功都计入它的熔断状态（见「熔断」）；重试中间的失败不单独计

#### Scenario: 失败以后重试

- **GIVEN** PM 在 K-1 调用，先试 p-1
- **WHEN** p-1 失败（限流）
- **THEN** 重试 p-1，这是 p-1 的第 2 次尝试
- **WHEN** 接着 p-1 成功
- **THEN** 调用成功，实际使用的模型是 p-1，没有切换；p-1 正常，没有记下不可用

#### Scenario: 重试用完才不可用

- **GIVEN** PM 在 K-1 调用
- **WHEN** p-1 失败（超时），再失败（连接失败）
- **THEN** p-1 不可用，原因是连接失败；换到 p-2，这是 p-2 的第 1 次尝试

#### Scenario: 每种调用错误都算

- **GIVEN** PM 在 K-1 调用
- **WHEN** p-1 的两次尝试都失败，调用错误分别是超时、连接失败、限流、额度或余额用完、认证失败、服务端出错、其他调用错误
- **THEN** 都是 p-1 不可用，原因是这个调用错误，换到 p-2

#### Scenario: 格式不合法不算不可用

- **GIVEN** News 在 K-1 为 T-1 调用
- **WHEN** s-1 成功，输出是不是 JSON 的文字"看多，理由见上"
- **THEN** 调用成功，实际使用的模型是 s-1，不切换；s-1 正常，没有记下不可用
- **AND** T-1 的 Result 是失败，原因是格式不合法，模型是 s-1（task-dispatch spec）

#### Scenario: PM 的输出不合法不算不可用

- **WHEN** 调用 K-1 的 PM，p-1 给出不合法的输出；退回重交以后再调用 K-1 的 PM
- **THEN** 两次调用都从 p-1 开始，p-1 没有记下不可用
