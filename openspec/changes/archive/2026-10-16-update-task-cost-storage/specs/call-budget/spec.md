# Spec Delta

## ADDED Requirements

### Requirement: 费用的存储

费用记录 SHALL 存在状态库所在的数据库里（费用表 gateway_costs，state-store spec「表的归属和迁移」），只由 Agent 网关写入：

- 读回的记录和记下的完全相同：案件 ID、案件类型、agent、模型、用量、费用的每一位小数、预算；记下的时刻存为带时区的时刻，读回的是同一时刻，和数据库服务器、本机的时区都无关
- 读写出错（数据库连不上、表不存在）时，记下和取得预算的情况都 SHALL 报错：MUST NOT 当作已经记下，也 MUST NOT 当作没有记录、今天的费用是 0
- 几个调用（不同的案件，或者一个案件里并行的子 agent）同时记下时，每一条 SHALL 都写入
- 「费用记到哪个预算」里"记之前普通预算是否已经用完"，按这一条记下时读到的预算的情况算。同时记下的几条 SHALL NOT 互相等待：都在普通预算用完以前读到的，都记普通预算，普通预算因此可以超出额度（见「已经开始的案件」）

本 requirement 的场景使用本 spec 的基准数据；"重启"指用同一个数据库新建存储和 Agent 网关。

#### Scenario: 原样读回

- **GIVEN** 进程的本机时区是 UTC+14
- **WHEN** K-3 的 Quant 用 s-1 的一次尝试拿到用量：输入 1、没有输出；重启，读回今天的记录
- **THEN** 读到一条：案件 K-3，持仓事件，Quant，s-1，输入 1、输出 0，费用 0.0000003，普通预算，2026-10-14 15:00Z

#### Scenario: 读写出错

- **GIVEN** 数据库连不上
- **WHEN** K-1 的 PM 用 p-1 的一次尝试拿到用量，记下；或者取得预算的情况
- **THEN** 都报错
- **GIVEN** 空数据库，没有升级
- **WHEN** 取得预算的情况
- **THEN** 报错，不当作三个预算今天的费用都是 0

#### Scenario: 同时记下都写入

- **WHEN** 10 个调用同时各为 K-1 记下 0.01
- **THEN** 10 条都写入，普通预算今天的费用 0.10

#### Scenario: 同时记下的几条都记普通预算

- **GIVEN** K-1 记下 1.95
- **WHEN** K-3 和 K-6 同时各记下 0.10，两条都在对方写入以前读到普通预算没用完
- **THEN** 两条都记普通预算：普通预算今天的费用 2.15，已经用完；持仓保留预算是 0
- **WHEN** 接着 K-3 记下 0.10
- **THEN** 记持仓保留预算，持仓保留预算今天的费用 0.10
