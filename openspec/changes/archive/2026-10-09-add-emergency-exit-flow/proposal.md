# Proposal

## Why

紧急退出的规则（`modules/emergency`）、提前撤单（`cancel_orders`、`cancel_buy_orders`）和本地备用止损的判断（`backup_stop_due`）都在 M1 写好了，但没有人调用：程序运行时不取持仓的行情，不判定个股跌幅和单日亏损熔断，熔断状态永远是「没有触发」，无保护或错开中的仓位跌破止损价也没人卖。盘中巡检（add-session-patrol）有了全天运行、每 15 秒一轮的循环和全程序一把锁，下单流程（add-order-flow）有了风控用的账户数据和下单前再校验的接法，紧急退出可以挂到巡检的每一轮上。

本变更的目的只有一个：**盘中巡检的每一轮在常规交易时段内判定紧急风险退出和本地备用止损，触发的股票先撤掉挂着的订单、作废还没下单的方案，订单都结束以后用代码触发的清仓方案市价清仓，熔断时撤掉全部买单，执行后在 Discord 通知。**

引用的 Proposal（完整版）章节：

- 「持仓与退出」：
  - 退出路径表的「紧急风险退出」一行：代码规则触发，只允许减仓或清仓，默认不需要人工确认、执行后立即通知，分钟级
  - 「紧急风险退出的触发」：只在常规交易时段判断；个股跌幅从前一交易日收盘价算，当天有开仓成交的从成交均价算；组合单日亏损达到熔断线时清仓全部持仓、当天收盘前不再开仓
- 「订单生命周期」表：
  - 「紧急风险退出」一行：先撤掉这只股票还挂着的订单（买单和卖单），都结束以后再下清仓卖单；熔断时还要撤掉所有还挂着的买单
  - 「止损单挂单失败」一行：无保护仓位由本地行情监控按止损价执行备用止损
  - 「加仓」一行：买单和止损单错开时，买单挂着期间由本地行情监控按止损价执行备用止损
- 「故障处理」：
  - 「紧急风险事件例外」：不排队；同时作废这只股票还没提交订单的方案（开仓类和退出类）并释放预留
  - 降级模式：紧急风险退出照常有效
- 「架构」的「不经过主流程的保护」：紧急风险退出由代码规则触发，只能减仓或清仓，执行后立即通知
- 「技术栈与部署」：通知与人工确认一行（告警发 Discord，发不出去时只写程序日志，不另设备用通道）；数据源一行（行情来自 moomoo）

已经定了的（M1 和拆分 M2 时）：紧急退出的判定规则、代码触发的清仓方案（市价单，方案 ID 由股票和交易日确定，每只股票每天一个，被拒后当天不再重试）、本地备用止损用同一个方案；先撤单、订单都结束以后再清仓，熔断时撤掉全部买单；在 Alpaca（买单和止损单错开）上备用止损卖出之前也要先撤掉这只股票挂着的买单；默认不需要人工确认，执行后立即通知；M2 的告警发 Discord，其余写 Python 日志（M4 才有程序日志）。

## What Changes

- 盘中巡检的每一轮在第 3 步（对齐止损单）之后、收盘对账之前加一步「紧急退出」。盘外什么都不做；盘中依次：
  1. 判定（不拿锁）：读执行模块的账户数据（券商的权益、前一交易日收盘时的权益，每只持仓的板块、紧急阈值、今天开仓成交的均价），一次取全部持仓的 moomoo 行情，用紧急退出模块判定个股跌幅和熔断，再对每只持仓判断本地备用止损
  2. 熔断已触发：拿锁撤掉全部还没撤的买单；每个交易日告警一次
  3. 每只要清仓的股票各一项，拿一次锁：今天的清仓方案已经有订单就不再处理；否则释放这只股票还没下单的方案的预留（下单流程之后再校验时得到「方案已结束」而作废），撤掉这只股票挂着的订单；没有挂着的订单时，用风控检查并再校验代码触发的清仓方案，按结果提交订单，之后由巡检跟进
  4. 报告结果（不拿锁）：清仓单结束时告警成交或失败
- 当天触发过的股票做到底：撤单期间价格回升也照样清仓（见「需要人决定」第 2 条）；本地备用止损和紧急退出走同一条路（见「需要人决定」第 1 条）
- 取不到行情时这一轮只判定熔断（熔断只用券商的权益）；读券商账户失败时这一轮不判定
- 告警（Discord）：一只股票开始紧急退出、熔断触发、清仓单结束（成交或失败）、没有可卖的股数、收盘前没能下清仓单；其余只写 Python 日志
- 风控加一个只读查询：有效预留的方案（作废时按股票找方案）
- bootstrap：装配紧急退出流程，交给盘中巡检

## Non-goals

- 紧急退出需要人工确认的开关：M3「人工确认的规则」（会改本变更）
- 健康信号、行情延迟的判定、降级模式的进入和退出、降级告警：「健康监控接线」；本变更只读健康监控的当前状态传给风控
- 中止同一股票正在运行的案件、清仓后转为候选：M4 的案件流程
- 改变执行模块、风控、紧急退出模块、下单流程已有的行为；模块只加只读查询
- 减仓：紧急退出只清仓（M1 已定）
- 部署机器上的检查：整个「流程」组做完统一做
- 程序日志：M4；现在写 Python 日志
- 省略的少见情况：见 design 的省略清单

## Capabilities

### New Capabilities

- `emergency-exit-flow`：巡检里的紧急退出（位置、时机、频率）；判定的输入；要清仓的股票（紧急退出、本地备用止损、当天做到底）；一只股票的清仓（作废方案、撤单、风控、提交）；单日亏损熔断；告警；重启以后；失败；执行模块和风控的调用串行

### Modified Capabilities

- `bootstrap`：「模拟盘的装配」的盘中巡检一行加上紧急退出用到的部件，加一个盘中紧急清仓的场景
- `session-patrol`：「每一轮」写明第 3 步之后还做别的 spec 规定的项（紧急退出、健康判定，收盘对账是最后一项）；「没有持仓也没有订单」场景限定为第 1 到 3 步只读一次全部持仓（盘中紧急退出每一轮还读一次账户），加一个第 3 步之后的项的场景

## Impact

- **代码**：
  - 新增 `src/tradingagentspro/workflows/emergency_flow.py`：判定、熔断撤买单、一只股票的清仓、报告结果，告警文字
  - `workflows/patrol.py`：构造参数加紧急退出流程，`run_round` 在对齐止损单之后、收盘对账之前加一步；模块说明写明第 3 步之后的项
  - `modules/risk/service.py`：只读的 `active_plans`
  - `bootstrap/app.py`：装配紧急退出流程，交给巡检
  - contracts、shared、integrations 不改
- **测试**：新增 `tests/workflows/` 下紧急退出的测试；巡检测试的装配加上紧急退出（中性的账户和行情）；`tests/modules/risk/`、`tests/bootstrap/` 补测试。不需要部署机器、真实 Alpaca、Discord 或 OpenD
- **依赖**：无新依赖；没有新表和迁移
- **请求量**：盘中每一轮多读一次 Alpaca 账户（2 次请求）和一次 moomoo 快照；清仓时每只股票多几次 Alpaca 请求
- **前置变更**：「下单流程」（`TradeServices`、风控用的账户数据）、「收盘对账」（收盘对账是一轮的最后一项）、「改单未生效时不再改单」（清仓提交时会紧接着巡检再对齐止损单）都要先 apply
- **对后续变更的影响**：
  - 「健康监控接线」：往每一轮里加步骤时，紧急退出仍在对齐止损单之后、收盘对账之前
  - M3「人工确认的规则」：在「一只股票的清仓」提交之前加确认
  - M4：紧急退出时中止这只股票正在运行的案件、清仓后转为候选
- **文档**：`docs/实现路线.md` 的进度；人同意「需要人决定」以后改完整版 Proposal

## 需要人决定

1. **本地备用止损触发以后，这只股票别的订单和方案怎么办、要不要通知，完整版没写。** 「止损单挂单失败」一行只写了「由本地行情监控按止损价执行备用止损」，「加仓」一行写的是「买单挂着期间由本地行情监控按止损价执行备用止损，不告警」。备用止损和紧急退出用同一个清仓方案（M1 已定），但这只股票挂着的订单、还没下单的方案、执行后的通知只在「紧急风险退出」一行和「紧急风险事件例外」里写了。
   推荐做法（spec 已按它写）：
   - 备用止损触发以后完全按紧急风险退出处理：先撤掉这只股票挂着的订单（买单和卖单），都结束以后市价清仓；作废还没下单的方案；执行后通知。挂着的卖单不撤就卖不全，挂着的买单不撤在 Alpaca 上卖单会被拒，还没下单的方案留着会在清仓以后再下单
   - 「加仓」一行的「不告警」指买单挂着、止损单撤掉的这段时间不算无保护仓位、不发无保护告警；备用止损真的卖出时照样通知
   完整版的改法：「止损单挂单失败」一行「由本地行情监控按止损价执行备用止损」后面加「（触发以后按「紧急风险退出」一行处理，执行后通知）」；「加仓」一行「买单挂着期间由本地行情监控按止损价执行备用止损，不告警」改为「买单挂着期间不算无保护仓位、不告警，由本地行情监控按止损价执行备用止损」。

   已决定：同意推荐做法，完整版 Proposal 已经照改，spec 和 design 不变。
2. **触发以后、撤单结束以前价格回升，还清不清仓，完整版没写。** 有挂着的订单时要等它们撤掉才能下清仓卖单，通常要 15 到 30 秒（巡检的一到两轮）。这段时间里跌幅可能回到阈值以内，或者价格回到止损价以上。
   推荐做法（spec 已按它写）：当天触发过的股票做到底，价格回升也照样清仓。
   - 和券商端止损单一致：止损单触发以后就是市价卖出，不会因为价格回升收回
   - 撤单和作废已经做了：价格回升就不卖的话，这只股票的订单被撤、方案被作废，却什么都没卖，状态更乱
   - 只在当天：清仓方案每只股票每天一个，第二天按新的前一交易日收盘价重新判定
   - 进程在这十几秒里重启时记录会丢，重启以后按当时的价格重新判定（见 design 省略清单）

   完整版的改法：「紧急风险退出的触发」末尾加一条「触发以后当天做到底：等撤单结束期间价格回升也照样清仓；本地备用止损相同」。

   已决定：同意推荐做法，完整版 Proposal 已经照改，spec 和 design 不变。
