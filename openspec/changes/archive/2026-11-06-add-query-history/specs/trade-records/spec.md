## MODIFIED Requirements

### Requirement: 保存交易记录

执行模块 SHALL 把交易记录保存在存储中，可以按客户端订单 ID 读取，可以列出累计成交大于 0 的全部交易记录，也可以按股票读某个时刻累计成交大于 0 的交易记录：每条取写入时刻早于这个时刻的最新版本（state-store spec「读取某个时刻的版本」），这个版本累计成交大于 0 才给出。数据库实现按 state-store spec 的只追加版本表保存在交易记录表里，列出时只看每条的最新版本。进程重启后，执行模块 SHALL 从存储读出交易记录，给出同样的已结算资金和最近成交日。

#### Scenario: 列出有成交的交易记录

- **GIVEN** P1 全部成交；P5 已撤销，累计成交 0；BBB-STOP-1 部分成交，累计成交 40
- **WHEN** 列出有成交的交易记录
- **THEN** 结果是 P1 和 BBB-STOP-1 的交易记录，都是最新版本；没有 P5

#### Scenario: 交易记录原样读回

- **GIVEN** P1 的交易记录：部分成交 30 股，成交均价 49.9533333333，累计费用 2.15，创建时刻 2026-10-14 15:00Z，成交日 2026-10-14，结算日 2026-10-15
- **WHEN** 保存，再按 P1 读取
- **THEN** 读到的交易记录和保存的相同

#### Scenario: 重启后给出同样的账户数据

- **GIVEN** 「盘中当天的卖出未结算」场景的数据
- **WHEN** 进程重启（用同一个存储重新创建执行模块），2026-10-14 19:00Z 读取账户数据
- **THEN** 已结算资金 33,940，AAA 的最近成交日是 2026-10-14

#### Scenario: 按股票读某个时刻的交易记录

- **GIVEN** BBB 的 P1 在 14:00Z 写入已提交、累计成交 0，14:30Z 写入部分成交 30 股，15:30Z 写入全部成交 100 股；AAA 的 P3 在 14:20Z 写入全部成交
- **WHEN** 按 15:00Z 读 BBB 的交易记录
- **THEN** 只有 P1，累计成交 30
- **WHEN** 按 14:10Z 读 BBB 的交易记录
- **THEN** 为空
