## MODIFIED Requirements

### Requirement: 读取案件记录

案件记录 SHALL 提供下面的读取：

| 读取 | 给出 |
| --- | --- |
| 按案件 ID 读案件记录 | 这个案件的记录；没有这个案件的记录时报错 |
| 按案件 ID 读方案记录 | 这个案件的方案记录；没有交易方案的案件没有 |
| 按案件 ID 读发现 | 这个案件的发现，按写入的顺序；没有时为空 |
| 一只股票最近结束的案件 | 股票是这只股票、状态是已结束的案件，按结束时刻从晚到早，最多给定的个数；进行中和不再运行的不算 |
| 一只股票已结束的全部案件 | 股票是这只股票、状态是已结束的案件，按结束时刻从晚到早，时刻相同的按案件 ID；进行中和不再运行的不算 |
| 最近一次得出结论的案件 | 给定案件类型（针对一只股票的类型再给定股票），有结论的案件里结论时刻最晚的一个，进行中的也算；没有时没有 |

读取不写任何东西。

#### Scenario: 按案件 ID 读

- **GIVEN** 15:00Z 开始 K-1；15:20Z 写 K-1 的结论；写审核（通过）；20:10Z 开始 K-3；20:30Z 写 K-3 的结论；K-2 写了三项发现
- **WHEN** 按案件 ID 读 K-1
- **THEN** 案件记录是进行中、带 K-1 的结论；方案记录是方案 P-1 和一次审核；发现为空
- **WHEN** 按案件 ID 读 K-3
- **THEN** 没有方案记录
- **WHEN** 按案件 ID 读 K-2 的发现
- **THEN** 依次是 DDD、EEE、AAA 三项
- **WHEN** 按案件 ID 读 K-9 的案件记录，K-9 没有写过
- **THEN** 报错

#### Scenario: 一只股票最近结束的案件

- **GIVEN** CCC 的案件：15:00Z 开始 K-5、15:30Z K-5 结束（人工拒绝，2，6）；16:00Z 开始 K-6、16:03Z K-6 结束（复盘完成，0，1）；20:10Z 开始 K-3、20:12Z K-3 结束（系统故障，0，2）；20:15Z 写 CCC 的跟进 K-11 不再运行；20:20Z 开始 CCC 的持仓跟进 K-10，还在进行
- **WHEN** 读 CCC 最近结束的案件，最多 2 个
- **THEN** 依次是 K-3、K-6
- **WHEN** 读 CCC 最近结束的案件，最多 5 个
- **THEN** 依次是 K-3、K-6、K-5，没有 K-10 和 K-11
- **WHEN** 读 BBB 最近结束的案件，最多 5 个
- **THEN** 为空

#### Scenario: 最近一次得出结论的案件

- **GIVEN** 2026-10-13 的寻股 K-12 在 2026-10-13 20:30Z 得出结论、结束；20:05Z 开始 K-2，20:30Z 写 K-2 的结论，20:31Z K-2 结束（没有交易方案，3，8）；2026-10-15 的寻股 K-13 在唤醒 PM 时因系统故障结束，没有结论
- **WHEN** 读寻股最近一次得出结论的案件
- **THEN** 是 K-2，结论时刻 20:30Z
- **GIVEN** AAA 的候选评估 K-7 在 2026-10-13 21:00Z 得出结论；DDD 没有候选评估得出过结论
- **WHEN** 读 AAA 的候选评估最近一次得出结论的案件；读 DDD 的
- **THEN** AAA 的是 K-7；DDD 的没有
- **GIVEN** 15:00Z 开始 K-1；15:20Z 写 K-1 的结论，方案在等人工确认
- **WHEN** 读 BBB 的关注股事件最近一次得出结论的案件
- **THEN** 是 K-1，虽然它还在进行

#### Scenario: 一只股票已结束的全部案件

- **GIVEN** CCC 的案件：15:00Z 开始 K-5、15:30Z K-5 结束（人工拒绝，2，6）；16:00Z 开始 K-6、16:03Z K-6 结束（复盘完成，0，1）；20:15Z 写 CCC 的跟进 K-11 不再运行；20:20Z 开始 CCC 的持仓跟进 K-10，还在进行
- **WHEN** 读 CCC 已结束的全部案件
- **THEN** 依次是 K-6、K-5，没有 K-10 和 K-11
- **WHEN** 读 BBB 已结束的全部案件
- **THEN** 为空
