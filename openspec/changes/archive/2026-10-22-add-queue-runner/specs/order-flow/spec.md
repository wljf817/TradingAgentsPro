# Spec Delta

## ADDED Requirements

### Requirement: 作废案件的方案

排队运行要求作废一个案件的方案时（queue-runner spec「作废方案」），这个方案的下单流程 SHALL 按它这时在做什么处理：

| 下单流程 | 处理 | 送回案件 |
| --- | --- | --- |
| 在等确认 | 报告确认消息已作废（discord-notification spec「结束确认」）；拿锁释放全部预留；下单流程结束；不告警 | 方案被作废 |
| 已经确认，在等开盘或者等重试 | 拿锁释放全部预留；报告确认消息已作废（消息上的已确认改为已作废）；推送告警（见「告警」）；下单流程结束 | 方案被作废 |
| 正在做一步（请求确认、再校验和提交），或者在两步之间 | 这一步做完再看：接下来要等确认、等开盘或者等重试的，按上面两行作废；这一步提交了订单、作废了方案的，按下一行 | 按上面两行或者下一行 |
| 已经结束：拒绝、确认超时、确认请求发不出去、订单交给盘中巡检、再校验作废 | 不再处理 | 不再送回 |

- 作废时这个方案已经有订单（比如提交时出了意外的错，订单已经建立）：不释放预留、不报告确认消息、不告警，订单交给盘中巡检，送回订单已提交（同「提交的结果」）
- 释放预留写程序日志的释放预留，原因写明这只股票有新案件排队、方案作废；报告确认消息已作废由通知模块写程序日志的结束确认（program-log spec「系统的动作」）
- 作废和确认按钮的结果都送到时，按下单流程收到的先后处理：先收到确认的照常进入「等开盘」，盘中马上提交了订单的，之后的作废不再处理
- 作废送到以后、处理以前进程退出：重启以后照样作废（见「持久化和恢复」）
- 只有案件的方案会被排队运行作废：`/plan` 录入的方案不会

本要求的场景使用「案件的方案」的数据。

#### Scenario: 等确认时作废

- **GIVEN** K1 交来 P1，P1 的确认消息已经发出，截止时刻 2026-10-14 15:30Z
- **WHEN** 15:05Z 排队运行要求作废 P1
- **THEN** 确认消息去掉按钮，显示已作废和 15:05Z；BBB 没有有效预留；送回 K1：方案被作废；没有告警
- **AND** 程序日志依次有 P1 的结束确认（已作废）和释放预留（原因写明 BBB 有新案件排队、方案作废）
- **AND** 到了 15:30Z 以后没有 P1 的确认超时，确认消息仍显示已作废

#### Scenario: 请求确认时送到

- **GIVEN** K1 交来 P1，Discord 发 P1 的确认消息很慢
- **WHEN** 确认消息还没发出去时排队运行要求作废 P1，之后确认消息发出
- **THEN** 确认消息随后改为已作废；BBB 没有有效预留；送回 K1：方案被作废

#### Scenario: 等开盘时作废

- **GIVEN** 当前时刻 2026-10-14 21:00Z；K1 交来 P1，21:05Z 按确认，下单流程在等 2026-10-15 13:30Z
- **WHEN** 22:00Z 排队运行要求作废 P1
- **THEN** BBB 没有有效预留；确认消息由已确认改为已作废；推送一条告警，写明 P1 作废、不会下单、买入 BBB 20 股、方案 ID 和原因 BBB 有新案件排队
- **AND** 依次送回 K1：已确认、方案被作废
- **AND** 到了 2026-10-15 13:30Z，券商没有收到 P1 的订单

#### Scenario: 等重试时作废

- **GIVEN** K1 交来 P1；15:05Z 按确认，再校验以前读券商账户超时，下单流程等重试
- **WHEN** 15:05:10Z 排队运行要求作废 P1
- **THEN** BBB 没有有效预留，推送一条作废的告警；依次送回 K1：已确认、方案被作废
- **AND** 15:05:30Z 以后券商没有收到 P1 的订单

#### Scenario: 已经下单以后送到

- **GIVEN** K1 交来 P1
- **WHEN** 15:05Z 按确认，券商受理 P1；之后排队运行要求作废 P1
- **THEN** 不再处理：BBB 的预留仍是 20 股，确认消息仍显示已确认，没有告警
- **AND** K1 一共收到已确认、订单已提交

#### Scenario: 已经有订单

- **GIVEN** K1 交来 P1；15:05Z 按确认，提交 P1 时券商回答 401，P1 的订单已经建立、还是待提交，下单流程等重试
- **WHEN** 15:05:10Z 排队运行要求作废 P1
- **THEN** 不释放预留，没有作废的告警；订单交给盘中巡检；依次送回 K1：已确认、订单已提交

#### Scenario: 作废送到以后进程退出

- **GIVEN** 当前时刻 2026-10-14 21:00Z；K1 交来 P1，21:05Z 按确认，下单流程在等开盘；22:00Z 排队运行要求作废 P1，下单流程处理以前进程退出
- **WHEN** 程序重启
- **THEN** P1 作废：BBB 没有有效预留，送回 K1 方案被作废
- **AND** 2026-10-15 13:30Z 券商没有收到 P1 的订单

## MODIFIED Requirements

### Requirement: 结果送回案件

案件的方案的下单流程 SHALL 在下表的每个结局把结果按案件 ID 送回案件，`/plan` 录入的方案不送：

| 下单流程 | 送回 |
| --- | --- |
| 收下确认（「确认的结果」） | 已确认 |
| 收下拒绝 | 已拒绝 |
| 确认超时；确认请求发不出去 | 已超时 |
| 订单交给盘中巡检：提交返回订单（包括券商拒绝受理、状态未知），或者作废时这个方案已经有订单 | 订单已提交 |
| 确认以后（或者不要确认的方案）作废：再校验拒绝、到有效期还没下单、对账不一致 | 再校验作废 |
| 排队运行要求作废，在等确认、等开盘或者等重试（「作废案件的方案」） | 方案被作废 |
| 意料之外的错误让下单流程停下（比如释放预留时状态库出错） | 出错；送回以后下单流程停下 |

- 已确认在确认以后立即送回，然后才等开盘；不要确认的方案不送已确认
- 每个结局只送一次：进程重启以后已经送回的不再送
- 释放预留、告警和程序日志照「确认的结果」「下单前再校验和提交」「提交的结果」「告警」「日志」，送回结果不改变它们
- 等开盘、等重试时，除了被作废，不送回：案件在等下单时一直等（case-stages spec「等下单」）

#### Scenario: 确认以后下单

- **GIVEN** K1 交来 P1
- **WHEN** 2026-10-14 15:05Z 按确认，券商受理 P1
- **THEN** 依次送回 K1：已确认、订单已提交

#### Scenario: 拒绝和超时

- **GIVEN** K1 交来 P1
- **WHEN** 按拒绝
- **THEN** 送回 K1：已拒绝；BBB 没有有效预留
- **WHEN** 同样的情况下一直没有人按到 2026-10-14 15:30Z
- **THEN** 送回 K1：已超时

#### Scenario: 确认请求发不出去

- **GIVEN** Discord 对发消息报错
- **WHEN** K1 交来 P1
- **THEN** 送回 K1：已超时；BBB 没有有效预留

#### Scenario: 盘后确认等到开盘

- **GIVEN** 当前时刻 2026-10-14 21:00Z；K1 交来 P1，生效的有效期 2026-10-15 20:00Z
- **WHEN** 21:05Z 按确认
- **THEN** 送回 K1：已确认；没有别的结果
- **WHEN** 到了 2026-10-15 13:30Z，BBB 最新价 50，券商受理 P1
- **THEN** 送回 K1：订单已提交

#### Scenario: 再校验作废

- **GIVEN** 当前时刻 2026-10-14 21:00Z；K1 交来 P1，21:05Z 按确认
- **WHEN** 2026-10-15 13:30Z，BBB 最新价 53
- **THEN** P1 作废，原因是"价格偏离"；依次送回 K1：已确认、再校验作废

#### Scenario: 到有效期作废

- **GIVEN** 案件 K4 交来 P4，Critic 审核的结果是通过；AAA 一直是无保护仓位
- **WHEN** 2026-10-14 19:59Z 按确认，到了 20:00Z 以后
- **THEN** P4 作废，原因是有效期；依次送回 K4：已确认、再校验作废

#### Scenario: 被排队运行作废

- **GIVEN** K1 交来 P1
- **WHEN** 等确认时排队运行要求作废 P1
- **THEN** 送回 K1：方案被作废
- **WHEN** 另一种情况下，当前时刻 2026-10-14 21:00Z，21:05Z 按确认，在等开盘时排队运行要求作废 P1
- **THEN** 依次送回 K1：已确认、方案被作废

#### Scenario: 券商拒绝受理也是订单已提交

- **GIVEN** K1 交来 P1；券商会拒绝受理 P1
- **WHEN** 按确认
- **THEN** P1 的订单已拒绝，推送一条告警；依次送回 K1：已确认、订单已提交

#### Scenario: 自动执行的方案

- **GIVEN** 模型退出自动执行打开
- **WHEN** K3 交来 P3，P3 有订单
- **THEN** 只送回 K3 一个结果：订单已提交

#### Scenario: 意料之外的错误

- **GIVEN** K1 交来 P1；按拒绝以后释放预留时状态库会出错
- **WHEN** 按拒绝
- **THEN** 送回 K1：出错；P1 的下单流程出错停下
- **AND** 没有再送回别的结果

#### Scenario: 重启以后不重送

- **GIVEN** 当前时刻 2026-10-14 21:00Z；K1 交来 P1，21:05Z 按确认，已经送回已确认
- **WHEN** 程序在 2026-10-14 23:00Z 重启；2026-10-15 13:30Z 券商受理 P1
- **THEN** K1 一共收到两个结果：已确认、订单已提交

#### Scenario: /plan 的方案不送回

- **WHEN** 本人用 `/plan` 提交 P1，按确认，券商受理 P1
- **THEN** 没有送给任何案件的结果

### Requirement: 告警

下单流程 SHALL 只为下面这些结果推送告警（discord-notification spec「告警」）：

| 结果 | 告警的内容 |
| --- | --- |
| 已经确认的方案作废：再校验拒绝、到有效期还没下单、对账不一致、排队运行作废（「作废案件的方案」） | 方案作废、不会下单；动作、股票、股数、方案 ID；原因：再校验拒绝的写每条不通过的规则和说明，到有效期的写最近一次没能下单的原因（有的话），对账不一致的写暂停开仓，排队运行作废的写这只股票有新案件排队 |
| 下单被券商拒绝 | 下单被券商拒绝；动作、股票、股数、方案 ID |
| 这个方案第一次出意外的错 | 下单出错和错误；动作、股票、方案 ID；每隔重试间隔重试，到有效期为止 |
| 案件的方案确认超时或确认请求发不出去，「案件的方案」决定超时以后告警（退出类方案） | 确认超时（或者确认请求没有发出去）、方案没有执行；动作、股票、股数、方案 ID；持仓的止损单照挂 |

不要人工确认的方案作废时，按第一行告警。

下面这些 SHALL NOT 告警，只写日志：人工拒绝、确认超时（确认消息已改为已超时）、确认请求发不出去（上表最后一行的除外）、在等确认时被排队运行作废（确认消息已改为已作废）、等开盘、等重试、订单已提交、订单状态未知。

推送告警时 MUST NOT 拿着锁。告警发不出去时按 discord-notification spec 只写错误日志，下单流程照常继续。

#### Scenario: 再校验拒绝的告警

- **GIVEN** 当前时刻 2026-10-14 21:00Z；提交 P1，21:05Z 按确认
- **WHEN** 2026-10-15 13:30Z，BBB 最新价 53
- **THEN** 告警写明：P1 作废，不会下单；买入 BBB 20 股；方案 ID；价格偏离：实时价 53 偏离限价 50 超过允许的 0.03

#### Scenario: 到有效期的告警

- **GIVEN** 已经提交 P4；AAA 一直是无保护仓位；2026-10-14 19:59Z 按确认
- **WHEN** 到了 2026-10-14 20:00Z 以后
- **THEN** 告警写明：P4 作废，不会下单；加仓 AAA 5 股；原因是到了有效期，最近一次没能下单的原因是 AAA 是无保护仓位

#### Scenario: 排队运行作废已经确认的方案的告警

- **GIVEN** 当前时刻 2026-10-14 21:00Z；K1 交来 P1，21:05Z 按确认
- **WHEN** 22:00Z 排队运行要求作废 P1
- **THEN** 告警写明：P1 作废，不会下单；买入 BBB 20 股；方案 ID；原因是 BBB 有新案件排队
- **WHEN** 另一种情况下，K1 交来 P1，还在等确认时排队运行要求作废 P1
- **THEN** 没有告警

#### Scenario: 人工拒绝和确认超时不告警

- **GIVEN** 已经提交 P1 和 P2
- **WHEN** 按 P1 的拒绝，P2 一直没有人按到截止时刻
- **THEN** 没有告警

#### Scenario: 案件的退出方案确认超时的告警

- **GIVEN** K3 交来 P3，一直没有人按按钮
- **WHEN** 到了 2026-10-14 15:30Z
- **THEN** 告警写明：P3 确认超时，没有执行；清仓 AAA 10 股；方案 ID；持仓的止损单照挂

#### Scenario: 告警发不出去

- **GIVEN** 当前时刻 2026-10-14 21:00Z；提交 P1，21:05Z 按确认；之后 Discord 报错
- **WHEN** 2026-10-15 13:30Z，BBB 最新价 53
- **THEN** 有一条错误日志，含告警文字和失败原因
- **AND** P1 照常作废，BBB 没有有效预留，下单流程结束
