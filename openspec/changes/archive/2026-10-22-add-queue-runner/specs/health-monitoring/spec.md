# Spec Delta

## MODIFIED Requirements

### Requirement: 健康信号

健康判定 SHALL 按下表拼健康信号（degraded-mode spec「健康检查」）：

| 信号 | 取值 | 理由 |
| --- | --- | --- |
| PM、Critic 还有可用的模型 | Agent 网关的备用模型给出的（model-fallback spec「还有可用的模型」） | 主模型和备用模型全部在冷却中才算没有 |
| 持仓保留预算用完 | Agent 网关现在的预算的情况（call-budget spec「预算用完」） | 每次判定重新读，收盘以后跟着恢复 |
| 调度器最近一次心跳 | 排队运行给出的（queue-runner spec「调度器心跳」） | 排队运行停了或者一直出错时，心跳不再前进 |
| 券商连接 | 这一轮第 3 步读券商的全部持仓：读到为连接，超时或断线为断开 | 巡检每一轮都读，不再另外调用券商 |
| 行情最近一次更新的时刻 | 这一轮取到的参考股票的更新时刻（market-data spec「行情最近一次更新的时刻」）；报行情不可用时，用程序启动以后最近一次取到的更新时刻，还没有取到过时为没有，并写一条 WARNING 写明取不到行情和原因 | 一次取不到不等于行情停了：数据延迟仍按数据延迟上限判断 |

- 每一轮都取一次行情，盘外也取；盘外不检查数据延迟（degraded-mode spec），取不到也不算异常
- 只有第 3 步的读取算券商连接：第 1 步跟进订单、第 3 步对齐时的超时和断线按 order-lifecycle spec、stop-protection spec 记为状态未知，不算断开
- 第 3 步读全部持仓出了超时、断线以外的错，或者第 3 步没有读，这一轮不判定，见「健康判定的失败」
- 读预算的情况出错（数据库出错）时，按「健康判定的失败」的判定时出了意外的错处理

本要求的场景里，排队运行照常运行，每次判定以前 5 秒以内做完过一轮；PM 和 Critic 都还有可用的模型；三个预算今天都没用完。另有说明的除外

#### Scenario: 读全部持仓超时算券商断开

- **WHEN** 券商断开，做一轮
- **THEN** 第 3 步读取全部持仓超时，巡检写 WARNING（session-patrol spec「一轮里的失败」）
- **AND** 判定的异常的检查是券商连接

#### Scenario: 跟进订单超时不算券商断开

- **GIVEN** P1 已经提交，订单已提交
- **WHEN** 做一轮，按 P1 查询时超时，第 3 步读取全部持仓正常
- **THEN** P1 状态未知
- **AND** 状态是正常，没有异常的检查

#### Scenario: 一次取不到行情按上一次取到的时刻

- **GIVEN** 14:59:45Z 做过一轮，取到 SPY 的更新时刻 14:59:35Z
- **WHEN** OpenD 断开，15:00:00Z 做一轮
- **THEN** 有一条 WARNING 写明取不到行情和 OpenD 给出的原因
- **AND** 行情最近一次更新的时刻按 14:59:35Z（延迟 25 秒），状态是正常
- **WHEN** OpenD 仍然断开，15:00:30Z 做一轮（延迟 55 秒）
- **THEN** 状态是正常
- **WHEN** OpenD 仍然断开，15:00:45Z 做一轮（延迟 70 秒）
- **THEN** 状态是降级，异常的检查是数据延迟
- **WHEN** OpenD 恢复，之后两轮
- **THEN** 第一轮以后是等待对账；第二轮对账，状态是正常

#### Scenario: 启动以后还没取到过行情

- **GIVEN** 程序 15:00Z 启动，OpenD 没开，启动以后还没取到过行情
- **WHEN** 15:00:10Z 做一轮
- **THEN** 有一条 WARNING 写明取不到行情
- **AND** 行情最近一次更新的时刻按没有，从当天开盘 13:30Z 起算延迟；状态是降级，异常的检查是数据延迟

#### Scenario: 行情停更

- **GIVEN** OpenD 连着，但 SPY 的更新时刻停在 14:58:00Z
- **WHEN** 15:00Z 做一轮
- **THEN** 没有取不到行情的 WARNING
- **AND** 状态是降级，异常的检查是数据延迟

#### Scenario: 盘外取不到行情不算异常

- **GIVEN** 当前时刻 2026-10-14 21:00Z（盘后），OpenD 断开
- **WHEN** 做一轮
- **THEN** 有一条 WARNING 写明取不到行情
- **AND** 状态是正常

#### Scenario: 一轮做得久不算调度器心跳异常

- **GIVEN** 这一轮从 15:00Z 开始，券商很慢，第 3 步做完时已经 15:06Z；排队运行 15:05:58Z 做完一轮
- **WHEN** 判定
- **THEN** 没有异常的检查

#### Scenario: 调度器心跳停了

- **GIVEN** 排队运行最近一次做完一轮是 14:54:59Z，之后每一轮都出错
- **WHEN** 15:00Z 做一轮
- **THEN** 状态是降级，异常的检查是调度器心跳；推送一条进入降级模式的告警
- **WHEN** 排队运行恢复，照常做完每一轮；之后两轮
- **THEN** 第一轮以后是等待对账；第二轮对账，状态是正常

#### Scenario: PM 没有可用的模型

- **GIVEN** PM 的主模型和备用模型都在冷却中（model-fallback spec「熔断」）
- **WHEN** 做一轮
- **THEN** 状态是降级，异常的检查是模型 API

#### Scenario: 持仓保留预算用完

- **GIVEN** 今天持仓保留预算已经用完
- **WHEN** 做一轮
- **THEN** 状态是降级，异常的检查是调用预算
- **WHEN** 2026-10-14 20:00:15Z（收盘以后，下一个交易日）之后两轮
- **THEN** 第一轮以后是等待对账；第二轮对账，状态是正常

#### Scenario: 读预算时数据库出错

- **GIVEN** 状态是正常；读预算的情况时数据库连不上
- **WHEN** 做一轮
- **THEN** 有一条 ERROR，带异常栈，写明健康判定出错；这一轮没有判定，状态仍是正常
