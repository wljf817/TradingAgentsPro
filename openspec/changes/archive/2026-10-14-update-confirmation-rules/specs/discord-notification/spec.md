# Spec Delta

## ADDED Requirements

### Requirement: 紧急退出的确认消息

请求紧急退出的确认时 SHALL 给出代码触发的清仓方案（emergency-exit spec「代码触发的清仓方案」）、这只股票当前的持仓股数和原因（调用方写好的一段文字）。截止时刻按「确认请求和截止时刻」算：请求的时刻 + 确认超时。

请求 SHALL 往配置的频道发一条确认消息，带「确认」和「拒绝」两个按钮，依次写明：

| 内容 | 说明 |
| --- | --- |
| @配置的用户和动作 | 第一行：@用户，然后「请确认紧急退出：清仓」加股票 |
| 原因 | 调用方给出的原因 |
| 当前持仓 | 「当前持仓」加股数 |
| 确认以后 | 作废这只股票还没下单的方案，撤掉挂着的订单，订单都结束以后市价卖出全部可卖股数 |
| 拒绝或超时 | 今天不再紧急退出这只股票，止损单照挂 |
| 截止时刻 | 过了截止时刻按超时处理；用 Discord 的时间戳标记 |
| 方案 ID | |

确认的四种结果（「确认请求和截止时刻」）、「重复请求同一个方案」「按钮的处理」「结束确认」和发不出去时报通知不可用，SHALL 和交易方案的确认消息相同：按钮自带方案 ID、选择和截止时刻，结果交给同一个回调。

本要求的场景使用下面的数据：方案 E1 是 AAPL 交易日 2026-10-08 的代码触发的清仓方案，当前持仓 100 股，原因「个股跌幅 8.2%（参考价 200 → 最新价 183.6），达到紧急阈值 8.0%」；请求的时刻 2026-10-08 14:00Z，确认超时用默认值。

#### Scenario: 紧急退出的确认消息

- **WHEN** 请求紧急退出的确认 E1
- **THEN** 发出一条确认消息，第一行是 @本人 和「请确认紧急退出：清仓 AAPL」
- **AND** 消息写了原因、当前持仓 100 股、确认以后和拒绝或超时会怎样、截止时刻 2026-10-08 14:30Z 和 E1 的方案 ID
- **AND** 消息带「确认」「拒绝」两个按钮
- **AND** 返回这条消息的标识和截止时刻 14:30Z

#### Scenario: 按钮和交易方案的确认消息一样处理

- **GIVEN** 已经请求紧急退出的确认 E1
- **WHEN** 本人在 14:05Z 按「确认」
- **THEN** 回调收到 E1 的方案 ID 和「确认」，消息去掉按钮，显示已确认和 14:05Z
- **WHEN** 本人又按了一次「拒绝」
- **THEN** 他得到仅自己可见的提示，写明已确认；回调没有再被调用

#### Scenario: 截止时刻以后按下

- **GIVEN** 已经请求紧急退出的确认 E1
- **WHEN** 本人在 14:30Z 按「确认」
- **THEN** 回调没有被调用，消息去掉按钮，显示已超时

#### Scenario: 报告作废

- **GIVEN** 已经请求紧急退出的确认 E1，没有人按
- **WHEN** 调用方在 14:10Z 报告已作废
- **THEN** 消息去掉按钮，显示已作废和 14:10Z

#### Scenario: 重复请求紧急退出的确认

- **GIVEN** 已经请求紧急退出的确认 E1
- **WHEN** 再次请求紧急退出的确认 E1
- **THEN** 频道里只有一条 E1 的确认消息，返回这条消息的标识和截止时刻 14:30Z

#### Scenario: 紧急退出的确认发不出去

- **GIVEN** Discord 对发消息报错
- **WHEN** 请求紧急退出的确认 E1
- **THEN** 报通知不可用
