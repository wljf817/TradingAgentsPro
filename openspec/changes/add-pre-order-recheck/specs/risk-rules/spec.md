# Spec Delta

## MODIFIED Requirements

### Requirement: 交易方案的格式

交易方案 SHALL 包含方案 ID、股票、板块、动作、股数、订单类型、限价、止损价、紧急阈值、有效期、允许价格偏离。动作有四种：买入、加仓属于开仓类，减仓、清仓属于减仓类。

方案 ID 是 UUID，四种动作都必填。预留、成交、释放、人工确认和下单都用它指向这个方案，一个 ID 只对应一个方案。

各字段按动作的要求如下。不符合时，构造方案 SHALL 报格式错误：

| 字段 | 买入、加仓 | 减仓 | 清仓 |
| --- | --- | --- | --- |
| 股数 | 必填，正整数 | 必填，正整数 | 不填，表示卖出全部可卖数量 |
| 订单类型 | 只能是限价单 | 限价单或市价单 | 限价单或市价单 |
| 限价 | 必填，大于 0 | 限价单必填且大于 0；市价单不填 | 同减仓 |
| 止损价 | 必填，大于 0 | 不填 | 不填 |
| 紧急阈值 | 可以不填；填写时大于 0 且小于 1 | 不填 | 不填 |
| 有效期 | 可以不填；填写时是带时区的时刻 | 同买入 | 同买入 |
| 允许价格偏离 | 可以不填；填写时大于 0 且小于 1 | 不填 | 不填 |

有效期和允许价格偏离在下单前再校验时使用，见 pre-order-recheck spec。股票和板块 MUST 非空。方案 MUST NOT 包含方案 ID 和上表以外的字段。

除「没有方案 ID」以外，本 spec 场景里的方案都带方案 ID，不逐一写出。

#### Scenario: 合法的开仓方案和退出方案

- **WHEN** 构造买入方案：100 股，限价单，限价 50，止损价 45，不填紧急阈值
- **AND** 构造加仓方案：50 股，限价单，限价 110，止损价 95，有效期 2026-10-15 20:00Z，允许价格偏离 0.05
- **AND** 构造减仓方案：60 股，市价单
- **AND** 构造清仓方案：不填股数，限价单，限价 120，有效期 2026-10-15 20:00Z
- **THEN** 四个方案都构造成功

#### Scenario: 没有方案 ID

- **WHEN** 构造不填方案 ID 的买入方案或清仓方案，或者方案 ID 不是 UUID（比如 "plan-1"）
- **THEN** 报格式错误

#### Scenario: 股数不是正整数

- **WHEN** 构造买入或减仓方案，股数为 0 或 -10
- **THEN** 报格式错误

#### Scenario: 减仓没写股数，清仓写了股数

- **WHEN** 构造不填股数的减仓方案，或填了 100 股的清仓方案
- **THEN** 报格式错误

#### Scenario: 买入和加仓只能用限价单

- **WHEN** 构造市价单的买入方案或加仓方案
- **THEN** 报格式错误

#### Scenario: 限价和订单类型不一致

- **WHEN** 构造没写限价的限价单、写了限价的市价单，或者限价为 0 的限价单
- **THEN** 报格式错误

#### Scenario: 开仓方案没写止损价

- **WHEN** 构造不填止损价的买入方案，或者止损价为 0 的加仓方案
- **THEN** 报格式错误

#### Scenario: 退出方案写了止损价或紧急阈值

- **WHEN** 构造带止损价的减仓方案，或者带紧急阈值的清仓方案
- **THEN** 报格式错误

#### Scenario: 紧急阈值的格式边界

- **WHEN** 构造买入方案，紧急阈值为 0 或 1
- **THEN** 报格式错误

#### Scenario: 有效期没有时区

- **WHEN** 构造买入方案，有效期是不带时区的 2026-10-15 20:00
- **THEN** 报格式错误

#### Scenario: 退出方案写了允许价格偏离

- **WHEN** 构造带允许价格偏离 0.03 的减仓方案或清仓方案
- **THEN** 报格式错误

#### Scenario: 允许价格偏离的格式边界

- **WHEN** 构造买入方案，允许价格偏离为 0 或 1
- **THEN** 报格式错误

### Requirement: 风控的输入和判定

风控 SHALL 根据以下输入给出结果，相同的输入总是得到相同的结果：

- 交易方案
- 账户数据：权益；已结算资金（可以用于开仓的现金，不含未结算的卖出款）；持仓列表，每只持仓包含股票、板块、股数、均价、最新价、止损价；每只股票最近一次成交的交易日（最近成交日）
- 其他已通过、尚未结束的方案占用的预留，见「其他方案的预留计入额度」
- 今天的单日亏损熔断是否已经触发
- 当前时刻和交易日历
- 阈值配置

结果 SHALL 包含：结论（通过、调整或拒绝）；最终股数，拒绝时没有；生效的紧急阈值，只有开仓类方案通过或调整时才有；生效的有效期，通过或调整时才有；原因列表，每条写明是哪条规则以及说明。

生效的有效期：方案写了就用方案的，没写时是执行交易日的收盘时刻（执行交易日见「开仓类规则」）。四种动作都有。

判定方法：

1. 请求股数：买入、加仓、减仓是方案写的股数；清仓是这只股票的可卖数量
2. 按 1 股检查全部适用的规则，有任何一条不通过：结论为拒绝，原因是 1 股时不通过的全部规则
3. 请求股数通过全部适用的规则：结论为通过，最终股数等于请求股数，原因为空
4. 否则结论为调整：最终股数是能通过全部适用规则的最大股数，原因是请求股数下不通过的规则

买入和加仓都使用开仓类规则，并且按实际持仓计算：这只股票没有持仓就按新建仓计算，有持仓就按加仓计算，不看方案标的是买入还是加仓。减仓和清仓使用减仓类规则。

本 spec 的场景除非另有说明，都使用默认阈值和下面的基准数据：

- 当前时刻 2026-10-14 15:00Z（周三，盘中），交易日历是纽交所日历
- 权益 100,000；已结算资金 40,000
- 持仓 AAA：板块"科技"，100 股，均价 100，最新价 110，止损价 90；最近成交日 2026-10-05
- 没有其他方案的预留；单日亏损熔断没有触发
- 基准方案：买入 BBB，板块"医疗"，100 股，限价单，限价 50，止损价 45，不填紧急阈值；BBB 没有成交记录
- 以 AAA 为对象的方案，板块都是"科技"；以 BBB 为对象的方案，没有另外说明时板块是"医疗"

#### Scenario: 通过

- **GIVEN** 基准数据
- **WHEN** 检查基准方案
- **THEN** 结论为通过，最终股数 100，生效的紧急阈值 0.08，生效的有效期 2026-10-14 20:00Z，原因为空

#### Scenario: 生效的有效期

- **GIVEN** 基准数据
- **WHEN** 检查基准方案，有效期写为 2026-10-16 20:00Z
- **THEN** 生效的有效期是 2026-10-16 20:00Z
- **WHEN** 当前时刻改为 2026-10-14 21:00Z（盘后），检查不填有效期的基准方案
- **THEN** 生效的有效期是 2026-10-15 20:00Z
- **WHEN** 当前时刻改为 2026-10-14 15:00Z，检查减仓 AAA：60 股，市价单
- **THEN** 生效的有效期是 2026-10-14 20:00Z

#### Scenario: 多条规则限制股数时取最小

- **GIVEN** 基准数据，已结算资金改为 5,025
- **WHEN** 检查基准方案，股数改为 300
- **THEN** 结论为调整，最终股数 100
- **AND** 原因包括"已结算资金"和"单笔计划风险"

#### Scenario: 1 股都通不过时拒绝

- **GIVEN** 基准数据，已结算资金改为 50
- **WHEN** 检查基准方案
- **THEN** 结论为拒绝，没有最终股数，没有生效的紧急阈值和有效期，原因是"已结算资金"

#### Scenario: 拒绝时列出全部不通过的规则

- **GIVEN** 基准数据，单日亏损熔断已经触发
- **WHEN** 检查基准方案，止损价改为 50
- **THEN** 结论为拒绝，原因包括"单日亏损熔断"和"止损价"

#### Scenario: 按实际持仓判断新建仓还是加仓

- **GIVEN** 基准数据，最多持仓数设为 1
- **WHEN** 检查"买入 AAA"：10 股，限价 110，止损价 105
- **THEN** 按加仓计算，不需要新的持仓名额，结论为通过，最终股数 10
- **WHEN** 检查"加仓 BBB"：100 股，限价 50，止损价 45
- **THEN** 按新建仓计算，结论为拒绝，原因是"最多持仓数"

#### Scenario: 调整后的股数是能通过的最大股数

- **GIVEN** 任意账户数据、预留、熔断状态和合法的方案
- **WHEN** 结论为调整
- **THEN** 最终股数小于请求股数，并且通过全部适用的规则
- **AND** 最终股数再加 1 股，至少有一条规则不通过


### Requirement: 开仓类规则

买入和加仓 SHALL 检查下表的全部规则。比例上限都是"不超过"，等于上限时通过。"必须带止损价"由方案格式保证。

| 规则 | 通过的条件 | 不通过时 |
| --- | --- | --- |
| 已结算资金 | 方案股数 × 限价 ×（1 + 缓冲比例）≤ 已结算资金 − 开仓预留的资金之和 | 调整 |
| 单只仓位上限 | 这只股票的持仓市值 + 方案买入部分的市值 ≤ 权益 × 单只仓位比例 | 调整 |
| 单笔计划风险 | 这只股票合并后的计划风险 ≤ 权益 × 单笔风险比例 | 调整 |
| 组合合计风险 | 其他持仓的计划风险之和 + 这只股票合并后的计划风险 + 开仓预留的风险之和 ≤ 权益 × 合计风险比例 | 调整 |
| 板块集中度 | 同板块的持仓市值 + 同板块开仓预留的市值 + 方案买入部分的市值 ≤ 权益 × 板块比例 | 调整 |
| 最多持仓数 | 只对没有持仓的股票检查：持仓的股票、有开仓预留的股票和这只股票去重后的个数 ≤ 最多持仓数 | 拒绝 |
| 未完成的开仓方案 | 这只股票没有开仓预留 | 拒绝 |
| 最短交易间隔 | 这只股票有最近成交日时：从最近成交日到执行交易日的交易日个数（不含最近成交日，含执行交易日）≥ 最短交易间隔 | 拒绝 |
| 止损价 | 止损价 < 限价 | 拒绝 |
| 紧急阈值 | 方案没填时使用默认值；生效的紧急阈值在下限和上限之间（含两端） | 拒绝 |
| 允许价格偏离 | 方案没填时使用默认值；生效的允许价格偏离在下限和上限之间（含两端） | 拒绝 |
| 单日亏损熔断 | 今天的单日亏损熔断没有触发 | 拒绝 |

执行交易日：当前时刻在常规交易时段内时是当天的交易日，否则是下一个开盘的交易日。

#### Scenario: 已结算资金不足时调整

- **GIVEN** 基准数据，已结算资金改为 2,010
- **WHEN** 检查基准方案
- **THEN** 结论为调整，最终股数 40（40 × 50 × 1.005 恰好等于 2,010），原因是"已结算资金"

- **GIVEN** 基准数据
- **WHEN** 检查加仓 AAA：100 股，限价 110，止损价 105
- **THEN** 结论为调整，最终股数 81（11,000 + 81 × 110 = 19,910 ≤ 20,000），原因是"单只仓位上限"

#### Scenario: 超过单笔计划风险时调整

- **GIVEN** 基准数据
- **WHEN** 检查基准方案，股数改为 300
- **THEN** 结论为调整，最终股数 190（190 × 5.25 = 997.5 ≤ 1,000），原因是"单笔计划风险"

#### Scenario: 已有持仓风险超过上限时，不提高止损价就不能加仓

- **GIVEN** 基准数据
- **WHEN** 检查加仓 AAA：10 股，限价 110，止损价 90
- **THEN** 结论为拒绝，原因是"单笔计划风险"（加仓 1 股时合并后的计划风险就是 1,070.55）

#### Scenario: 超过组合合计风险时调整

- **GIVEN** 基准数据，另外持有 CCC：板块"能源"，400 股，均价 50，最新价 50，止损价 42（计划风险 3,300）

#### Scenario: 超过板块集中度时调整

### Requirement: 风控阈值配置

风控的阈值 SHALL 是可配置项，默认值如下：

| 配置项 | 默认值 | 含义 |
| --- | --- | --- |
| 单笔风险比例 | 0.01 | 一只股票的计划风险不超过权益的 1% |
| 合计风险比例 | 0.05 | 组合合计风险不超过权益的 5% |
| 单只仓位比例 | 0.20 | 一只股票的市值不超过权益的 20% |
| 板块比例 | 0.40 | 一个板块的市值不超过权益的 40% |
| 最多持仓数 | 8 | 持仓和有开仓预留的股票合计不超过 8 只 |
| 缓冲比例 | 0.005 | 费用和滑点缓冲是成交额的 0.5% |
| 最短交易间隔 | 1 | 同一股票两次交易至少相隔 1 个交易日 |
| 紧急阈值下限 | 0.03 | 方案的紧急阈值不低于 3% |
| 紧急阈值上限 | 0.20 | 方案的紧急阈值不高于 20% |
| 紧急阈值默认值 | 0.08 | 方案没填紧急阈值时使用 8% |
| 允许价格偏离下限 | 0.01 | 方案的允许价格偏离不低于 1% |
| 允许价格偏离上限 | 0.10 | 方案的允许价格偏离不高于 10% |
| 允许价格偏离默认值 | 0.03 | 方案没填允许价格偏离时使用 3% |

紧急阈值是一个跌幅比例；从什么价格算起，由紧急风险退出的变更定义，风控只检查它的范围。

允许价格偏离是实时最新价相对限价的比例，涨跌都算，只在下单前再校验时使用，见 pre-order-recheck spec；首次检查只检查它的范围。

#### Scenario: 不提供配置时使用默认值

- **WHEN** 不提供任何配置
- **THEN** 各配置项等于上表的默认值
