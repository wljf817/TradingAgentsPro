# Spec Delta

## ADDED Requirements

### Requirement: 中止这只股票的案件

一只股票开始紧急退出时，紧急退出 SHALL 中止这只股票正在运行的、复盘以外的案件。"开始紧急退出"指推送开始紧急退出的告警（「告警」的第一行）的那一次处理：这次运行里第一次按「一只股票的清仓」处理它当天的清仓，要确认的是确认以后的第一次；重启以后再推送一次开始紧急退出的告警（「重启以后」），以及本地备用止损越过确认以后重新开始的（「紧急退出的人工确认」），也各算一次。

这一次处理 SHALL 在写程序日志的紧急风险退出之后、拿锁之前依次：

1. 读运行中的案件：每个案件的案件 ID、案件类型、股票、是否还在调用模型，以及还没提交订单的方案，都取自案件的进展（case-workflow spec「案件的进展」），和 queue-runner spec「一轮」的表里这两项的取法相同
2. 取得这只股票的紧急退出的决定（case-queue spec「紧急退出」）
3. 把中止按案件 ID 交给决定里中止的案件（case-workflow spec「紧急退出中止」）

之后才拿锁做「一只股票的清仓」的第 1 到 4 步。

- 决定里作废的方案 SHALL NOT 另外交给下单流程：它们都属于中止的案件，还在审核的随案件结束，等人工确认、等下单的由案件交回下单流程作废（order-flow spec「案件中止时作废它的方案」）；它们的预留在这一项的第 2 步释放
- SHALL NOT 中止：在等紧急退出的确认、确认被拒绝、确认超时或确认请求发不出去的股票（「紧急退出的人工确认」）；等撤单结束的之后几轮；复盘案件；别的股票的案件
- 这只股票排队的案件不动：正在紧急退出的股票，排队运行不启动它的案件；清仓卖单结束以后按新的状态运行（queue-runner spec「一轮」）
- 降级模式下照常中止
- 读运行中的案件和交出中止 MUST NOT 拿着锁
- 读运行中的案件或交出中止出错（比如数据库出错）时，照「一轮里的失败」跳过这一项：这一轮不撤单、不清仓；之后的轮次从开始紧急退出重新做，紧急风险退出的程序日志再写一条

本要求的场景另外使用下面的运行中的案件（case-workflow spec），场景里没有写到的就没有：

- K-1：AAA 的持仓事件，在唤醒 PM
- K-2：AAA 的卖出复盘
- K-3：BBB 的持仓复查，在唤醒 PM
- K-4：AAA 的持仓复查，在等人工确认，方案 P6：加仓 AAA 5 股，限价 99，止损价 92，预留 5 股，没有订单
- "K-1 收到中止"指紧急退出把中止交给 K-1

#### Scenario: 开始紧急退出时中止

- **GIVEN** 运行中 K-1、K-2、K-3
- **WHEN** AAA 最新价 92，做一轮
- **THEN** K-1 收到中止；K-2、K-3 没有收到
- **AND** 交出 K-1 的中止在写 AAA 的紧急风险退出之后、AAA 的清仓方案的风控检查之前
- **AND** AAA 的清仓单已经建立：卖出 50 股；开始紧急退出的告警写明中止了 K-1（持仓事件）

#### Scenario: 没有运行中的案件

- **GIVEN** 运行中 K-3
- **WHEN** AAA 最新价 92，做一轮
- **THEN** 没有案件收到中止；开始紧急退出的告警没有写中止的案件

#### Scenario: 中止的案件的方案

- **GIVEN** 运行中 K-4
- **WHEN** AAA 最新价 92，做一轮
- **THEN** K-4 收到中止；P6 没有有效预留；AAA 的清仓单已经建立：卖出 50 股
- **AND** 开始紧急退出的告警写明中止了 K-4（持仓复查）、作废了 P6（加仓 AAA）
- **AND** 紧急退出没有把 P6 交给下单流程

#### Scenario: 熔断时每只持仓各中止

- **GIVEN** 运行中 K-1、K-3；当前权益 9,300
- **WHEN** 做一轮
- **THEN** K-1、K-3 都收到中止

#### Scenario: 降级模式下照常中止

- **GIVEN** 处于降级模式；运行中 K-1
- **WHEN** AAA 最新价 92，做一轮
- **THEN** K-1 收到中止

#### Scenario: 等确认时不中止，确认以后中止

- **GIVEN** 紧急退出要确认打开；运行中 K-1
- **WHEN** AAA 最新价 92，做一轮
- **THEN** 频道里出现 AAA 的确认消息；K-1 没有收到中止
- **WHEN** 15:05Z 按确认，之后一轮
- **THEN** K-1 收到中止；券商收到 AAA-STOP-1 的撤单请求

#### Scenario: 拒绝以后不中止

- **GIVEN** 紧急退出要确认打开；运行中 K-1；AAA 最新价 92 时做过一轮，已经请求确认
- **WHEN** 15:05Z 按拒绝，之后两轮
- **THEN** K-1 没有收到中止，照常运行

#### Scenario: 等撤单的轮次不再中止

- **GIVEN** 运行中 K-1；P2 的订单已提交；AAA-STOP-1 已经改为 30 股
- **WHEN** AAA 最新价 92，做一轮
- **THEN** K-1 收到中止；券商收到 P2 的撤单请求
- **WHEN** K-1 正在调用 PM、还没结束，券商回报 P2 仍是已受理、未结束，之后一轮
- **THEN** K-1 没有再收到中止

#### Scenario: 重启以后再开始时再中止

- **GIVEN** 运行中 K-1；AAA 最新价 92 时做过一轮，K-1 收到中止，券商收到了 P2 的撤单请求，P2 仍是已提交；K-1 结束以后程序重启，重启以后排队运行开始了 AAA 的持仓事件 K-5，在唤醒 PM
- **WHEN** AAA 最新价 91，巡检做第一轮
- **THEN** K-5 收到中止；推送一条开始紧急退出的告警，写明中止了 K-5（持仓事件）
- **AND** 券商没有再收到 P2 的撤单请求

#### Scenario: 读运行中的案件出错

- **GIVEN** 运行中 K-1；读运行中的案件时数据库会出错一次
- **WHEN** AAA 最新价 92，做一轮
- **THEN** 有一条 ERROR 写明紧急退出处理 AAA 出错，带异常栈；K-1 没有收到中止
- **AND** AAA 的清仓方案没有订单，券商没有收到 AAA-STOP-1 的撤单请求，没有开始紧急退出的告警
- **WHEN** 之后一轮
- **THEN** K-1 收到中止；AAA 的清仓单已经建立：卖出 50 股
- **AND** 程序日志有两条 AAA 的紧急风险退出

## MODIFIED Requirements

### Requirement: 一只股票的清仓

「紧急退出要确认」打开时，要清仓的股票先按「紧急退出的人工确认」处理，需要确认的在确认以后才做下面几步。开始紧急退出的那一次处理，先按「中止这只股票的案件」中止这只股票的案件，再做下面几步。

要清仓的每只股票 SHALL 在一次拿锁里依次：

1. 这只股票当天的清仓方案已经有订单：什么都不做（订单由巡检跟进）
2. 作废这只股票还没下单的方案：有有效预留、还没有订单的每个方案（开仓类和退出类都算，不论在等确认、等开盘还是等重试，当天的清仓方案除外），释放它的预留（risk-reservations spec）。案件的方案由中止的案件交回下单流程作废（「中止这只股票的案件」，order-flow spec「案件中止时作废它的方案」）；`/plan` 录入的方案由下单流程之后再校验时得到"方案已结束"而作废（order-flow spec、pre-order-recheck spec「已经结束的方案」）
3. 这只股票还有没结束的订单（买单和卖单）：其中有还没记下撤单要求的，就撤掉这只股票的订单（order-lifecycle spec「提前撤单」）；已经都有撤单要求的不再撤。这一项到此结束，等之后的轮次
4. 没有没结束的订单：用风控检查当天的清仓方案（熔断取紧急退出的当前状态，降级取健康监控的当前状态，同 order-flow spec「提交方案」），通过或调整时做下单前再校验，再校验通过或调整时按它的结果提交订单（order-lifecycle spec「提交订单」）

第 4 步的结果 SHALL 按下表处理：

| 结果 | 处理 |
| --- | --- |
| 检查或再校验拒绝（可卖数量为 0） | 不下单；这只股票当天的紧急退出结束；告警 |
| 提交返回订单 | 订单交给巡检跟进：卖单等止损单撤掉才提交给券商，撤掉以后由巡检的跟进提交；之后的结果见「告警」 |
| 提交时券商超时或断线 | 订单记为状态未知（order-lifecycle spec「券商调用失败时状态未知」），交给巡检跟进 |

- 清仓股数是再校验时的可卖数量：撤单之前和撤单期间的成交都已经计入券商持仓
- 第 4 步出了别的错（数据库出错、券商的认证错误、意外的异常），按「一轮里的失败」处理，之后的轮次再从第 1 步来

#### Scenario: 先撤掉挂着的订单，结束以后再清仓

- **GIVEN** P2 的订单已提交；AAA-STOP-1 已经改为 30 股
- **WHEN** AAA 最新价 92，做一轮
- **THEN** 券商收到 P2 的撤单请求；AAA 的清仓方案没有订单
- **AND** 推送一条告警，写明撤掉了 P2、订单结束以后清仓
- **WHEN** 券商回报 P2 变为撤销、累计成交 0，之后一轮
- **THEN** P2 已撤销，没有有效预留
- **AND** AAA 的清仓单已经建立：卖出 50 股，市价单

#### Scenario: 撤单期间有成交

- **GIVEN** P2 的订单已提交；AAA-STOP-1 已经改为 30 股
- **WHEN** AAA 最新价 92，做一轮
- **THEN** 券商收到 P2 的撤单请求
- **WHEN** 券商回报 P2 变为撤销、累计成交 10，券商持仓变为 40 股，之后一轮
- **THEN** AAA 的清仓单已经建立：卖出 40 股

#### Scenario: 撤单迟迟不结束

- **GIVEN** P2 的订单已提交；AAA-STOP-1 已经改为 30 股
- **WHEN** AAA 最新价 92，做一轮
- **THEN** 券商收到 P2 的撤单请求
- **WHEN** 券商回报 P2 仍是已受理、未结束，之后两轮
- **THEN** AAA 的清仓方案没有订单
- **AND** 券商一共只收到一次 P2 的撤单请求

#### Scenario: 作废这只股票还没下单的方案

- **GIVEN** P3：加仓 AAA 5 股，限价 99，止损价 92，在等确认，预留 5 股；P4：减仓 AAA 10 股，市价单，已经确认、在等重试，预留 10 股；P5 在等确认；三个方案都没有订单
- **WHEN** AAA 最新价 92，做一轮
- **THEN** P3、P4 没有有效预留；P5 仍然预留 100 股
- **AND** AAA 的清仓单已经建立：卖出 50 股
- **AND** 推送一条告警，写明作废了 P3、P4
- **WHEN** 之后对 P3 做下单前再校验
- **THEN** 结论为拒绝，原因是"方案已结束"

#### Scenario: 没有可卖的股数

- **GIVEN** P2 改为减仓 AAA 50 股，限价 93，订单已提交；AAA-STOP-1 已经撤销
- **WHEN** AAA 最新价 92，做一轮
- **THEN** 券商收到 P2 的撤单请求
- **WHEN** 券商回报 P2 变为全部成交（撤单生效之前成交）、累计成交 50，券商持仓变为 0，之后一轮
- **THEN** AAA 的清仓方案没有订单
- **AND** 推送一条告警，写明 AAA 没有可卖的股数，紧急退出结束
- **WHEN** 之后一轮
- **THEN** 没有关于 AAA 的新告警

#### Scenario: 提交时券商超时

- **GIVEN** BBB 从 14:50Z 起是无保护仓位，没有挂着的止损单；券商会一直拒绝挂 BBB 的止损单；券商受理下一笔订单时会超时
- **WHEN** BBB 最新价 35，做一轮
- **THEN** BBB 的清仓单状态未知
- **WHEN** 券商回报 BBB 的清仓单已受理、累计成交 0，2026-10-14 15:00:30Z 做一轮
- **THEN** 巡检按客户端订单 ID 查到它，BBB 的清仓单已提交；券商没有收到第二笔 BBB 的清仓单

### Requirement: 告警

紧急退出 SHALL 只为下面这些情况推送告警（discord-notification spec「告警」），对象是股票（熔断是 `account`）；通知模块把每条告警写进程序日志（program-log spec「系统的动作」）：

| 情况 | 告警写明 |
| --- | --- |
| 一只股票开始紧急退出：这次运行里第一次按「一只股票的清仓」处理它当天的清仓（需要确认的，是确认以后的第一次） | 股票；原因：个股跌幅写参考价、最新价、跌幅和紧急阈值，组合熔断，本地备用止损写无保护仓位或错开中、最新价和止损价；这一项做了什么：中止的案件（案件类型、案件 ID），作废的方案（动作、方案 ID），撤掉的订单（买卖方向、股数、方案 ID），已经建立的清仓单（股数），或者等订单都结束以后清仓，或者没有可卖的股数 |
| 熔断触发：这次运行里每个交易日第一次看到 | 前一交易日收盘时的权益、当前权益、单日亏损和它占前一交易日收盘时权益的比例、熔断比例；清仓全部持仓，撤掉全部买单，收盘前不再开仓。「紧急退出要确认」打开时写明每只持仓的清仓要确认 |
| 清仓单进入终态 | 全部成交：股票、卖出股数和成交均价。其他终态（已拒绝、已过期、已撤销）：股票、状态、累计成交和委托股数；今天不再清仓这只股票，剩下的持仓由止损单保护 |
| 之后的轮次里没有可卖的股数 | 股票；没有可卖的股数，紧急退出结束 |
| 到收盘还没有清仓单：当天开始、不在等确认的紧急退出，收盘以后的第一轮仍没有订单 | 股票；到收盘还没下清仓单（等撤单结束），今天不再清仓。同时拿锁释放当天清仓方案剩下的预留（有的话） |
| 紧急退出的确认超时 | 股票；到截止时刻没有确认，没有执行；今天不再紧急退出这只股票，止损单照挂 |
| 紧急退出的确认请求发不出去 | 股票；确认请求没有发出去，没有执行；今天不再紧急退出这只股票，止损单照挂 |
| 到收盘还在等确认：收盘以后的第一轮仍在等 | 股票；到收盘还没有确认，没有执行，今天不再紧急退出这只股票。同时报告确认消息已作废 |

- 一只股票开始紧急退出时，先写程序日志的紧急风险退出（原因），再做这一项；熔断触发时写程序日志的熔断，和熔断告警同时
- 其余只写程序日志（program-log spec）：撤单、作废的方案（释放预留）、清仓方案的风控检查和下单前再校验、建立清仓单（提交订单：股数和状态）、到收盘还没有清仓单时释放剩下的预留（有有效预留的话）。等订单结束的轮次 SHALL NOT 写
- 推送告警 MUST NOT 拿着锁。发不出去时按 discord-notification spec 写错误日志，告警的条目写明没有发出去；紧急退出照常继续，之后不重发
- 告警过什么只记在内存里：进程重启以后见「重启以后」

#### Scenario: 开始紧急退出的告警

- **GIVEN** AAA 最新价 92
- **WHEN** 做一轮
- **THEN** 推送一条告警，写明 AAA、个股跌幅、参考价 100、最新价 92、跌幅 8.0%、紧急阈值 8.0%、已建立清仓单卖出 50 股
- **AND** 程序日志依次有：AAA 的紧急风险退出（原因写个股跌幅 8.0%、参考价 100、最新价 92、紧急阈值 8.0%）、清仓方案的风控检查、下单前再校验、提交订单（清仓 AAA 50 股，市价单，待提交），最后是这条告警，内容和推送的相同

#### Scenario: 熔断告警的内容

- **GIVEN** 当前权益 9,300
- **WHEN** 做一轮
- **THEN** 熔断告警写明前一交易日收盘时的权益 10,000、当前权益 9,300、单日亏损 700（7.0%）、熔断比例 7.0%，清仓全部持仓、撤掉全部买单、收盘前不再开仓

#### Scenario: 清仓完成的告警

- **GIVEN** 接着「盘中一轮里触发并清仓」，券商已经收到 AAA 的清仓单
- **WHEN** 券商回报 AAA 的清仓单全部成交、累计成交 50、成交均价 91.5，券商持仓变为 0，之后一轮
- **THEN** 推送一条告警，写明 AAA 紧急清仓完成，卖出 50 股，成交均价 91.5
- **WHEN** 之后一轮
- **THEN** 没有关于 AAA 的新告警

#### Scenario: 清仓被拒的告警

- **GIVEN** AAA 最新价 92，做一轮，AAA 的清仓单已经建立；券商会拒绝下一笔订单
- **WHEN** 券商回报 AAA-STOP-1 变为撤销，之后一轮
- **THEN** 推送一条告警，写明 AAA 的清仓单已拒绝、成交 0 / 50 股、今天不再清仓 AAA、剩下的持仓由止损单保护

#### Scenario: 到收盘还没有清仓单

- **GIVEN** 当前时刻 2026-10-14 19:59:50Z；P2 的订单已提交，AAA-STOP-1 已经改为 30 股；AAA 最新价 92，做一轮，券商收到 P2 的撤单请求
- **WHEN** 券商回报 P2 仍是已受理、未结束，2026-10-14 20:00:05Z 之后一轮
- **THEN** 推送一条告警，写明 AAA 到收盘还没下清仓单，今天不再清仓
- **AND** AAA 的清仓方案没有订单，也没有有效预留

#### Scenario: 告警发不出去

- **GIVEN** AAA 最新价 92；Discord 报错
