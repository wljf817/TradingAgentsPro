# Spec Delta

## ADDED Requirements

### Requirement: 案件中止时作废它的方案

案件在等人工确认或等下单时被紧急退出中止，把方案交回下单那一侧（case-workflow spec「紧急退出中止」）时，这个方案的下单流程 SHALL 按「作废案件的方案」的表处理，下表几项除外：

| 项 | 排队运行要求作废 | 案件中止时交回 |
| --- | --- | --- |
| 释放预留的原因 | 这只股票有新案件排队、方案作废 | 这只股票的紧急退出作废还没下单的方案 |
| 已经确认、在等开盘或等重试时 | 推送作废的告警 | SHALL NOT 告警 |
| 送回案件 | 照「结果送回案件」 | SHALL NOT 送回 |

- 紧急退出通常已经在它那一项里释放了这个方案的预留（emergency-exit-flow spec「一只股票的清仓」第 2 步）：这时释放什么也不改，不写释放预留（program-log spec「风控引擎的动作」）
- 不告警：开始紧急退出的告警已经写明中止的案件和作废的方案
- 不送回：案件已经结束。这个方案已经有订单的，照样交给盘中巡检，也不送回
- 确认消息照样改为已作废：在等确认的去掉按钮，已经确认的由已确认改为已作废
- 交回以后、处理以前进程退出：重启以后照样作废（见「持久化和恢复」）
- `/plan` 录入的方案没有案件，不会被交回

本要求的场景使用「案件的方案」的数据，另外：案件 K4 交来 P4，Critic 审核的结果是通过；"K4 交回 P4"指 K4 被紧急退出中止，把 P4 交回下单流程；"AAA 是无保护仓位"指 AAA 的止损单补挂成功以前，加仓的提交被执行模块拒绝，下单流程等重试。

#### Scenario: 等确认时交回

- **GIVEN** K4 交来 P4，P4 的确认消息已经发出；AAA 的紧急退出已经释放了 P4 的预留
- **WHEN** 15:05Z K4 交回 P4
- **THEN** 确认消息去掉按钮，显示已作废和 15:05Z；P4 的下单流程结束
- **AND** 程序日志有 P4 的结束确认（已作废），没有 P4 的释放预留
- **AND** 没有告警；没有送给 K4 的结果

#### Scenario: 交回时预留还在

- **GIVEN** K4 交来 P4，P4 的确认消息已经发出，AAA 有 P4 的 5 股预留
- **WHEN** K4 交回 P4
- **THEN** AAA 没有 P4 的有效预留；程序日志有 P4 的释放预留，原因写明 AAA 的紧急退出作废还没下单的方案
- **AND** 没有告警；没有送给 K4 的结果

#### Scenario: 等重试时交回

- **GIVEN** K4 交来 P4；15:05Z 按确认，AAA 是无保护仓位，下单流程等重试；AAA 的紧急退出已经释放了 P4 的预留
- **WHEN** 15:05:10Z K4 交回 P4
- **THEN** 确认消息由已确认改为已作废；没有告警
- **AND** 送给 K4 的只有已确认；15:05:30Z 以后券商没有收到 P4 的订单

#### Scenario: 已经下单以后交回

- **GIVEN** K4 交来 P4；15:05Z 按确认，券商受理 P4
- **WHEN** 之后 K4 交回 P4
- **THEN** 不再处理：确认消息仍显示已确认，没有告警
- **AND** 送给 K4 的一共是已确认、订单已提交

#### Scenario: 交回时已经有订单

- **GIVEN** K4 交来 P4；15:05Z 按确认，提交 P4 时券商回答 401，P4 的订单已经建立、还是待提交，下单流程等重试
- **WHEN** 15:05:10Z K4 交回 P4
- **THEN** 不释放预留，没有告警；订单交给盘中巡检
- **AND** 送给 K4 的只有已确认

#### Scenario: 交回以后进程退出

- **GIVEN** K4 交来 P4；15:05Z 按确认，AAA 是无保护仓位，下单流程等重试；15:05:10Z K4 交回 P4，下单流程处理以前进程退出
- **WHEN** 程序重启
- **THEN** 确认消息显示已作废；券商没有收到 P4 的订单
- **AND** 送给 K4 的只有已确认

## MODIFIED Requirements

### Requirement: 结果送回案件

案件的方案的下单流程 SHALL 在下表的每个结局把结果按案件 ID 送回案件，`/plan` 录入的方案不送：

| 下单流程 | 送回 |
| --- | --- |
| 收下确认（「确认的结果」） | 已确认 |
| 收下拒绝 | 已拒绝 |
| 确认超时；确认请求发不出去 | 已超时 |
| 订单交给盘中巡检：提交返回订单（包括券商拒绝受理、状态未知），或者作废时这个方案已经有订单 | 订单已提交 |
| 确认以后（或者不要确认的方案）作废：再校验拒绝、到有效期还没下单、对账不一致 | 再校验作废 |
| 排队运行要求作废，在等确认、等开盘或者等重试（「作废案件的方案」） | 方案被作废 |
| 意料之外的错误让下单流程停下（比如释放预留时状态库出错） | 出错；送回以后下单流程停下 |

- 已确认在确认以后立即送回，然后才等开盘；不要确认的方案不送已确认
- 每个结局只送一次：进程重启以后已经送回的不再送
- 案件被紧急退出中止、把方案交回以后（「案件中止时作废它的方案」），这个方案之后的结局 SHALL NOT 送回：案件已经结束
- 释放预留、告警和程序日志照「确认的结果」「下单前再校验和提交」「提交的结果」「告警」「日志」，送回结果不改变它们
- 等开盘、等重试时，除了被作废，不送回：案件在等下单时一直等（case-stages spec「等下单」）

#### Scenario: 确认以后下单

- **GIVEN** K1 交来 P1
- **WHEN** 2026-10-14 15:05Z 按确认，券商受理 P1
- **THEN** 依次送回 K1：已确认、订单已提交

#### Scenario: 拒绝和超时

- **GIVEN** K1 交来 P1
- **WHEN** 按拒绝
- **THEN** 送回 K1：已拒绝；BBB 没有有效预留
- **WHEN** 同样的情况下一直没有人按到 2026-10-14 15:30Z
- **THEN** 送回 K1：已超时

#### Scenario: 确认请求发不出去

- **GIVEN** Discord 对发消息报错
- **WHEN** K1 交来 P1
- **THEN** 送回 K1：已超时；BBB 没有有效预留

#### Scenario: 盘后确认等到开盘

- **GIVEN** 当前时刻 2026-10-14 21:00Z；K1 交来 P1，生效的有效期 2026-10-15 20:00Z
- **WHEN** 21:05Z 按确认
- **THEN** 送回 K1：已确认；没有别的结果
- **WHEN** 到了 2026-10-15 13:30Z，BBB 最新价 50，券商受理 P1
- **THEN** 送回 K1：订单已提交

#### Scenario: 再校验作废

- **GIVEN** 当前时刻 2026-10-14 21:00Z；K1 交来 P1，21:05Z 按确认
- **WHEN** 2026-10-15 13:30Z，BBB 最新价 53
- **THEN** P1 作废，原因是"价格偏离"；依次送回 K1：已确认、再校验作废

#### Scenario: 到有效期作废

- **GIVEN** 案件 K4 交来 P4，Critic 审核的结果是通过；AAA 一直是无保护仓位
- **WHEN** 2026-10-14 19:59Z 按确认，到了 20:00Z 以后
- **THEN** P4 作废，原因是有效期；依次送回 K4：已确认、再校验作废

#### Scenario: 被排队运行作废

- **GIVEN** K1 交来 P1
- **WHEN** 等确认时排队运行要求作废 P1
- **THEN** 送回 K1：方案被作废
- **WHEN** 另一种情况下，当前时刻 2026-10-14 21:00Z，21:05Z 按确认，在等开盘时排队运行要求作废 P1
- **THEN** 依次送回 K1：已确认、方案被作废

#### Scenario: 案件中止交回的方案不送回

- **GIVEN** K1 交来 P1
- **WHEN** 等确认时 K1 被紧急退出中止，把 P1 交回
- **THEN** P1 作废，没有送给 K1 的结果
- **WHEN** 另一种情况下 15:05Z 按确认，P1 在等重试时 K1 交回 P1
- **THEN** 送给 K1 的只有已确认

#### Scenario: 券商拒绝受理也是订单已提交

- **GIVEN** K1 交来 P1；券商会拒绝受理 P1
- **WHEN** 按确认
- **THEN** P1 的订单已拒绝，推送一条告警；依次送回 K1：已确认、订单已提交

#### Scenario: 自动执行的方案

- **GIVEN** 模型退出自动执行打开
- **WHEN** K3 交来 P3，P3 有订单
- **THEN** 只送回 K3 一个结果：订单已提交

#### Scenario: 意料之外的错误

- **GIVEN** K1 交来 P1；按拒绝以后释放预留时状态库会出错
- **WHEN** 按拒绝
- **THEN** 送回 K1：出错；P1 的下单流程出错停下
- **AND** 没有再送回别的结果

#### Scenario: 重启以后不重送

- **GIVEN** 当前时刻 2026-10-14 21:00Z；K1 交来 P1，21:05Z 按确认，已经送回已确认
- **WHEN** 程序在 2026-10-14 23:00Z 重启；2026-10-15 13:30Z 券商受理 P1
- **THEN** K1 一共收到两个结果：已确认、订单已提交

#### Scenario: /plan 的方案不送回

- **WHEN** 本人用 `/plan` 提交 P1，按确认，券商受理 P1
- **THEN** 没有送给任何案件的结果
