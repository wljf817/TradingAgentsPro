# Spec Delta

## Purpose

规定 Agent 网关怎样记下每次模型调用的费用，按案件侧的"每日"（交易日）算普通预算、持仓保留预算和寻股预算今天花了多少、是否用完，并给出队列要的普通预算和寻股预算是否用完、健康监控要的持仓保留预算是否用完。

## ADDED Requirements

### Requirement: 费用的记录

调用方 SHALL 在每次尝试（向一个模型发一次请求，model-fallback spec「什么算不可用」）拿到厂商给出的 token 用量以后，把案件、agent、模型和用量交给 Agent 网关记下一条费用记录，"现在"是记下的时刻。记录包含：

| 项 | 内容 |
| --- | --- |
| 案件 ID、案件类型 | 发出请求的案件；案件类型是开始运行时确定的（case-types spec「案件类型」） |
| agent | PM、News、Quant、Fundamentals、Critic、Reviewer 之一 |
| 模型 | 这次尝试用的模型 |
| 用量 | 输入和输出的 token 数 |
| 费用 | 美元，见「费用的算法」 |
| 预算 | 普通预算、持仓保留预算、寻股预算之一，见「费用记到哪个预算」 |
| 记下的时刻 | 现在 |

- 每次尝试一条：重试、切换备用模型的每次尝试各记一条；成功的和输出格式不合法的都记，失败但厂商给出了用量的也记
- 拿不到用量的尝试（比如连接失败、限流、超时）SHALL NOT 记
- 记录只追加，写入以后 SHALL NOT 被修改；记录保存在存储里，进程重启以后三个预算按存储里的记录接着算

本 spec 的场景除非另有说明，都使用默认配置和下面的基准数据：

- 当前时刻 2026-10-14 15:00Z（周三，盘中），交易日历是纽交所日历；2026-10-14 这个交易日从 2026-10-13 20:00Z（含）到 2026-10-14 20:00Z（不含）
- 模型的配置是 model-fallback spec 的基准模型的配置，单价（美元/百万 token）如下：

  | 模型 | 输入单价 | 输出单价 |
  | --- | --- | --- |
  | p-1、p-2 | 2 | 10 |
  | p-3 | 1 | 4 |
  | c-1、c-2 | 1.25 | 10 |
  | s-1、s-2 | 0.3 | 2.5 |

- 案件和开始时确定的案件类型（前四个和 task-dispatch spec 的基准数据相同）：

  | 案件 | 案件类型 |
  | --- | --- |
  | K-1 | BBB 的关注股事件 |
  | K-2 | 寻股 |
  | K-3 | CCC 的持仓事件 |
  | K-4 | BBB 的关注复查 |
  | K-5 | 每周复盘 |
  | K-6 | CCC 的持仓跟进 |
  | K-7 | BBB 的关注跟进 |
  | K-8 | AAA 的候选评估 |

- 费用、额度都是美元；"K-n 记下 x"指为 K-n 记下一次 p-1 的尝试，输入 x 乘 500,000 个 token、没有输出，费用正好是 x。agent 是 PM，K-5 是 Reviewer
- "预算的情况"指现在取得的：现在归属的交易日、三个预算今天的费用、用完的预算（见「预算用完」）
- 时刻没有写明时，都是当前时刻
- GIVEN 里的几步依次进行；一个 WHEN 里用"；"隔开的几种情况，各自从 GIVEN 的数据开始；同一个场景里的几组 WHEN、THEN，除非写"接着"，也各自从 GIVEN 的数据开始；场景中间新的 GIVEN 从基准数据重新开始

#### Scenario: 记下一次尝试

- **WHEN** K-1 的 PM 用 p-1 的一次尝试拿到用量：输入 20,000、输出 2,000
- **THEN** 记下一条：案件 K-1，关注股事件，PM，p-1，输入 20,000、输出 2,000，费用 0.06，普通预算，2026-10-14 15:00Z

#### Scenario: 每次尝试各记一条

- **WHEN** K-3 的 Quant 用 s-1 的一次尝试拿到用量：输入 8,000、没有输出，接着用 s-2 的一次尝试拿到用量：输入 8,000、输出 1,000
- **THEN** 记下两条：s-1 的费用 0.0024，s-2 的费用 0.0049，都是 K-3、Quant、普通预算
- **AND** 预算的情况：普通预算今天的费用 0.0073

#### Scenario: 重启以后接着算

- **GIVEN** K-1 记下 2.00
- **WHEN** 进程重启，用同一个存储重新开始，取得预算的情况
- **THEN** 普通预算今天的费用 2.00，已经用完

### Requirement: 模型的单价

模型的配置（model-fallback spec「模型的配置」）SHALL 同时给出每个模型的单价，单位是美元/百万 token：

| 项 | 要求 |
| --- | --- |
| 输入单价 | 不小于 0 |
| 输出单价 | 不小于 0 |

- 任何 agent 的主模型或备用模型没有单价、同一个模型配了两份单价、单价不符合上表，都 MUST 配置报错；bootstrap 启动时读取配置，报错就 SHALL 拒绝启动
- 没有 agent 用到的模型配了单价，不报错
- 单价在启动时读取，运行中不变

#### Scenario: 基准单价

- **WHEN** 用基准模型的配置和基准单价
- **THEN** 配置正确；p-1 的输入单价 2、输出单价 10

#### Scenario: 缺少单价或单价不合法

- **WHEN** 不配 c-2 的单价；p-3 的输入单价配置为 -0.01；s-1 的输出单价配置为 -1；p-1 配了两份单价
- **THEN** 都配置报错

#### Scenario: 单价可以是 0，可以多配

- **WHEN** s-2 的两个单价都配置为 0；另外给没有 agent 用到的 openai/x-9 配了单价
- **THEN** 都配置正确

### Requirement: 费用的算法

一次尝试的费用 SHALL 是：输入 token 数 × 输入单价 ÷ 1,000,000 + 输出 token 数 × 输出单价 ÷ 1,000,000，单价是这次尝试用的模型的单价，精确计算、不舍入。

- 用量是调用方从模型的返回里取得的这次尝试的输入和输出 token 数，都是不小于 0 的整数；推理 token 算输出，缓存命中的 token 算输入，按输入单价算
- 用量小于 0 或者不是整数 MUST 报错

#### Scenario: 按单价算

- **WHEN** K-1 的 PM 用 p-1，输入 20,000、输出 2,000；K-3 的 Quant 用 s-1，输入 8,000、输出 1,000；K-3 的 Critic 用 c-1，输入 30,000、输出 3,000
- **THEN** 费用分别是 0.06、0.0049、0.0675

#### Scenario: 不舍入

- **WHEN** 用 p-1，输入 1、没有输出；用 s-1，输入 1、没有输出；用 p-1，输入 0、输出 0
- **THEN** 费用分别是 0.000002、0.0000003、0

#### Scenario: 用量不合法

- **WHEN** 用量的输入是 -1；输出是 1.5
- **THEN** 都报错，不记下

### Requirement: 费用记到哪个预算

每条费用记录 SHALL 按案件类型和记这一条以前普通预算是否已经用完（见「预算用完」），整笔记到一个预算：

| 案件类型 | 记之前普通预算没用完 | 记之前普通预算已经用完 |
| --- | --- | --- |
| 寻股 | 寻股预算 | 寻股预算 |
| 持仓风险事件、持仓事件、持仓复查、持仓催化剂复查、持仓跟进 | 普通预算 | 持仓保留预算 |
| 关注股事件、关注复查、关注催化剂复查、关注跟进、候选股事件、候选评估、每周复盘、卖出复盘 | 普通预算 | 普通预算 |

- 一条记录 SHALL NOT 拆到两个预算：记之前普通预算没用完，这一条即使让它超出额度，也整笔记普通预算
- 寻股预算和持仓保留预算用完以后照常记到它们，可以超出额度（见「已经开始的案件」）
- 一个案件里所有 agent（PM、子 agent、Critic、Reviewer）的尝试都按这个案件的类型记
- 跟进案件和其他案件一样按案件类型记：持仓跟进按持仓的案件，关注跟进用普通预算。每天的跟进申请次数由 follow-ups spec「每天的申请次数」限制，调用预算不另外计数

#### Scenario: 普通预算没用完时

- **WHEN** K-1 记下 0.10；K-3 记下 0.10；K-5 记下 0.10；K-6 记下 0.10；K-8 记下 0.10
- **THEN** 都记普通预算

#### Scenario: 寻股只记寻股预算

- **WHEN** K-2 记下 0.30
- **THEN** 记寻股预算；普通预算今天的费用是 0
- **GIVEN** K-1 记下 2.00
- **WHEN** K-2 记下 0.30
- **THEN** 记寻股预算；普通预算今天的费用仍是 2.00

#### Scenario: 跨过额度的一条整笔记普通预算

- **GIVEN** K-1 记下 1.95
- **WHEN** K-3 记下 0.10
- **THEN** 记普通预算：普通预算今天的费用 2.05，已经用完；持仓保留预算是 0
- **WHEN** 接着 K-3 记下 0.10
- **THEN** 记持仓保留预算：持仓保留预算 0.10，普通预算仍是 2.05

#### Scenario: 普通预算用完以后非持仓案件照常记普通预算

- **GIVEN** K-1 记下 2.00
- **WHEN** K-1 记下 0.10；K-5 记下 0.10；K-7 记下 0.10；K-8 记下 0.10
- **THEN** 都记普通预算，普通预算今天的费用 2.10；持仓保留预算是 0

#### Scenario: 跟进案件按案件类型

- **GIVEN** K-1 记下 2.00
- **WHEN** K-6 记下 0.10
- **THEN** 记持仓保留预算
- **WHEN** K-7 记下 0.10
- **THEN** 记普通预算

#### Scenario: 案件里各个 agent 都按案件类型

- **GIVEN** K-1 记下 2.00
- **WHEN** K-3 的 Quant 用 s-1，输入 8,000、输出 1,000；K-3 的 Critic 用 c-1，输入 30,000、输出 3,000
- **THEN** 都记持仓保留预算

### Requirement: 每日的划分

"今天" SHALL 是现在归属的交易日（trading-calendar spec「时刻归属的交易日」）：从上一个交易日收盘（含）到这个交易日收盘（不含），周末和休市日并进下一个交易日。一个预算今天的费用是记下的时刻归属今天、记到这个预算的记录的费用之和。

- 收盘那一刻起是下一个交易日，三个预算一起恢复，不另外重置
- 进程重启不影响：记录在存储里（见「费用的记录」）

#### Scenario: 交易日从上一个交易日收盘开始

- **GIVEN** 2026-10-13 19:59:59Z K-1 记下 1.00；2026-10-13 20:00:00Z K-1 记下 0.50
- **WHEN** 取得预算的情况
- **THEN** 交易日 2026-10-14，普通预算今天的费用 0.50

#### Scenario: 收盘时恢复

- **GIVEN** K-1 记下 2.00；K-3 记下 1.00
- **WHEN** 2026-10-14 19:59:59Z 取得预算的情况
- **THEN** 交易日 2026-10-14；普通预算和持仓保留预算都已经用完
- **WHEN** 2026-10-14 20:00:00Z 取得预算的情况
- **THEN** 交易日 2026-10-15；三个预算今天的费用都是 0，都没用完

#### Scenario: 周末并进下一个交易日

- **GIVEN** 2026-10-16 20:30Z（周五收盘以后）K-1 记下 0.50；2026-10-17 15:00Z（周六）K-1 记下 0.50；2026-10-18 15:00Z（周日）K-5 记下 0.50
- **WHEN** 2026-10-19 15:00Z（周一）取得预算的情况
- **THEN** 交易日 2026-10-19，普通预算今天的费用 1.50

#### Scenario: 休市日并进下一个交易日

- **GIVEN** 2026-11-26 15:00Z（感恩节休市）K-1 记下 2.00
- **WHEN** 2026-11-27 17:59:59Z 取得预算的情况
- **THEN** 交易日 2026-11-27，普通预算已经用完
- **WHEN** 2026-11-27 18:00:00Z（提前收盘的收盘时刻）取得预算的情况
- **THEN** 交易日 2026-11-30，普通预算今天的费用是 0

#### Scenario: 夏令时结束以后按新的收盘时刻

- **GIVEN** 2026-11-02 20:30Z K-1 记下 2.00
- **WHEN** 2026-11-02 20:59:59Z 取得预算的情况
- **THEN** 交易日 2026-11-02，普通预算已经用完
- **WHEN** 2026-11-02 21:00:00Z 取得预算的情况
- **THEN** 交易日 2026-11-03，普通预算今天的费用是 0

### Requirement: 预算用完

一个预算 SHALL 在今天的费用不小于它的额度（见「预算的配置」）时算用完。Agent 网关 SHALL 给出预算的情况：现在归属的交易日，三个预算今天的费用（没有记录的是 0），以及按下表用完的预算：

| 预算 | 用完的条件 | 交给 |
| --- | --- | --- |
| 普通预算 | 今天的费用不小于普通预算的额度 | 队列：普通预算是否用完（case-queue spec「调用预算」） |
| 寻股预算 | 今天的费用不小于寻股预算的额度 | 队列：寻股预算是否用完（case-queue spec「调用预算」） |
| 持仓保留预算 | 今天的费用不小于持仓保留预算的额度 | 健康监控：持仓保留预算是否用完（degraded-mode spec「健康检查」） |

- 三个预算各自判断，互不影响
- 预算的情况只根据现在和存储里的记录算出，每次取得时重新算

#### Scenario: 没有记录

- **WHEN** 取得预算的情况
- **THEN** 交易日 2026-10-14；三个预算今天的费用都是 0，都没用完

#### Scenario: 普通预算的边界

- **GIVEN** K-1 记下 1.99
- **WHEN** 取得预算的情况
- **THEN** 普通预算没用完
- **WHEN** 接着 K-1 记下 0.01，取得预算的情况
- **THEN** 普通预算今天的费用 2.00，已经用完；寻股预算和持仓保留预算没用完

#### Scenario: 寻股预算的边界

- **GIVEN** K-2 记下 0.49
- **WHEN** 取得预算的情况
- **THEN** 寻股预算没用完
- **WHEN** 接着 K-2 记下 0.01，取得预算的情况
- **THEN** 寻股预算已经用完；普通预算和持仓保留预算没用完

#### Scenario: 持仓保留预算的边界

- **GIVEN** K-1 记下 2.00；K-3 记下 0.99
- **WHEN** 取得预算的情况
- **THEN** 普通预算已经用完，持仓保留预算没用完
- **WHEN** 接着 K-3 记下 0.01，取得预算的情况
- **THEN** 持仓保留预算今天的费用 1.00，已经用完

### Requirement: 已经开始的案件

Agent 网关 SHALL NOT 因为预算用完拒绝任务或者模型调用。预算只在案件开始时起作用：队列按普通预算、寻股预算是否用完决定排队的案件能不能启动（case-queue spec「调用预算」）；持仓保留预算用完时健康监控进入降级模式，不开始新案件（degraded-mode spec）。

- 已经开始的案件 SHALL 照常运行到结束，尝试照常按「费用记到哪个预算」记下，预算可以超出额度
- 超出的部分受每个案件的上限约束：PM 的任务数和轮次、Critic 的补充研究额度（task-dispatch spec「派发的配置」），结论最多重交次数和质询轮次（case-stages spec），以及并发上限（case-queue spec「队列配置」）
- 调用预算用完不算模型不可用（model-fallback spec「什么算不可用」）：不切换备用模型，不计入熔断

#### Scenario: 普通预算用完以后运行中的案件照常派发

- **GIVEN** K-1 记下 2.00
- **WHEN** PM 在 K-1 派发 task-dispatch spec 的价格请求
- **THEN** 派发 T-1，不被拒绝
- **WHEN** 接着 K-1 的 Quant 为 T-1 用 s-1，输入 8,000、输出 1,000
- **THEN** 记普通预算，普通预算今天的费用 2.0049

#### Scenario: 寻股预算用完以后寻股照常运行

- **GIVEN** K-2 记下 0.50
- **WHEN** PM 在 K-2 派发 DDD 的价格请求
- **THEN** 派发，不被拒绝
- **WHEN** 接着 K-2 记下 0.30
- **THEN** 记寻股预算，寻股预算今天的费用 0.80

#### Scenario: 持仓保留预算用完以后照常记

- **GIVEN** K-1 记下 2.00；K-3 记下 1.00
- **WHEN** PM 在 K-3 派发 CCC 的价格请求
- **THEN** 派发，不被拒绝
- **WHEN** 接着 K-3 记下 0.10
- **THEN** 记持仓保留预算，持仓保留预算今天的费用 1.10

#### Scenario: 预算用完不切换模型

- **GIVEN** K-1 记下 2.00；K-3 记下 1.00；K-2 记下 0.50
- **WHEN** PM 在 K-3 调用
- **THEN** 先试 p-1（model-fallback spec「切换顺序」）；p-1 没有记下不可用

### Requirement: 子 agent 任务的费用

调用方 SHALL 把一个子 agent 任务的各次尝试记下的费用之和，作为这个任务的费用交给任务派发（task-dispatch spec「Result 的格式」「子 agent 的输出变成 Result」「超时」「调用失败」）：

- 包括重试和切换备用模型的尝试；拿不到用量、没有记下的尝试不算
- 被拒绝和复用的任务没有尝试，费用是 0

#### Scenario: 重试和备用模型的费用相加

- **GIVEN** PM 在 K-1 派发价格请求（T-1）；T-1 的调用里，s-1 的第一次尝试超时，没有用量，不记；s-1 的第二次尝试失败（其他调用错误），厂商给出了用量：输入 8,000、没有输出，记下 0.0024
- **WHEN** 换到 s-2 拿到输出，输入 8,000、输出 1,000，记下 0.0049，调用方把两条之和交给任务派发
- **THEN** T-1 的 Result 是完成，费用 0.0073

#### Scenario: 超时和调用失败的任务

- **GIVEN** PM 在 K-1 派发价格请求（T-1）
- **WHEN** T-1 的调用里，s-1 的第一次尝试失败（其他调用错误），记下 0.0024，之后到了截止时间停止尝试，记超时
- **THEN** T-1 超时，费用 0.0024
- **WHEN** T-1 的调用里，s-1 和 s-2 的尝试都连接失败，没有用量，调用方给出调用失败
- **THEN** T-1 失败，费用 0

### Requirement: 预算的配置

三个预算的额度 SHALL 是可配置项，都是每个交易日多少美元：

| 配置项 | 说明 | 默认值 | 要求 |
| --- | --- | --- | --- |
| 普通预算的额度 | 今天记到普通预算的费用到这么多就用完 | 2.00 | 大于 0 |
| 持仓保留预算的额度 | 今天记到持仓保留预算的费用到这么多就用完 | 1.00 | 大于 0 |
| 寻股预算的额度 | 今天记到寻股预算的费用到这么多就用完 | 0.50 | 大于 0 |

不满足要求时 MUST 配置报错。额度在启动时读取，运行中不变。

#### Scenario: 默认配置

- **WHEN** 不传任何配置项新建配置
- **THEN** 普通预算的额度 2.00，持仓保留预算的额度 1.00，寻股预算的额度 0.50

#### Scenario: 配置不合法

- **WHEN** 普通预算的额度配置为 0；持仓保留预算的额度配置为 -1；寻股预算的额度配置为 0
- **THEN** 都配置报错

#### Scenario: 改成别的值

- **GIVEN** 普通预算的额度配置为 1.00
- **WHEN** K-1 记下 1.00，取得预算的情况
- **THEN** 普通预算已经用完
- **WHEN** 接着 K-3 记下 0.10
- **THEN** 记持仓保留预算
- **GIVEN** 持仓保留预算的额度配置为 0.10，寻股预算的额度配置为 0.20
- **WHEN** K-1 记下 2.00，K-3 记下 0.10，K-2 记下 0.20，取得预算的情况
- **THEN** 三个预算都已经用完
