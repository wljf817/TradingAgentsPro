# Spec Delta

## MODIFIED Requirements

### Requirement: 风控

风控阶段 SHALL 按风控的结果（risk-rules spec「风控的输入和判定」）和要不要人工确认（confirmation-rules spec「案件方案的确认」，调用方随风控的结果一起给出）转换：

| 风控的结果 | 要人工确认 | 结果 |
| --- | --- | --- |
| 通过 | 要 | 进入等人工确认 |
| 调整 | 要 | 进入等人工确认；确认消息标明已被风控调整及原因（discord-notification spec） |
| 通过或调整 | 不要 | 进入等下单：模型退出自动执行，不经人工确认（只有退出类方案会这样） |
| 拒绝 | 不看 | 结束：风控拒绝 |

- 风控拒绝 SHALL NOT 在同一个案件里退回 PM 重来：案件结束并记下原因，PM 在这只股票的下一个案件里看到
- Critic 审核的结果是有分歧或 Critic 不可用的方案，照常经过风控，结果不变

#### Scenario: 风控通过

- **GIVEN** 开仓案件 Critic 通过，在风控
- **WHEN** 风控通过，要人工确认
- **THEN** 进入等人工确认，Critic 审核的结果仍是通过

#### Scenario: 风控调整

- **GIVEN** 开仓案件 Critic 通过，在风控
- **WHEN** 风控调整（股数从 100 调为 40），要人工确认
- **THEN** 进入等人工确认

#### Scenario: 风控拒绝

- **GIVEN** 开仓案件 Critic 通过，在风控
- **WHEN** 风控拒绝；或者处于降级模式，风控因为降级模式拒绝
- **THEN** 结束：风控拒绝，有结论

#### Scenario: 有分歧的方案照常过风控

- **GIVEN** 开仓案件质询满两轮仍有分歧，在风控
- **WHEN** 风控通过，要人工确认
- **THEN** 进入等人工确认，Critic 审核的结果仍是有分歧

#### Scenario: 不要人工确认的退出方案

- **GIVEN** 退出案件 Critic 通过，在风控
- **WHEN** 风控通过，不要人工确认；另一种情况下风控调整（股数从 60 调为 40），不要人工确认
- **THEN** 都进入等下单，没有经过等人工确认；方案的阶段是等下单
- **WHEN** 接着订单已提交
- **THEN** 结束：订单已提交，有结论

#### Scenario: 拒绝时不看要不要确认

- **GIVEN** 退出案件 Critic 通过，在风控
- **WHEN** 风控拒绝，不要人工确认
- **THEN** 结束：风控拒绝

### Requirement: 人工确认

要人工确认的方案 SHALL 在通过风控以后进入等人工确认；要不要确认由 confirmation-rules spec「案件方案的确认」决定，不要确认的退出方案直接进入等下单（见「风控」）。等人工确认阶段 SHALL 按确认的结果转换：

| 确认的结果 | 结果 |
| --- | --- |
| 已确认 | 进入等下单 |
| 已拒绝 | 结束：人工拒绝 |
| 已超时 | 结束：确认超时 |

调用方 SHALL 按 Critic 审核的结果在确认消息里附上说明；人按确认就算对分歧做了决定：

| Critic 审核的结果 | 确认消息附上 |
| --- | --- |
| 通过 | 不附 |
| 有分歧 | PM 和 Critic 双方的意见：PM 的方案理由和各轮回应，Critic 的质询或异议 |
| Critic 不可用 | 注明 Critic 不可用，方案没有经过审核 |

确认请求发不出去时按确认超时处理（discord-notification spec）。

#### Scenario: 人工确认

- **GIVEN** 开仓案件 Critic 通过、风控通过，在等人工确认
- **WHEN** 已确认
- **THEN** 进入等下单
- **AND** 确认消息不附双方意见

#### Scenario: 人工拒绝

- **GIVEN** 开仓案件在等人工确认
- **WHEN** 已拒绝
- **THEN** 结束：人工拒绝，有结论

#### Scenario: 确认超时

- **GIVEN** 退出案件在等人工确认
- **WHEN** 已超时，或者确认请求发不出去
- **THEN** 结束：确认超时，有结论

#### Scenario: 有分歧的方案带着双方意见交给人

- **GIVEN** 开仓案件质询满两轮仍有分歧；退出案件 Critic 有异议；两个案件都通过风控，在等人工确认
- **WHEN** 调用方发出确认请求
- **THEN** 两条确认消息都附上 PM 和 Critic 双方的意见
- **WHEN** 人按了确认
- **THEN** 都进入等下单

#### Scenario: Critic 不可用的退出方案注明

- **GIVEN** 退出案件因为 Critic 不可用跳过审核，通过风控，在等人工确认
- **WHEN** 调用方发出确认请求
- **THEN** 确认消息注明 Critic 不可用
