# Proposal

## Why

Proposal 规定子 agent 的输出是统一格式的信号（评估窗口、评分、置信度、数据时效、引用、理由和主要风险，允许无信号），PM 每次提交结论时也给出一个同样格式的评分，作为股票池的「最新评分」并和子 agent 的信号一样参与评估；格式不合法视为无效，由 Agent 网关校验。M3 前面的「案件类型与结论」只把 PM 的评分写成了 -2 到 +2 的整数，并把"评分的完整格式"留给本变更；Agent 网关组后面的「任务派发」要把子 agent 的输出变成 Result，需要先知道输出合不合法、为什么不合法。

本变更的目的只有一个：**规定子 agent 的信号和 PM 结论里评分的统一格式，并校验模型输出是否合法。**

引用的 Proposal（完整版）章节：

- 「Agent」的「信号统一格式」全段；「备用模型」里"输出格式不合法不算不可用，按「格式不合法视为无效」处理，不切换模型"一句
- 「Task / Result 通信」的 Result 字段（五种状态里有「无信号」，没有「无效」）和任务清单（任务类型的输出格式固定）
- 「共享上下文」系统宪章的"评分刻度"和"数据不足答「无信号」"
- 「持仓与退出」的「负向信号的含义」：只写进 Non-goals
- 「记录、复盘与经验 · 复盘」的信号准确性一句：只用来对齐评分的口径（相对板块 ETF 的超额收益）

## What Changes

- 新增 Agent 网关模块 `modules/gateway/`：本变更只有纯逻辑和配置，导出纯函数，没有 service 和存储
- contracts 新增 `contracts/signal.py`：信号和无信号两种模型，子 agent 的输出是两者之一
- 信号的格式：

  | 项 | 要求 |
  | --- | --- |
  | 评估窗口 | 交易日数，从配置的选项里选（默认 3、5、20、60），写入后不能修改 |
  | 评分 | -2 到 +2 的整数，五档：强烈看空、看空、中性、看多、强烈看多 |
  | 置信度 | 0 到 1 |
  | 数据截至时刻 | 带时区，不能晚于收到输出的时刻 |
  | 引用的条目 | 状态库条目 ID，至少一条 |
  | 理由、主要风险 | 必填的文字 |

- 评分比较的是评估窗口内相对板块 ETF 的超额收益，每档给出名字和一句话含义，供 M5 写进系统宪章
- 无信号只写原因，可以引用看过的条目；PM 的信号不能是无信号
- 收到输出时的校验：格式由 Pydantic 检查；格式正确的信号再查评估窗口在不在配置的选项里、数据截至时刻是否晚于现在，给出第一项不通过的原因。无信号格式正确就合法
- PM 的结论：持仓、关注、候选的结论的整数评分改为一个信号，寻股加入的每只候选的整数评分也改为一个信号（**BREAKING**：contracts 里四处 `score: int` 改为 `signal: Signal`）；Agent 网关按同样的规则检查结论里的每个信号。股票池的最新评分仍然只存整数评分，由调用方取信号里的评分
- 可配置项：评估窗口的选项，默认 3、5、20、60 个交易日

## Non-goals

- 「任务派发」：Task 和 Result 的格式、状态和派发规则；格式不合法的输出怎样变成 Result（已决定第 1 条）；Task 带上股票（第 9 条）；Result 的引用取自信号或无信号的引用
- 「备用模型」：主模型不可用时切换。本变更只写明格式不合法不算不可用
- 「调用预算」
- M5：
  - 把模型输出解析成信号：输出以什么形式到达、PydanticAI 的输出类型和重试。本变更给出模型和收到输出时的检查
  - 提示词：每档评分的完整说明、评估窗口的选项、无信号什么时候用、让模型按格式输出。本变更只给出每档的名字和一句话含义
  - PM 的结论格式不合法以后怎样退回 PM（第 10 条）
  - 「负向信号的含义」：持仓股的 -1 应考虑减仓，-2 且置信度不低于 0.7 应考虑清仓，不采纳要写理由；非持仓股的负向信号只表示不买，连续为负可以移出股票池。这是给 PM 的提示，代码不检查
- M4：把信号和结论存进状态库；结论通过以后把信号里的评分记为股票池的最新评分（股票池已经有记录评分）
- M6：按评估窗口评估信号的准确性（从什么时刻算起、超额收益、命中率、IC、置信度校准、无信号的覆盖率、同一只股票一个窗口只取一条）
- 状态库条目 ID 的格式、引用的条目是否存在（第 5 条）：M4 定状态库快照时再定

## Capabilities

### New Capabilities

- `signal-format`：信号的格式；评分的刻度；无信号；收到输出时的校验；结论里的信号；信号的配置

### Modified Capabilities

- `case-types`：「结论的公共部分」「寻股的结论」里的整数评分改为信号；「触发」里的基准数据改用基准信号

stock-pool spec 不改：最新评分仍是 -2 到 +2 的整数，"把结论里的评分记到这只股票上"指信号里的评分。

## 需要人决定

已决定（2026-10-08）：

1. **格式不合法的 Result 记成什么状态**：Result 的五种状态里没有「无效」。决定：记为「失败」并注明格式不合法，不切换模型。本变更给出"格式不合法"和原因，记成 Result 的哪个状态由「任务派发」落实

新发现的，已按推荐做法写进 spec，不同意可以改：

2. **无信号怎么表示**：推荐子 agent 的输出是两种之一：信号，或者无信号。无信号只写原因（必填），可以引用看过的条目，不写评估窗口、评分、置信度、数据截至时刻、理由和主要风险。理由：无信号是"给不出判断"，硬填评分和置信度会被当成判断统计；Result 本来就把完成和无信号分成两种状态。评分 0（中性）是一个判断，和无信号不同：数据不足时答无信号，不给 0。PM 的信号不能是无信号：股票池要用它作最新评分，候选评估按它排序；PM 判断不了时给置信度低的信号
3. **数据时效怎么写**：推荐写成"数据截至时刻"：所依据的数据最新到哪个时刻，带时区；晚于收到输出的时刻算格式不合法，挡住把美东时间当成 UTC 写、或者编一个未来时刻的输出。不设"太旧"的上限：多旧算旧因数据而异（财报按季度，行情按分钟），由 PM 和复盘判断
4. **评分的刻度**：推荐评分是整数，比较的是评估窗口内相对板块 ETF 的超额收益，和「复盘」的信号准确性同一个口径（Proposal 写明不用绝对涨跌）：

   | 评分 | 名字 | 含义 |
   | --- | --- | --- |
   | +2 | 强烈看多 | 预计评估窗口内明显跑赢板块 |
   | +1 | 看多 | 预计评估窗口内跑赢板块，但幅度有限 |
   | 0 | 中性 | 预计评估窗口内和板块大致同步 |
   | -1 | 看空 | 预计评估窗口内跑输板块，但幅度有限 |
   | -2 | 强烈看空 | 预计评估窗口内明显跑输板块 |

   置信度是这个判断成立的把握，和评分分开：把握不大时降低置信度，不把评分往 0 靠，置信度校准才有意义
5. **引用、理由和主要风险**：推荐信号至少引用 1 条状态库条目，理由和主要风险都必填，各是一段文字（风险不拆成列表）。不检查引用的条目是否存在、是否在本案件的快照里：条目 ID 的格式要到 M4 才定，乱引用由复盘发现
6. **评估窗口只在收到输出时检查**：推荐选项以外的窗口算格式不合法；之后改了配置，已经写入的信号不受影响，照旧按自己的窗口评估，否则改配置会让历史信号读不回来
7. **PM 的信号自带理由、风险和引用**：推荐和子 agent 的信号完全同样格式，不借用结论的理由和引用。结论的理由说的是为什么这样决定，信号的理由说的是为什么这样看这只股票，两者可以不同（比如看多，但仓位已满所以持有）；同样格式才能和子 agent 的信号一起评估
8. **PM 的信号也查评估窗口和数据截至时刻**：推荐 Agent 网关收到 PM 的结论时，按和子 agent 相同的两项检查结论里的每个信号，寻股按加入的顺序，给出第一个不通过的原因，不指明是哪一只候选
9. **一个信号针对哪只股票**：推荐信号里不写股票。子 agent 的信号针对 Task 指定的股票：「任务派发」给 Task 加上股票，单只股票的案件就是案件的股票，寻股由 PM 指定，一个 Task 只评估一只；PM 的信号针对案件的股票，寻股是加入的那只候选。否则 M6 不知道寻股案件里子 agent 的信号该按哪只股票评估
10. **PM 的信号不合法怎么办**：推荐整份结论格式不合法，和结论其他部分的格式错误一样处理（case-stages spec 写明由 Agent 网关处理），不能只丢掉信号、照常采用结论。怎样退回 PM（重试几次、算不算重交次数）由 M5 接模型时和其他格式错误一起定
