# Spec Delta

## MODIFIED Requirements

### Requirement: 触发

开案件时调用方 SHALL 给出触发，触发有四种：

| 触发 | 带的内容 |
| --- | --- |
| 事件 | 股票、事件类别（见「事件要求的子 agent」）、是否是持仓风险级别（由事件检测标注） |
| 定时心跳的检查项 | 检查项开出的案件类型（见下表）；针对单只股票的检查项带股票 |
| 跟进 | 股票、申请时写下的问题 |
| 卖出成交 | 股票。止损单成交、紧急风险退出、PM 发起的减仓和清仓都算 |

| 定时心跳的检查项 | 开出的案件类型 | 带股票 |
| --- | --- | --- |
| 持仓复查日到期 | 持仓复查 | 是 |
| 投资论点的催化剂截止日期到期 | 持仓催化剂复查 | 是 |
| 关注复查日到期 | 关注复查 | 是 |
| 关注论点的催化剂截止日期到期 | 关注催化剂复查 | 是 |
| 有新候选 | 候选评估 | 是 |
| 股票池候选不足 | 寻股 | 否 |
| 每周固定时间 | 每周复盘 | 否 |

不合法的触发 SHALL 报错：定时心跳给出的案件类型不在上表里；带不带股票和上表不符。

本 spec 的场景除非另有说明，都使用默认配置和下面的基准数据：

- 股票：AAA 是候选；BBB 是关注，板块"医疗"；CCC 是持仓，板块"能源"
- 基准关注论点：和 stock-pool spec 的基准关注论点相同
- 基准投资论点：
  - 买入理由"新品周期带动收入加速"
  - 催化剂"Q3 财报"，截止日期 2026-10-29，不引用日程项或事件
  - 目标价 60
  - 证伪条件"毛利率连续两个季度下滑"，其中代码能检测的部分一条：价格不高于 42
  - 复查日 2026-10-21
- 基准方案条款：100 股，限价单，限价 50，止损价 45，紧急阈值 0.08，不写有效期和允许价格偏离
- 基准跟进申请：原因是外部日程，引用日程项"S-9"；问题"竞争对手 11 月 18 日发财报，之后对这只股票有什么影响？"；可能采取的动作"减仓"；触发时间 2026-11-19 14:30Z
- 结论的公共部分：回答"论点仍然成立"，理由"订单和毛利率都符合预期"，信号是 signal-format spec 的基准信号（评分 1），引用 R-1 和 R-2
- "评分 n 的信号"指只把基准信号的评分改为 n；场景里加入的候选只写"评分 n"时，它的信号就是评分 n 的信号
- 本案件派过任务的子 agent 是 News 和 Quant；状态是完成的 Result 有两个：R-1 出自 News，R-2 出自 Quant
- "某个案件开始运行"指这个触发开出的案件开始运行，股票的状态是这个时候的状态

#### Scenario: 不合法的触发

- **WHEN** 定时心跳给出的案件类型是持仓事件；持仓复查不带股票；寻股带了股票 AAA
- **THEN** 都报错

### Requirement: 结论的公共部分

PM 的结论 SHALL 是四种之一：持仓的结论、关注的结论、候选的结论、寻股的结论。每种都包含：

| 字段 | 说明 |
| --- | --- |
| 回答 | 对案件问题的正面回答，文字 |
| 理由 | 文字；无动作时也要写 |
| 引用的 Result | Result ID 的列表，可以为空 |
| 信号 | 只有持仓、关注、候选的结论有：PM 对这只股票的信号，格式见 signal-format spec「信号的格式」，不能是无信号；信号里的评分就是股票池的最新评分。寻股的结论没有，每只加入的候选各有一个（见「寻股的结论」） |

文字去掉首尾空白后为空、信号不符合 signal-format spec「信号的格式」或者是无信号、缺少必填的字段、包含本 spec 规定以外的字段，都 MUST 是格式错误。信号的评估窗口是否在配置的选项里、数据截至时刻是否晚于现在，由 Agent 网关检查（signal-format spec「结论里的信号」）。

#### Scenario: 完整的公共部分

- **WHEN** 用结论的公共部分构造持仓的结论，决定持有
- **THEN** 格式正确
- **WHEN** 不引用任何 Result
- **THEN** 格式正确

#### Scenario: 回答或理由为空

- **WHEN** 回答是 "  "，或者理由是 ""
- **THEN** 都是格式错误

#### Scenario: 评分的边界

- **WHEN** 信号是评分 -2 或 2 的信号
- **THEN** 格式正确
- **WHEN** 信号的评分是 -3、3 或 1.5，或者不写信号
- **THEN** 都是格式错误

#### Scenario: 信号的格式错误或者是无信号

- **WHEN** 信号缺少主要风险；或者信号是 signal-format spec 的基准无信号
- **THEN** 都是格式错误

### Requirement: 寻股的结论

寻股的结论 SHALL 只增删股票池：除公共部分外，包含要加入的候选和要删除的股票两个列表，都可以为空（这次不增删也要回答问题、写理由）。

- 每只加入的候选：股票代码、理由与论点草稿、信号（格式和「结论的公共部分」的信号相同，不能是无信号）
- 每只删除的股票：股票代码、理由

文字去掉首尾空白后为空、加入的候选缺少信号或者信号的格式错误，都是格式错误。加入和删除是否通过由股票池检查（stock-pool spec「加入候选」「删除」），来源是 PM 探索。

#### Scenario: 增删股票池

- **WHEN** 加入 DDD（理由"放量突破，论点草稿：订单回暖"，评分 1 的信号）和 EEE（理由"盈利预期上调"，评分 2 的信号），删除 AAA（理由"论点不再成立"）
- **THEN** 格式正确

#### Scenario: 这次不增删

- **WHEN** 加入和删除都为空
- **THEN** 格式正确

#### Scenario: 加入的候选必须有评分

- **WHEN** 加入 DDD，不写信号；信号的评分是 3；或者信号是 signal-format spec 的基准无信号
- **THEN** 都是格式错误

#### Scenario: 增删要写理由

- **WHEN** 加入 DDD 的理由是 " "；或者删除 AAA 的理由是 ""
- **THEN** 都是格式错误
