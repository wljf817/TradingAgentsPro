# Spec Delta

## MODIFIED Requirements

### Requirement: 程序日志的条目

程序 SHALL 把每个动作写成程序日志的一条记录。程序日志存在状态库所在的数据库里（表 `programlog_entries`，state-store spec「表的归属和迁移」），只由程序日志模块写入：别的模块、流程和启动程序都经它写，不直接写表。每条记录有：

| 字段 | 内容 |
| --- | --- |
| 编号 | 按写入的先后递增 |
| 时间 | 写入时从时钟读取的时刻；存为带时区的时刻，读回的是同一时刻，和数据库服务器、本机的时区都无关 |
| 行为者 | 风控引擎、执行模块、人、系统、股票池、调度器、Agent 网关、事件检测层，各自的动作见下面以「<行为者>的动作」为名的要求；以后的变更加别的行为者和动作 |
| 动作 | 行为者的一个动作 |
| 对象 | 动作针对的东西的标识：方案 ID、止损单的客户端订单 ID、股票代码、跟进 ID、task_id、案件 ID、快照的版本（`s<版本>`，和案件 ID 一起标识一版快照，state-snapshot spec「条目和条目 ID」）、事件 ID（event-rules spec「事件 ID 和去重」）；针对整个券商账户写 `account`，针对整个程序写 `system` |
| 案件 ID | 动作所属的案件；不属于案件时为空 |
| 输入的引用、输出的引用 | 动作用到的、产生的东西的标识，比如确认消息的标识、交易日、状态库条目 ID；各是一组文字，可以为空 |
| 说明 | 动作的内容和结果，中文；可以为空 |
| 耗时、token、费用 | 可以为空；费用是金额，原样保存每一位小数 |

行为者和动作各是一组固定的值。案件 ID、耗时、token 和费用只在动作的要求写明时才有，其余为空。

#### Scenario: 写一条

- **GIVEN** 进程的本机时区是 UTC+14；时钟是 2026-10-14T15:00:00.123Z
- **WHEN** 写一条：行为者是人，动作是确认，对象是方案 ID P1，输入的引用是确认消息的标识 M1，说明是"买入 BBB"
- **THEN** 程序日志多了一条，读回的时间是 2026-10-14T15:00:00.123Z，行为者、动作、对象、输入的引用和说明都是写入的值
- **AND** 输出的引用为空，案件 ID、耗时、token、费用为空

#### Scenario: 可以为空的字段原样读回

- **WHEN** 写一条带案件 ID、耗时 1.5 秒、token 1200、费用 0.0123 的条目
- **THEN** 读回的案件 ID、耗时、token 和费用都和写入的相同，费用仍是 0.0123

## ADDED Requirements

### Requirement: 事件检测层的动作

事件检测层的下面这些动作 SHALL 各写一条，行为者是事件检测层，都不属于案件，案件 ID 为空（event-detection spec）：

| 动作 | 什么时候写 | 对象 | 引用 | 说明 |
| --- | --- | --- | --- | --- |
| 检测到事件 | 记下一个新事件以后、排进案件以前（event-detection spec「记下和排队」） | 事件 ID | 输入：事件的引用（新闻 ID、accession number 或财报发布的键），没有时为空 | 类别、股票和这时的状态、是否持仓风险级别、来源、强度、事件的说明（event-rules spec「事件的内容」）；处理：排队，或者交给紧急风险退出、不排队 |
| 丢弃事件 | 一条新闻或一份公告对一只监控股票没有成为事件（event-detection spec「没成为事件的新闻和公告」） | 股票 | 输入：新闻 ID 或 accession number | 新闻的标题，或者公告的表单和 item；原因 |

- 卖出成交不是事件，不写这两种：排进的卖出复盘由调度器写排队（「调度器的动作」）
- 价格和成交量没有成为事件、财报日历还没到或已经有事件、不在监控范围的股票，SHALL NOT 写程序日志（event-detection spec「没成为事件的新闻和公告」）
- 记下事件以后写条目出错时照「写入失败」处理：已经记下的事件不撤回，这一轮按出错处理

#### Scenario: 检测到事件

- **GIVEN** event-detection spec 的基准数据；CCC 最新价 95.5
- **WHEN** 做一轮
- **THEN** 程序日志依次有：检测到事件（行为者是事件检测层，对象 CCC:2026-10-14:price_down，没有案件 ID，没有引用；说明写明价格和成交量异动、CCC 持仓、持仓风险级别、来源行情、强度 -0.045、跌 4.5%、处理是排队）；调度器的排队（对象 K-1）

#### Scenario: 交给紧急风险退出

- **GIVEN** event-detection spec 的基准数据；CCC 最新价 91
- **WHEN** 做一轮
- **THEN** 程序日志有一条检测到事件，说明写明交给紧急风险退出、不排队；没有排队

#### Scenario: 丢弃事件

- **GIVEN** event-detection spec 的基准数据；新闻源有 AAA 的标题"Goldman Upgrades AAA to Buy"的新闻
- **WHEN** 做一轮
- **THEN** 程序日志有一条丢弃事件：行为者是事件检测层，对象 AAA，输入的引用是 101，没有案件 ID；说明写明标题和原因级别不够

#### Scenario: 卖出成交只写排队

- **GIVEN** event-detection spec 的基准数据；交易记录里 CCC-STOP-1 全部成交，成交日 2026-10-14
- **WHEN** 做一轮
- **THEN** 程序日志只有调度器的一条排队，说明写明 CCC 的卖出成交和 CCC-STOP-1；没有事件检测层的条目
