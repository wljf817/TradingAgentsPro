# Spec Delta

## MODIFIED Requirements

### Requirement: 触发

开案件时调用方 SHALL 给出触发，触发有四种：

| 触发 | 带的内容 |
| --- | --- |
| 事件 | 股票、事件类别（见「事件要求的子 agent」）、是否是持仓风险级别（由事件检测标注）、事件 ID（event-rules spec「事件 ID 和去重」） |
| 定时心跳的检查项 | 检查项开出的案件类型（见下表）；针对单只股票的检查项带股票 |
| 跟进 | 股票、申请时写下的问题 |
| 卖出成交 | 股票、卖出的客户端订单 ID（交易记录的键，trade-records spec）。每笔已经结束、有成交的卖单和止损单都算：止损单成交、紧急风险退出（包括本地备用止损）、PM 发起的减仓和清仓、`/plan` 的卖出 |

| 定时心跳的检查项 | 开出的案件类型 | 带股票 |
| --- | --- | --- |
| 持仓复查日到期 | 持仓复查 | 是 |
| 投资论点的催化剂截止日期到期 | 持仓催化剂复查 | 是 |
| 关注复查日到期 | 关注复查 | 是 |
| 关注论点的催化剂截止日期到期 | 关注催化剂复查 | 是 |
| 有新候选 | 候选评估 | 是 |
| 股票池候选不足 | 寻股 | 否 |
| 每周固定时间 | 每周复盘 | 否 |

不合法的触发 SHALL 报错：定时心跳给出的案件类型不在上表里；带不带股票和上表不符。

本 spec 的场景除非另有说明，都使用默认配置和下面的基准数据：

- 股票：AAA 是候选；BBB 是关注，板块"医疗"；CCC 是持仓，板块"能源"
- 基准关注论点：和 stock-pool spec 的基准关注论点相同
- 基准投资论点：
  - 买入理由"新品周期带动收入加速"
  - 催化剂"Q3 财报"，截止日期 2026-10-29，不引用日程项或事件
  - 目标价 60
  - 证伪条件"毛利率连续两个季度下滑"，其中代码能检测的部分一条：价格不高于 42
  - 复查日 2026-10-21
- 基准方案条款：100 股，限价单，限价 50，止损价 45，紧急阈值 0.08，不写有效期和允许价格偏离
- 基准跟进申请：原因是外部日程，引用日程项"S-9"；问题"竞争对手 11 月 18 日发财报，之后对这只股票有什么影响？"；可能采取的动作"减仓"；触发时间 2026-11-19 14:30Z
- 结论的公共部分：回答"论点仍然成立"，理由"订单和毛利率都符合预期"，信号是 signal-format spec 的基准信号（评分 1），引用 R-1 和 R-2
- "评分 n 的信号"指只把基准信号的评分改为 n；场景里加入的候选只写"评分 n"时，它的信号就是评分 n 的信号
- 本案件派过任务的子 agent 是 News 和 Quant；状态是完成的 Result 有两个：R-1 出自 News，R-2 出自 Quant
- "某个案件开始运行"指这个触发开出的案件开始运行，股票的状态是这个时候的状态
- 事件的触发没有写事件 ID 时，事件 ID 是任意一个；卖出成交没有写客户端订单 ID 时同理

#### Scenario: 不合法的触发

- **WHEN** 定时心跳给出的案件类型是持仓事件；持仓复查不带股票；寻股带了股票 AAA
- **THEN** 都报错

#### Scenario: 事件和卖出成交带的内容

- **WHEN** 给出 CCC 的价格和成交量异动事件，持仓风险级别，事件 ID CCC:2026-10-14:price_down；给出 CCC 的卖出成交，客户端订单 ID CCC-STOP-1
- **THEN** 两个触发都合法，各自带着给出的事件 ID 和客户端订单 ID
