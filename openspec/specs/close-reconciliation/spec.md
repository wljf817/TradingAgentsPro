# close-reconciliation Specification

## Purpose

每个交易日收盘后，由盘中巡检触发一次执行模块和券商的全量对账：找出这一天的差异，按交易日记下差异和连续无差异的交易日数，在 Discord 推送结果；有不一致时暂停开仓，之后的对账没有不一致时恢复。

## Requirements

### Requirement: 收盘对账的时机

收盘对账以交易日为单位，每个交易日最多做一次。设 D 是收盘时刻不晚于当前时刻的最后一个交易日（trading-calendar spec），执行模块 SHALL 按下表判断现在要不要做收盘对账：

| 当前时刻 | 判断 |
| --- | --- |
| 在常规交易时段内 | 不做 |
| D 收盘以后，不到 D 收盘加延迟（「收盘对账配置」） | 不做 |
| D 收盘加延迟以后、下一个交易日开盘以前，状态库里还没有 D 的收盘对账记录 | 做 D 的收盘对账 |
| D 收盘加延迟以后、下一个交易日开盘以前，已经有 D 的记录 | 不做 |

- D 收盘加延迟以后到下一个交易日开盘以前都可以做，周末和节假日也在这段时间里。程序在 D 收盘时没有运行、下一个交易日开盘以前重启的，重启以后照样做 D 的收盘对账
- 下一个交易日开盘以后 SHALL NOT 再做 D 的收盘对账：D 没有收盘对账，见「连续天数」
- 半日市按当天实际的收盘时刻
- 启动对账（bootstrap spec「启动对账」）不算收盘对账，也不影响这里的判断
- 判断只读交易日历和状态库，不调用券商

本 spec 的场景除非另有说明，都使用下面的基准数据：

- order-lifecycle spec 的基准数据和 stop-protection spec 的约定，比如 P1 到 P4、"持有 BBB 100 股，止损单已对齐"、"券商回报……变为……"、"券商持仓变为……"。券商没有 AAA 的持仓，不用 order-lifecycle spec 基准数据里的 AAA 100 股
- 当前交易日 2026-10-14（周三），收盘 20:00Z；上一个交易日 2026-10-13（周二），收盘 20:00Z；下一个交易日 2026-10-15，开盘 13:30Z
- 收盘对账的延迟用默认值 10 分钟：2026-10-14 的收盘对账在 20:10Z 到期，它的「当天出现过的无保护仓位」从 2026-10-13 20:10Z 算起
- 执行配置和巡检配置用默认值；执行模块已经完成一次没有不一致的对账（启动对账）
- 状态库里没有任何收盘对账记录，除非另有说明
- "判断"指在给出的时刻按本 requirement 判断一次；"做 10-14 的收盘对账"指在给出的时刻（没写时是 2026-10-14 20:10Z）直接让执行模块做 2026-10-14 的收盘对账，拿着锁，不经过巡检；"巡检做一轮"见 session-patrol spec
- "连续天数 N 的记录"指那个交易日的收盘对账记录，连续天数是 N

#### Scenario: 收盘加延迟以后到期

- **GIVEN** 持有 BBB 100 股，止损单已对齐
- **WHEN** 2026-10-14 20:09:59Z 判断
- **THEN** 不做
- **WHEN** 2026-10-14 20:10:00Z 判断
- **THEN** 做 2026-10-14 的收盘对账

#### Scenario: 盘中不做

- **WHEN** 2026-10-14 15:00Z 判断，以及 19:59:59Z 判断
- **THEN** 两次都不做

#### Scenario: 一个交易日只做一次

- **GIVEN** 2026-10-14 20:10Z 已经做完 2026-10-14 的收盘对账
- **WHEN** 2026-10-14 20:10:15Z 判断，以及 2026-10-15 03:00Z 判断
- **THEN** 两次都不做

#### Scenario: 开盘以前重启时补做

- **GIVEN** 程序 2026-10-14 19:00Z 停止，2026-10-15 13:00Z（开盘前 30 分钟）重启；没有 2026-10-14 的记录
- **WHEN** 2026-10-15 13:00:10Z 判断
- **THEN** 做 2026-10-14 的收盘对账

#### Scenario: 开盘以后不再补做

- **GIVEN** 程序 2026-10-14 19:00Z 停止，2026-10-15 13:30Z 重启；没有 2026-10-14 的记录
- **WHEN** 2026-10-15 13:30:10Z 判断
- **THEN** 不做
- **WHEN** 2026-10-15 20:10Z 判断
- **THEN** 做 2026-10-15 的收盘对账；2026-10-14 一直没有记录

#### Scenario: 半日市按实际收盘

- **GIVEN** 2026-11-27（感恩节次日）美东 13:00 收盘，即 18:00Z
- **WHEN** 2026-11-27 18:09:59Z 判断
- **THEN** 不做
- **WHEN** 2026-11-27 18:10Z 判断
- **THEN** 做 2026-11-27 的收盘对账

#### Scenario: 周末补做周五的

- **GIVEN** 程序 2026-10-16（周五）19:00Z 停止，2026-10-17（周六）15:00Z 重启；没有 2026-10-16 的记录
- **WHEN** 2026-10-17 15:00:10Z 判断
- **THEN** 做 2026-10-16 的收盘对账

#### Scenario: 节假日不另做

- **GIVEN** 2026-11-25（周三）的收盘对账已经做过；2026-11-26 感恩节休市
- **WHEN** 2026-11-26 18:00Z 判断
- **THEN** 不做

### Requirement: 巡检里的收盘对账

盘中巡检的每一轮 SHALL 在最后做一项「收盘对账」：在第 3 步（对齐止损单，session-patrol spec「每一轮」）之后，也在加在第 3 步之后的别的项（health-monitoring spec 的健康判定、emergency-exit-flow spec 的紧急退出）之后：

1. 按「收盘对账的时机」判断要不要做；不做就结束这一项。判断不拿锁
2. 要做时拿着锁（session-patrol spec「执行模块和风控的调用串行」）做收盘对账（「收盘对账的步骤」），做完放开锁
3. 放开锁以后按「结果消息」推送结果。推送时 MUST NOT 拿着锁

收盘对账是一轮的最后一项：同一轮刚跟进过订单、对齐过止损单，收盘对账补上的就是巡检没能补上的。这一项和巡检的其他项一样（session-patrol spec「巡检的开始、间隔和停止」）：停止时正在做，就做完（包括推送）再结束；出错见「收盘对账的失败」。

#### Scenario: 一轮对齐止损单以后做收盘对账

- **GIVEN** 持有 BBB 100 股，止损单已对齐
- **WHEN** 券商回报 BBB-STOP-1 变为撤销，2026-10-14 20:10Z 巡检做一轮
- **THEN** 第 3 步对齐 BBB，券商收到止损单 BBB-STOP-2：卖出 100 股，止损价 45
- **AND** 之后做 2026-10-14 的收盘对账：没有对账补挂或重挂的止损单，没有差异，推送一条结果

#### Scenario: 不到时刻的轮次不做

- **GIVEN** 持有 BBB 100 股，止损单已对齐
- **WHEN** 2026-10-14 20:09:45Z 巡检做一轮
- **THEN** 没有做收盘对账：券商没有收到读取全部挂单的请求，没有推送

#### Scenario: 别的调用拿着锁时等待

- **GIVEN** 持有 BBB 100 股，止损单已对齐；另一个线程拿着锁
- **WHEN** 2026-10-14 20:10Z 巡检做收盘对账这一项
- **THEN** 那个线程放开锁之前，券商没有收到读取全部挂单的请求
- **WHEN** 那个线程放开锁
- **THEN** 做 2026-10-14 的收盘对账

#### Scenario: 推送结果时不拿锁

- **GIVEN** 2026-10-14 20:10Z 巡检做完 2026-10-14 的收盘对账，推送结果时 Discord 一直没有响应
- **WHEN** 巡检还在等这次推送
- **THEN** 另一个线程可以立即拿到锁

#### Scenario: 停止时正在收盘对账

- **GIVEN** 2026-10-14 20:10Z 巡检正在做 2026-10-14 的收盘对账，券商对读取全部挂单的请求还没有响应
- **WHEN** 程序停止
- **THEN** 券商响应以后，对账做完、记录保存、结果推送，巡检才结束

### Requirement: 收盘对账的步骤

执行模块做交易日 D 的收盘对账时 SHALL 依次：

1. 读取券商的全部持仓，记下有持仓的股票数
2. 记下对账以前的情况：还没结束的订单；每只股票的止损保护用过的止损单序号（stop-protection spec「止损单」），没有止损保护记录的算 0；最近一次完成的对账有没有不一致
3. 对账（reconciliation spec「对账」）。暂停和恢复开仓照 reconciliation spec「有不一致时暂停开仓」，按这次对账的结果
4. 按「差异」找出差异
5. 按「连续天数」算出 D 的连续天数，保存 D 的收盘对账记录（「收盘对账记录」），给出这条记录

D 已经有收盘对账记录时 SHALL NOT 再对账，直接给出已有的记录，也不推送结果。收盘对账 SHALL NOT 撤销券商那边的任何挂单，也不提交普通订单：它对券商的写操作只有对账里对齐止损单时的挂单、改单和撤单。

#### Scenario: 没有差异

- **GIVEN** 持有 BBB 100 股，止损单已对齐，没有未结束的订单
- **WHEN** 做 10-14 的收盘对账
- **THEN** 没有差异，有持仓的股票数 1，连续天数 1
- **AND** 券商没有收到挂单、改单和撤单
- **AND** 状态库里有 2026-10-14 的收盘对账记录

#### Scenario: 已经有记录时不再对账

- **GIVEN** 2026-10-14 20:10Z 已经做完 2026-10-14 的收盘对账
- **WHEN** 2026-10-14 20:11Z 再让执行模块做 2026-10-14 的收盘对账
- **THEN** 券商没有收到任何请求，给出的是已有的记录，记录没有新版本

### Requirement: 差异

收盘对账 SHALL 按下表找出差异，任何一类不为空，这个交易日就有差异：

| 差异 | 内容 | 算不一致 |
| --- | --- | --- |
| 不认得的挂单 | 对账结果里的同名一类（reconciliation spec「不认得的挂单」）：股票、客户端订单 ID、券商订单号 | 是 |
| 多出来的止损单 | 对账结果里的同名一类（reconciliation spec「多出来的止损单」）：股票，券商挂着的这些止损单的客户端订单 ID 和券商订单号 | 是 |
| 来历不明的持仓 | 对账结果里的同名一类（reconciliation spec「来历不明的持仓」）：股票、券商持仓股数 | 是 |
| 收盘时没结束的订单 | 「收盘对账的步骤」第 2 步记下的每一笔还没结束的订单：股票、方案 ID、买卖方向、对账以后的状态。不论对账有没有把它结束；因为券商查不到而结束的订单都在这一类里 | 否 |
| 对账补挂或重挂的止损单 | 对账以后用过的止损单序号比第 2 步记下的大的股票：股票、对账以后当前止损单的客户端订单 ID | 否 |
| 当天出现过的无保护仓位 | 从上一个交易日收盘加延迟的时刻起，到对账完成为止，任何时刻是无保护仓位（stop-protection spec「挂单或改单被拒」）的股票。每一段无保护一条（按无保护开始的时刻区分）：股票、无保护开始的时刻 | 否 |

- 三类不一致照 reconciliation spec「有不一致时暂停开仓」暂停开仓。其余三类只算差异、不暂停开仓：对账已经补挂了止损单，无保护仓位和状态未知的订单由巡检接着处理
- 只有收盘对账自己补上的变化才算差异。巡检在收盘对账之前补上的（比如巡检的对齐补挂了止损单）、启动对账补上的（比如停机期间的成交、补挂的止损单），都不算
- 上一个交易日指交易日历上的前一个交易日；它的收盘加延迟按它当天的收盘时刻

#### Scenario: 来历不明的持仓

- **GIVEN** 持有 BBB 100 股，止损单已对齐；券商另有持仓 CCC 100 股，执行模块没有 CCC 的订单
- **WHEN** 做 10-14 的收盘对账
- **THEN** 差异有来历不明的持仓：CCC 100 股，算不一致
- **WHEN** 之后提交买入方案
- **THEN** 报对账不一致的错误，没有创建订单

#### Scenario: 不认得的挂单

- **GIVEN** 持有 BBB 100 股，止损单已对齐；券商另外挂着一笔买入 CCC 的订单，客户端订单 ID 是 X1，券商订单号 B9
- **WHEN** 做 10-14 的收盘对账
- **THEN** 差异有不认得的挂单：CCC、X1、B9，算不一致
- **AND** 券商没有收到撤单请求

#### Scenario: 多出来的止损单

- **GIVEN** 持有 BBB 100 股，止损单已对齐；券商另外挂着一张 BBB 的止损单 X2
- **WHEN** 做 10-14 的收盘对账
- **THEN** 差异有多出来的止损单：BBB，BBB-STOP-1 和 X2，算不一致

#### Scenario: 收盘时还状态未知的订单

- **GIVEN** P1 已经提交，记下了券商订单号；2026-10-14 20:09:50Z 跟进时券商查不到 P1，P1 状态未知
- **WHEN** 2026-10-14 20:10Z 做 10-14 的收盘对账，券商仍查不到 P1
- **THEN** 券商没有收到按 P1 的查询（还没满等待时长），P1 仍是状态未知
- **AND** 差异有收盘时没结束的订单：BBB、P1、买入、状态未知，不算不一致

#### Scenario: 券商查不到而结束的订单

- **GIVEN** P1 已经提交，记下了券商订单号；2026-10-14 20:09:00Z 跟进时券商查不到 P1，P1 状态未知
- **WHEN** 2026-10-14 20:10Z 做 10-14 的收盘对账，券商仍查不到 P1，券商挂着的订单里也没有它
- **THEN** P1 已过期，累计成交 0
- **AND** 差异有收盘时没结束的订单：BBB、P1、买入、已过期

#### Scenario: 巡检在收盘对账以前结束的订单不算

- **GIVEN** P1 部分成交，累计成交 30；券商持仓 BBB 30 股，BBB-STOP-1 挂着 30 股，止损价 45
- **AND** 2026-10-14 20:00:10Z 巡检请求撤单，20:00:25Z 巡检跟进时 P1 已过期
- **WHEN** 做 10-14 的收盘对账
- **THEN** 没有差异

#### Scenario: 对账重挂的止损单

- **GIVEN** 持有 BBB 100 股，止损单已对齐
- **WHEN** 券商回报 BBB-STOP-1 变为撤销，做 10-14 的收盘对账
- **THEN** 券商收到止损单 BBB-STOP-2：卖出 100 股，止损价 45
- **AND** 差异有对账补挂或重挂的止损单：BBB、BBB-STOP-2，不算不一致
- **WHEN** 之后提交买入方案
- **THEN** 订单已提交

#### Scenario: 对账给还没有止损单的持仓补挂

- **GIVEN** P1 全部成交，跟进 P1 时查询持仓断线，BBB 没有止损单；券商持仓 BBB 100 股
- **WHEN** 做 10-14 的收盘对账
- **THEN** 券商收到止损单 BBB-STOP-1：卖出 100 股，止损价 45
- **AND** 差异有对账补挂或重挂的止损单：BBB、BBB-STOP-1

#### Scenario: 对账补挂又被拒

- **GIVEN** 持有 BBB 100 股，止损单已对齐；券商会一直拒绝挂单
- **WHEN** 券商回报 BBB-STOP-1 变为撤销，做 10-14 的收盘对账
- **THEN** BBB 是无保护仓位，开始时刻 2026-10-14 20:10Z
- **AND** 差异有对账补挂或重挂的止损单（BBB、BBB-STOP-2）和当天出现过的无保护仓位（BBB，从 2026-10-14 20:10Z 起）

#### Scenario: 启动对账补挂的止损单不算

- **GIVEN** 持有 BBB 100 股，止损单已对齐；程序 2026-10-14 16:00Z 停止，停机期间券商回报 BBB-STOP-1 变为撤销
- **AND** 2026-10-14 17:00Z 重启，启动对账挂上 BBB-STOP-2
- **WHEN** 做 10-14 的收盘对账
- **THEN** 没有差异

#### Scenario: 当天出现过的无保护仓位

- **GIVEN** 持有 BBB 100 股；BBB 从 2026-10-14 15:00Z 起是无保护仓位，15:05Z 补挂成功，之后止损单已对齐
- **WHEN** 做 10-14 的收盘对账
- **THEN** 差异有当天出现过的无保护仓位：BBB，从 2026-10-14 15:00Z 起，不算不一致

#### Scenario: 两段无保护各一条

- **GIVEN** 持有 BBB 100 股；BBB 在 2026-10-14 15:00Z 到 15:05Z、16:00Z 到 16:30Z 两段时间是无保护仓位，之后止损单已对齐
- **WHEN** 做 10-14 的收盘对账
- **THEN** 当天出现过的无保护仓位有两条：BBB 从 15:00Z 起，BBB 从 16:00Z 起

#### Scenario: 上一个交易日收盘对账以前结束的无保护不算

- **GIVEN** 持有 BBB 100 股；BBB 从 2026-10-13 19:00Z 起是无保护仓位，19:30Z 补挂成功，之后止损单已对齐
- **WHEN** 做 10-14 的收盘对账
- **THEN** 没有差异

#### Scenario: 跨过上一个交易日收盘对账的无保护

- **GIVEN** 持有 BBB 100 股；BBB 从 2026-10-13 20:05Z 起是无保护仓位，2026-10-14 14:00Z 补挂成功，之后止损单已对齐
- **WHEN** 做 10-14 的收盘对账
- **THEN** 差异有当天出现过的无保护仓位：BBB，从 2026-10-13 20:05Z 起

### Requirement: 连续天数

每次收盘对账 SHALL 按下表算出这个交易日的连续天数，存进记录：

| 这个交易日 | 连续天数 |
| --- | --- |
| 没有差异，收盘对账第 1 步读到券商那边有持仓 | 上一个交易日的连续天数加 1；上一个交易日没有收盘对账记录时为 1 |
| 有差异 | 0 |
| 没有差异，收盘对账第 1 步读到券商那边没有持仓 | 0 |

- 上一个交易日指交易日历上的前一个交易日，周末和节假日不算
- 某个交易日收盘后没有做收盘对账（「收盘对账的时机」「收盘对账的失败」），它没有记录；下一个交易日从 1 算起
- 程序重启、降级模式都不影响连续天数：只看每个交易日的记录

#### Scenario: 第一个交易日

- **GIVEN** 持有 BBB 100 股，止损单已对齐；没有任何收盘对账记录
- **WHEN** 做 10-14 的收盘对账
- **THEN** 连续天数 1

#### Scenario: 接着上一个交易日

- **GIVEN** 持有 BBB 100 股，止损单已对齐；有 2026-10-13 连续天数 4 的记录
- **WHEN** 做 10-14 的收盘对账，没有差异
- **THEN** 连续天数 5

#### Scenario: 跨过周末

- **GIVEN** 持有 BBB 100 股，止损单已对齐；有 2026-10-16（周五）连续天数 3 的记录
- **WHEN** 2026-10-19（周一）20:10Z 做 2026-10-19 的收盘对账，没有差异
- **THEN** 连续天数 4

#### Scenario: 跨过节假日和半日市

- **GIVEN** 持有 BBB 100 股，止损单已对齐；有 2026-11-25 连续天数 6 的记录；2026-11-26 休市
- **WHEN** 2026-11-27 18:10Z 做 2026-11-27 的收盘对账，没有差异
- **THEN** 连续天数 7

#### Scenario: 有差异时清零

- **GIVEN** 持有 BBB 100 股，止损单已对齐；有 2026-10-13 连续天数 4 的记录；券商另有持仓 CCC 100 股，执行模块没有 CCC 的订单
- **WHEN** 做 10-14 的收盘对账
- **THEN** 连续天数 0
- **WHEN** 券商持仓 CCC 变为 0 股，2026-10-15 20:10Z 做 2026-10-15 的收盘对账，没有差异
- **THEN** 连续天数 1

#### Scenario: 漏做一天时清零

- **GIVEN** 持有 BBB 100 股，止损单已对齐；有 2026-10-13 连续天数 4 的记录；没有 2026-10-14 的记录（程序从 2026-10-14 19:00Z 停到 2026-10-15 14:00Z）
- **WHEN** 2026-10-15 20:10Z 做 2026-10-15 的收盘对账，没有差异
- **THEN** 连续天数 1

#### Scenario: 收盘时没有持仓

- **GIVEN** 有 2026-10-13 连续天数 4 的记录；券商没有持仓，没有未结束的订单，没有止损单
- **WHEN** 做 10-14 的收盘对账
- **THEN** 没有差异，有持仓的股票数 0，连续天数 0

#### Scenario: 重启不清零

- **GIVEN** 持有 BBB 100 股，止损单已对齐；有 2026-10-13 连续天数 4 的记录；程序 2026-10-14 16:00Z 停止、17:00Z 重启
- **WHEN** 做 10-14 的收盘对账，没有差异
- **THEN** 连续天数 5

#### Scenario: 降级模式不清零

- **GIVEN** 持有 BBB 100 股，止损单已对齐；有 2026-10-13 连续天数 4 的记录；2026-10-14 15:00Z 到 16:00Z 因为行情延迟处于降级模式
- **WHEN** 2026-10-14 20:10Z 巡检做一轮
- **THEN** 做了 2026-10-14 的收盘对账，没有差异，连续天数 5

### Requirement: 结果消息

每次收盘对账做完（不含直接给出已有记录的那种），巡检 SHALL 先写一条程序日志：执行模块的对账（program-log spec「执行模块的动作」），对象 `account`，输出的引用是交易日，说明是下面消息的全文；再推送这条消息（discord-notification spec「告警」），告警的对象是 `account`：

| 情况 | 消息的内容 |
| --- | --- |
| 没有差异，收盘时有持仓 | 交易日、没有差异、有持仓的股票数、连续天数 |
| 没有差异，收盘时没有持仓 | 交易日、没有差异、收盘时没有持仓所以连续天数清零 |
| 有差异 | 第一行：交易日、有差异、连续天数清零；之后每一条差异一行，写明差异的类别和「差异」表里的内容，时刻写 UTC、到分钟 |

另外在消息末尾：

| 情况 | 加一行 |
| --- | --- |
| 这次对账有不一致 | 已暂停开仓，之后的对账没有不一致时恢复 |
| 对账以前最近一次完成的对账（启动对账或收盘对账）有不一致，这次没有 | 没有不一致，已恢复开仓 |

推送发不出去时写错误日志（discord-notification spec「告警」），告警的条目写明没有发出去，不重发。

#### Scenario: 没有差异

- **GIVEN** 持有 BBB 100 股，止损单已对齐；有 2026-10-13 连续天数 2 的记录
- **WHEN** 2026-10-14 20:10Z 巡检做一轮
- **THEN** 推送一条消息，写明 2026-10-14、没有差异、持仓 1 只、连续 3 个交易日
- **AND** 程序日志有一条对账，输出的引用是 2026-10-14，说明和消息相同

#### Scenario: 收盘时没有持仓

- **GIVEN** 券商没有持仓，没有未结束的订单
- **WHEN** 2026-10-14 20:10Z 巡检做一轮
- **THEN** 推送一条消息，写明 2026-10-14、没有差异、收盘时没有持仓、连续天数清零

#### Scenario: 有不一致

- **GIVEN** 持有 BBB 100 股，止损单已对齐；券商另有持仓 CCC 100 股，执行模块没有 CCC 的订单
- **WHEN** 2026-10-14 20:10Z 巡检做一轮
- **THEN** 推送一条消息：第一行写明 2026-10-14、有差异、连续天数清零；有一行写明来历不明的持仓 CCC 100 股；最后一行写明已暂停开仓，之后的对账没有不一致时恢复
- **AND** 程序日志有一条对账，说明是这条消息的全文

#### Scenario: 有差异、没有不一致

- **GIVEN** 持有 BBB 100 股；BBB 从 2026-10-14 15:00Z 起是无保护仓位，15:05Z 补挂成功，之后止损单已对齐
- **WHEN** 2026-10-14 20:10Z 巡检做一轮
- **THEN** 推送一条消息，有一行写明当天出现过的无保护仓位 BBB、从 2026-10-14 15:00 UTC 起
- **AND** 消息里没有暂停开仓的那一行

#### Scenario: 收盘对账以后恢复开仓

- **GIVEN** 持有 BBB 100 股，止损单已对齐；2026-10-13 的收盘对账有来历不明的持仓 CCC 100 股，暂停开仓；之后券商持仓 CCC 变为 0 股
- **WHEN** 2026-10-14 20:10Z 巡检做一轮
- **THEN** 推送的消息写明没有差异，最后一行写明没有不一致，已恢复开仓
- **WHEN** 之后提交买入方案
- **THEN** 订单已提交

#### Scenario: 启动对账的不一致在收盘对账时恢复

- **GIVEN** 持有 BBB 100 股，止损单已对齐；程序 2026-10-14 17:00Z 重启，启动对账有来历不明的持仓 CCC 100 股；之后券商持仓 CCC 变为 0 股
- **WHEN** 2026-10-14 20:10Z 巡检做一轮
- **THEN** 推送的消息最后一行写明没有不一致，已恢复开仓

#### Scenario: 推送发不出去

- **GIVEN** 持有 BBB 100 股，止损单已对齐；Discord 报错
- **WHEN** 2026-10-14 20:10Z 巡检做一轮
- **THEN** 写一条错误日志，含消息的文字和失败原因；程序日志有对账和写明没有发出去的告警；2026-10-14 的记录已经保存
- **WHEN** Discord 恢复，之后一轮
- **THEN** 没有再推送 2026-10-14 的结果

### Requirement: 收盘对账记录

每次收盘对账 SHALL 在状态库（state-store spec）里按交易日保存一条记录，只由执行模块写入：

| 项 | 内容 |
| --- | --- |
| 交易日 | 对账的交易日 |
| 完成的时刻 | 对账完成的时刻 |
| 对账结果 | 三类不一致，见 reconciliation spec |
| 收盘时没结束的订单、对账补挂或重挂的止损单、当天出现过的无保护仓位 | 见「差异」 |
| 有持仓的股票数 | 「收盘对账的步骤」第 1 步读到的 |
| 恢复开仓 | 对账以前最近一次完成的对账有不一致，这次没有 |
| 连续天数 | 见「连续天数」 |

进程重启以后 SHALL 读到之前保存的全部记录：「收盘对账的时机」看这个交易日有没有记录，「连续天数」看上一个交易日的记录。

#### Scenario: 重启以后接着算

- **GIVEN** 持有 BBB 100 股，止损单已对齐；有 2026-10-13 连续天数 1 的记录；2026-10-14 20:10Z 做完 2026-10-14 的收盘对账，连续天数 2
- **WHEN** 2026-10-14 20:20Z 程序重启（用同一个状态库新建执行模块），判断
- **THEN** 不做
- **WHEN** 2026-10-15 20:10Z 做 2026-10-15 的收盘对账，没有差异
- **THEN** 连续天数 3

#### Scenario: 记录原样读回

- **GIVEN** 2026-10-14 的收盘对账有来历不明的持仓 CCC 100 股、收盘时没结束的订单 P1（BBB、买入、状态未知）、对账重挂的止损单 BBB-STOP-2、BBB 从 2026-10-14 15:00Z 起的一段无保护，有持仓的股票数 2，连续天数 0
- **WHEN** 保存以后，用同一个状态库读 2026-10-14 的记录
- **THEN** 读到的记录和保存的相同

### Requirement: 收盘对账的失败

收盘对账出错时 SHALL 按下表处理，巡检不因此停下：

| 失败 | 处理 |
| --- | --- |
| 「收盘对账的步骤」第 1 步读券商持仓，或者对账第 1 步的读取超时、断线 | 写一条 WARNING，写明交易日和券商不可用；不保存记录，不推送；巡检下一轮再判断、再做，直到下一个交易日开盘 |
| 对账第 3、4 步里券商超时、断线 | 照 reconciliation spec 记为状态未知，对账照样完成；还没结束的订单照常记为差异 |
| 数据库出错、券商的认证错误、意外的异常 | 照 session-patrol spec「一轮里的失败」写 ERROR，带异常栈；不推送；巡检下一轮再判断、再做 |
| 推送发不出去 | 见「结果消息」 |

券商到下一个交易日开盘都不可用时，这个交易日没有收盘对账记录（「连续天数」）。

#### Scenario: 读持仓超时，下一轮再做

- **GIVEN** 持有 BBB 100 股，止损单已对齐；读取券商的全部持仓会超时
- **WHEN** 2026-10-14 20:10Z 巡检做一轮
- **THEN** 有一条 WARNING 写明 2026-10-14 的收盘对账没做成、券商不可用；没有 2026-10-14 的记录，没有推送
- **WHEN** 读取恢复正常，2026-10-14 20:10:15Z 巡检做一轮
- **THEN** 做了 2026-10-14 的收盘对账，推送结果

#### Scenario: 对账读挂单时断线

- **GIVEN** 持有 BBB 100 股，止损单已对齐
- **WHEN** 做 10-14 的收盘对账，读取券商全部挂单时断线
- **THEN** 报券商不可用的错误；券商没有收到挂单、改单和撤单；没有 2026-10-14 的记录

#### Scenario: 券商到开盘都不可用

- **GIVEN** 持有 BBB 100 股，止损单已对齐；有 2026-10-13 连续天数 4 的记录；券商从 2026-10-14 19:00Z 到 2026-10-15 14:00Z 一直不可用
- **WHEN** 巡检照常每一轮都试
- **THEN** 没有 2026-10-14 的记录；2026-10-15 13:30Z 以后不再做 2026-10-14 的收盘对账
- **WHEN** 2026-10-15 20:10Z 做 2026-10-15 的收盘对账，没有差异
- **THEN** 连续天数 1

#### Scenario: 对账跟进订单时超时

- **GIVEN** P1 部分成交，累计成交 30，截止时刻 2026-10-14 20:00Z，已经请求过撤单，券商还没回报结束；券商持仓 BBB 30 股，BBB-STOP-1 挂着 30 股
- **WHEN** 做 10-14 的收盘对账，按 P1 的查询超时
- **THEN** 对账完成，P1 状态未知
- **AND** 差异有收盘时没结束的订单：BBB、P1、买入、状态未知

#### Scenario: 保存记录时数据库出错

- **GIVEN** 持有 BBB 100 股，止损单已对齐；保存收盘对账记录时数据库会出错一次
- **WHEN** 2026-10-14 20:10Z 巡检做一轮
- **THEN** 有一条 ERROR 写明收盘对账出错，带异常栈；没有推送
- **WHEN** 之后一轮
- **THEN** 做了 2026-10-14 的收盘对账，保存记录，推送结果

### Requirement: 收盘对账配置

收盘对账的阈值 SHALL 可以配置，属于执行模块的配置（order-lifecycle spec「执行配置」之外新加的一项）：

| 配置项 | 默认值 | 要求 | 理由 |
| --- | --- | --- | --- |
| 收盘对账的延迟 | 10 分钟 | 大于 0 | 收盘时刻截止的订单在收盘以后由巡检请求撤单（session-patrol spec），巡检 15 秒一轮、状态未知 30 秒以后再查，一两分钟内都会结束；10 分钟留足余量，收盘后不久就有结果 |

#### Scenario: 默认配置

- **WHEN** 不改执行配置
- **THEN** 收盘对账的延迟是 10 分钟

#### Scenario: 修改延迟

- **GIVEN** 收盘对账的延迟改为 30 分钟
- **WHEN** 2026-10-14 20:29:59Z 判断，以及 20:30Z 判断
- **THEN** 第一次不做，第二次做 2026-10-14 的收盘对账

#### Scenario: 延迟不大于 0

- **WHEN** 收盘对账的延迟设为 0 分钟或 -1 分钟
- **THEN** 配置报错
