# degraded-mode Specification

## Purpose

健康监控根据模型 API、券商连接、数据延迟、调用预算和调度器心跳五项检查，判定系统是否进入降级模式；全部恢复并完成一次对账后退出，并给出恢复后的第一个交易日。

## Requirements

### Requirement: 健康检查

健康监控 SHALL 根据调用方传入的健康信号、当前时刻、交易日历和配置，给出哪些检查异常：

| 检查 | 健康信号 | 异常的条件 |
| --- | --- | --- |
| 模型 API | PM 是否还有可用的模型；Critic 是否还有可用的模型 | PM 或 Critic 没有可用的模型，即主模型和备用模型全部不可用 |
| 券商连接 | 券商是否连接 | 券商断开 |
| 数据延迟 | 行情最近一次更新的时刻 | 当前时刻在常规交易时段内，并且行情延迟超过数据延迟上限 |
| 调用预算 | 持仓保留预算是否用完 | 持仓保留预算用完 |
| 调度器心跳 | 调度器最近一次心跳的时刻 | 当前时刻减去最近一次心跳，超过调度器心跳超时 |

行情延迟 = 当前时刻减去行情最近一次更新的时刻；今天开盘以来还没有更新时（包括从来没有更新过），从今天开盘起算。常规交易时段之外不检查数据延迟。调度器心跳任何时刻都检查。

只有一个模型不可用、还能换备用模型时，"是否还有可用的模型"为是，不算异常。

本 spec 的场景除非另有说明，都使用默认配置和下面的基准数据：

- 当前时刻 2026-10-14 15:00Z（周三，盘中），交易日历是纽交所日历，这一天的常规交易时段是 13:30Z 到 20:00Z
- 基准信号，五项检查都正常：PM 和 Critic 都还有可用的模型；券商已连接；行情最近一次更新在当前时刻之前 10 秒；持仓保留预算没有用完；调度器最近一次心跳在当前时刻之前 2 分钟。当前时刻是 2026-10-14 15:00Z 时，就是 14:59:50Z 和 14:58:00Z；场景拨动时间时，这两个时刻跟着变，另外写明的除外
- 健康监控刚刚新建，状态是正常
- "判定"指在当前时刻用健康信号判定一次；"对账完成"指调用方告诉健康监控刚完成了一次对账

#### Scenario: 全部正常

- **GIVEN** 基准数据
- **WHEN** 判定
- **THEN** 没有异常的检查

#### Scenario: PM 或 Critic 没有可用的模型

- **GIVEN** 基准数据
- **WHEN** PM 没有可用的模型，判定
- **THEN** 异常的检查是模型 API
- **WHEN** PM 还有可用的模型，Critic 没有，判定
- **THEN** 异常的检查是模型 API

#### Scenario: 券商断开

- **GIVEN** 基准数据，券商断开
- **WHEN** 判定
- **THEN** 异常的检查是券商连接

#### Scenario: 数据延迟的边界

- **GIVEN** 基准数据
- **WHEN** 行情最近一次更新在 2026-10-14 14:59:00Z（延迟 60 秒），判定
- **THEN** 没有异常的检查
- **WHEN** 行情最近一次更新在 2026-10-14 14:58:59Z（延迟 61 秒），判定
- **THEN** 异常的检查是数据延迟

#### Scenario: 开盘时从开盘起算延迟

- **GIVEN** 基准数据，行情最近一次更新在前一交易日 2026-10-13 20:00Z
- **WHEN** 当前时刻 2026-10-14 13:31:00Z，判定
- **THEN** 没有异常的检查
- **WHEN** 当前时刻 2026-10-14 13:31:01Z，判定
- **THEN** 异常的检查是数据延迟
- **WHEN** 行情从来没有更新过，当前时刻 2026-10-14 13:31:01Z，判定
- **THEN** 异常的检查是数据延迟

#### Scenario: 盘外不检查数据延迟

- **GIVEN** 基准数据，调度器最近一次心跳在当前时刻之前 1 分钟
- **WHEN** 当前时刻 2026-10-14 21:00Z（盘后），行情最近一次更新在 2026-10-14 20:00Z，判定
- **THEN** 没有异常的检查
- **WHEN** 当前时刻 2026-10-15 12:00Z（盘前），判定
- **THEN** 没有异常的检查

#### Scenario: 持仓保留预算用完

- **GIVEN** 基准数据，持仓保留预算用完
- **WHEN** 判定
- **THEN** 异常的检查是调用预算

#### Scenario: 调度器心跳超时的边界

- **GIVEN** 基准数据
- **WHEN** 调度器最近一次心跳在 2026-10-14 14:55:00Z（300 秒前），判定
- **THEN** 没有异常的检查
- **WHEN** 调度器最近一次心跳在 2026-10-14 14:54:59Z（301 秒前），判定
- **THEN** 异常的检查是调度器心跳
- **WHEN** 当前时刻 2026-10-14 21:00Z（盘后），调度器最近一次心跳在 2026-10-14 20:54:59Z，判定
- **THEN** 异常的检查是调度器心跳

#### Scenario: 多项同时异常

- **GIVEN** 基准数据，券商断开，持仓保留预算用完
- **WHEN** 判定
- **THEN** 异常的检查是券商连接和调用预算

### Requirement: 进入和退出降级模式

健康监控 SHALL 处于三种状态之一：正常、降级、等待对账。降级和等待对账都算处于降级模式。状态只在判定和对账完成时变化：

| 当前状态 | 事件 | 之后的状态 |
| --- | --- | --- |
| 正常 | 判定，有异常的检查 | 降级，进入时刻是这次判定的时刻 |
| 正常 | 判定，没有异常的检查 | 正常 |
| 正常 | 对账完成 | 正常 |
| 降级 | 判定，有异常的检查 | 降级 |
| 降级 | 判定，没有异常的检查 | 等待对账 |
| 降级 | 对账完成 | 降级：降级期间完成的对账不算 |
| 等待对账 | 判定，有异常的检查 | 降级 |
| 等待对账 | 判定，没有异常的检查 | 等待对账 |
| 等待对账 | 对账完成 | 正常 |

健康监控 SHALL 给出当前状态：三种状态之一，是否处于降级模式，最近一次判定时异常的检查，进入降级模式的时刻。进入时刻从进入降级起保持不变，经过等待对账再回到降级也不变；回到正常时清掉。

状态放在内存里：健康监控新建以后是正常，进程重启以后由下一次判定重新算。调用方按当前状态告警、写程序日志，并把是否处于降级模式交给风控暂停开仓。

#### Scenario: 一项检查异常就进入降级

- **GIVEN** 基准数据，券商断开
- **WHEN** 判定
- **THEN** 状态是降级，处于降级模式，异常的检查是券商连接，进入时刻 2026-10-14 15:00Z

#### Scenario: 正常时判定和对账都不改变状态

- **GIVEN** 基准数据
- **WHEN** 判定，再对账完成
- **THEN** 状态都是正常，不处于降级模式，没有进入时刻

#### Scenario: 降级期间异常的检查跟着判定变化

- **GIVEN** 基准数据，券商断开，判定，状态是降级
- **WHEN** 当前时刻 2026-10-14 15:01Z，券商已连接，持仓保留预算用完，判定
- **THEN** 状态仍是降级，异常的检查是调用预算，进入时刻仍是 2026-10-14 15:00Z

#### Scenario: 全部恢复以后等待对账

- **GIVEN** 基准数据，券商断开，判定，状态是降级
- **WHEN** 当前时刻 2026-10-14 15:05Z，券商已连接，判定
- **THEN** 状态是等待对账，仍处于降级模式，没有异常的检查，进入时刻仍是 2026-10-14 15:00Z

#### Scenario: 降级期间完成的对账不算

- **GIVEN** 基准数据，PM 没有可用的模型，判定，状态是降级
- **WHEN** 当前时刻 2026-10-14 15:02Z，对账完成
- **THEN** 状态仍是降级
- **WHEN** 当前时刻 2026-10-14 15:05Z，PM 恢复可用的模型，判定
- **THEN** 状态是等待对账

#### Scenario: 等待对账时对账完成就退出

- **GIVEN** 基准数据，券商断开，判定；2026-10-14 15:05Z 券商已连接，判定，状态是等待对账
- **WHEN** 当前时刻 2026-10-14 15:06Z，判定，没有异常的检查
- **THEN** 状态仍是等待对账
- **WHEN** 当前时刻 2026-10-14 15:07Z，对账完成
- **THEN** 状态是正常，不处于降级模式，没有进入时刻

#### Scenario: 等待对账时又有检查异常

- **GIVEN** 基准数据，券商断开，判定；2026-10-14 15:05Z 券商已连接，判定，状态是等待对账
- **WHEN** 当前时刻 2026-10-14 15:06Z，PM 没有可用的模型，判定
- **THEN** 状态是降级，异常的检查是模型 API，进入时刻仍是 2026-10-14 15:00Z
- **WHEN** 当前时刻 2026-10-14 15:07Z，对账完成
- **THEN** 状态仍是降级

#### Scenario: 进程重启以后重新判定

- **GIVEN** 基准数据，券商断开，判定，状态是降级
- **WHEN** 进程重启，新建健康监控
- **THEN** 状态是正常
- **WHEN** 当前时刻 2026-10-14 15:10Z，券商仍然断开，判定
- **THEN** 状态是降级，进入时刻 2026-10-14 15:10Z

### Requirement: 恢复后的第一个交易日

降级期间到期、因为故障没有结论的事项，顺延到恢复后的第一个交易日。给定退出降级模式的时刻，健康监控 SHALL 给出恢复后的第一个交易日：收盘时刻晚于这个时刻的第一个交易日。

| 退出降级模式的时刻 | 恢复后的第一个交易日 |
| --- | --- |
| 交易日盘前 | 当天 |
| 盘中 | 当天 |
| 收盘时刻或之后 | 下一个交易日 |
| 休市日 | 之后的第一个交易日 |

#### Scenario: 盘前和盘中恢复是当天

- **WHEN** 退出时刻分别是 2026-10-14 12:00Z（盘前）和 2026-10-14 19:59Z（盘中）
- **THEN** 恢复后的第一个交易日都是 2026-10-14

#### Scenario: 收盘时刻或之后恢复是下一个交易日

- **WHEN** 退出时刻分别是 2026-10-14 20:00Z（收盘）和 2026-10-14 23:00Z
- **THEN** 恢复后的第一个交易日都是 2026-10-15
- **WHEN** 退出时刻是 2026-11-27 18:00Z（感恩节次日提前收盘的收盘时刻）
- **THEN** 恢复后的第一个交易日是 2026-11-30

#### Scenario: 休市日恢复

- **WHEN** 退出时刻是 2026-10-17 15:00Z（周六）
- **THEN** 恢复后的第一个交易日是 2026-10-19

### Requirement: 健康配置

健康监控的阈值 SHALL 是可配置项，默认值如下：

| 配置项 | 默认值 | 含义 |
| --- | --- | --- |
| 数据延迟上限 | 60 秒 | 常规交易时段内，行情超过这么久没有更新算异常 |
| 调度器心跳超时 | 300 秒 | 调度器超过这么久没有心跳算异常 |

两项都必须大于 0，否则配置报错。

#### Scenario: 默认配置

- **WHEN** 不传任何配置项新建配置
- **THEN** 数据延迟上限是 60 秒，调度器心跳超时是 300 秒

#### Scenario: 配置不大于 0

- **WHEN** 数据延迟上限或调度器心跳超时配置为 0 秒
- **THEN** 配置报错

#### Scenario: 改数据延迟上限

- **GIVEN** 基准数据，数据延迟上限 120 秒
- **WHEN** 行情最近一次更新在 2026-10-14 14:58:00Z（延迟 120 秒），判定
- **THEN** 没有异常的检查
- **WHEN** 行情最近一次更新在 2026-10-14 14:57:59Z，判定
- **THEN** 异常的检查是数据延迟
