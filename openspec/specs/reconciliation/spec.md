# reconciliation Specification

## Purpose

执行模块和券商全量对账：补上停机期间漏掉的成交和止损单变化，结束查不到的订单和止损单，找出券商那边对不上的挂单和持仓，并按对账结果决定是否接受新订单。

## Requirements

### Requirement: 对账

执行模块 SHALL 支持对账。对账在任何时刻都可以调用，也可以重复调用。一次对账依次做下面几步：

1. 读取券商那边全部挂着的订单（不含止损单）、全部挂着的止损单、全部持仓
2. 用第 1 步读到的挂单和止损单，按「不认得的挂单」「多出来的止损单」找出不一致
3. 跟进执行模块每一笔未结束的订单，见 order-lifecycle spec；查不到时按「结束查不到的订单和止损单」处理
4. 对齐下面这些股票的止损单，见 stop-protection spec「对齐止损单」：
   - 第 1 步读到有持仓的
   - 当前止损单还没结束（还没挂出去、挂着或状态未知）的
   - 是无保护仓位的
5. 按「来历不明的持仓」找出不一致
6. 给出对账结果，即三类不一致各自的清单。三类都为空时，这次对账没有不一致

第 1 步任何一项读取超时或断线，对账就失败：报券商不可用的错误，不做后面的步骤，这次不算完成对账。第 3、4 步里的券商调用超时或断线，按 order-lifecycle spec 和 stop-protection spec 的规则记为状态未知，对账照样完成。

第 3、4 步补上的变化都不算不一致，比如停机期间的成交、订单结束，以及止损单被撤销之后补挂。对账 SHALL NOT 撤销券商那边的任何挂单。告警由调用方按对账结果发出。

本 spec 的场景除非另有说明，都使用 order-lifecycle spec 的基准数据和 stop-protection spec 的约定，比如 P1 到 P4、"持有 BBB 100 股，止损单已对齐"、"券商回报 BBB-STOP-1 变为……"。另外：

- 券商没有 AAA 的持仓，不用 order-lifecycle spec 基准数据里的 AAA 100 股
- "对账"指在当前时刻调用一次对账
- "重启"指用同一套存储新建执行模块。新建的执行模块还没有对过账；不是重启之后的场景，执行模块都已经完成过一次没有不一致的对账
- "券商另外挂着……"指券商那边挂着的订单或止损单里多出来的一笔，不是执行模块按自己的记录提交或挂出去的
- "券商查不到 X"指之后查询 X 时券商没有结果，并且券商那边挂着的订单和止损单里也没有它，除非另有说明
- "没有不一致"指对账结果的三类不一致都为空

#### Scenario: 停机期间买入成交

- **GIVEN** P1 已经提交，订单已提交；重启
- **AND** 停机期间券商回报 P1 变为全部成交，累计成交 100，成交均价 49.95；券商持仓变为 BBB 100 股
- **WHEN** 对账
- **THEN** P1 全部成交，累计成交 100，成交均价 49.95
- **AND** 券商收到止损单 BBB-STOP-1：卖出 BBB 100 股，止损价 45
- **AND** 没有不一致

#### Scenario: 停机期间止损单被撤销，对账时补挂

- **GIVEN** 持有 BBB 100 股，止损单已对齐；重启
- **AND** 券商回报 BBB-STOP-1 变为撤销，比如长期有效单到期
- **WHEN** 对账
- **THEN** 券商收到止损单 BBB-STOP-2：卖出 BBB 100 股，止损价 45
- **AND** 没有不一致

#### Scenario: 停机期间止损单触发

- **GIVEN** 持有 BBB 100 股，止损单已对齐；重启
- **AND** 券商回报 BBB-STOP-1 变为全部成交，券商持仓变为 0 股
- **WHEN** 对账
- **THEN** BBB-STOP-1 已经结束，没有挂新的止损单
- **AND** 没有不一致

#### Scenario: 读取券商数据时断线

- **GIVEN** P1 已经提交，订单已提交；重启
- **WHEN** 对账，读取全部持仓时断线
- **THEN** 对账报券商不可用的错误
- **AND** 券商没有收到按 P1 的查询，也没有收到任何一张止损单的查询、挂单、改单或撤单
- **AND** 执行模块仍然不接受新订单，见「对账之前不接受新订单」

#### Scenario: 跟进订单时断线，对账照样完成

- **GIVEN** P1 已经提交，订单已提交；重启
- **WHEN** 2026-10-14 15:10Z 对账，按 P1 的查询断线
- **THEN** 对账完成，没有不一致
- **AND** P1 状态未知，记下的时刻是 2026-10-14 15:10Z
- **AND** 之后提交新订单，不再报还没对账的错误

#### Scenario: 重复对账

- **GIVEN** 持有 BBB 100 股，止损单已对齐
- **WHEN** 连续对账两次
- **THEN** 两次都没有不一致
- **AND** 券商没有收到挂单、改单和撤单，券商只有一张 BBB-STOP-1

### Requirement: 不认得的挂单

执行模块 SHALL 按下表判断，券商那边挂着的每一笔订单（不含止损单）是不是执行模块的：

| 券商挂着的订单 | 是不是执行模块的 |
| --- | --- |
| 客户端订单 ID 是一笔未结束订单的方案 ID，券商订单号和这笔订单记下的相同 | 是 |
| 客户端订单 ID 是一笔未结束订单的方案 ID，这笔订单还没有记下券商订单号 | 是，比如提交之后、保存结果之前进程退出 |
| 客户端订单 ID 是一笔未结束订单的方案 ID，券商订单号和这笔订单记下的不同 | 不是：同一个客户端订单 ID 的另一笔订单 |
| 客户端订单 ID 是一笔已经结束的订单的方案 ID | 不是：执行模块已经结束的订单在券商仍挂着 |
| 客户端订单 ID 不是任何订单的方案 ID | 不是 |

不是执行模块的挂单 SHALL 记入"不认得的挂单"，带上股票、客户端订单 ID 和券商订单号。账户只给系统用，所以这些情况不再细分。判断时用对账第 1 步读到的挂单，以及第 3 步跟进之前执行模块的订单。

#### Scenario: 执行模块的订单挂着

- **GIVEN** P1 已经提交，订单已提交，记下了券商订单号
- **WHEN** 对账
- **THEN** 没有不一致

#### Scenario: 订单还没有记下券商订单号

- **GIVEN** 存储里有 P1 的待提交订单；券商已经受理了 P1，挂着（进程在提交后、保存结果前退出）；重启
- **WHEN** 对账
- **THEN** 没有不一致
- **AND** P1 已提交，记下了券商订单号；券商只有一笔 P1 的订单

#### Scenario: 同一个客户端订单 ID 的第二笔订单

- **GIVEN** P1 已经提交，订单已提交，记下的券商订单号是 B1
- **AND** 券商另外挂着一笔客户端订单 ID 也是 P1 的订单，券商订单号是 B2
- **WHEN** 对账
- **THEN** 不认得的挂单有一笔：BBB，客户端订单 ID P1，券商订单号 B2
- **AND** 券商没有收到撤单请求

#### Scenario: 已经结束的订单在券商仍挂着

- **GIVEN** 基准结果的生效有效期改为 2026-10-14 16:00Z；2026-10-14 15:59:50Z 提交基准方案，提交超时，券商没有收到；2026-10-14 16:00:20Z 跟进，P1 已过期
- **AND** 之后券商另外挂着一笔客户端订单 ID 是 P1 的订单
- **WHEN** 2026-10-14 16:10Z 对账
- **THEN** 不认得的挂单有一笔：BBB，客户端订单 ID P1
- **AND** P1 仍是已过期

#### Scenario: 执行模块从没见过的订单

- **GIVEN** 券商另外挂着一笔买入 CCC 的订单，客户端订单 ID 是 X1
- **WHEN** 对账
- **THEN** 不认得的挂单有一笔：CCC，客户端订单 ID X1

### Requirement: 多出来的止损单

对券商那边挂着止损单的每一只股票，执行模块 SHALL 按下表判断：

| 券商挂着的止损单 | 执行模块这只股票的当前止损单 | 结果 |
| --- | --- | --- |
| 1 张 | 还没挂出去、挂着或状态未知 | 一致 |
| 1 张 | 没有，或者已经结束 | 不一致 |
| 2 张或更多 | 任何 | 不一致 |

不一致的股票 SHALL 记入"多出来的止损单"，带上券商挂着的这些止损单的客户端订单 ID 和券商订单号。只比较张数，不比较订单号，因为 Alpaca 改单会生成订单号不同的新订单。判断时用对账第 1 步读到的止损单，以及第 3 步之前执行模块的止损保护。

#### Scenario: 执行模块的止损单还没记下受理结果

- **GIVEN** 券商持仓 BBB 30 股，P1 部分成交、累计成交 30；存储里 BBB-STOP-1 还没挂出去，券商已经受理了 BBB-STOP-1，挂着（进程在挂单之后、保存结果之前退出）；重启
- **WHEN** 对账
- **THEN** 没有不一致
- **AND** 没有再挂单，BBB-STOP-1 挂着，券商只有一张 BBB-STOP-1

#### Scenario: 执行模块没有在用的止损单，券商却挂着一张

- **GIVEN** 券商另外挂着一张 BBB 的止损单 X2：卖出 100 股，止损价 45
- **AND** 执行模块没有 BBB 的止损单，券商没有 BBB 的持仓
- **WHEN** 对账
- **THEN** 多出来的止损单有 BBB，列出 X2
- **AND** 券商没有收到撤单请求

#### Scenario: 一只股票挂着两张止损单

- **GIVEN** 持有 BBB 100 股，止损单已对齐
- **AND** 券商另外挂着一张 BBB 的止损单 X2
- **WHEN** 对账
- **THEN** 多出来的止损单有 BBB，列出 BBB-STOP-1 和 X2
- **AND** 券商没有收到撤单请求

### Requirement: 来历不明的持仓

对第 1 步读到持仓大于 0 的每只股票，第 3 步跟进之后，执行模块这只股票的订单里，如果既没有累计成交大于 0 的买单（买入或加仓），也没有未结束的买单，这只股票 SHALL 算不一致，记入"来历不明的持仓"，带上股票和券商持仓股数。

这样的持仓没有止损价，执行模块不会为它挂止损单，见 stop-protection spec「止损价」。

#### Scenario: 执行模块没有买过的持仓

- **GIVEN** 券商持仓 CCC 100 股，执行模块没有 CCC 的订单
- **WHEN** 对账
- **THEN** 来历不明的持仓有 CCC 100 股
- **AND** 券商没有收到 CCC 的止损单

#### Scenario: 还没查清的买单能解释持仓

- **GIVEN** 2026-10-14 15:00Z 提交基准方案，提交超时；券商其实收到了，并且已经全部成交，券商持仓 BBB 100 股；P1 状态未知，记下 2026-10-14 15:00Z
- **WHEN** 2026-10-14 15:00:10Z 对账
- **THEN** 券商没有收到按 P1 的查询，P1 仍是状态未知
- **AND** 没有不一致

#### Scenario: 结束时没有记下成交的买单解释不了持仓

- **GIVEN** P1 已经提交，订单已提交，记下了券商订单号；券商查不到 P1，而 P1 其实已经全部成交，券商持仓 BBB 100 股
- **WHEN** 2026-10-14 15:10Z 对账
- **THEN** P1 已撤销，累计成交 0
- **AND** 来历不明的持仓有 BBB 100 股

### Requirement: 结束查不到的订单和止损单

对账第 3 步跟进订单时，如果一笔券商受理过（有券商订单号）的订单查不到，并且第 1 步读到的挂单里也没有这个券商订单号，执行模块 SHALL 结束这笔订单：

- 当前时刻早于截止时刻，记为已撤销；否则记为已过期
- 累计成交和成交均价保留已经记下的

挂单里有这个券商订单号时，按 order-lifecycle spec 处理，订单仍是状态未知。

对账第 3、4 步对齐止损单时，如果一张券商受理过（有券商订单号）的止损单查不到，并且第 1 步读到的止损单里这只股票一张都没有，执行模块 SHALL 把这张止损单记为已经结束，然后照常对齐，需要时挂一张序号加 1 的新止损单。这只股票还挂着止损单时，按 stop-protection spec 处理，仍是状态未知。

对账时，状态未知、还没满等待时长的订单和止损单，同样不调用券商，也不结束。对账之外的跟进和对齐，查不到时仍按 order-lifecycle spec 和 stop-protection spec 记为状态未知。

#### Scenario: 订单查不到，券商挂单里也没有

- **GIVEN** P1 已经提交，记下了券商订单号；2026-10-14 15:05Z 跟进时券商查不到 P1，P1 状态未知
- **WHEN** 2026-10-14 15:10Z 对账，券商仍查不到 P1
- **THEN** P1 已撤销，累计成交 0；券商没有收到 P1 的提交
- **WHEN** 提交 P2
- **THEN** 不再暂停，P2 的订单已提交

#### Scenario: 截止时刻之后结束为已过期，保留成交

- **GIVEN** P1 部分成交，累计成交 30，成交均价 49.90；券商持仓 BBB 30 股，BBB-STOP-1 挂着 30 股；券商查不到 P1
- **WHEN** 2026-10-14 20:10Z 对账
- **THEN** P1 已过期，累计成交 30，成交均价 49.90
- **AND** 没有不一致

#### Scenario: 订单查不到，但券商挂单里有它

- **GIVEN** P1 已经提交，订单已提交，记下的券商订单号是 B1
- **AND** 查询 P1 时券商查不到，但券商挂着的订单里有 B1
- **WHEN** 2026-10-14 15:10Z 对账
- **THEN** P1 状态未知，记下的时刻是 2026-10-14 15:10Z
- **AND** 没有不一致

#### Scenario: 止损单查不到，这只股票也没有挂着的止损单

- **GIVEN** 持有 BBB 100 股，止损单已对齐；券商查不到 BBB-STOP-1
- **WHEN** 对账
- **THEN** BBB-STOP-1 已经结束
- **AND** 券商收到止损单 BBB-STOP-2：卖出 BBB 100 股，止损价 45
- **AND** 没有不一致

#### Scenario: 止损单查不到，但这只股票还挂着一张止损单

- **GIVEN** 持有 BBB 100 股，止损单已对齐
- **AND** 查询 BBB-STOP-1 时券商查不到，但券商挂着的止损单里 BBB 还有一张
- **WHEN** 2026-10-14 15:10Z 对账
- **THEN** BBB-STOP-1 状态未知，记下的时刻是 2026-10-14 15:10Z；没有挂新的止损单
- **AND** 没有不一致

#### Scenario: 还没满等待时长时不结束

- **GIVEN** P1 已经提交，记下了券商订单号；2026-10-14 15:00Z 跟进时券商查不到 P1，P1 状态未知
- **WHEN** 2026-10-14 15:00:10Z 对账，券商仍查不到 P1
- **THEN** 券商没有收到按 P1 的查询
- **AND** P1 仍是状态未知，记下的时刻仍是 2026-10-14 15:00Z

### Requirement: 对账之前不接受新订单

执行模块新建以后（包括进程重启），完成第一次对账之前，SHALL 拒绝为任何方案新建订单，买入和卖出都算：报还没对账的错误，不创建订单，也不调用券商。对账失败不算完成。

下面这些不受影响：已经有订单的方案再次提交、跟进订单、单独对齐止损单。

#### Scenario: 重启后先对账，才接受新订单

- **GIVEN** 重启
- **WHEN** 提交基准方案
- **THEN** 报还没对账的错误，没有 P1 的订单，券商没有收到任何调用
- **WHEN** 对账，没有不一致；然后提交基准方案
- **THEN** P1 的订单已提交

#### Scenario: 卖单也要等对账

- **GIVEN** 持有 BBB 100 股，止损单已对齐；重启
- **WHEN** 提交 P3
- **THEN** 报还没对账的错误，没有 P3 的订单，券商没有收到和 P3 有关的调用

#### Scenario: 对账失败时仍不接受新订单

- **GIVEN** 重启
- **WHEN** 对账，读取全部挂单时超时；然后提交基准方案
- **THEN** 报还没对账的错误，没有 P1 的订单

#### Scenario: 已经有订单的方案和跟进不受影响

- **GIVEN** P1 已经提交，订单已提交；重启
- **WHEN** 券商回报 P1 变为全部成交、累计成交 100，券商持仓变为 BBB 100 股；再次提交基准方案
- **THEN** 不报错，P1 全部成交
- **AND** 券商收到止损单 BBB-STOP-1：卖出 BBB 100 股，止损价 45

### Requirement: 有不一致时暂停开仓

执行模块 SHALL 按最近一次完成的对账，决定是否为方案新建订单：

| 最近一次完成的对账 | 新的买单（买入、加仓） | 新的卖单（减仓、清仓） |
| --- | --- | --- |
| 还没有 | 拒绝，报还没对账的错误，见「对账之前不接受新订单」 | 拒绝，同左 |
| 有不一致 | 拒绝，报对账不一致的错误 | 接受 |
| 没有不一致 | 接受 | 接受 |

拒绝时不创建订单，也不调用券商。已经有订单的方案再次提交，不受影响。对账失败不改变"最近一次完成的对账"：有不一致的，仍然暂停开仓。

#### Scenario: 有不一致时买入被拒，卖出照常

- **GIVEN** 券商持仓 CCC 100 股，执行模块没有 CCC 的订单
- **WHEN** 对账
- **THEN** 来历不明的持仓有 CCC 100 股
- **WHEN** 提交基准方案
- **THEN** 报对账不一致的错误，没有 P1 的订单，券商没有收到和 P1 有关的调用
- **WHEN** 提交清仓 CCC 的方案，再校验通过，最终股数 100
- **THEN** 券商收到这笔卖单的提交：卖出 CCC 100 股

#### Scenario: 加仓也被拒

- **GIVEN** 持有 BBB 100 股，止损单已对齐；券商另外挂着一笔买入 CCC 的订单，客户端订单 ID 是 X1
- **WHEN** 对账，然后提交 P2
- **THEN** 报对账不一致的错误，没有 P2 的订单

#### Scenario: 之后的对账没有不一致时恢复

- **GIVEN** 最近一次对账有来历不明的持仓 CCC 100 股
- **AND** 之后券商持仓 CCC 变为 0 股
- **WHEN** 对账
- **THEN** 没有不一致
- **WHEN** 提交基准方案
- **THEN** P1 的订单已提交

#### Scenario: 对账失败时仍然暂停开仓

- **GIVEN** 最近一次对账有来历不明的持仓 CCC 100 股
- **WHEN** 对账，读取全部持仓时断线；然后提交基准方案
- **THEN** 报对账不一致的错误，没有 P1 的订单

#### Scenario: 已经有订单的方案不受暂停影响

- **GIVEN** 基准方案已经提交，订单已提交
- **AND** 之后券商持仓 CCC 100 股，执行模块没有 CCC 的订单；对账，有来历不明的持仓
- **WHEN** 再次提交基准方案
- **THEN** 不报错，返回 P1 的订单，状态是已提交
