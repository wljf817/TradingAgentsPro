# pool-position-sync Specification

## Purpose
股票池跟上持仓：盘中巡检每一轮按券商持仓和订单，把买入成交和清仓交给股票池，状态变了再交给跟进审批，让股票池里的持仓总有投资论点，清仓以后按发起者转为关注、候选或移出。

## Requirements

### Requirement: 股票池跟上持仓

盘中巡检的每一轮（session-patrol spec「每一轮」）SHALL 读一次股票池的全部股票；股票池不为空时读一次券商的全部持仓，然后按股票代码顺序把股票池里的每只股票按下表处理（stock-pool spec「状态变化」）：

| 股票池里的状态 | 券商持仓 | 条件 | 处理 |
| --- | --- | --- | --- |
| 候选或关注 | 有 | 这只股票最近创建的买单有来源案件（order-lifecycle spec「提交订单」） | 买入成交：投资论点是那个案件的结论附的投资论点，上次复查的那一天是结论时刻归属的交易日 |
| 候选或关注 | 有 | 最近创建的买单没有来源案件（`/plan` 录入的） | 不动 |
| 候选或关注 | 没有 | | 不动 |
| 持仓 | 有 | | 不动：加仓和减仓不改变股票池 |
| 持仓 | 没有 | 这只股票还有没结束的订单 | 这一轮不动，等订单结束 |
| 持仓 | 没有 | 这只股票最近创建的订单是一个案件的清仓方案的卖单，并且全部成交 | PM 发起的清仓，按那个案件的结论的去向：转为关注（关注论点是结论附的，上次复查的那一天是结论时刻归属的交易日），或移出 |
| 持仓 | 没有 | 其余：止损单成交、紧急风险退出（包括本地备用止损）、`/plan` 的清仓、案件的减仓卖完了全部持仓、清仓单没有全部成交 | 代码触发的清仓，转为候选 |

- 结论时刻归属的交易日：结论时刻以后最早收盘的那个交易日，盘后给出的结论归下一个交易日（review-dates spec「上次复查的那一天」：买入那一天是给出开仓方案结论的那个交易日）
- 状态变了以后 SHALL 交给跟进审批（follow-ups spec「股票状态往下走时作废」）：股票、之前的状态和之后的状态（移出时之后为空）
- `/plan` 录入的方案成交以后股票池不动：不在股票池里的股票买入以后仍不在股票池里，股票池里的候选或关注被 `/plan` 买入以后仍是候选或关注；股票池里的持仓不论被谁卖完，只要不是案件的清仓方案全部成交，都转为候选
- 不在股票池里的股票不看
- 盘中、盘外每一轮都做：停机期间的成交和清仓，重启以后的第一轮补上
- 股票池和跟进审批各自写程序日志（program-log spec「股票池的动作」「调度器的动作」），这一项不另写

本 spec 的场景除非另有说明，都使用下面的基准数据：

- 当前时刻 2026-10-14 15:00Z（周三，盘中；当天 20:00Z 收盘），交易日历是纽交所日历
- 股票池里有三只股票：AAA 候选；BBB 关注，关注论点是 stock-pool spec 的基准关注论点；CCC 持仓，投资论点是 stock-pool spec 的基准投资论点，上次复查的那一天 2026-10-07。CCC 有一个待执行的跟进 F-1
- 券商持仓：CCC 100 股，CCC-STOP-1 挂着 100 股；没有别的持仓
- 案件：
  - K1：BBB 的关注股事件，结论是开仓方案 P1（买入 BBB 100 股，限价单），附基准投资论点，结论时刻 2026-10-13 19:00Z
  - K3：CCC 的持仓复查，结论是清仓方案 P3（清仓 CCC，市价单），去向转为关注，附基准关注论点，结论时刻 2026-10-14 14:00Z
  - K4：和 K3 相同，去向是移出，清仓方案是 P4
  - K5：CCC 的持仓事件，结论是减仓方案 P5（减仓 CCC 100 股）
- 方案的订单都以它的案件为来源案件；"做一轮"指巡检做一轮，股票池跟上持仓在第 3 步跟进订单、对齐止损单之后

#### Scenario: 买入部分成交变为持仓

- **GIVEN** P1 的订单已提交
- **WHEN** 券商回报 P1 部分成交、累计成交 30，券商持仓 BBB 30 股，做一轮
- **THEN** BBB 是持仓，投资论点是基准投资论点，上次复查的那一天 2026-10-13
- **AND** 股票池写了 BBB 的买入成交；跟进审批收到 BBB 从关注变为持仓
- **WHEN** 券商回报 P1 全部成交、累计成交 100，券商持仓 BBB 100 股，之后一轮
- **THEN** BBB 的记录不变，股票池没有新的买入成交

#### Scenario: 盘后的结论归下一个交易日

- **GIVEN** K1 的结论时刻改为 2026-10-13 21:00Z；P1 的订单已提交
- **WHEN** 券商回报 P1 部分成交，券商持仓 BBB 30 股，做一轮
- **THEN** BBB 是持仓，上次复查的那一天 2026-10-14

#### Scenario: 买单挂着时降为候选

- **GIVEN** P1 的订单已提交；之后 BBB 降为候选
- **WHEN** 券商回报 P1 部分成交，券商持仓 BBB 30 股，做一轮
- **THEN** BBB 是持仓，投资论点是基准投资论点

#### Scenario: 订单记录还没跟上成交

- **GIVEN** P1 的订单已提交
- **WHEN** 券商那边 P1 部分成交、持仓 BBB 30 股；做一轮时跟进 P1 超时，P1 状态未知
- **THEN** BBB 照样按 K1 变为持仓：最近创建的买单是 P1

#### Scenario: /plan 的买入不进股票池

- **WHEN** 本人用 `/plan` 买入 ZZZ 20 股，全部成交，券商持仓 ZZZ 20 股，做一轮
- **THEN** ZZZ 不在股票池里
- **WHEN** 本人用 `/plan` 买入 BBB 20 股，全部成交，券商持仓 BBB 20 股，做一轮
- **THEN** BBB 仍是关注；之后的每一轮也不变

#### Scenario: PM 清仓以后转为关注

- **GIVEN** P3 的订单已提交
- **WHEN** 券商回报 P3 全部成交、累计成交 100，券商没有 CCC 的持仓，做一轮
- **THEN** CCC 是关注，关注论点是基准关注论点，上次复查的那一天 2026-10-14，没有投资论点
- **AND** F-1 已作废

#### Scenario: PM 清仓以后移出

- **GIVEN** P4 的订单已提交
- **WHEN** 券商回报 P4 全部成交，券商没有 CCC 的持仓，做一轮
- **THEN** CCC 不在股票池里，移出的原因是清仓后移出
- **AND** F-1 已作废；跟进审批收到 CCC 从持仓变为不在股票池

#### Scenario: 清仓单还没结束时等

- **GIVEN** P3 的订单已提交
- **WHEN** 券商那边 P3 全部成交、没有 CCC 的持仓；做一轮时跟进 P3 超时，P3 状态未知
- **THEN** CCC 仍是持仓，F-1 仍是待执行
- **WHEN** 之后一轮跟进到 P3 全部成交
- **THEN** CCC 是关注

#### Scenario: 止损单成交以后转为候选

- **WHEN** 券商回报 CCC-STOP-1 全部成交，券商没有 CCC 的持仓，做一轮
- **THEN** CCC 是候选，成为候选的时刻 2026-10-14 15:00Z，没有投资论点
- **AND** F-1 已作废

#### Scenario: 不是 PM 的清仓都转为候选

- **WHEN** 分别是：紧急风险退出的清仓单全部成交；本地备用止损的清仓单全部成交；本人用 `/plan` 清仓 CCC，全部成交；P5 全部成交卖完 100 股；之后都没有 CCC 的持仓，做一轮
- **THEN** 每种情况下 CCC 都是候选，F-1 都已作废

#### Scenario: 清仓单没有全部成交

- **GIVEN** P3 的订单部分成交 40 股以后过期，券商持仓 CCC 60 股，CCC-STOP-1 恢复为 60 股
- **WHEN** 做一轮
- **THEN** CCC 仍是持仓
- **WHEN** 之后 CCC-STOP-1 全部成交，没有 CCC 的持仓，之后一轮
- **THEN** CCC 是候选

#### Scenario: 没有变化时不动

- **GIVEN** BBB 关注，没有持仓；CCC 持仓，券商持仓 CCC 100 股
- **WHEN** 做一轮
- **THEN** 股票池和跟进都不变，没有股票池的程序日志

#### Scenario: 停机期间的成交

- **GIVEN** P1 的订单已提交；停机期间券商回报 P1 部分成交，券商持仓 BBB 30 股
- **WHEN** 程序重启：启动对账跟进 P1；巡检开始第一轮
- **THEN** BBB 是持仓

### Requirement: 读取失败和出错

股票池跟上持仓 SHALL 按下表处理读取失败和出错：

| 情况 | 处理 |
| --- | --- |
| 股票池为空 | 不读券商持仓，这一项什么都不做 |
| 读券商的全部持仓超时或断线 | 写一条 WARNING，这一轮不做这一项；之后的轮次照常补上 |
| 处理一只股票时出错（比如读订单、案件记录或者写股票池时数据库出错） | 按 session-patrol spec「一轮里的失败」写 ERROR，带异常栈和这只股票；接着处理别的股票，之后的轮次再处理它 |

#### Scenario: 股票池为空

- **GIVEN** 股票池里没有股票
- **WHEN** 做一轮
- **THEN** 这一项没有向券商读持仓

#### Scenario: 读券商持仓超时

- **GIVEN** P3 全部成交，券商没有 CCC 的持仓；这一项读券商的全部持仓会超时一次
- **WHEN** 做一轮
- **THEN** CCC 仍是持仓；有一条 WARNING
- **WHEN** 之后一轮正常读到
- **THEN** CCC 是关注

#### Scenario: 一只股票出错不影响别的

- **GIVEN** P1 部分成交，券商持仓 BBB 30 股；CCC-STOP-1 全部成交，没有 CCC 的持仓；读 K1 的案件记录会出错一次
- **WHEN** 做一轮
- **THEN** 有一条 ERROR 写明 BBB；BBB 仍是关注；CCC 是候选
- **WHEN** 之后一轮
- **THEN** BBB 是持仓
