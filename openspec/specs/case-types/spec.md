# case-types Specification

## Purpose

调度器按触发和开始运行时的股票状态确定案件类型，类型固定 PM 要回答的问题、允许的结论、最低研究要求和排队优先级；并规定 PM 结论的格式（交易方案、投资论点、跟进申请、股票池增删），按案件类型校验 PM 提交的结论。

## Requirements

### Requirement: 触发

开案件时调用方 SHALL 给出触发，触发有四种：

| 触发 | 带的内容 |
| --- | --- |
| 事件 | 股票、事件类别（见「事件要求的子 agent」）、是否是持仓风险级别（由事件检测标注） |
| 定时心跳的检查项 | 检查项开出的案件类型（见下表）；针对单只股票的检查项带股票 |
| 跟进 | 股票、申请时写下的问题 |
| 卖出成交 | 股票。止损单成交、紧急风险退出、PM 发起的减仓和清仓都算 |

| 定时心跳的检查项 | 开出的案件类型 | 带股票 |
| --- | --- | --- |
| 持仓复查日到期 | 持仓复查 | 是 |
| 投资论点的催化剂截止日期到期 | 持仓催化剂复查 | 是 |
| 关注复查日到期 | 关注复查 | 是 |
| 关注论点的催化剂截止日期到期 | 关注催化剂复查 | 是 |
| 有新候选 | 候选评估 | 是 |
| 股票池候选不足 | 寻股 | 否 |
| 每周固定时间 | 每周复盘 | 否 |

不合法的触发 SHALL 报错：定时心跳给出的案件类型不在上表里；带不带股票和上表不符。

本 spec 的场景除非另有说明，都使用默认配置和下面的基准数据：

- 股票：AAA 是候选；BBB 是关注，板块"医疗"；CCC 是持仓，板块"能源"
- 基准关注论点：和 stock-pool spec 的基准关注论点相同
- 基准投资论点：
  - 买入理由"新品周期带动收入加速"
  - 催化剂"Q3 财报"，截止日期 2026-10-29，不引用日程项或事件
  - 目标价 60
  - 证伪条件"毛利率连续两个季度下滑"，其中代码能检测的部分一条：价格不高于 42
  - 复查日 2026-10-21
- 基准方案条款：100 股，限价单，限价 50，止损价 45，紧急阈值 0.08，不写有效期和允许价格偏离
- 基准跟进申请：原因是外部日程，引用日程项"S-9"；问题"竞争对手 11 月 18 日发财报，之后对这只股票有什么影响？"；可能采取的动作"减仓"；触发时间 2026-11-19 14:30Z
- 结论的公共部分：回答"论点仍然成立"，理由"订单和毛利率都符合预期"，信号是 signal-format spec 的基准信号（评分 1），引用 R-1 和 R-2
- "评分 n 的信号"指只把基准信号的评分改为 n；场景里加入的候选只写"评分 n"时，它的信号就是评分 n 的信号
- 本案件派过任务的子 agent 是 News 和 Quant；状态是完成的 Result 有两个：R-1 出自 News，R-2 出自 Quant
- "某个案件开始运行"指这个触发开出的案件开始运行，股票的状态是这个时候的状态

#### Scenario: 不合法的触发

- **WHEN** 定时心跳给出的案件类型是持仓事件；持仓复查不带股票；寻股带了股票 AAA
- **THEN** 都报错

### Requirement: 案件类型

案件类型 SHALL 是下表的 14 种之一，每种固定针对的股票状态、PM 要回答的问题、PM 提交的结论种类和排队优先级：

| 案件类型 | 触发 | 针对的状态 | 要回答的问题 | 结论 | 优先级 |
| --- | --- | --- | --- | --- | --- |
| 持仓风险事件 | 事件，持仓风险级别 | 持仓 | 这个事件是否削弱或推翻了论点？ | 持仓的结论 | 1 |
| 持仓事件 | 事件，不是持仓风险级别 | 持仓 | 这个事件是否削弱或推翻了论点？ | 持仓的结论 | 2 |
| 持仓复查 | 持仓复查日到期 | 持仓 | 论点是否仍然成立？ | 持仓的结论 | 3 |
| 持仓催化剂复查 | 投资论点的催化剂截止日期到期 | 持仓 | 催化剂兑现了吗？论点是否仍然成立？ | 持仓的结论 | 3 |
| 持仓跟进 | 跟进 | 持仓 | 申请时写下的问题 | 持仓的结论 | 3 |
| 关注股事件 | 事件 | 关注 | 入场机会是否出现？ | 关注的结论 | 4 |
| 关注复查 | 关注复查日到期 | 关注 | 是否还值得关注？ | 关注的结论 | 5 |
| 关注催化剂复查 | 关注论点的催化剂截止日期到期 | 关注 | 催化剂兑现了吗？是否还值得关注？ | 关注的结论 | 5 |
| 关注跟进 | 跟进 | 关注 | 申请时写下的问题 | 关注的结论 | 5 |
| 候选股事件 | 事件 | 候选 | 是否值得升级为关注？ | 候选的结论 | 6 |
| 候选评估 | 有新候选 | 候选 | 是否升级？ | 候选的结论 | 7 |
| 寻股 | 股票池候选不足 | 不针对单只股票 | 补充哪些候选？ | 寻股的结论 | 8 |
| 每周复盘 | 每周固定时间 | 不针对单只股票 | 不唤醒 PM | 没有 | 9 |
| 卖出复盘 | 卖出成交 | 不看状态 | 不唤醒 PM | 没有 | 9 |

- 优先级 1 最高、9 最低，同一个数的类型优先级相同；九档的顺序是 Proposal 规定的：持仓风险事件 > 持仓其他事件 > 持仓的心跳和跟进 > 关注股事件 > 关注股的心跳和跟进 > 候选股事件 > 候选评估 > 寻股 > 复盘
- 持仓复查和持仓催化剂复查都是 Proposal 的"持仓复查"，问题不同，所以分成两种类型；关注复查同理。这四种合称复查类案件
- 持仓跟进和关注跟进合称跟进案件；它们的结论和同一状态的其他案件一样，只是不能再申请跟进（见「结论的校验」）
- 每周复盘和卖出复盘合称复盘案件，由 Reviewer 处理，不唤醒 PM，内容不在本 spec 的范围内

#### Scenario: 持仓风险事件

- **WHEN** CCC 的价格和成交量异动事件开始运行，事件标注为持仓风险级别
- **THEN** 案件类型是持仓风险事件，问题"这个事件是否削弱或推翻了论点？"，优先级 1，PM 提交持仓的结论

#### Scenario: 持仓事件

- **WHEN** CCC 的新闻事件开始运行，事件不是持仓风险级别
- **THEN** 案件类型是持仓事件，问题"这个事件是否削弱或推翻了论点？"，优先级 2，PM 提交持仓的结论

#### Scenario: 持仓复查

- **WHEN** CCC 的持仓复查日到期开出的案件开始运行
- **THEN** 案件类型是持仓复查，问题"论点是否仍然成立？"，优先级 3，PM 提交持仓的结论

#### Scenario: 持仓催化剂复查

- **WHEN** CCC 的投资论点的催化剂截止日期到期开出的案件开始运行
- **THEN** 案件类型是持仓催化剂复查，问题"催化剂兑现了吗？论点是否仍然成立？"，优先级 3，PM 提交持仓的结论

#### Scenario: 持仓跟进

- **GIVEN** CCC 是持仓时申请的跟进，问题"大单公布 3 小时后盘中反应如何？"
- **WHEN** 这个跟进开出的案件开始运行，CCC 仍是持仓
- **THEN** 案件类型是持仓跟进，问题"大单公布 3 小时后盘中反应如何？"，优先级 3，PM 提交持仓的结论

#### Scenario: 关注股事件

- **WHEN** BBB 的财报发布事件开始运行
- **THEN** 案件类型是关注股事件，问题"入场机会是否出现？"，优先级 4，PM 提交关注的结论

#### Scenario: 关注复查

- **WHEN** BBB 的关注复查日到期开出的案件开始运行
- **THEN** 案件类型是关注复查，问题"是否还值得关注？"，优先级 5，PM 提交关注的结论

#### Scenario: 关注催化剂复查

- **WHEN** BBB 的关注论点的催化剂截止日期到期开出的案件开始运行
- **THEN** 案件类型是关注催化剂复查，问题"催化剂兑现了吗？是否还值得关注？"，优先级 5，PM 提交关注的结论

#### Scenario: 关注跟进

- **GIVEN** BBB 是关注时申请的跟进，问题"12 月行业大会之后市场反应如何？"
- **WHEN** 这个跟进开出的案件开始运行，BBB 仍是关注
- **THEN** 案件类型是关注跟进，问题"12 月行业大会之后市场反应如何？"，优先级 5，PM 提交关注的结论

#### Scenario: 候选股事件

- **WHEN** AAA 的新闻事件开始运行
- **THEN** 案件类型是候选股事件，问题"是否值得升级为关注？"，优先级 6，PM 提交候选的结论

#### Scenario: 候选评估

- **WHEN** AAA 的有新候选开出的案件开始运行
- **THEN** 案件类型是候选评估，问题"是否升级？"，优先级 7，PM 提交候选的结论

#### Scenario: 寻股

- **WHEN** 股票池候选不足开出的案件开始运行
- **THEN** 案件类型是寻股，不针对单只股票，问题"补充哪些候选？"，优先级 8，PM 提交寻股的结论

#### Scenario: 每周复盘

- **WHEN** 每周固定时间开出的案件开始运行
- **THEN** 案件类型是每周复盘，不针对单只股票，优先级 9，不唤醒 PM，没有问题和结论

#### Scenario: 卖出复盘

- **WHEN** CCC 的止损单成交，卖出成交开出的案件开始运行
- **THEN** 案件类型是卖出复盘，优先级 9，不唤醒 PM，没有问题和结论

#### Scenario: 九档优先级的顺序

- **WHEN** 按优先级从高到低排列 14 种案件类型
- **THEN** 依次是：持仓风险事件；持仓事件；持仓复查、持仓催化剂复查、持仓跟进；关注股事件；关注复查、关注催化剂复查、关注跟进；候选股事件；候选评估；寻股；每周复盘、卖出复盘

### Requirement: 开始运行时确定案件类型

案件类型 SHALL 在案件开始运行时，按触发和这只股票这个时候的状态确定：

| 触发 | 怎么确定 | 不运行的情况 |
| --- | --- | --- |
| 事件 | 按这个时候的状态：持仓、关注、候选各对应一种事件案件；持仓并且事件标注为持仓风险级别时是持仓风险事件，其他状态忽略这个标注 | 股票已经不在股票池，也不是持仓 |
| 针对单只股票的定时心跳检查项 | 检查项开出的类型 | 股票已经不在这个类型针对的状态 |
| 跟进 | 按这个时候的状态：持仓是持仓跟进，关注是关注跟进 | 股票已经是候选，或者已经不在股票池也不是持仓 |
| 寻股、每周复盘、卖出成交 | 固定的类型 | 不看状态，都运行 |

不运行的案件 SHALL 没有案件类型，调用方据此不再运行它。同一个触发在不同时刻确定的类型可以不同；案件运行期间用开始时确定的类型，不再改变。

#### Scenario: 止损成交后排队的事件按新状态运行

- **GIVEN** CCC 是持仓，CCC 的新闻事件在排队
- **WHEN** CCC 的止损单成交、变为候选以后，这个案件开始运行
- **THEN** 案件类型是候选股事件，优先级 6

#### Scenario: 持仓风险级别只对持仓有效

- **WHEN** BBB 的价格和成交量异动事件开始运行，事件标注为持仓风险级别
- **THEN** 案件类型是关注股事件，优先级 4

#### Scenario: 不在股票池的股票的事件不运行

- **GIVEN** AAA 的新闻事件在排队
- **WHEN** AAA 被删除以后，这个案件开始运行
- **THEN** 不运行

#### Scenario: 复查案件开始时已经不是那个状态

- **WHEN** CCC 的持仓复查日到期开出的案件开始运行，CCC 已经被止损清仓、变为候选
- **THEN** 不运行
- **WHEN** BBB 的关注复查日到期开出的案件开始运行，BBB 已经买入成交、变为持仓
- **THEN** 不运行
- **WHEN** BBB 的关注论点的催化剂截止日期到期开出的案件开始运行，BBB 已经降为候选
- **THEN** 不运行
- **WHEN** CCC 的投资论点的催化剂截止日期到期开出的案件开始运行，CCC 已经由 PM 清仓后移出
- **THEN** 不运行

#### Scenario: 候选评估开始时已经不是候选

- **WHEN** AAA 的有新候选开出的案件开始运行，AAA 已经升级为关注
- **THEN** 不运行
- **WHEN** AAA 的有新候选开出的案件开始运行，AAA 已经被删除
- **THEN** 不运行

#### Scenario: 关注股买入以后的跟进按持仓运行

- **GIVEN** BBB 是关注时申请的跟进，问题"12 月行业大会之后市场反应如何？"
- **WHEN** 这个跟进开出的案件开始运行，BBB 已经买入成交、变为持仓
- **THEN** 案件类型是持仓跟进，问题"12 月行业大会之后市场反应如何？"，优先级 3，PM 提交持仓的结论

#### Scenario: 跟进开始时已经是候选或不在股票池

- **GIVEN** BBB 是关注时申请的跟进
- **WHEN** 这个跟进开出的案件开始运行，BBB 已经降为候选
- **THEN** 不运行
- **WHEN** 这个跟进开出的案件开始运行，BBB 已经被删除
- **THEN** 不运行

#### Scenario: 寻股和复盘不看状态

- **WHEN** 股票池候选不足开出的案件开始运行
- **THEN** 案件类型是寻股
- **WHEN** CCC 由 PM 清仓后移出，卖出成交开出的案件开始运行
- **THEN** 案件类型是卖出复盘

### Requirement: 事件要求的子 agent

子 agent SHALL 有三个：News、Quant、Fundamentals。事件案件（持仓风险事件、持仓事件、关注股事件、候选股事件）SHALL 要求本案件至少向事件类别对应的子 agent 派过任务，这是下限，PM 可以多派：

| 事件类别 | 至少派给 |
| --- | --- |
| 价格和成交量异动 | Quant |
| 新闻 | News |
| 公告 | Fundamentals |
| 财报发布 | Fundamentals |
| 关注股的入场条件满足 | Quant |
| 持仓达到目标价或证伪条件触发 | Quant |

- 派过任务就算，不论 Result 的状态：超时或失败时 PM 在缺少该信息的情况下继续
- 其他案件类型没有这项要求
- 是否满足由「结论的校验」检查

#### Scenario: 新闻事件至少派给 News

- **WHEN** CCC 的新闻事件开始运行
- **THEN** 案件要求至少派过任务的子 agent 是 News

#### Scenario: 公告和财报发布至少派给 Fundamentals

- **WHEN** BBB 的公告事件开始运行；BBB 的财报发布事件开始运行
- **THEN** 两个案件要求至少派过任务的子 agent 都是 Fundamentals

#### Scenario: 价格类事件至少派给 Quant

- **WHEN** AAA 的价格和成交量异动事件开始运行；BBB 的入场条件满足事件开始运行；CCC 的达到目标价或证伪条件触发事件开始运行
- **THEN** 三个案件要求至少派过任务的子 agent 都是 Quant

#### Scenario: 不是事件的案件没有这项要求

- **WHEN** CCC 的持仓复查日到期、BBB 的跟进、AAA 的有新候选、股票池候选不足开出的案件开始运行
- **THEN** 这些案件都没有要求至少派过任务的子 agent

### Requirement: 结论的公共部分

PM 的结论 SHALL 是四种之一：持仓的结论、关注的结论、候选的结论、寻股的结论。每种都包含：

| 字段 | 说明 |
| --- | --- |
| 回答 | 对案件问题的正面回答，文字 |
| 理由 | 文字；无动作时也要写 |
| 引用的 Result | Result ID 的列表，可以为空 |
| 信号 | 只有持仓、关注、候选的结论有：PM 对这只股票的信号，格式见 signal-format spec「信号的格式」，不能是无信号；信号里的评分就是股票池的最新评分。寻股的结论没有，每只加入的候选各有一个（见「寻股的结论」） |

文字去掉首尾空白后为空、信号不符合 signal-format spec「信号的格式」或者是无信号、缺少必填的字段、包含本 spec 规定以外的字段，都 MUST 是格式错误。信号的评估窗口是否在配置的选项里、数据截至时刻是否晚于现在，由 Agent 网关检查（signal-format spec「结论里的信号」）。

#### Scenario: 完整的公共部分

- **WHEN** 用结论的公共部分构造持仓的结论，决定持有
- **THEN** 格式正确
- **WHEN** 不引用任何 Result
- **THEN** 格式正确

#### Scenario: 回答或理由为空

- **WHEN** 回答是 "  "，或者理由是 ""
- **THEN** 都是格式错误

#### Scenario: 评分的边界

- **WHEN** 信号是评分 -2 或 2 的信号
- **THEN** 格式正确
- **WHEN** 信号的评分是 -3、3 或 1.5，或者不写信号
- **THEN** 都是格式错误

#### Scenario: 信号的格式错误或者是无信号

- **WHEN** 信号缺少主要风险；或者信号是 signal-format spec 的基准无信号
- **THEN** 都是格式错误

### Requirement: 持仓的结论

持仓的结论 SHALL 有一个决定，按下表附带其他内容；不符合下表、或者决定不是这四种，都是格式错误：

| 决定 | 交易方案 | 论点更新 | 跟进申请 | 清仓后的去向 |
| --- | --- | --- | --- | --- |
| 持有 | 不写 | 可以附 | 可以附 | 不写 |
| 加仓 | 必须写，动作是加仓 | 可以附 | 可以附 | 不写 |
| 减仓 | 必须写，动作是减仓 | 可以附 | 可以附 | 不写 |
| 清仓 | 必须写，动作是清仓 | 不写 | 不写 | 必须写 |

- 论点更新是一份完整的投资论点（见「投资论点的格式」），代替原来的论点；复查日、催化剂只改一项也要整份写
- 清仓后的去向：转为关注，必须附完整的关注论点（stock-pool spec「关注论点的格式」）；或者移出股票池，不附关注论点
- 交易方案见「PM 写的交易方案」，跟进申请见「跟进申请的格式」

#### Scenario: 持有

- **WHEN** 决定持有，不附任何内容
- **THEN** 格式正确

### Requirement: PM 写的交易方案

PM 写的交易方案 SHALL 包含股数、订单类型、限价、止损价、紧急阈值、有效期、允许价格偏离，动作由结论的决定给出：加仓、减仓、清仓的动作是同名的动作，开仓方案的动作是买入。

- 各字段按动作的要求和 risk-rules spec「交易方案的格式」相同（包括限价和止损价的最小变动单位），另外买入和加仓 MUST 写紧急阈值；有效期和允许价格偏离可以不写，由风控使用默认值
- 方案的理由和引用的 Result 就是结论的理由和引用，不另写
- PM 不写方案 ID、股票和板块。结论通过校验以后，代码 SHALL 补上方案 ID（新生成）、股票（案件的股票）和板块（股票池里这只股票的板块），连同动作变成交易方案（risk-rules spec「交易方案的格式」），其余字段照抄

#### Scenario: 按动作检查字段

- **THEN** 格式错误
- **WHEN** 决定清仓，交易方案写了 100 股
- **THEN** 格式错误
- **WHEN** 决定开仓方案，交易方案不写止损价
- **THEN** 格式错误
- **WHEN** 决定开仓方案，限价 50.005；或者止损价 44.999
- **THEN** 都是格式错误，不符合最小变动单位

#### Scenario: 买入和加仓必须写紧急阈值

- **WHEN** 决定开仓方案或加仓，交易方案不写紧急阈值
- **THEN** 都是格式错误
- **WHEN** 决定减仓，交易方案是 60 股、限价单、限价 52，不写紧急阈值
- **THEN** 格式正确

#### Scenario: 有效期和允许价格偏离可以不写

- **WHEN** 决定开仓方案，基准方案条款加上有效期 2026-10-15 20:00Z 和允许价格偏离 0.05
- **THEN** 格式正确
- **WHEN** 决定开仓方案，用基准方案条款（不写这两项）
- **THEN** 格式正确

#### Scenario: 变成交易方案

- **GIVEN** CCC 的持仓的结论：决定加仓，基准方案条款
- **WHEN** 以方案 ID P-1 变成交易方案
- **THEN** 交易方案是：方案 ID P-1，股票 CCC，板块"能源"，加仓，100 股，限价单，限价 50，止损价 45，紧急阈值 0.08，没有有效期和允许价格偏离

- **THEN** 没有交易方案

### Requirement: 投资论点的格式

投资论点 SHALL 包含下面几项，缺任何一项、或者文字去掉首尾空白后为空，都是格式错误：

| 项 | 说明 |
| --- | --- |
| 买入理由 | 文字 |
| 催化剂 | 和关注论点的催化剂相同：描述、截止日期，可以引用一个日程项或事件 |
| 目标价 | 大于 0 |
| 证伪条件 | 文字 |
| 证伪条件中代码能检测的部分 | 代码能检测的条件（stock-pool spec「关注论点的格式」的三类），可以没有；任一条件满足就算触发 |
| 复查日 | 日期 |

复查日和催化剂截止日期取什么值，不在本 spec 的范围内。

#### Scenario: 完整的投资论点

- **THEN** 格式正确
- **WHEN** 证伪条件中代码能检测的部分没有条件
- **THEN** 格式正确

#### Scenario: 缺少一项

- **THEN** 都是格式错误

#### Scenario: 只有空白的文字

- **WHEN** 买入理由、证伪条件或催化剂描述是 "  "
- **THEN** 都是格式错误

#### Scenario: 目标价和代码能检测的条件

- **WHEN** 目标价是 0
- **THEN** 格式错误
- **WHEN** 证伪条件中代码能检测的部分是：价格不高于 0
- **THEN** 格式错误
- **WHEN** 证伪条件中代码能检测的部分是：价格不高于 42，以及涨跌幅不高于 -0.08
- **THEN** 格式正确

### Requirement: 跟进申请的格式

跟进申请 SHALL 包含下面几项，缺少必填的项、或者文字去掉首尾空白后为空，都是格式错误：

| 项 | 说明 |
| --- | --- |
| 原因类型 | 事件后反应、外部日程、价格或指标观察 |
| 引用的对象 | 一个事件或日程项（带 ID），或者一个代码能检测的条件；可以不写 |
| 要回答的问题 | 文字 |
| 可能采取的动作 | 文字 |
| 触发时间 | 带时区的时刻 |

引用的对象可以不写：没有引用具体对象的申请由「跟进审批」拒绝并提示 PM 改为调整复查日。原因类型和引用的对象是否对应、触发时间的范围，也由「跟进审批」检查。

#### Scenario: 完整的跟进申请

- **WHEN** 用基准跟进申请的各项构造跟进申请
- **THEN** 格式正确

#### Scenario: 引用的对象

- **WHEN** 原因是事件后反应，引用事件 "V-7"；原因是价格或指标观察，引用条件"价格不低于 55"；不写引用的对象
- **THEN** 格式都正确
- **WHEN** 引用事件，ID 为空
- **THEN** 格式错误

#### Scenario: 缺少必填的项

- **WHEN** 分别缺少原因类型、要回答的问题、可能采取的动作、触发时间；或者问题是 " "
- **THEN** 都是格式错误

#### Scenario: 触发时间不带时区

- **WHEN** 触发时间是不带时区的 2026-11-19 14:30
- **THEN** 格式错误

### Requirement: 结论的校验

PM 提交结论以后，调度器 SHALL 按下表的顺序检查，给出第一项不通过的原因；全部通过才算有效。不通过的原因作为结果返回，由调用方退回 PM。

| 顺序 | 检查 | 不通过时的原因 |
| --- | --- | --- |
| 1 | 结论的种类是案件类型对应的（见「案件类型」的"结论"列） | 结论不属于这个案件 |
| 2 | 跟进案件的结论没有附跟进申请 | 跟进案件不能再申请跟进 |
| 3 | 复查类案件里，决定是持有、加仓、减仓或继续关注时附了论点更新（续期，下一个复查日以及催化剂到期后新的催化剂都写在里面） | 续期缺少论点更新 |
| 4 | 事件案件：本案件向事件类别要求的子 agent 派过任务 | 缺少事件要求的子 agent |
| 5 | 决定是开仓方案、加仓或升级时：引用的 Result 里，状态是完成的来自至少"研究要求的子 agent 数"（默认 2）个不同子 agent | 研究不足 |

- 调用方传入：案件类型（事件案件带要求的子 agent）、结论、本案件派过任务的子 agent、本案件状态是完成的 Result 各自出自哪个子 agent。没传入的 Result（状态不是完成，或者不是本案件的）不计数
- 第 3 项只检查附了论点更新；复查日和催化剂截止日期是不是新的、取值是否合理，由「复查日与催化剂」检查
- 复盘案件不唤醒 PM，校验复盘案件的结论 SHALL 报错

#### Scenario: 结论不属于这个案件

- **WHEN** 持仓风险事件提交关注的结论（继续关注）；寻股提交候选的结论（保持）；候选评估提交寻股的结论
- **THEN** 都被拒绝，原因是"结论不属于这个案件"
- **WHEN** 关注跟进提交关注的结论（继续关注）
- **THEN** 通过

#### Scenario: 跟进案件不能再申请跟进

- **WHEN** 持仓跟进提交持仓的结论：持有，附基准跟进申请
- **THEN** 被拒绝，原因是"跟进案件不能再申请跟进"
- **WHEN** 关注跟进提交关注的结论：继续关注，附基准跟进申请
- **THEN** 被拒绝，原因是"跟进案件不能再申请跟进"
- **WHEN** 持仓事件提交持仓的结论：持有，附基准跟进申请
- **THEN** 通过

#### Scenario: 复查案件续期要附论点更新

- **WHEN** 持仓复查提交持仓的结论：持有，不附论点更新
- **THEN** 被拒绝，原因是"续期缺少论点更新"
- **WHEN** 持仓复查提交持仓的结论：持有，附基准投资论点作为论点更新
- **THEN** 通过
- **WHEN** 持仓催化剂复查提交持仓的结论：减仓（60 股、市价单），不附论点更新
- **THEN** 被拒绝，原因是"续期缺少论点更新"
- **WHEN** 关注催化剂复查提交关注的结论：继续关注，不附论点更新
- **THEN** 被拒绝，原因是"续期缺少论点更新"
- **WHEN** 关注复查提交关注的结论：继续关注，附基准关注论点作为论点更新
- **THEN** 通过

#### Scenario: 不续期的决定不用附论点更新

- **WHEN** 持仓复查提交持仓的结论：清仓，去向移出；关注复查提交关注的结论：降为候选；关注复查提交关注的结论：开仓方案（基准方案条款、基准投资论点）
- **THEN** 都通过

#### Scenario: 不是复查类案件不要求续期

- **WHEN** 持仓事件提交持仓的结论：持有，不附论点更新；持仓跟进提交持仓的结论：持有，不附论点更新
- **THEN** 都通过

#### Scenario: 缺少事件要求的子 agent

- **GIVEN** BBB 的公告事件开出的关注股事件（要求 Fundamentals）
- **WHEN** 本案件只向 News 和 Quant 派过任务，提交关注的结论：继续关注
- **THEN** 被拒绝，原因是"缺少事件要求的子 agent"
- **WHEN** 本案件还向 Fundamentals 派过任务，它的 Result 是超时
- **THEN** 通过

#### Scenario: 非事件案件不要求派任务

- **WHEN** 候选评估没有派过任何任务，提交候选的结论：保持，不引用 Result
- **THEN** 通过

#### Scenario: 研究要求的边界

- **WHEN** 关注股事件提交关注的结论：开仓方案（基准方案条款、基准投资论点），引用 R-1（News）和 R-2（Quant）
- **THEN** 通过
- **WHEN** 同上，只引用 R-1
- **THEN** 被拒绝，原因是"研究不足"
- **WHEN** 同上，引用 R-1 和 R-3，R-3 也出自 News，状态是完成
- **THEN** 被拒绝，原因是"研究不足"

#### Scenario: 状态不是完成的 Result 不算

- **GIVEN** 本案件还有 R-4，出自 Fundamentals，状态是无信号，没有作为完成的 Result 传入
- **WHEN** 关注股事件提交关注的结论：开仓方案，引用 R-1 和 R-4
- **THEN** 被拒绝，原因是"研究不足"

#### Scenario: 加仓和升级也有研究要求

- **WHEN** 持仓事件提交持仓的结论：加仓（基准方案条款），只引用 R-1
- **THEN** 被拒绝，原因是"研究不足"
- **WHEN** 候选股事件提交候选的结论：升级（基准关注论点），只引用 R-2
- **THEN** 被拒绝，原因是"研究不足"
- **WHEN** 同上两个结论，都引用 R-1 和 R-2
- **THEN** 都通过

#### Scenario: 其他决定没有研究要求

- **WHEN** 持仓事件提交持仓的结论：持有、减仓（60 股、市价单）、清仓（去向移出），都不引用 Result；候选评估提交候选的结论：保持、移出，都不引用 Result；寻股提交寻股的结论：加入 DDD（评分 1），不引用 Result
- **THEN** 都通过

#### Scenario: 多项不通过时给出第一项

- **WHEN** 持仓复查提交持仓的结论：加仓（基准方案条款），不附论点更新，只引用 R-1
- **THEN** 被拒绝，原因是"续期缺少论点更新"
- **GIVEN** BBB 的新闻事件开出的关注股事件（要求 News），本案件只向 Quant 派过任务，状态是完成的 Result 只有 R-2
- **WHEN** 提交关注的结论：开仓方案（基准方案条款、基准投资论点），只引用 R-2
- **THEN** 被拒绝，原因是"缺少事件要求的子 agent"
- **WHEN** 持仓跟进提交关注的结论：继续关注，附基准跟进申请
- **THEN** 被拒绝，原因是"结论不属于这个案件"

#### Scenario: 复盘案件没有结论

- **WHEN** 校验每周复盘或卖出复盘的任何结论
- **THEN** 都报错

### Requirement: 研究要求的配置

研究要求的子 agent 数 SHALL 是可配置项：开仓方案、加仓和升级引用的状态是完成的 Result，至少来自这么多个不同子 agent。默认值 2，MUST 在 1 到 3（子 agent 的个数）之间，否则配置报错。

#### Scenario: 默认配置

- **WHEN** 不传任何配置项新建配置
- **THEN** 研究要求的子 agent 数是 2

#### Scenario: 配置不合法

- **WHEN** 研究要求的子 agent 数配置为 0 或 4
- **THEN** 都配置报错

#### Scenario: 改成 1 个或 3 个

- **GIVEN** 研究要求的子 agent 数配置为 1
- **WHEN** 关注股事件提交关注的结论：开仓方案，只引用 R-1
- **THEN** 通过
- **GIVEN** 研究要求的子 agent 数配置为 3
- **WHEN** 关注股事件提交关注的结论：开仓方案，引用 R-1 和 R-2
- **THEN** 被拒绝，原因是"研究不足"
