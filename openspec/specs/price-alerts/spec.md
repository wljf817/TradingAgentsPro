# price-alerts Specification

## Purpose
到价提醒把股票池里关注股和持仓的论点中价格类的条件设成行情源的到价提醒，每一轮跟着论点和状态同步，提醒推送时叫醒事件检测提前判断条件；条件本身仍由事件检测按行情判断（event-rules spec「论点条件」）。

## Requirements

### Requirement: 需要的到价提醒

需要的到价提醒 SHALL 由股票池里每只股票的状态和论点算出：关注取关注论点的入场条件；持仓取"价格不低于投资论点的目标价"和证伪条件中代码能检测的部分；候选没有。每条条件按下表对应一个到价提醒，或者没有：

| 条件 | 到价提醒 |
| --- | --- |
| 价格不低于 v | 价格涨到 v |
| 价格不高于 v | 价格跌到 v |
| 涨跌幅不低于 v，v ≥ 0 | 当日涨幅达到 v |
| 涨跌幅不高于 v，v ≤ 0 | 当日跌幅达到 −v |
| 涨跌幅不低于 v，v < 0；涨跌幅不高于 v，v > 0 | 没有：只由事件检测每一轮判断 |
| 成交量不低于 v | 当日成交量达到 v |

- 一个到价提醒由股票、类型和值确定；几条条件对应同一个到价提醒时只要一个
- 只有股票池里的股票：`/plan` 买入、不在股票池里的持仓没有论点，不要到价提醒

本 spec 的场景除非另有说明，都使用下面的基准数据：股票池里 AAA 是候选；BBB 是关注，入场条件是价格不高于 95；CCC 是持仓，目标价 120，证伪条件中代码能检测的部分是价格不高于 94；行情源上没有任何到价提醒；"做一轮"指事件检测做一轮（event-detection spec「一轮」）。

#### Scenario: 基准数据要的提醒

- **WHEN** 算需要的到价提醒
- **THEN** 有三个：BBB 价格跌到 95；CCC 价格涨到 120；CCC 价格跌到 94
- **AND** AAA 没有

#### Scenario: 三类条件

- **GIVEN** BBB 的入场条件改为：价格不低于 110、涨跌幅不低于 0.03、涨跌幅不高于 -0.05、成交量不低于 2,000,000 股
- **WHEN** 算需要的到价提醒
- **THEN** BBB 有四个：价格涨到 110、当日涨幅达到 0.03、当日跌幅达到 0.05、当日成交量达到 2,000,000

#### Scenario: 对应不了的涨跌幅

- **GIVEN** BBB 的入场条件改为：涨跌幅不低于 -0.02、涨跌幅不高于 0.01
- **WHEN** 算需要的到价提醒
- **THEN** BBB 没有到价提醒

#### Scenario: 一样的提醒只要一个

- **GIVEN** CCC 的证伪条件中代码能检测的部分改为价格不低于 120
- **WHEN** 算需要的到价提醒
- **THEN** CCC 只有一个价格涨到 120

### Requirement: 同步

事件检测的每一轮 SHALL 把行情源上系统设的到价提醒同步成这一轮需要的那一组：

- 系统设的、不在需要的里面的，删掉
- 需要的、系统还没设的，设上
- 已经设着的不动，不重新设
- 不是系统设的到价提醒（比如在 moomoo app 里手工设的）不读进来、不删、不改
- 同步写 Python 日志：设了几个、删了几个（有变化时写 INFO）；不写程序日志

所以论点更新、升降级、买入卖出、移出以后，最多一轮到价提醒就跟上；重启以后不重复设。

#### Scenario: 第一轮设齐

- **WHEN** 做一轮
- **THEN** 行情源上设了三个到价提醒：BBB 价格跌到 95；CCC 价格涨到 120；CCC 价格跌到 94
- **WHEN** 之后一轮，股票池没有变
- **THEN** 行情源没有收到设置和删除的请求

#### Scenario: 论点更新

- **GIVEN** 已经设好基准数据的三个到价提醒
- **WHEN** CCC 的投资论点更新，目标价改为 130，之后一轮
- **THEN** 删掉 CCC 价格涨到 120，设上 CCC 价格涨到 130；另外两个不动

#### Scenario: 状态变化

- **GIVEN** 已经设好基准数据的三个到价提醒
- **WHEN** CCC 清仓变为候选，BBB 移出股票池，之后一轮
- **THEN** 三个都删掉
- **WHEN** AAA 升级为关注，入场条件是价格不高于 40，之后一轮
- **THEN** 设上 AAA 价格跌到 40

#### Scenario: 手工设的提醒不动

- **GIVEN** 行情源上有一个不是系统设的 BBB 价格跌到 80
- **WHEN** 做一轮
- **THEN** 设上基准数据的三个到价提醒；BBB 价格跌到 80 还在

#### Scenario: 重启以后

- **GIVEN** 已经设好基准数据的三个到价提醒，进程重启
- **WHEN** 做一轮
- **THEN** 行情源没有收到设置和删除的请求

### Requirement: 同步失败

同步时 SHALL 按下表处理，事件检测的其余部分照常，论点条件照常每一轮按行情判断：

| 失败 | 处理 |
| --- | --- |
| 读不到系统设的到价提醒（行情源不可用） | 这一轮不同步，写一条 WARNING；下一轮再同步 |
| 一个到价提醒设置或删除失败（比如超过行情源的额度） | 写一条 WARNING，写明是哪个提醒和行情源给的原因；其余照做；下一轮再试 |

#### Scenario: 行情源不可用

- **GIVEN** 读系统设的到价提醒时行情源不可用
- **WHEN** 做一轮
- **THEN** 写一条 WARNING；行情源没有收到设置和删除的请求
- **WHEN** 行情源恢复，之后一轮
- **THEN** 设上基准数据的三个到价提醒

#### Scenario: 一个提醒设不上

- **GIVEN** 行情源设置 CCC 价格涨到 120 时报额度已满
- **WHEN** 做一轮
- **THEN** 写一条 WARNING，写明 CCC 价格涨到 120 和额度已满；BBB 价格跌到 95、CCC 价格跌到 94 都设上了
- **WHEN** 之后一轮，行情源不再报错
- **THEN** 设上 CCC 价格涨到 120

### Requirement: 推送

行情源推送任何一个到价提醒触发时，SHALL 叫醒事件检测（event-detection spec「什么时候做一轮」）：

- 推送本身不是事件：不记下事件、不排队、不写程序日志；事件只在之后那一轮按行情判断出来
- 行情源只在越过提醒的值时推送，设上时已经满足的条件不会推送：它们由每一轮照常判断出来
- 不论推送的是不是系统设的提醒、推送的内容是什么，都只叫醒一次
- 推送在行情源自己的线程里到达，只做叫醒，不读写数据库、不拿锁

#### Scenario: 推送以后的那一轮判断出事件

- **GIVEN** 已经设好基准数据的三个到价提醒；事件检测 15:00:04Z 做完一轮，在等下一轮
- **WHEN** 15:00:20Z 行情源推送 BBB 价格跌到 95 触发；这时 BBB 最新价 94.9
- **THEN** 事件检测 15:00:20Z 开始一轮，排进 BBB 的入场条件满足事件

#### Scenario: 推送以后行情又回去了

- **GIVEN** 同上
- **WHEN** 15:00:20Z 行情源推送 BBB 价格跌到 95 触发；那一轮读到的 BBB 最新价 95.2
- **THEN** 没有 BBB 的入场条件满足事件，没有程序日志
