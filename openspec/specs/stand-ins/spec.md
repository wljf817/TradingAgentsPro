# stand-ins Specification

## Purpose
替身按脚本代替 PM、Critic、三个子 agent 和 Reviewer，让案件流程在接入模型以前就能在模拟盘里跑通：每种案件类型给出一个固定的、能通过已有校验的结论，方案和论点的数由快照和配置算出，同样的请求总是给出同样的输出。M5 用真实模型替换它们。

## Requirements

### Requirement: 替身

替身 SHALL 实现 agent-calls spec 的调用接口，代替六个 agent 交回输出：

- 不调用任何模型和外部服务，SHALL NOT 抛出调用错误：Agent 网关的每次调用都在主模型上一次成功
- 输出只由请求（快照、案件上下文、对话、Task）和配置决定：同样的请求 SHALL 给出同样的输出，不读时钟、不生成 ID
- 每次请求的用量是输入 0、输出 0：照常记一条费用，费用是 0
- 回答、理由、问题、证伪条件、复盘总结等文字都是固定的，写明是替身给出的

本 spec 的场景除非另有说明，都使用默认配置和下面的基准数据：

- 当前时刻 2026-10-14 15:00Z（周三，盘中），交易日历是纽交所日历；今天 2026-10-14 之后第 3 个交易日 10-19，第 5 个 10-21，第 8 个 10-26
- 模型的配置是「替身的模型」；Agent 网关、调度器和复查日检查都用各自的默认配置
- 股票池：AAA 候选，板块 XLK；BBB 关注，板块 XLV；CCC 持仓，板块 XLE
- 每个案件的第 1 版快照，生成时刻 2026-10-14 15:00Z，交易日 2026-10-14：
  - 账户权益 100,000；CCC 持仓 100 股，均价 80
  - 行情：AAA 最新价 30、前一交易日收盘价 29（条目 `s1/quote/AAA`）；BBB 52、50（`s1/quote/BBB`）；CCC 85、84（`s1/quote/CCC`）；市场状态条目 `s1/market`
  - 寻股的快照另有粗筛名单，依次是 DDD、EEE、GGG（条目 `s1/screen`）
- 案件上下文：问题是案件类型的问题；BBB 的关注论点是 stock-pool spec 的基准关注论点，CCC 的投资论点是 case-types spec 的基准投资论点，复查日都是 2026-10-21，催化剂都是"Q3 财报"、截止日期 2026-10-29、不引用日程项或事件。"复查日到期的论点"指只把复查日改为 2026-10-14；"催化剂到期的论点"指只把催化剂截止日期改为 2026-10-14
- 替身的信号：评估窗口 5，评分 1，置信度 0.5，数据截至 2026-10-14 15:00Z（快照的生成时刻），理由和主要风险是固定的文字
- 新的催化剂：描述"替身催化剂，截止 2026-10-26"，截止日期 2026-10-26，不引用日程项或事件
- "Quant 的任务"指任务类型价格反应、股票是案件的股票、输入是案件股票的行情条目的任务请求；"Fundamentals 的任务""News 的任务"同理，任务类型分别是财报对比预期、事件影响评估
- 替身的子 agent 经 Agent 网关运行任务，任务都完成

#### Scenario: 同样的请求给出同样的输出

- **WHEN** 用同样的案件上下文、快照和对话调用两次 PM 替身；用同样的 Task 和快照调用两次 Quant 替身
- **THEN** 两次的输出都相同

#### Scenario: 用量和费用都是 0

- **WHEN** 经 Agent 网关调用一次 PM 替身
- **THEN** 记下一条费用：模型 `standin/pm`，输入 0、输出 0，费用 0

### Requirement: 替身的模型

替身的模型配置 SHALL 是下表，每个 agent 只有主模型、没有备用模型，单价都是 0：

| agent | 模型（厂商/模型名） |
| --- | --- |
| PM | standin/pm |
| News | standin/news |
| Quant | standin/quant |
| Fundamentals | standin/fundamentals |
| Critic | standin-critic/critic |
| Reviewer | standin/reviewer |

- Critic 和 PM 的厂商不同，满足 model-fallback spec「厂商校验」
- 替身给出的输出，实际使用的模型就是表里这个 agent 的模型，不是备用模型；Result 和案件记录照常记下它

#### Scenario: 替身的模型配置

- **WHEN** 用替身的模型配置
- **THEN** 配置正确；PM、News、Quant、Fundamentals、Critic、Reviewer 的模型依次是上表的六个，都没有备用模型，单价都是 0

#### Scenario: 实际使用的模型

- **WHEN** 经 Agent 网关运行 BBB 的 Quant 的任务
- **THEN** Result 的模型是 `standin/quant`，不是备用模型

### Requirement: PM 替身派发任务

PM 替身在研究阶段 SHALL 按下表决定派不派任务：

| 案件和结论 | 派给 |
| --- | --- |
| 结论是开仓方案或升级（见「PM 替身的结论」） | Quant 和 Fundamentals；事件案件另加事件要求的子 agent |
| 其他事件案件 | 事件要求的子 agent |
| 其他案件 | 不派 |

- 要派任务、对话里还没有派发任务时，交回派发任务：每个子 agent 一个请求，News 是事件影响评估，Quant 是价格反应，Fundamentals 是财报对比预期；按 News、Quant、Fundamentals 的顺序；股票是案件的股票；问题是固定的文字；输入是案件股票的行情条目 ID，快照里没有这个条目时为空
- 不派任务，或者对话里已经有派发任务时，交回提交结论；结论引用对话里全部状态是完成的 Result，按交回的先后、不重复
- 结论被退回重交时，再交回同样的结论

#### Scenario: 开仓方案派给 Quant 和 Fundamentals

- **WHEN** 调用 BBB 的入场条件满足开出的关注股事件的 PM 替身，对话为空
- **THEN** 交回派发任务：Quant 的任务、Fundamentals 的任务（入场条件满足要求的 Quant 已经在里面）
- **WHEN** 接着两个任务完成（T-1、T-2），再调用
- **THEN** 交回开仓方案，引用 T-1 和 T-2

#### Scenario: 升级派给 Quant 和 Fundamentals

- **WHEN** 调用 AAA 的候选评估的 PM 替身，对话为空
- **THEN** 交回派发任务：Quant 的任务、Fundamentals 的任务

#### Scenario: 其他事件案件派给事件要求的子 agent

- **WHEN** 调用 CCC 的新闻事件开出的持仓事件、CCC 的价格和成交量异动开出的持仓风险事件、AAA 的公告事件开出的候选股事件、BBB 的新闻事件开出的关注股事件的 PM 替身，对话都为空
- **THEN** 依次交回派发任务：CCC 的 News 的任务；CCC 的 Quant 的任务；AAA 的 Fundamentals 的任务；BBB 的 News 的任务

#### Scenario: 其他案件不派任务

- **WHEN** 调用 CCC 的持仓复查、BBB 的关注复查、寻股、CCC 的持仓跟进的 PM 替身，对话都为空
- **THEN** 都直接交回提交结论，不引用 Result

#### Scenario: 案件股票没有行情条目

- **GIVEN** CCC 的新闻事件开出的持仓事件，快照里没有 CCC 的行情条目
- **WHEN** 调用 PM 替身，对话为空
- **THEN** 交回 CCC 的 News 的任务，输入为空

#### Scenario: 只派一次，被拒绝或超时的 Result 不引用

- **GIVEN** BBB 的入场条件满足开出的关注股事件，对话有一轮派发任务：T-1 完成，T-2 超时
- **WHEN** 调用 PM 替身
- **THEN** 交回开仓方案，只引用 T-1，不再派任务

#### Scenario: 退回以后再交同样的结论

- **GIVEN** 上一个场景的开仓方案被退回，原因是"研究不足"
- **WHEN** 再调用 PM 替身
- **THEN** 交回和上一次相同的开仓方案

### Requirement: PM 替身的结论

PM 替身 SHALL 按案件类型交回下表的结论：

| 案件类型 | 结论 |
| --- | --- |
| 持仓风险事件、持仓事件、持仓跟进 | 持仓的结论：持有，不附内容 |
| 持仓复查 | 持仓的结论：持有，附续期的投资论点（见「续期」） |
| 持仓催化剂复查 | 持仓的结论：清仓，市价单，去向是移出股票池 |
| 关注股事件，事件类别是入场条件满足 | 关注的结论：开仓方案，附投资论点（见「开仓方案」） |
| 关注股事件，其他事件类别 | 关注的结论：继续关注，不附内容 |
| 关注复查、关注催化剂复查 | 关注的结论：继续关注，附续期的关注论点（见「续期」） |
| 关注跟进 | 关注的结论：继续关注，不附内容 |
| 候选股事件 | 候选的结论：保持 |
| 候选评估 | 候选的结论：升级，附关注论点（见「升级」） |
| 寻股 | 寻股的结论：加入粗筛名单的前几只（见「寻股」），不删除 |
| 每周复盘、卖出复盘 | 没有：不唤醒 PM，由 Reviewer 替身处理 |

- 回答和理由是固定的文字；持仓、关注、候选的结论的信号见「PM 替身的信号」
- 不附跟进申请

#### Scenario: 持仓的事件和跟进都持有

- **WHEN** CCC 的持仓风险事件、持仓事件、持仓跟进的 PM 替身提交结论
- **THEN** 都是持仓的结论：持有，没有交易方案、论点更新和跟进申请

#### Scenario: 持仓复查持有并续期

- **GIVEN** CCC 的持仓复查，CCC 的投资论点是复查日到期的论点
- **WHEN** PM 替身提交结论
- **THEN** 持仓的结论：持有，论点更新是 CCC 的投资论点只把复查日改为 2026-10-21

#### Scenario: 持仓催化剂复查清仓

- **WHEN** CCC 的持仓催化剂复查的 PM 替身提交结论
- **THEN** 持仓的结论：清仓，交易方案是市价单、不写股数，去向是移出，不附关注论点

#### Scenario: 入场条件满足时开仓

- **WHEN** BBB 的入场条件满足开出的关注股事件的 PM 替身提交结论
- **THEN** 关注的结论：开仓方案，交易方案和投资论点见「开仓方案」的基准场景

#### Scenario: 关注股的其他事件继续关注

- **WHEN** BBB 的新闻、公告、财报发布、价格和成交量异动开出的关注股事件的 PM 替身提交结论
- **THEN** 都是关注的结论：继续关注，不附论点更新和跟进申请

#### Scenario: 关注复查继续关注并续期

- **GIVEN** BBB 的关注复查，BBB 的关注论点是复查日到期的论点
- **WHEN** PM 替身提交结论
- **THEN** 关注的结论：继续关注，论点更新是 BBB 的关注论点只把复查日改为 2026-10-21

#### Scenario: 关注催化剂复查换新的催化剂

- **GIVEN** BBB 的关注催化剂复查，BBB 的关注论点是催化剂到期的论点
- **WHEN** PM 替身提交结论
- **THEN** 关注的结论：继续关注，论点更新是 BBB 的关注论点把复查日改为 2026-10-21、催化剂改为新的催化剂

#### Scenario: 关注跟进继续关注

- **WHEN** BBB 的关注跟进的 PM 替身提交结论
- **THEN** 关注的结论：继续关注，不附内容

#### Scenario: 候选股事件保持

- **WHEN** AAA 的新闻事件开出的候选股事件的 PM 替身提交结论
- **THEN** 候选的结论：保持

#### Scenario: 候选评估升级

- **WHEN** AAA 的候选评估的 PM 替身提交结论
- **THEN** 候选的结论：升级，关注论点见「升级」的基准场景

#### Scenario: 寻股加入粗筛的前 2 名

- **WHEN** 寻股的 PM 替身提交结论
- **THEN** 寻股的结论：加入 DDD、EEE，不删除

#### Scenario: 复盘案件不唤醒 PM

- **WHEN** 用每周复盘的快照、CCC 的卖出复盘的快照调用 PM 替身
- **THEN** 都报错：复盘案件由 Reviewer 替身处理（见「Reviewer 替身」）

### Requirement: 参考价

方案和论点里的价格 SHALL 从参考价算出：快照里案件股票的行情条目的最新价；开盘以后还没有成交、最新价为空时，用前一交易日收盘价。只有开仓方案和升级要用参考价；这时快照里没有案件股票的行情条目，SHALL 报错，不给出结论。

#### Scenario: 用最新价

- **WHEN** BBB 的行情最新价 52、前一交易日收盘价 50
- **THEN** 参考价 52

#### Scenario: 还没有成交时用前一交易日收盘价

- **WHEN** BBB 的行情没有最新价、前一交易日收盘价 50，入场条件满足开出的关注股事件的 PM 替身提交结论
- **THEN** 参考价 50；限价 50.25，止损价 47.74，股数 199，目标价 55.28

#### Scenario: 没有行情条目时不能开仓和升级

- **WHEN** 快照里没有 BBB 的行情条目，入场条件满足开出的关注股事件的 PM 替身在任务完成以后提交结论；快照里没有 AAA 的行情条目，候选评估的 PM 替身提交结论
- **THEN** 都报错

### Requirement: 开仓方案

开仓方案的交易方案和投资论点 SHALL 按下面算，价格按最小变动单位四舍五入（1 美元及以上到 0.01，低于 1 美元到 0.0001）：

| 项 | 取值 |
| --- | --- |
| 订单类型 | 限价单 |
| 限价 | 参考价 ×（1 +"限价的加价比例"） |
| 止损价 | 限价 ×（1 −"止损的比例"） |
| 股数 | 权益 ×"开仓金额占权益的比例"÷ 限价，向下取整；不足 1 股时是 1 股 |
| 紧急阈值 | "紧急阈值" |
| 有效期、允许价格偏离 | 不写，由风控使用默认值 |
| 投资论点 | 买入理由和证伪条件是固定的文字；催化剂是新的催化剂（截止日期是今天之后第"催化剂的间隔"个交易日）；目标价是限价 ×（1 +"目标价的比例"）；证伪条件中代码能检测的部分没有；复查日是今天之后第"复查日的间隔"个交易日 |

今天是快照的交易日。新的催化剂的描述是"替身催化剂，截止 <截止日期>"。

#### Scenario: 开仓方案的基准

- **WHEN** BBB 的入场条件满足开出的关注股事件的 PM 替身提交结论
- **THEN** 交易方案：限价单，限价 52.26，止损价 49.65，191 股，紧急阈值 0.08，不写有效期和允许价格偏离
- **AND** 投资论点：目标价 57.49，催化剂是新的催化剂，复查日 2026-10-21，证伪条件中代码能检测的部分没有

#### Scenario: 不足 1 股时买 1 股

- **WHEN** BBB 的最新价是 12,000，入场条件满足开出的关注股事件的 PM 替身提交结论
- **THEN** 限价 12,060，股数 1

### Requirement: 升级

候选评估升级时附的关注论点 SHALL 是：看好理由和证伪条件是固定的文字；入场条件一条：价格不高于参考价 ×（1 +"入场条件的比例"），按最小变动单位四舍五入；催化剂是新的催化剂；复查日是今天之后第"复查日的间隔"个交易日。

#### Scenario: 升级的关注论点

- **WHEN** AAA 的候选评估的 PM 替身提交结论
- **THEN** 关注论点：入场条件价格不高于 30.60，催化剂是新的催化剂，复查日 2026-10-21

### Requirement: 续期

持仓复查、关注复查、关注催化剂复查的续期 SHALL 附一份论点更新：照抄这只股票现在的论点（持仓是投资论点，关注是关注论点），只改：

- 复查日改为今天之后第"复查日的间隔"个交易日
- 原来的催化剂已经到期（截止日期不晚于今天，review-dates spec「催化剂到期以后」）时，催化剂改为新的催化剂；没到期时原样保留

#### Scenario: 催化剂没到期时原样保留

- **GIVEN** CCC 的持仓复查，CCC 的投资论点是复查日到期的论点
- **WHEN** PM 替身提交结论
- **THEN** 论点更新的复查日 2026-10-21，催化剂仍是"Q3 财报"、截止日期 2026-10-29，其余各项和原来的相同

#### Scenario: 催化剂到期时换新的

- **GIVEN** BBB 的关注催化剂复查，BBB 的关注论点是催化剂到期的论点
- **WHEN** PM 替身提交结论
- **THEN** 论点更新的复查日 2026-10-21，催化剂是新的催化剂，入场条件、看好理由和证伪条件和原来的相同

#### Scenario: 到期当天也换新的

- **GIVEN** CCC 的持仓复查，CCC 的投资论点复查日和催化剂截止日期都是 2026-10-14
- **WHEN** PM 替身提交结论
- **THEN** 论点更新的复查日 2026-10-21，催化剂是新的催化剂

### Requirement: 寻股

寻股的结论 SHALL 按快照里粗筛名单的先后加入前"寻股加入的只数"只，名单不足时全部加入，名单为空时不加入：

- 每只加入的候选：理由是"替身：粗筛第 n 名"（n 是名次），信号见「PM 替身的信号」
- 不删除股票；加入是否通过由股票池检查（stock-pool spec「加入候选」）

#### Scenario: 名单不足

- **WHEN** 粗筛名单只有 DDD，寻股的 PM 替身提交结论
- **THEN** 只加入 DDD，理由"替身：粗筛第 1 名"
- **WHEN** 粗筛名单为空
- **THEN** 不加入、不删除，回答和理由照常写

### Requirement: PM 替身的信号

PM 替身的结论里的信号 SHALL 是替身的信号：

| 结论 | 引用的条目 |
| --- | --- |
| 持仓、关注、候选的结论 | 案件股票的行情条目；快照里没有时引用市场状态条目 |
| 寻股加入的每只候选 | 粗筛结果的条目 |

#### Scenario: 引用案件股票的行情

- **WHEN** CCC 的持仓事件的 PM 替身提交结论
- **THEN** 信号是替身的信号，引用 `s1/quote/CCC`

#### Scenario: 没有行情条目时引用市场状态

- **WHEN** 快照里没有 CCC 的行情条目，CCC 的持仓事件的 PM 替身提交结论
- **THEN** 信号引用 `s1/market`

#### Scenario: 寻股的候选引用粗筛结果

- **WHEN** 寻股的 PM 替身提交结论
- **THEN** DDD 和 EEE 的信号都是替身的信号，引用 `s1/screen`

### Requirement: PM 替身回应质询

PM 替身回应 Critic 的质询时 SHALL 维持方案：逐条回应，条数和这次质询的条数相同，每条是固定的文字，不写方案条款。

#### Scenario: 维持

- **GIVEN** BBB 的开仓方案被 Critic 质询两条
- **WHEN** 调用 PM 替身（回应）
- **THEN** 回应是维持，两条回应，没有方案条款

### Requirement: Critic 替身

Critic 替身 SHALL 不派补充研究，第一次审核就通过：理由是固定的文字，不写质询，不引用 Result。开仓类和退出类方案都一样。

#### Scenario: 通过开仓方案和退出方案

- **WHEN** Critic 替身审核 BBB 的开仓方案；审核 CCC 的清仓方案
- **THEN** 都是通过，没有质询，不引用 Result

### Requirement: 子 agent 替身

News、Quant、Fundamentals 的替身 SHALL 对任何任务都交回替身的信号的 JSON 文本，引用 Task 的输入；输入为空时引用快照的市场状态条目。

#### Scenario: 引用 Task 的输入

- **WHEN** 经 Agent 网关运行 BBB 的 Quant 的任务
- **THEN** 任务完成，信号是替身的信号，引用 `s1/quote/BBB`，模型 `standin/quant`

#### Scenario: 输入为空

- **WHEN** 经 Agent 网关运行 CCC 的 News 的任务，输入为空
- **THEN** 任务完成，信号引用 `s1/market`

### Requirement: Reviewer 替身

Reviewer 替身 SHALL 对任何复盘案件交回同一份复盘报告，总结是固定的文字。

#### Scenario: 复盘报告

- **WHEN** 调用每周复盘、CCC 的卖出复盘的 Reviewer 替身
- **THEN** 都交回总结相同的复盘报告

### Requirement: 替身的结论通过已有的校验

PM 替身给出的结论 SHALL 在默认配置下通过已有的检查：

- 结论里的信号（signal-format spec「结论里的信号」），收到结论的时刻不早于快照的生成时刻
- 备用模型的限制（model-fallback spec「备用模型的限制」）：替身的模型都是主模型
- 结论的校验（case-types spec「结论的校验」），派过任务的子 agent 和完成的 Result 是替身经 Agent 网关派发、运行得到的
- 论点里的日期（review-dates spec「检查论点里的日期」）：开仓方案的投资论点、升级的关注论点是新设，续期的论点更新是续期；持仓亏损超过"不能推后的亏损幅度"时也通过
- 交易方案的格式（risk-rules spec「交易方案的格式」）：补上方案 ID、股票和板块以后变成交易方案

#### Scenario: 每种案件类型的结论都通过

- **WHEN** 依次跑持仓风险事件（价格和成交量异动）、持仓事件（新闻）、持仓复查（复查日到期的论点）、持仓催化剂复查、持仓跟进、关注股事件（入场条件满足）、关注股事件（新闻）、关注复查（复查日到期的论点）、关注催化剂复查（催化剂到期的论点）、关注跟进、候选股事件（公告）、候选评估、寻股的 PM 替身，直到提交结论
- **THEN** 每个结论都通过上面各项检查
- **AND** 开仓方案变成 BBB、板块 XLV、买入的交易方案；清仓方案变成 CCC、板块 XLE、清仓的交易方案

#### Scenario: 亏损的持仓续期也通过

- **GIVEN** CCC 的持仓复查，CCC 的投资论点是复查日到期的论点，浮动盈亏比例 -0.10
- **WHEN** 检查 PM 替身的论点更新的日期
- **THEN** 通过：复查日是今天之后第 5 个交易日，不晚于复查日默认间隔

### Requirement: 替身的配置

替身 SHALL 有下面的可配置项：

| 配置项 | 含义 | 默认值 | 取值 |
| --- | --- | --- | --- |
| 信号的评估窗口 | 替身的信号的评估窗口，交易日数 | 5 | 正整数 |
| 信号的评分 | 替身的信号的评分 | 1 | -2 到 2 的整数 |
| 信号的置信度 | 替身的信号的置信度 | 0.5 | 0 到 1，含两端 |
| 开仓金额占权益的比例 | 开仓方案的股数按它算 | 0.10 | 大于 0，不大于 1 |
| 限价的加价比例 | 限价比参考价高出的比例 | 0.005 | 不小于 0，小于 1 |
| 止损的比例 | 止损价比限价低的比例 | 0.05 | 大于 0，小于 1 |
| 紧急阈值 | 开仓方案的紧急阈值 | 0.08 | 大于 0，小于 1 |
| 目标价的比例 | 目标价比限价高出的比例 | 0.10 | 大于 0 |
| 入场条件的比例 | 升级的入场条件比参考价高出的比例 | 0.02 | 不小于 0 |
| 复查日的间隔 | 新设和续期的复查日是今天之后第几个交易日 | 5 | 正整数 |
| 催化剂的间隔 | 新的催化剂的截止日期是今天之后第几个交易日 | 8 | 正整数 |
| 寻股加入的只数 | 寻股加入粗筛名单的前几只 | 2 | 正整数 |

取值不合法时 MUST 配置报错。替身的配置不和别的模块的配置互相检查：比如评估窗口不在 Agent 网关的选项里时，替身的信号照样给出，由网关按格式不合法处理。

#### Scenario: 默认配置

- **WHEN** 不传任何配置项新建配置
- **THEN** 各项是上表的默认值

#### Scenario: 配置不合法

- **WHEN** 信号的评估窗口配置为 0；信号的评分配置为 3；信号的置信度配置为 1.1；开仓金额占权益的比例配置为 0 或 1.5；限价的加价比例配置为 -0.01；止损的比例配置为 0 或 1；紧急阈值配置为 1；目标价的比例配置为 0；入场条件的比例配置为 -0.01；复查日的间隔、催化剂的间隔、寻股加入的只数配置为 0
- **THEN** 都配置报错

#### Scenario: 改配置改变输出

- **GIVEN** 开仓金额占权益的比例配置为 0.2
- **WHEN** BBB 的入场条件满足开出的关注股事件的 PM 替身提交结论
- **THEN** 股数 382
- **GIVEN** 复查日的间隔配置为 3，催化剂的间隔配置为 5
- **WHEN** AAA 的候选评估的 PM 替身提交结论
- **THEN** 关注论点的复查日 2026-10-19，催化剂截止日期 2026-10-21，描述"替身催化剂，截止 2026-10-21"
