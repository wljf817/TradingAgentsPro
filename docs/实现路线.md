# 实现路线

系统要做什么以 [Proposal](AI%20Agent%20美股交易系统需求%20Proposal.md) 为准，本文只定先做什么、后做什么，并在末尾的「进度」里记录进度。每个里程碑由若干 OpenSpec 变更组成，一个变更只改架构图里的一个节点（`shared` 除外）。

## 原则

- 先写纯逻辑和测试，再接数据库、券商和模型
- 交易侧先于案件侧，因为会直接亏钱的逻辑都在交易侧
- 交易侧内核写完就接 Alpaca 模拟盘，订单和止损逻辑要尽早用真实券商检验。实盘用 moomoo，和模拟盘共用业务代码，只换券商适配器
- 模型最后接：案件流程先用按脚本给结论的替身跑通

## 里程碑

```
M0 骨架 -> M1 交易侧内核 -> M2 交易侧接模拟盘 -> M3 案件侧内核
  -> M4 案件流程跑通 -> M5 接入模型 -> M6 复盘与评估 -> M7 小资金实盘
```

| 里程碑 | 内容 | 完成标志 |
| --- | --- | --- |
| M0 骨架 | 分层目录、依赖检查、架构测试 | 检查全部进入 CI |
| M1 交易侧内核 | 依次是：交易日历与时钟；风控规则、额度预留、下单前再校验、费用估算；订单状态机、止损保护、对账；紧急风险退出；降级策略 | 每条规则都有 spec 和测试，不接外部系统 |
| M2 交易侧接模拟盘 | 先定共享状态库方案；接入 PostgreSQL、DBOS、Alpaca 模拟盘、moomoo 行情、Discord；本地备用止损、紧急退出、收盘对账、健康监控 | 手工录入的交易方案在模拟盘走完风控、确认、下单、止损和对账；连续 10 个交易日对账无差异 |
| M3 案件侧内核 | 股票池、调度器、Agent 网关、人工确认的规则 | 同 M1 |
| M4 案件流程跑通 | 先定新闻、一致预期和寻股的数据源；状态库快照、案件工作流和队列、定时心跳、事件检测、案件记录和程序日志；PM 和 Critic 用替身 | 三种驱动都能开案件，排队符合 Proposal，替身给出的方案能在模拟盘下单 |
| M5 接入模型 | PM、子 agent、Critic；共享上下文；查询工具 | 真实模型在模拟盘运行，备用模型、预算和降级都生效 |
| M6 复盘与评估 | Reviewer、经验库、信号评估、快照回放 | 复盘自动产出；能回放案件，比较两个 prompt 版本 |
| M7 小资金实盘 | 先定上线门槛；接入 moomoo 实盘交易，达到门槛后切到实盘 | 验证模拟盘测不了的部分：moomoo 的订单和止损单、费用和结算 |

## 进度

状态分三种：未开始、进行中、完成。

- 里程碑开始时改为进行中，并在下面加一个小节，列出拆好的变更；变更全部完成、并且达到完成标志后改为完成
- 变更 propose 以后改为进行中，归档以后改为完成，同时更新总览里的完成数
